
## ErreurAvecDélaiAsynchrone (Fonction)

***En anglais : ErrorWithTimeoutAsynchronous***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Affiche un message d'erreur personnalisé dans une fenêtre d'erreur système non bloquante pendant un délai défini. Lorsque le délai est écoulé, la fenêtre système se ferme automatiquement. 

Remarques: 

- **Cette fenêtre d'erreur est non bloquante**. Le code WLangage qui suit l'appel à la fonction **ErreurAvecDélaiAsynchrone** continue de s'exécuter. Pour fermer la fenêtre, l'utilisateur doit valider le bouton OK ou attendre la fin du délai. Quand l'utilisateur clique sur le bouton "OK", il est possible d'exécuter le code d'une procédure WLangage.

- Dans le code WLangage suivant l'appel de la fonction, l'ouverture d'une autre fenêtre modale n'est pas possible avant la fermeture de la boîte de dialogue. 

- ![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png)![Mac Catalyst](https://doc.pcsoft.fr/ext/images/us/CATALYST.png) Pour utiliser cette fonction, vous devez intégrer une boîte de dialogue personnalisée dans votre projet. Pour plus de détails, consultez [Personnaliser les boîtes de dialogue](../WDLang1/3021003.md).

- ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) WINDEV permet d'appliquer le thème de votre projet à cette boîte de dialogue. Pour plus de détails, consultez [Personnaliser les boîtes de dialogue](../WDLang1/3021003.md).





<a name="Exemple1"></a>
<a name="sample_code"></a>

## Exemple


```wl
// Affiche "Une erreur a été détectée" dans une fenêtre d'erreur 
// Cette fenêtre d'erreur se fermera automatiquement après 10 secondes
ErreurAvecDélaiAsynchrone(1000, "Une erreur a été détectée")
```

<a name="XSYNTAXE"></a>

## Syntaxe
<a name="SYNTAXE1"></a>

`ErreurAvecDélai(<Délai> , <Texte> [, <Procédure WLangage>])`
---

**`<Délai> : (Entier ou Durée)`**

Délai (exprimé en centièmes de seconde) avant la fermeture automatique de la fenêtre d'erreur. Ce paramètre peut correspondre à: 

- un entier correspondant au nombre de centièmes de seconde, 

- une variable de type Durée, 

- l'indication directe de la durée (par exemple 1 s ou 10 ms). 




**`<Texte> : (Chaîne de caractères)`**

Texte à afficher.

**`<Procédure WLangage> : (Nom de procédure ou procédure lambda, optionnel)`**

Nom de la procédure WLangage (appelée "callback") appelée lorsque l'utilisateur clique sur le bouton "OK" de la fenêtre d'erreur. 

Cette procédure WLangage peut correspondre à: 

- un nom de procédure globale, 

- un nom de procédure interne, 

- une procédure lambda. 


Si ce paramètre n'est pas spécifié, aucune procédure n'est exécutée lorsque l'utilisateur clique sur le bouton "OK" de la fenêtre d'erreur.

## Remarques




### Caractéristiques de la boîte de dialogue
<a name="caracteristiques_boite_dialogue_ELTPARAGRAPHE000075"></a>



- Le titre de la boîte de dialogue correspond au titre de la fenêtre (ou page) en cours.
	![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png) Pour respecter les spécifications du système, le titre de la boîte de dialogue est vide par défaut. Pour définir ce titre, utilisez la fonction [TitreSuivant](../WDLang1/3038043.md).

- Pour modifier ou définir le titre de la boîte de dialogue, utilisez la fonction [TitreSuivant](../WDLang1/3038043.md).




- Le message est cadré à gauche.

- Le libellé du bouton dépend de la langue d'exécution de Windows.

- Le nombre maximum de caractères affichés est limité à 4096. Si une chaîne plus grande est passée en paramètre, elle sera tronquée.

- L'icône affichée (croix blanche) ne peut pas être modifiée.




![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) **Pour personnaliser cette boîte de dialogue** (ainsi que toutes les boîtes de dialogue système de votre application), cochez l'option "Personnaliser les fenêtres système (Info, OuiNon, Confirmer, Dialogue)" dans l'onglet "Style" de la description du projet. Pour plus de détails, consultez [Personnaliser les boîtes de dialogue](../WDLang1/3021003.md).

![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png)![Mac Catalyst](https://doc.pcsoft.fr/ext/images/us/CATALYST.png) Pour utiliser cette fonction, vous devez personnaliser les boîtes de dialogue de votre application. Dans la fenêtre de description du projet, dans l'onglet "Style", cochez l'option "Personnaliser les fenêtres système (Info, OuiNon, Confirmer, Dialogue)". Pour plus de détails, consultez [Personnaliser les boîtes de dialogue](../WDLang1/3021003.md).
<a name="NOTE0_2"></a>




### Saut de ligne dans la boîte de dialogue
<a name="saut_ligne_dans_boite_dialogue_ELTPARAGRAPHE000101"></a>

La chaîne prédéfinie RC (Retour Chariot) peut être utilisée pour forcer le passage à la ligne suivante. Par exemple:

```wl
ErreurAvecDélaiAsynchrone(500, "Une erreur a été détectée lors de la saisie de l'adresse. " + RC + ...
	"Merci de modifier les données concernant le client.")
```


Il est également possible d'utiliser la syntaxe des chaînes multilignes. Par exemple: 

```wl
ErreurAvecDélaiAsynchrone(
[
Une erreur a été détectée lors de la saisie de l'adresse. 

Merci de modifier les données concernant le client.
])
```

<a name="NOTE0_4"></a>




### Divers
<a name="divers_ELTPARAGRAPHE000115"></a>

- Les timers (fonction [TimerSys](../WDLang1/3015006.md)) ne sont pas stoppés lors de l'appel de cette fonction.

- ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) Les événements Windows ne sont pas stoppés lors de l'appel à cette fonction.

- Le libellé du bouton s'affiche dans la langue utilisée par Windows sur le poste en cours.

- ![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png) Cette fonction ne doit pas être utilisée: 

	- dans l'événement "Modification de la taille" des fenêtres. Dans le cas contraire, l'application sera bloquée.

	- dans l'événement "Changement d'orientation" des fenêtres. 

	- dans l'événement "Mise au premier-plan" associé au projet. 
			 Remarque: La fonction peut par contre être utilisée dans l'événement "Mise au premier plan" d'une fenêtre. 

	- dans un thread.

### Application en arrière-plan : Spécificité à partir de Android 10
<a name="application_arriereplan_specificite_partir_android_10_ELTPARAGRAPHE000306"></a>A partir de Android 10, il n'est plus possible d'ouvrir une fenêtre lorsque l'application est en arrière-plan. 

La fonction **ErreurAvecDélaiAsynchrone** peut provoquer l'ouverture d'une fenêtre. Si cette fonction est utilisée alors que l'application est en arrière-plan, une erreur fatale sera générée. 

Conseils : 

- Il est possible de savoir si l'application est en arrière-plan grâce à la fonction [EnModeArrièrePlan](../WDLang1/1000023457.md). 

- Si une application a besoin d'interagir avec l'utilisateur alors qu'elle se trouve en arrière-plan, la solution consiste à afficher une notification (via le type [Notification](../WDLang3/1000019441.md)). Lors du clic sur la notification, l'application sera remise au premier plan si la propriété **ActiveApplication** est à <u><u><u><u>Vrai</u></u></u></u>. Il est également possible d'ouvrir une fenêtre depuis la procédure passée à la propriété **ActionClic**.




Pour plus de détails, consultez [Android 10 : Comportement des applications en arrière-plan](../Editeurs/9000195.md).
