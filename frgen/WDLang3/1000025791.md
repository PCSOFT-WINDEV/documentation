


## Paramètres de la procédure gérant la réponse d'un serveur HTTP



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Procédure WLangage (également nommée "callback") appelée par la fonction [HTTPEnvoie](../WDLang3/1000021183.md) ou la fonction [HTTPEnvoieAsynchrone](../WDLang3/1410091208.md) lors de la réponse du serveur HTTP. 
<a name="Exemple1"></a>
<a name="sample_code"></a>

## Exemple


```wl
cMaRequête est un httpRequête
cMaRequête.URL = "http://www.monsite.fr/api/streamdata"
cMaRequête.ProcedureEntête = Procédure(cMonEntête est un httpRéponse) {
	SI cMonEntête.CodeEtat = 200 ALORS Trace("Requête envoyée.")
}
cMaRequête.ProcedureDonnées = Procédure(bufMorceau est un Buffer) {
	Trace("Je traite [%taille(bufMorceau)%] octets de données")
}
PROCEDURE INTERNE procFin(cMaRéponse est un httpRéponse)
	Trace("requête http terminée")
FIN
HTTPEnvoieAsynchrone(cMaRequête, procFin)
```

<a name="XSYNTAXE"></a>

## Syntaxe
<a name="SYNTAXE1"></a>

`EnvoieAsynchrone_Callback(<Réponse>)`
---

**`<Réponse> : (Variable de type httpRéponse)`**

Variable de type [httpRéponse](../WDLang3/1000021165.md) contenant la réponse reçue du serveur HTTP.



<a name="NOTE0"></a>
<a name="NOTE0_1"></a>

## Remarques


### Gestion des erreurs
<a name="gestion_des_erreurs_ELTPARAGRAPHE000040"></a>

Pour gérer les erreurs dans cette procédure : 

- La variable [ErreurDétectée](../WDLang1/3087001.md) et la fonction [ErreurInfo](../WDLang1/3013008.md) permettent de savoir si le serveur contacté n'est pas joignable.  

- La propriété **CodeEtat** de la variable de type [httpRéponse](../WDLang3/1000021165.md) permet de connaître la réponse du serveur et de détecter une erreur éventuelle. Par défaut 200 indique que la requête est acceptée, une éventuelle erreur sera détaillée par un autre code HTTP.





### Mode Chunked : Récupération du résultat de la requête en morceaux
<a name="mode_chunked_recuperation_resultat_requete_morceaux_ELTPARAGRAPHE000057"></a>

Si le serveur HTTP renvoie une requête en morceaux, il est possible de gérer la récupération des données en précisant dans la variable httpRequête : 

- Une procédure de lecture d'en-tête (propriété **ProcédureEntête**). 

- Une procédure de récupération des données (propriété **ProcédureDonnées**). 




Dans ce cas, la procédure callback appelée par la fonction [HTTPEnvoie](../WDLang3/1000021183.md) ou la fonction [HTTPEnvoieAsynchrone](../WDLang3/1410091208.md) permet de récupérer la réponse du serveur via une variable de type [httpRéponse](../WDLang3/1000021165.md). 

Remarques : 

- Si la propriété **ProcédureDonnées** était précisée dans la requête envoyée, la propriété **httpRéponse.Contenu** sera vide.

- L'entête reçue dans cette callback peut être plus grande que celle reçue au début. L'en-tête peut en effet contenir des informations spécifiques liées à l'envoi fragmenté des données (chunked trailer). 





### Erreur de sécurité dans une transaction sécurisée
<a name="erreur_securite_dans_une_transaction_securisee_ELTPARAGRAPHE000217"></a>Lors d'une transaction sécurisée, certaines erreurs de sécurité peuvent faire échouer la requête :

- certificat invalide ou ne provenant pas d'une société connue.

- nom du site figurant dans le certificat ne correspond pas à un serveur.

- date du certificat non-valide ou expiré.

- renvoi vers un serveur non sécurisé.




Ces erreurs sont renvoyées par la fonction [ErreurInfo](../WDLang1/3013008.md).

Si une de ces erreurs est rencontrée, il est possible d'exécuter à nouveau la requête en ignorant ces erreurs. Pour cela, il suffit de modifier la propriété **IgnoreErreur** de la variable de type [httpRequête](../WDLang3/1000021158.md) :

| Erreur renvoyée par la fonction [ErreurInfo](../WDLang1/3013008.md)<br> (avec la constante *errCode*) |   | Description |
| --- | --- | --- |
| *httpErreurCertificatInvalide*<br>Certificat invalide ou ne provenant pas d'une société connue. | *httpIgnoreCertificatInvalide* | Le certificat est ignoré. |
| *httpErreurNomCertificatInvalide*<br>Nom du site figurant dans le certificat ne correspond pas à un serveur. | *httpIgnoreNomCertificatInvalide* | Le nom du site figurant dans le certificat est ignoré. |
| *httpErreurCertificatExpiré*<br>Date du certificat non-valide ou expiré. | *httpIgnoreCertificatExpiré* | La date du certificat est ignorée. |
| <br><br> | *httpIgnoreDéprécié* | Ignore les erreurs en lien avec l'utilisation d'algorithmes dépréciés (exemple : signature de certificat en SHA-1). |
| *httpErreurRenvoiHTTP*<br>Renvoi vers un serveur non sécurisé. | *httpIgnoreRenvoiHTTP* | Le renvoi vers un serveur non sécurisé est autorisé. |
| *httpErreurRenvoiHTTPS*<br>Renvoi vers un serveur sécurisé. | *httpIgnoreRenvoiHTTPS* | Le renvoi vers un serveur sécurisé est autorisé. |
|   | *httpIgnoreRenégociationNonSecurisée* | Ignore l'erreur stipulant que le serveur ne supporte pas la renégociation sécurisée (RFC 5746). |
|   | *httpIgnoreRévocation* | Le contrôle du certificat dans la liste des certificats révoqués n'est pas effectué. |


Remarques : 

- Lorsque des requêtes HTTP sont faites dans plusieurs threads, la variable **HTTP.IgnoreErreur** possède une valeur spécifique par thread.

- ![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![Widget Android](https://doc.pcsoft.fr/ext/images/us/ANDROIDWIDGET.png) Les erreurs suivantes sont gérées : *httpIgnoreCertificatExpiré*, *httpIgnoreCertificatInvalide*, *httpIgnoreNomCertificatInvalide*, *httpIgnoreRévocation*, *httpIgnoreRedirection*.
