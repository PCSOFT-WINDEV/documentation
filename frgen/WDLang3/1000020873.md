


## inAppAchèteProduit (Fonction)

***En anglais : inAppPurchaseProduct***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Envoie : 

- une demande d'achat d'un produit "In-App" associé à l'application.

- une demande de souscription à un abonnement.




Remarque : La demande d'achat est asynchrone. Une procédure de type "Callback" est exécutée lors de lors de la réception de la réponse à la demande d'achat. 
<a name="Exemple1"></a>
<a name="sample_code"></a>

## Exemple


```wl
MonProduit est un inAppProduit = tabProduit[nIndex]
inAppAchèteProduit(monProduit, ValideAchatProduit)
```

```wl
PROCEDURE ValideAchatProduit(bSuccès est un booléen, Produit est un inAppProduit, Reçu)

SI PAS bSuccès ALORS
	ToastAffiche(ErreurInfo())
	RETOUR
SINON
	// Cas Android
	SI EnModeAndroid() ALORS
		// Consommation du produit (optionnel)
		inAppConsommeProduit(Produit, Reçu, ConsommationProduit)
	FIN
	// Cas iOS
	SI EnModeiOS() ALORS
		// Activation du produit dans l'application
		ActiveProduit(Produit)
		// Mémorisation de l'achat dans les préférences de l'application
		SauveParamètre(Produit..Identifiant, 1)
	FIN
FIN
```

## Syntaxe
<a name="SYNTAXE1"></a>
![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png) 
### iOS : Envoyer une demande d'achat

`<Résultat> = inAppAchèteProduit(<Produit à acheter> , <Quantité> , <Procédure WLangage>)`
---

**`<Résultat> : (Booléen)`**



- <u><u><u><u>Vrai</u></u></u></u> si la demande d'achat a été effectuée, 

- <u><u><u><u>Faux</u></u></u></u> dans le cas contraire. Pour plus de détails sur l'erreur, utilisez la fonction [ErreurInfo](../WDLang1/3013008.md).




**`<Produit à acheter> : (Variable de type inAppProduit)`**

Nom de la variable de type [inAppProduit](../WDLang3/1000020868.md) correspondant : 

- au produit à acheter.

- à l'abonnement à souscrire ou à renouveler.




**`<Quantité> : (Entier)`**

Quantité à acheter. 

- Dans le cas d'un abonnement, ce paramètre doit correspondre à 1.

- Si ce paramètre a pour valeur 0, &lt;Résultat&gt; vaut <u><u><u><u>Faux</u></u></u></u> et la procédure n'est pas appelée.




**`<Procédure WLangage> : (Nom de procédure)`**

Nom de la procédure WLangage (également nommée "callback") exécutée lors de la réception de la réponse à la demande d'achat. Pour plus de détails sur cette procédure, consultez [Paramètres de la procédure utilisée par la fonction inAppAchèteProduit](../WDLang3/1000024694.md).

## Remarques


### Cas particuliers
<a name="cas_particuliers_ELTPARAGRAPHE000116"></a>

- Si l'achat est valide, l'application doit fournir le contenu de l'achat à l'utilisateur.

- ![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png) Si l'achat a été effectué, l'application doit mémoriser cette information. Il est par exemple possible de stocker cette information dans les préférences grâce à la fonction [SauveParamètre](../WDLang1/3025046.md). 

- Si la fonction **inAppAchèteProduit** est utilisée pour souscrire un abonnement déjà actif pour l'utilisateur, cet abonnement est alors automatiquement prolongé de la période correspondante.

- ![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png) Il n'est pas possible d'acheter un produit que l'utilisateur a déjà acheté. Il est nécessaire de consommer le produit (avec la fonction [inAppConsommeProduit](../WDLang3/1000020880.md)) avant de pouvoir l'acheter à nouveau. 
	La fonction [inAppListeAchat](../WDLang3/1000020888.md) permet de récupérer les produits achetés par l'utilisateur et pas encore consommés.

- ![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png) Il n'est pas possible d'indiquer la quantité de produits à acheter. Il est nécessaire de créer dans la console développeur Google Play des produits correspondant à la quantité voulue. Il appartient alors à l'application de gérer l'utilisation des quantités achetées.

- ![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png) Il n'est pas possible de lancer simultanément plusieurs demandes d'achat. Il est nécessaire d'attendre la réponse à une demande d'achat avant d'effectuer une nouvelle demande.

- ![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png) La fonction **inAppAchèteProduit** sera sans effet si elle est exécutée depuis le simulateur ou l'émulateur Android.

### Application en arrière-plan : Spécificité à partir de Android 10
<a name="application_arriereplan_specificite_partir_android_10_ELTPARAGRAPHE000295"></a>A partir de Android 10, il n'est plus possible d'ouvrir une fenêtre lorsque l'application est en arrière-plan. 

La fonction **inAppAchèteProduit** peut provoquer l'ouverture d'une fenêtre. Si cette fonction est utilisée alors que l'application est en arrière-plan, une erreur fatale sera générée. 

Conseils : 

- Il est possible de savoir si l'application est en arrière-plan grâce à la fonction [EnModeArrièrePlan](../WDLang1/1000023457.md). 

- Si une application a besoin d'interagir avec l'utilisateur alors qu'elle se trouve en arrière-plan, la solution consiste à afficher une notification (via le type [Notification](../WDLang3/1000019441.md)). Lors du clic sur la notification, l'application sera remise au premier plan si la propriété **ActiveApplication** est à <u><u><u><u>Vrai</u></u></u></u>. Il est également possible d'ouvrir une fenêtre depuis la procédure passée à la propriété **ActionClic**.




Pour plus de détails, consultez [Android 10 : Comportement des applications en arrière-plan](../Editeurs/9000195.md).
