


## &lt;Variable adminWBAuth&gt;.SupprimeApplication (Fonction)

***En anglais : &lt;WBadminAuth variable&gt;.DeleteApplication***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Supprime une application du serveur d'application WEBDEV.
<a name="Exemple1"></a>
<a name="sample_code"></a>

## Exemple


```wl
CompteAdmin est un AdminWBAuth
CompteAdmin.AdresseServeur = "https://monserveur.com"
CompteAdmin.Utilisateur = "user"
CompteAdmin.MotDePasse = "password"

Applications est un tableau de AdminWBApplication
Applications = CompteAdmin.ListeApplication()
POUR i = 1 _À_ Applications.Occurrence  
    	SI Applications[i].Type = adminWBTypeSite ALORS
		// Supprime un site
		CompteAdmin.SupprimeApplication(Applications[i].ComptePropriétaire, Applications[i].Nom, adminWBTypeSite)
	FIN
FIN
```

<a name="XSYNTAXE"></a>

## Syntaxe
<a name="SYNTAXE1"></a>

`<Résultat> = <Serveur d'application WEBDEV>.SupprimeApplication(<Compte propriétaire> , <Nom de l'application> , <Type d'application>)`
---

**`<Résultat> : (Booléen)`**



- <u><u><u><u>Vrai</u></u></u></u> si l'application a été supprimée, 

- <u><u><u><u>Faux</u></u></u></u> dans le cas contraire. Pour connaître le libellé de l'erreur, utilisez la fonction [ErreurInfo](../WDLang1/3013008.md) avec la constante *errMessage*.




**`<Serveur d'application WEBDEV> : (Variable de type adminWBAuth)`**

Nom de la variable de type [adminWBAuth](../WDLang2/1410089328.md) décrivant le serveur et le compte administrateur utilisé pour interroger le Serveur d'application WEBDEV.

**`<Compte propriétaire> : (Chaîne de caractères)`**

Nom du compte propriétaire de l'application.

**`<Nom de l'application> : (Chaîne de caractères)`**

Nom de l'application à désinstaller.

**`<Type d'application> : (Constante de type Entier)`**

Type d'application à supprimer :


|   |   |
| --- | --- |
| *adminWBTypeSite* | Site WEBDEV. |
| *adminWBTypeWebserviceREST* | Webservices REST. |
| *adminWBTypeWebserviceSOAP* | Webservices SOAP. |
| *adminWBTypeWebSocket* | WebSockets. |

## Remarques


### Gestion de la double authentification
<a name="gestion_double_authentification_ELTPARAGRAPHE000206"></a>Il est possible d'activer la double authentification sur un compte via l'administrateur distant WEBDEV. La vérification en 2 étapes nécessite d'obtenir un code unique pour vérifier l'identité de l'utilisateur. Ce code peut être reçu par email ou via une application "Authenticator".

Lors de l'utilisation d'une fonction de pilotage du serveur d'application WEBDEV, si le compte utilise la double authentification, une erreur d'authentification peut survenir. Deux cas doivent être pris en compte : 

- si la fonction renvoie un booléen, &lt;Résultat&gt; est à <u><u><u><u>Faux</u></u></u></u>. Pour vérifier si l'erreur concerne l'authentification, il est nécessaire de vérifier la valeur de la variable [ErreurDétectée](../WDLang1/3087001.md) et la valeur renvoyée par la fonction [ErreurInfo](../WDLang1/3013008.md).

- si la fonction ne renvoie pas de booléen. Pour vérifier si l'erreur concerne l'authentification, les conditions suivantes doivent être réunies : 

	- la variable [ErreurDétectée](../WDLang1/3087001.md) est à <u><u><u><u>Vrai</u></u></u></u>, 

	- la fonction [ErreurInfo](../WDLang1/3013008.md) utilisée avec la constante *errCode* renvoie 2. 







La procédure à suivre pour gérer cette erreur est la suivante : 

- Faire une fenêtre / page permettant à l'utilisateur de saisir son code de vérification. 

- En cas d'erreur due à la double authentification : 

	- Afficher la fenêtre de saisie du code de vérification. 

	- L'utilisateur reçoit automatiquement le code d'authentification selon la méthode choisie dans l'administrateur distant WEBDEV. Il peut alors saisir le code dans la fenêtre / page.

	- Affecter le code à la propriété **CodeVérification** de la variable [adminWBAuth](../WDLang2/1410089328.md). 

	- Ré-exécuter la fonction de pilotage.
