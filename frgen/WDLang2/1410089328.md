
## adminWBAuth (Type de variable)

***En anglais : WBAdminAuth***
			
				



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Le type **adminWBAuth** permet de définir toutes les caractéristiques avancées de l'API authentifiée de gestion à distance d'un serveur d'application WEBDEV. Les caractéristiques de cette API peuvent être définies et modifiées à l'aide de différentes propriétés WLangage. 

**Remarque** : Pour plus de détails sur la déclaration de ce type de variable et l'utilisation des propriétés WLangage, consultez [Déclaration d'une variable](../Motscles/1514032.md).
<a name="Exemple1"></a>
<a name="sample_code"></a>

## Exemple


```wl
wbAuthLogin est un adminWBAuth
wbAuthLogin.AdresseServeur = "https://mon-serveur.interne/"
wbAuthLogin.Utilisateur = "WWW\DATA"
wbAuthLogin.MotDePasse = "www"

ConnexionsWB est un tableau de adminWBConnexions = AdminWBListeConnexion(wbAuthLogin)

SI ErreurDétectée = Vrai ALORS
	Info(ErreurInfo)
	RETOUR
FIN

POUR i = 1 _À_ ConnexionsWB.Occurrence  
	Trace(ConnexionsWB[i].Site)
	Trace(DateHeureVersChaîne(ConnexionsWB[i].DateHeureDébutConnexion))
	Trace(DuréeVersChaîne(ConnexionsWB[i].TempsInactivité, duréeCentième))
FIN
```

## Propriétés


### Propriétés spécifiques à la description des variables de type **adminWBAuth**
<a name="proprietes_specifiques_description_des_variables_type_docparampagetitleshort_ELTPARAGRAPHE000026"></a>Les propriétés suivantes peuvent être utilisées pour manipuler une variable de type **adminWBAuth** :

| Nom de la propriété | Type manipulé | Effet |
| --- | --- | --- |
| AdresseServeur | Chaîne de caractères | Adresse du Serveur d'application WEBDEV de la forme "https://www.monserveur.com/". <br>Attention : il est nécessaire de préciser l'adresse avec le protocole utilisé (http/https).  |
| CodeVérification | Chaîne de caractères | Code de vérification permettant la connexion si la vérification en 2 étapes est activée pour le compte via le site d'administration WEBDEV. <br><br>**Remarques** : <br><br>- La vérification en 2 étapes nécessite d'obtenir un code unique pour vérifier l'identité de l'utilisateur. Ce code peut être reçu par email ou via une application "Authenticator". <br><br>- Si les différentes fonctions AdminWBxxx échouent avec le code d'erreur 2, il est nécessaire de renseigner la propriété **CodeVérification**. Pour cela, l'application doit prévoir une fenêtre (ou page) dans laquelle l'utilisateur pourra saisir le code reçu. Ce code reçu pourra ainsi être utilisé pour renseigner la propriété **CodeVérification**. <br><br><br> |
| MotDePasse | Chaîne de caractères | Mot de passe associé à l'utilisateur.<br>**Utilisation de chaînes secrètes** : Si vous utilisez le coffre-fort de chaînes secrètes, le type de la chaîne secrète utilisable pour ce paramètre doit être "Chaîne Ansi ou Unicode".<br>Pour plus de détails sur les chaînes secrètes et l'utilisation du coffre-fort, consultez [Coffre-fort de chaînes secrètes](../Editeurs/1410087353.md). |
| Port | Entier | Numéro du port utilisé (par exemple, 443 par défaut pour https). |
| Utilisateur | Chaîne de caractères | Nom de l'utilisateur qui veut gérer le Serveur d'application WEBDEV. Cet utilisateur doit être un administrateur WEBDEV. |

## Remarques
<a name="NOTE0_1"></a>


### Divers
<a name="divers_ELTPARAGRAPHE000091"></a>

- L'API utilisée est un webservice REST. 

- Il n'y a pas de session active et la connexion est authentifiée pour chaque appel de l'API.
