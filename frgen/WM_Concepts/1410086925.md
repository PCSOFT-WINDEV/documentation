
## 11. Les champs Table / Zone répétée

<a name="NOTE1"></a>
<a name="NOTE1_1"></a>
Les champs Table/Zone répétée peuvent être utilisés pour afficher un ensemble d'informations (par exemple, le contenu d'une table). Le contenu de ces champs peut être issu de plusieurs sources différentes:

- Champ Table/Zone répétée liée aux données "accès direct".

- Champ Table/Zone répétée "par programmation".

- Champ Table/Zone répétée liée aux données "chargée en mémoire".


**Remarque**: Ces trois modes de remplissage vont être détaillés ici pour le champ Table. Les mêmes concepts s'appliquent au champ Zone répétée.

<a name="NOTE2"></a>
<a name="NOTE2_1"></a>


## Champ Table liée aux données "accès direct"
<a name="champ_table_liee_aux_donnees_acces_direct_ELTTEXTE000160"></a>
Un champ Table liée aux données de type "accès direct" permet d'afficher directement les données provenant d'une table, d'une requête ou d'une variable de type tableau. Un parcours de la table permet d'afficher les données dans le champ Table. Pour chaque ligne affichée, la table est lue: l'enregistrement lu est affiché dans une ligne du champ Table.<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=213&name=P66-Les%20champs%20Table%20Zone%20R%E9p%E9t%E9e.gif)
Les données affichées non liées à la table ne sont pas conservées lors de l'affichage de la ligne (par exemple, valeur d'une colonne de type Interrupteur).

Il est possible de limiter les enregistrements affichés dans le champ en utilisant un filtre (fonction [HFiltre](../WDLang4/3044100.md) utilisée dans le code d'initialisation du champ).

Les fonctions WLangage commençant par "Table" permettent de manipuler les champs Table liée aux données "accès direct". L'ajout ou la suppression d'une ligne dans le champ Table entraîne l'ajout ou la suppression de l'enregistrement dans la table liée.

<a name="NOTE3"></a>
<a name="NOTE3_1"></a>


## Champ Table "par programmation"
<a name="champ_table_par_programmation_ELTTEXTE000184"></a>
Un champ Table par programmation permet d'afficher directement des données chargées en mémoire. Les données sont ajoutées dans le champ Table par programmation (par exemple avec la fonction [TableAjouteLigne](../WDLang1/3074006.md)).<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=213&name=P66-Les%20champs%20Table%20Zone%20R%E9p%E9t%E9e-2.gif)
Les données étant présentes en mémoire, le champ Table permet toutes les manipulations sur les données (tri sur n'importe quelle colonne, recherche dans les colonnes, ...).

<a name="NOTE4"></a>
<a name="NOTE4_1"></a>


## Champ Table liée aux données "chargé en mémoire"
<a name="champ_table_liee_aux_donnees_charge_memoire_ELTTEXTE000208"></a>
Les champs table liée aux données de type "chargé en mémoire" combinent les avantages des champs table liée aux données de type "accès direct" et ceux des champs table par programmation.

Le champ Table est lié à la table mais le contenu de la table est totalement chargé en mémoire. Le tri et la recherche sont disponibles sur toutes les colonnes.

Les données non liées à la table sont conservées lors de la manipulation de l'ascenseur du champ Table (colonne de type Interrupteur par exemple).

Les enregistrements de la table étant chargés en mémoire, ce type de champ Table est conseillé pour les tables de moins de 100 000 enregistrements (pour éviter une saturation mémoire).<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=213&name=P66-Les%20champs%20Table%20Zone%20R%E9p%E9t%E9e-3.gif)
**Remarque**: Les différents modes de remplissage (par programmation, fichier accès direct et fichier chargé en mémoire) sont disponibles pour les champs Liste, Combo, Table, Zone répétée, ...
