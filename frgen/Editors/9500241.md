
## Fenêtre de description d'un schéma des données
			

<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Présentation
<a name="presentation_ELTTEXTE000330"></a>
La fenêtre de description d'un schéma des données regroupe toutes les caractéristiques et les options du schéma des données en cours dans l'éditeur de schémas des données. 

Pour afficher la fenêtre de description du schéma des données ouvert sous l'éditeur de schémas des données :

- sous le volet "Schéma des données", dans le groupe "Élément courant", cliquez sur "Description". 

- dans le menu contextuel de l'éditeur de schémas des données, sélectionnez l'option "Description du schéma des données". 




La fenêtre de description du schéma des données présente différentes options regroupées par onglets. 

<a name="NOTE2"></a>
<a name="NOTE2_1"></a>


## Onglet "Général"
<a name="onglet_general_ELTTEXTE000354"></a>
L'onglet "Général" de la fenêtre de description du schéma des données permet de connaître les informations générales sur le schéma des données en cours.  

Les informations suivantes sont disponibles : 

- **Nom du schéma des données** : Nom du schéma des données en cours. Ce nom peut être modifié. Dans ce cas, le schéma des données sera renommé. L'éditeur de schémas des données propose alors d'associer le schéma des données renommé au projet en cours. 

- **Libellé** : Libellé associé au schéma des données en cours. 

- **Répertoire** : Répertoire dans lequel le schéma des données est enregistré. 

- **Nom complet** : Nom complet du fichier "wda" correspondant au schéma des données décrit sous l'éditeur de schémas des données. 

- **Créé par** : Nom de l'auteur du schéma des données. La date et l'heure de création sont également indiquées. Ces informations ne sont pas modifiables. 

- **Mis à jour par** : Nom de l'utilisateur ayant modifié le schéma des données. La date et l'heure de modification sont également indiquées. Ces informations ne sont pas modifiables. 

- **GUID Schéma des données** : Identifiant du schéma des données. Cette information ne peut pas être modifiée. Cette information peut être connue par programmation grâce à la propriété [GUIDAnalyse](../Proprietes/2512098.md).

## Onglet "Détail"
<a name="onglet_detail_ELTTEXTE000378"></a>
L'onglet "Détail" de la fenêtre de description du schéma des données permet de connaître et de modifier les informations concernant l'accès au schéma des données.  

Les informations suivantes sont disponibles : 

- **Mot de passe éditeur** : Mot de passe utilisé pour ouvrir le schéma des données sous l'éditeur de schémas des données.

- **Mot de passe en exécution** : Mot de passe du schéma des données utilisé en exécution. Ce mot de passe est par exemple utilisé lors de l'ouverture du schéma des données avec le Centre de Contrôle HFSQL ou avec la fonction [HOuvreSchémaDesDonnées](../WDLang4/3044106.md). 

- **Répertoire par défaut des tables** : Répertoire utilisé par défaut pour créer les tables du schéma des données en cours. 

- **Descriptif** : Description du schéma des données qui sera utilisé dans le dossier technique. 

- **Schéma des données lié à un schéma des données WinDev 5.5 ou WebDev 1.5** : Si le schéma des données conserve une compatibilité avec WinDev 5.5 ou WEBDEV 1.5, il est possible de sélectionner le schéma des données correspondant et si nécessaire son mot de passe.

## Onglet "Journalisation"
<a name="onglet_journalisation_ELTTEXTE000402"></a>
L'onglet "Journalisation" de la fenêtre de description du schéma des données permet de connaître et de modifier les informations générales concernant la journalisation des tables.  

Les informations suivantes sont disponibles : 

- Répertoire et mot de passe des fichiers contenant l'historique des accès sur les fichiers (fichiers JournalOperation et JournalIdentification). 

- Répertoire contenant la description des réplicas pour les tables répliquées.

## Onglet "Archivage"
<a name="onglet_archivage_ELTTEXTE000426"></a>
L'onglet "Archivage" de la fenêtre de description du schéma des données permet de savoir si le schéma des données doit être archivé.

<a name="NOTE6_1"></a>


## Onglet "Langage"
<a name="onglet_langage_ELTTEXTE000450"></a>
L'onglet "Langage" de la fenêtre de description du schéma des données permet de connaître et de modifier le langage de programmation utilisé avec le schéma des données. Par défaut, le langage utilisé est le WLangage. 

Il est possible d'utiliser d'autres langages de programmation. Dans ce cas, il est nécessaire de préciser le répertoire de génération des sources.

Pour plus de détails sur la programmation via des langages externes, consultez [Présentation des langages externes](../LangageExt/7510002.md).

<a name="NOTE7_1"></a>


## Onglet "International"
<a name="onglet_international_ELTTEXTE000474"></a>
L'onglet "International" de la fenêtre de description du schéma des données permet de sélectionner les langues gérées dans le schéma des données. 

Un schéma des données peut gérer plus de langues que le projet associé (car par exemple d'un schéma des données partagé par plusieurs projets ne gérant pas les mêmes langues). 

Il est également possible de synchroniser les langues du schéma des données avec les langues du projet en cours grâce au bouton "Synchroniser avec le projet".

## Onglet "Options"
<a name="onglet_options_ELTTEXTE000498"></a>
L'onglet "Options" de la fenêtre de description du schéma des données permet de connaître et de modifier les options d'affichage, de synchronisation, d'édition sous l'éditeur de schémas des données. 

Les informations suivantes sont disponibles : 

- **Afficher le détail des rubriques dans le graphique** : Affiche le type de la rubrique sous forme d'une icône devant le nom de la rubrique dans la représentation graphique de la table. 

- **Liaisons pointent les clés liées** : Les liaisons décrites sous l'éditeur sont affichées entre les clés liées dans les fichiers. 

- **Afficher la fenêtre de recherche des rubriques de même nom dans les autres tables** : Permet lors de la création d'une rubrique, d'afficher la liste des rubriques de même nom existant dans les autres descriptions des tables du schéma des données en cours. 

- **Restaurer les tables supprimées** : Lors de la création de la description d'une table ayant le même nom qu'une table précédemment supprimée, propose la restauration de la table supprimée ainsi que de ses rubriques. 

- **Restaurer les rubriques supprimées** : Lors de la création d'une rubrique ayant le même nom qu'une rubrique supprimée, la rubrique supprimée est automatiquement proposée. 

- **Vérifier l'abonnement des tables à l'ouverture du schéma des données** : Permet de vérifier si une modification a été effectuée dans le dictionnaire contenant la table abonnée. 
	Remarque : Cette option est conservée par compatibilité. Elle nécessite l'utilisation d'un [Dictionnaire](../Editeurs/2023002.md) personnel.   

- **Synchronisation** : Permet d'indiquer si une synchronisation entre le projet et le schéma des données doit être effectuée lorsque le schéma des données a été modifié. Cette synchronisation peut être faite automatiquement ou être proposée (cas par défaut). 

- **A l'ouverture du projet** : Action à réaliser lors de l'ouverture du projet : 

	- Restaurer le dernier état du schéma des données,

	- Ne pas ouvrir le schéma des données, 

	- Toujours ouvrir le schéma des données. 




- **Proposer la synchronisation avec les bases externes** : Permet de proposer automatiquement la synchronisation des informations provenant d'une base de données externe. Il suffit de préciser la fréquence de synchronisation. Pour plus de détails, consultez [Synchroniser le schéma des données avec les bases de données externes](../Editeurs/2011024.md).

- **Ne pas proposer la SDD après la génération** : Permet de ne pas proposer la mise à jour des tables après la génération du schéma des données. 

- **Autoriser les caractères spéciaux dans les noms de rubrique** : Permet d'autoriser ou non les caractères spéciaux dans les noms des rubriques des tables. Attention, cette option n'est pas compatible avec le moteur HFSQL. 

- **Proposer automatiquement les Métatypes pendant la saisie de création de rubrique** : Propose automatiquement les métatypes définis dans le schéma des données lors de la création d'une rubrique. 

- **Unicode** : Permet d'autoriser ou non la gestion des caractères Unicode dans le schéma des données ET d'exécuter les procédures stockées en mode Unicode.

## Onglet "Compilation"
<a name="onglet_compilation_ELTTEXTE000522"></a>
L'onglet "Compilation" de la fenêtre de description du schéma des données permet de connaître et de modifier les caractéristiques de compilation des procédures stockées définies dans l'éditeur de schémas des données. .  

Les options disponibles sont les suivantes : 

- **Activer les erreurs de compilation pour la compatibilité 64 bits** : Permet d'activer l'affichage des erreurs pour une exécution sur une plateforme 64 bits.

- **Activer les erreurs de compilation pour la compatibilité Linux** : Permet d'activer l'affichage des erreurs pour une exécution sur une plateforme Linux. 

- **Norme de programmation : Syntaxe classique ou préfixée** : Il est possible de : 

	- Autoriser les mélanges : dans ce cas, aucune erreur de norme de programmation ne sera affichée. 

	- Signaler les syntaxes préfixées : Une erreur de norme de programmation sera affichée en cas d'utilisation d'une syntaxe préfixée ("ChampListe.Ajoute" par exemple). 

	- Signaler les syntaxes classiques : Une erreur de norme de programmation sera affichée si une syntaxe classique ayant son équivalent en syntaxe préfixée est utilisée. 




- **Norme de programmation : Signaler les messages multilingues partagés** : Si cette option est cochée, il est possible d'identifier rapidement les messages multilingues partagés grâce à une erreur de compilation. Cette option doit être utilisée dans le cadre de la conversion des messages multilingues au format 27 et supérieur. Pour plus de détails, consultez [Traduction des messages de programmation](../Editeurs/2013004.md).

- **Autoriser "[% %]" dans les chaînes** : Cette option permet d'autoriser la saisie directe d'un nom de variable dans une chaîne de caractères (également appelée "construction dynamique des chaînes"). Il suffit d'utiliser la syntaxe suivante : 
	
	```txt
	[%Nomdevariable%]
	```
Par exemple : 
	
	```wl
	// Demande de confirmation du client
	SI OuiNon(Oui, "Confirmez-vous la création du client [%sNomClient%]") = Non ALORS
		RETOUR
	FIN
	```
**Attention** : l'utilisation de cette option peut impliquer la modification du code pour certaines fonctions WLangage utilisant déjà les caractères "[% %]" dans leurs paramètres. Dans ce cas, pour ne pas interpréter les caractères "[% %]", il est nécessaire de les faire précéder par "-%". Exemple : 
	
	```wl
	grBulle(GR_Echéance, grFormatBulle, "[%CATEGORIE%]" + RC + RC+ "[%VALEUR%]" + " H")
	```
 devient
	```wl
	grBulle(GR_Echéance, grFormatBulle, -%"[%CATEGORIE%]" + RC + RC + -%"[%VALEUR%]" + " H")
	```
Pour plus de détails, consultez [Interpolation de chaînes](../Motscles/1514044.md). 

- **Autoriser les types nullables** : Permet d'activer les types nullables dans un projet WINDEV, WEBDEV ou WINDEV Mobile. L'activation des types nullables entraîne de nombreuses modifications dans la gestion du Null effectuée par votre projet. Pour plus de détails, consultez [Gestion de la valeur NULL : Activation des types nullables](../Motscles/1511031.md). 

- **Tableaux : l'affectation copie le contenu**
	Lorsque cette option est active, les tableaux sont locaux par défaut, c'est-à-dire que l'opérateur ** '='** fait une copie du tableau.
	Le mot-clé "dynamique" permet de conserver ponctuellement la prise de référence à l'affectation.

- **Tableaux : accès protégé aux éléments passés en paramètre à une procédure**
	Cette option permet de protéger un élément de tableau passé en paramètre à une procédure. Il devient ainsi possible de modifier, supprimer ou ajouter des éléments dans le tableau depuis cette procédure. 
	Remarque : Si cette option est sélectionnée, les accès au tableau peuvent être légèrement ralentis.  

- **Optimisation : Activer l'extension inline** : cette option permet d'accélérer l'exécution du code de l'application. Le compilateur remplace automatiquement l'appel d'une procédure par son code lorsque c'est possible. La taille globale du code peut être augmentée, au profit d'appels plus rapides des procédures.

- **"Nommage des sources de données"** : 

	- "Nom de la variable" : 
			Les variables de type "Source de données" créent une source de donnée utilisant le nom de la variable. Cela peut poser un problème dans les cas suivants : 

		- utilisation de tableaux de sources de données

		- utilisation de sources de données en tant que membres de classe.

		- lorsque deux fenêtres utilisent la même variable de type Source de données.




- "Nom automatique"  : 
			Les variables de type "Source de données" utilisent un nom unique pour la source de données. Attention : les guillemets doivent être supprimés pour manipuler la source de données. Il ne faut plus écrire : 
			
		```txt
		M1 est une Source de Données
		HLitPremier("M1")
		```
 mais 
		```txt
		M1 est une Source de Données
		HLitPremier(M1)
		```


- "Nom automatique avec références" :
			Les variables de type "Source de données" utilisent un nom unique pour la source de données. Il devient possible de référencer une source de données existante, par exemple en utilisant la syntaxe suivante : 
			
		```txt
		x est une Source de Données
		x = NomFichier
		x = NomRequête
		```
La valeur NULL est gérée. 
			![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png) L'option "Nom automatique avec références" n'est pas disponible.
