
## Tester et déboguer une application sur un appareil Android
			

<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Présentation
<a name="presentation_ELTTEXTE000198"></a>
Le test et le débogage d'application directement sur le matériel est apprécié de tous les développeurs.

WINDEV Mobile permet de tester et de déboguer directement sur le téléphone une fonctionnalité qui ne peut pas être émulée efficacement sur PC: position GPS, imprimante embarquée, scanner, accès aux contacts et à l'agenda du téléphone, prise des photos et vidéos, gesture (suppression de ligne par balayage, etc.), etc.

Le principe est simple: Lorsque le projet est exécuté en mode "Déboguer sur appareil mobile": 

- l'application Android est générée sous un nom spécifique (GO &lt;Nom du projet&gt;)

- l'application est exécutée sur le périphérique Android connecté au poste de développement (via USB ou en Wi-Fi). 
	


Il est ainsi possible de placer des points d'arrêt dans le code WLangage. Dès qu'un point d'arrêt sera rencontré, le débogueur sera automatiquement lancé sur le poste de développement.

## Comment le faire?
<a name="comment_faire_ELTTEXTE000231"></a>


### Lancer le test / débogage d'un projet en Android
<a name="lancer_test_debogage_projet_android_ELTPARAGRAPHE000027"></a>

Pour déboguer un projet en Android: 

1. Lancez le test de votre projet via les boutons d'accès rapide: <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=213&name=Go_Android%20-%20HC%20N%B0002.gif)


2. Si l'application n'a jamais été générée, un message d'avertissement propose de lancer l'assistant de génération de l'application Android. 
	Remarque: l'assistant de génération peut également être lancé si des modifications importantes ont été effectuées dans l'application (ajout d'un champ Carte, etc.). 

3. L'application est générée. 




Plusieurs cas peuvent se présenter: 

- Si un périphérique Android est connecté physiquement au poste de développement (via USB), l'application se lance automatiquement sur ce périphérique. L'éditeur de code est affiché en mode débogueur sur le poste de développement. 

- Dans les autres cas, la liste des périphériques disponibles est affichée: <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=213&name=Go_Android%20-%20HC%20N%B0003.gif)

	Cette liste permet de sélectionner le périphérique voulu. 
	Pour apparaître dans cette liste, l'appareil doit au choix: 

	- être connecté au poste de développement et autoriser le débogage USB. 

	- être associé via le wifi et autoriser le débogage.


 Il suffit de sélectionner le périphérique voulu pour lancer l'application en mode test. 





### Associer un nouvel appareil sans fil
<a name="associer_nouvel_appareil_sans_fil_ELTPARAGRAPHE000057"></a>

Dans la liste des périphériques disponibles, il est possible d'ajouter un nouvel appareil sans fil (bouton "Connecter un périphérique sans fil"). 

1. Activez le mode développeur sur votre périphérique ainsi que le mode "Débogage sans fil". Pour plus de détails, consultez [Préparation du téléphone Android pour test](../Editeurs/9000117.md). 

2. Dans la fenêtre de sélection du périphérique, cliquez sur "Connecter un périphérique sans fil". 

3. Dans la fenêtre qui s'affiche, indiquez les informations provenant de votre périphérique: <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=213&name=Go_Android%20-%20HC%20N%B0004.gif)


4. Saisissez le code de validation sur votre périphérique.

## Remarques
<a name="remarques_ELTTEXTE000270"></a>


- L'arrêt du débogage sur le poste de développement ne ferme pas l'application sur le périphérique Android. 

- Lors du test via USB, il est possible de déconnecter le périphérique du poste PC et de continuer l'utilisation de l'application. Cependant, si vous fermez l'application, le test ne pourra être relancé que si vous reconnectez le périphérique au poste PC.

- Le débogueur n'est pas disponible sur un émulateur. 

- Le [Centre de Contrôle Android](../CCAndroid/1410086630.md) permet de visualiser les traces et les informations de débogages de l'application en cours de test. 





### Fonction EnModeTest
<a name="fonction_enmodetest_ELTPARAGRAPHE000089"></a>

La fonction [EnModeTest](../WDLang1/3013011.md) renvoie <u><u><u><u>Vrai</u></u></u></u> dans les cas suivants: 

- Si le test du projet est effectué sur le périphérique mobile depuis WINDEV Mobile. 

- Si l'application &lt;Nom du projet&gt;.go est lancée sur le périphérique Android. 



<a name="NOTE3_2"></a>


### Ajoutez l'application générée pour le débogage sur votre console Firebase
<a name="ajoutez_application_generee_pour_debogage_sur_votre_console_firebase_ELTPARAGRAPHE000106"></a>

Le package de nouvelle application générée par WINDEV Mobile pour le débogage porte le même nom que que le package de l'application originale avec l'extension ".go". Par exemple, si le package de votre application se nomme "com.wmsport.android", le package de l'application pour le débogage se nomme "com.wmsport.android.go".

Si vous utilisez des services Google qui nécessitent d'activer Firebase pour votre application (comme par exemple les notifications Push): 

- Ajoutez également l'application de débogage dans la console Firebase (Pour plus de détails, consultez [Notification Push: Configuration Android (Firebase)](../WDLang3/1000022215.md)).

- Téléchargez le nouveau fichier google-services.json incluant les deux applications, afin de le fournir en lieu et place du précédent.



<a name="NOTE3_3"></a>


### Fonctionnalités non disponibles
<a name="fonctionnalites_non_disponibles_ELTPARAGRAPHE000121"></a>

Certaines fonctionnalités du débogueur ne sont pas disponibles dans cette version: 

- Utilisation de F8 pour changer de traitement ou d'événement. 

- Définir l'instruction suivante. 

- Modes particuliers des points d'arrêt (ignorer les points d'arrêts intermédiaires, ignorer les timers, etc.).

- Evaluations automatiques (identifiants des lignes de code courantes, valeurs de retour, variables locales et globales, membres de la classe en cours (this), HFSQL (EnDehors, Erreur, etc.), WLangage (Erreur, etc.)).

- Informations HFSQL (tables, requêtes, etc.).

- Informations système (sections critiques, sémaphores, etc.).

- Sauvegarde des résultats d'une requête.

- Corrige et continue.

- Audit, profiler, mémoire.

- Affichage des valeurs des variables non simples (structures, xml, json, tableaux, etc.) 

- Arrêt sur les déclarations de types simples pour lesquels aucune valeur n'est assignée. 
	Exemple: 
	
	```txt
	n est un entier // Le débogueur ne peut pas s'arrêter sur cette ligne
	n est un entier = 3 // Le débogueur peut s'arrêter sur cette ligne.
	```
