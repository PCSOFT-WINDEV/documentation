


## Description du projet : Onglet Tables
			



<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Présentation
<a name="presentation_ELTTEXTE000162"></a>
La fenêtre de description du projet permet de configurer de nombreux éléments de votre projet. Cette fenêtre est constituée des onglets suivants :

- L'onglet ["Projet"](../Editeurs/2030046.md) qui permet de saisir les informations générales du projet.

- L'onglet "Schéma des données" qui permet d'associer un ou plusieurs schémas des données au projet et / ou un modèle UML.

- L'onglet **"Tables"** qui permet de saisir différentes informations sur les tables gérées par l'application (uniquement disponible si le projet est lié à un schéma des données).

- L'onglet "Live data" qui permet de configurer l'affichage des données (provenant des tables) sous les différents éditeurs.

- L'onglet ["Langues"](../Editeurs/9500219.md) qui permet de paramétrer les différentes langues manipulées par le projet ainsi que les options linguistiques à utiliser pour chaque langue.

- ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png)![WINDEV Mobile](https://doc.pcsoft.fr/ext/images/us/WM.png) L'onglet ["Style"](../Editeurs/9500234.md) qui permet de choisir le thème, la feuille de styles personnalisée et de personnaliser l'aperçu avant impression. Il est également possible de paramétrer la taille des écrans.

- ![WEBDEV - Code Serveur](https://doc.pcsoft.fr/ext/images/us/WBS.png) L'onglet ["Thème"](../Editeurs/1410087360.md) qui permet de choisir le thème du projet, la palette associée, la feuille de styles et les ressources externes. 

- L'onglet ["GDS"](../Editeurs/9500239.md) qui permet de gérer le travail en groupe (GDS ou GIT).

- L'onglet ["Options"](../Editeurs/9500227.md) qui permet de configurer les options de création, de mise à jour, et de sauvegarde des éléments. Cet onglet permet également de gérer la synchronisation des modèles, d'activer le mode strict et de définir la charte de programmation.

- L'onglet ["Avancé"](../Editeurs/9500236.md) qui permet de gérer l'utilisation de "Etats & Requêtes", les FAA et le verrouillage de l'application.

- L'onglet ["Compilation"](../Editeurs/9500218.md) qui permet de configurer les options de compilation.

- L'onglet ["Télémétrie"](../Editeurs/9500223.md) qui permet de configurer les options de télémétrie pour le projet. 
	![WEBDEV - Code Serveur](https://doc.pcsoft.fr/ext/images/us/WBS.png) Cette option n'est pas disponible.

## Onglet Tables
<a name="onglet_tables_ELTTEXTE000245"></a>


### Répertoire des tables à utiliser en mode test
<a name="repertoire_des_tables_utiliser_mode_test_ELTPARAGRAPHE000031"></a>

Cette option permet de définir le répertoire des tables à utiliser en mode test : débogage, Go de fenêtre, de page ou de projet. 

Par défaut, le répertoire utilisé est le répertoire de la configuration courante (sous-répertoire du répertoire EXE du projet).

Il est possible de spécifier un répertoire spécifique. 

Cette option est intéressante si WINDEV est utilisé avec l'UAC active : il est possible d'utiliser en mode test le répertoire des données de l'application.
<a name="NOTE2_2"></a>


### Automatismes
<a name="automatismes_ELTPARAGRAPHE000044"></a>

Les options suivantes sont disponibles sur tous les types de données : 

- **Activer l'assistance automatique HFSQL**
	Cette option permet d'activer la gestion automatique des erreurs par le moteur HFSQL. Pour plus de détails, consultez [Gestion assistée des erreurs](../WDLang4/3044188.md).

- **Créer les tables automatiquement au moment de leur ouverture** : 
	Cette option permet de créer automatiquement les tables décrites dans le schéma des données si ces tables n'existent pas lors de l'utilisation de fonctions nécessitant leur ouverture. Dans ce cas, la fonction [HCréeSiInexistant](../WDLang4/3044254.md) est automatiquement exécutée.
	![Connecteurs Natifs (Accès Natifs)](https://doc.pcsoft.fr/ext/images/us/AN.png) Cette option est prise en compte par les connecteurs natifs à SQL Server, Informix, Sybase, MySQL, MariaDB et PostgreSQL.



<a name="NOTE2_3"></a>


### Ré-indexation automatique (Uniquement pour HFSQL)
<a name="reindexation_automatique_uniquement_pour_hfsql_ELTPARAGRAPHE000078"></a>

La ré-indexation d'une table peut être rendue nécessaire par la perte ou l'altération du fichier d'index. Une ré-indexation automatique des tables peut être mise en place.

L'option "Activer la réindexation automatique" permet d'activer la réindexation automatique des tables en spécifiant plusieurs paramètres :

- le nombre d'enregistrements maximum : Si la table contient moins de XXX enregistrements, la réindexation est automatique en cas d'erreur d'index. Par défaut, cette valeur vaut 100000. Si cette variable vaut 0, la ré-indexation automatique est désactivée.

- l'affichage de la fenêtre de jauge permettant de suivre la ré-indexation en cours.




Remarque : la ré-indexation automatique est disponible uniquement sur les tables HFSQL Classic et HFSQL Client/Serveur.
<a name="NOTE2_4"></a>


### Mode de gestion des tables (Uniquement pour HFSQL)
<a name="mode_gestion_des_tables_uniquement_pour_hfsql_ELTPARAGRAPHE000096"></a>

Cette option permet de définir le mode de gestion des tables de l'application. Par défaut, les applications créées avec WINDEV et WEBDEV sont des applications multi-utilisateurs : les blocages sont gérés de manière automatique.
Il est possible de demander une gestion "Mono-utilisateur" : dans ce cas, les tables sont totalement bloquées en lecture et en écriture dès leur ouverture. 
<a name="NOTE2_5"></a>


### Options pour les Connecteurs Natifs
<a name="options_pour_les_connecteurs_natifs_ELTPARAGRAPHE000107"></a>

Si l'option "Copier les connexions pendant la copie de contexte" est cochée, en utilisant un connecteur natif, lors de la copie de contexte, chaque contexte bénéficie en option de sa propre connexion au serveur de la base de données tierce. Cette option est nécessaire notamment dans le cas des transactions. 
 Cette nouveauté est disponible pour les bases : MS SQLServer, Oracle, MySQL, Sybase, Progress, Informix, DB2, SQLite, MariaDB.
