


## TableParcourue (Propriété)

***En anglais : BrowsedFile***
	



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
La propriété **TableParcourue** permet de connaître et de modifier la source de données utilisée pour l'affichage des enregistrements dans les champs basés sur une table ou sur une variable : 

- les champs Table ou Table hiérarchique.

- les champs Liste ou Liste image.

- les champs Combo.

- les colonnes de table de type combo.

- les champs Zone répétée.

- ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) les champs Agenda.

- les champs Planning.

- ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) les champs Arbre.

- ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) les champs Organigramme.

- ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) les champs Tableau croisé dynamique.

- les champs Kanban.

- les fenêtres internes (si le balayage est activé). 

- les superchamps. 




Cette source de données peut être :

- une table ou une requête. Les enregistrements affichés proviennent de cette table ou de cette requête.

- une variable (tableau, membre de classe, membre d'un type avancé, etc.).




Cette source de données est définie lors de la description du champ (onglet "Contenu").




<a name="Exemple1"></a>
<a name="sample_code"></a>

## Exemple


```wl
// Affiche tous les clients dans un champ Table
TABLE_Table1.TableParcourue = "Clients"
// Affiche tout le contenu de la requête Req_Clients dans un champ Table
TABLE_Table1.TableParcourue = "Req_Clients"

// Affiche les contacts de la variable gUnContact
// gUnContact est une variable de type gglContact
TABLE_Table1.TableParcourue = ":gUnContact"
```

## Syntaxe

### Connaître la table, la requête ou la variable utilisée comme source de données

`<Elément parcouru> = <Champ manipulé>.TableParcourue`
---

**`<Elément parcouru> : (Chaîne de caractères)`**

Nom de l'élément utilisé comme source de données du champ considéré. Cet élément peut correspondre :

- au nom de la table ou de la requête.

- au nom de la variable. Ce nom est de la forme ":&lt;préfixe&gt;&lt;Nom de la variable&gt;" ou bien ":&lt;Nom de la variable&gt;". Le préfixe est présent uniquement si la charte de programmation est activée dans le projet.




**`<Champ manipulé> : (Nom de champ)`**

Nom du champ manipulé. Ce champ doit être un champ de type : 

- Table, Table hiérarchique.

- Liste, Liste image.

- Combo.

- Colonne de table de type combo.

- Zone répétée.

- ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) Agenda.

- Planning.

- ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) Arbre.

- ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) Organigramme.

- Fenêtre interne.

- ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) Tableau croisé dynamique.

- Kanban.





<a name="SYNTAXE2"></a>

### Modifier la table, la requête ou la variable utilisée comme source de données

`<Champ manipulé>.TableParcourue = <Nouvelle source de données>`
---

**`<Champ manipulé> : (Nom de champ)`**

Nom du champ manipulé. Ce champ doit être un champ de type : 

- Table, Table hiérarchique.

- Liste, Liste image.

- Combo.

- Colonne de table de type combo.

- Zone répétée.

- ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) Agenda.

- Planning.

- ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) Arbre.

- ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) Organigramme.

- Fenêtre interne.

- ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) Tableau croisé dynamique.

- Kanban.




**`<Nouvelle source de données> : (Chaîne de caractères)`**

Nom de l'élément qui doit être associé au champ considéré :

- Nom de la table ou de la requête.

- Nom de la variable. Ce nom est de la forme ":&lt;préfixe&gt;&lt;Nom de la variable&gt;" ou bien ":&lt;Nom de la variable&gt;". Le préfixe doit être précisé si la charte de programmation est activée dans le projet (que les préfixes soient affichés ou non).


Si ce paramètre ne correspond pas à un nom valide, le champ sera vide. Si ce paramètre correspond à une chaîne vide, le parcours sera arrêté.  



<a name="NOTE0"></a>
<a name="NOTE0_1"></a>

## Remarques


### Utilisation de la propriété **TableParcourue**
<a name="utilisation_propriete_docparampagetitleshort_ELTPARAGRAPHE000184"></a>

La propriété **TableParcourue** peut être utilisée aussi bien lors d'un parcours programmé que lors d'un parcours automatique de la source de données.

Si la propriété **TableParcourue** est utilisée pour modifier la source de données utilisée, le parcours est ré-initialisé. Dans le cas d'un champ Table, ce fonctionnement est identique à l'utilisation de la fonction [TableAffiche](../WDLang1/3074003.md) avec la constante *taDébut*.
<a name="NOTE0_2"></a>




### Modification des propriétés liées au parcours d'un champ basé sur une table
<a name="modification_des_proprietes_liees_parcours_champ_base_sur_une_table_ELTPARAGRAPHE000203"></a>

Pour modifier plusieurs des propriétés [RubriqueParcourue](../Proprietes/2510111.md), [Filtre](../Proprietes/2510042.md) et **TableParcourue**, il est conseillé de :

1. Stopper le parcours en affectant une chaîne vide ("") à la propriété **TableParcourue**.

2. Modifier les propriétés nécessaires.

3. Relancer le parcours avec la propriété **TableParcourue**.


Cette méthode permet d'optimiser les modifications réalisées. En effet, chacune des modifications effectuée individuellement relance le parcours. Ces opérations peuvent vite devenir lentes sur des tables de taille importante.
<a name="NOTE0_3"></a>


### Type de parcours
<a name="type_parcours_ELTPARAGRAPHE000228"></a>

- ***Parcours automatique*** : WINDEV, WEBDEV et WINDEV Mobile prennent en charge le parcours de la table et l'affichage des données dans le champ. Le développeur n'a aucun code spécifique à saisir.
	Si le champ peut être trié (table, ...), le tri est effectué sur la rubrique de parcours définie dans l'onglet "Contenu" de la description de l'élément. 
	Si un filtre est spécifié (option "Filtre sur la rubrique de parcours" dans l'onglet "Contenu" de la description de l'objet), ce filtre est utilisé.

- ***Parcours programmé*** : Le développeur doit programmer le parcours de la table et l'affichage des données dans le champ.
	Un parcours programmé permet un contrôle total sur l'ordre et le filtrage des enregistrements. Cependant, un parcours programmé est plus complexe et plus lent qu'un parcours automatique.



<a name="NOTE0_4"></a>


### Manipulation des champs basés sur une table grâce aux propriétés
<a name="manipulation_des_champs_bases_sur_une_table_grace_aux_proprietes_ELTPARAGRAPHE000242"></a>

- Les enregistrements affichés dans les champs table proviennent de la table ou de la requête spécifiés avec la propriété **TableParcourue**.

- Le sens de tri est fixé par la propriété [RubriqueParcourue](../Proprietes/2510111.md).

- Selon le type de champ, un filtrage des enregistrements peut être réalisé grâce à la propriété [Filtre](../Proprietes/2510042.md) ou à la fonction [HFiltre](../WDLang4/3044100.md).



<a name="NOTE0_5"></a>


### Limites
<a name="limites_ELTPARAGRAPHE000262"></a>

La propriété **TableParcourue** s'applique uniquement aux champs d'une fenêtre ou d'une page. Cette propriété s'applique uniquement aux champs pouvant être liés à une source de données :

- Champs Table, Table hiérarchique,

- Champs Liste, Liste image, 

- Champs Combo, 

- Superchamps,

- Colonnes de table (permet de modifier la table liée à une colonne de table de type Combo).

- Champs Zone répétée,

- ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) Champs Agenda.

- Champs Planning.

- ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) Champs Arbre.

- ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) Champs Organigramme.

- ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) Champs Tableau croisé dynamique.

- les fenêtres internes (si le balayage est activé). 

- Champs Kanban.
