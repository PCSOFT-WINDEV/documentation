


## Champ Table lié à une table ou à une requête
			



<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Présentation
<a name="presentation_ELTTEXTE000209"></a>
Une champ Table peut être utilisé pour afficher le contenu d'une table ou d'une requête : un utilisateur peut ainsi sélectionner un ou plusieurs enregistrements de cette table ou de cette requête.

Un champ Table peut être lié à :

- une requête ***existante*** : il suffit de sélectionner cette requête parmi les requêtes de votre projet.

- une requête ***intégrée au champ Table*** : cette requête sera créée dans l'assistant de création du champ Table. Cette requête sera disponible uniquement pour ce champ.




Lorsqu'un champ Table est lié à une table (ou à une requête), le champ Table pourra être initialisé avec le contenu de la table :

- **soit automatiquement** : Aucun code spécifique n'est nécessaire pour initialiser le champ Table. Les caractéristiques du parcours de la table liée au champ sont décrites dans l'onglet "Contenu" de la fenêtre de description du champ Table.

- **soit par programmation** : Il est nécessaire de saisir le code de parcours de la table liée au champ Table dans les différents événements du champ Table. Cette méthode est déconseillée.
	![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png) Cette méthode n'est pas disponible.




**Remarque** : Lors de la création d'un champ Table, l'assistant demande les différents renseignements nécessaires pour effectuer la liaison entre le champ et une table (ou une requête).

Pour plus de détails sur la gestion des champs Table liés à une requête, consultez [Champs Table liés à une requête](../WDChamp/1013203.md).

## Champ Table lié à une table avec parcours automatique
<a name="champ_table_lie_une_table_avec_parcours_automatique_ELTTEXTE000233"></a>
Un champ table liée aux données permet d'afficher des données provenant d'une source de données spécifique (table, requête, etc.).

Le contenu du champ Table est défini lors de sa création et peut être modifié dans la fenêtre de description du champ (onglet "Contenu").<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=213&name=Champ_Table_Contenu.gif)
Cet écran permet de définir si le champ Table est un champ Table liée aux données ou un champ Table par programmation. Dans le cas d'un champ Table liée aux données, cet écran permet de déterminer les caractéristiques du parcours de la source de données :



|   |   |
| --- | --- |
| <br><br>- **Table parcourue**<br><br><br> | Fichier ou requête contenant les données à afficher.<br>Si le champ Table est basé sur une requête intégrée, le nom du fichier parcouru est de la forme &lt;Nom de la Fenêtre&gt;_&lt;Numéro&gt;$Requête. Dans ce cas, toutes les options du bouton "Requête intégrée" sont disponibles. |
| <br><br>- **Rubrique mémorisée** (optionnel)<br><br><br> | Rubrique dont la valeur est retournée au programme lorsque une ligne du champ Table est sélectionnée. |
| <br><br>- **Parcours automatique**<br><br><br> | Si cette option est cochée, le moteur d'exécution prend en charge le parcours du fichier et l'affichage des données dans le champ Table. Aucun code WLangage n'est nécessaire. |
| <br><br>- **Rubrique de parcours**<br><br><br> | Rubrique utilisée pour parcourir la source de données. Les enregistrements affichés dans le champ Table seront triés selon cette rubrique. <br>Si l'option &lt;Automatique&gt; est sélectionnée, le moteur HFSQL sélectionnera automatiquement la meilleure clé de parcours. |
| <br><br>- **Parcours inversé (décroissant)**<br><br><br> | Le sens de parcours dépend de la rubrique de parcours. Le sens de parcours a été défini dans l'éditeur de schémas des données, dans les caractéristiques de la rubrique.<br>Si cette option est cochée, le sens de parcours utilisé sera l'inverse de celui défini dans l'éditeur de schémas des données. |
| <br><br>- **Afficher les enregistrements dont la rubrique de parcours commence par**<br><br><br> | Condition utilisée pour filtrer les enregistrements affichés. Ce filtre est du type "Commence par" et s'applique sur la rubrique de parcours. Pour utiliser des filtres plus élaborés, utilisez la fonction [HFiltre](../WDLang4/3044100.md). Pour plus de détails sur les filtres, consultez [Filtre dans les champs Table liée aux données](../WDChamp/1013202.md).<br><br>![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png) Les options de filtrage ne sont pas disponibles sur les champs Table liée aux données avec accès direct. |
| ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) **Afficher le contenu pendant le déplacement de l'ascenseur** | Si cette option est cochée, la taille du curseur de l'ascenseur vertical sera proportionnelle au nombre d'éléments présents dans le champ Table. |
| ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png)![WINDEV Mobile](https://doc.pcsoft.fr/ext/images/us/WM.png) **Utiliser la fonction HFiltre pour parcourir la table** | Permet de filtrer les enregistrements affichés dans le champ Table et la table de base du champ. Pour plus de détails sur cette option, consultez [Filtre dans les champs Table liée aux données](../WDChamp/1013202.md).<br><br>![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png) Les options de filtrage ne sont pas disponibles sur les champs Table liée aux données avec accès direct. |
| ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) **Synchroniser l'affichage (HFSQL C/S)** | Cette option permet de rafraîchir automatiquement le champ table liée aux données, dès que la table HFSQL Client/Serveur associée est modifiée. <br><br>Pour plus de détails, consultez [Champ Table liée aux données : Synchronisation automatique (données HFSQL Client/Serveur)](../WDChamp/1013177.md). |
| ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) **Afficher un [ + ] de détail d'une ligne** | Cette option permet de dérouler une ligne du champ Table pour voir les enregistrements d'autres tables, reliés à la ligne sélectionnée.  <br><br>Pour plus de détails, consultez [Champ Table liée aux données : Visualisation automatique des enregistrements reliés](../WDChamp/1013177.md). |

## Programmation d'un champ Table liée aux données programmée
<a name="programmation_champ_table_liee_aux_donnees_programmee_ELTTEXTE000257"></a>
Si vous utilisez un champ Table basé sur une table avec initialisation programmée, il est nécessaire de saisir le code de parcours de la table dans les différents événements associés au champ. Cette méthode est déconseillée et conservée uniquement par compatibilité.

**Par exemple** : Initialisation d'un champ Table avec les clients de la table CLIENT.


```wl
// Initialisation du champ Table
HLitPremier(CLIENT, NOM)

// Enregistrement précédent 
HLitPrécédent(CLIENT, NOM)
// Enregistrement suivant 
HLitSuivant(CLIENT, NOM)
// Dernier enregistrement
HLitDernier(CLIENT, NOM)
```
