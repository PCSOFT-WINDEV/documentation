


## Triggers applicatifs
			



<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Qu'est-ce qu'un trigger?
<a name="questce_quun_trigger_ELTTEXTE000238"></a>


### Définition
<a name="definition_ELTPARAGRAPHE000011"></a>

Un trigger est une procédure WLangage appelée automatiquement par le moteur HFSQL à chaque modification (ajout, suppression, modification, etc.) d'un enregistrement d'une table.

Un trigger permet d'associer un traitement WLangage à une ou plusieurs fonctions HFSQL ([HAjoute](../WDLang4/3044147.md), [HModifie](../WDLang4/3044042.md), [HSupprime](../WDLang4/3044018.md), etc.) sans se préoccuper de l'emplacement de ces fonctions dans le code source. Même s'il s'agit d'une fenêtre ou d'un code créé par un assistant, les triggers associés aux fonctions HFSQL utilisées sont exécutés.

Remarque: Les triggers fonctionnent également avec les fonctions de gestion des champs Table liée aux données: [TableAjoute](../WDLang1/3074017.md), [TableAjouteLigne](../WDLang1/3074006.md), [TableModifie](../WDLang1/3074019.md), [TableModifieLigne](../WDLang1/3074028.md), [TableSupprime](../WDLang1/3074032.md), etc.

L'utilisation d'un trigger permet de:

- Diminuer la taille du code. Par exemple, les traitements associés à une ou plusieurs fonctions HFSQL (vérification de doublon, test de cohérence des données, etc.) peuvent être regroupés grâce à l'utilisation d'un trigger.

- Simplifier la lecture du code.

- Simplifier les évolutions futures de l'application.




Les triggers s'appliquent sur tous les types de tables:

- HFSQL

- Accès natifs (Oracle, AS/400, etc.)

- ODBC

- OLE DB




Remarques: 

- Avec une base de données HFSQL Client/Serveur, il est également possible de définir des triggers serveur. Pour plus de détails, consultez [Triggers serveur](../WDLang4/3044369.md). 

- Lors de modification de tables via une requête, les triggers serveurs, les triggers simples ou triggers client sont déclenchés.

## Types de triggers disponibles
<a name="types_triggers_disponibles_ELTTEXTE000262"></a>
Deux types de triggers sont disponibles:

- Les triggers "AVANT":
	Un trigger "AVANT" est appelé: 

	- *avant* l'exécution d'une fonction HFSQL ([HAjoute](../WDLang4/3044147.md), [HModifie](../WDLang4/3044042.md), [HSupprime](../WDLang4/3044018.md), etc.). 

	- *avant* l'exécution d'une fonction de gestion des champs Table liée aux données.
			Un trigger "AVANT" permet par exemple de vérifier la cohérence des données des rubriques d'un enregistrement. Avec ce type de trigger, il est possible d'initialiser une variable HFSQL pour annuler l'exécution de la fonction HFSQL associée.




- Les triggers "APRÈS":
	Un trigger "APRÈS" est appelé: 

	- *après* l'exécution d'une fonction HFSQL (sauf si le programme a été interrompu pendant l'exécution de cette fonction). 

	- *après* l'exécution d'une fonction de gestion des champs Table liée aux données. 
			Un trigger "APRÈS" permet par exemple de gérer le traitement des erreurs.

## Manipuler les triggers par programmation
<a name="manipuler_les_triggers_par_programmation_ELTTEXTE000286"></a>


### Les fonctions du WLangage
<a name="les_fonctions_wlangage_ELTPARAGRAPHE000110"></a>Plusieurs fonctions permettent de manipuler les triggers:



|   |   |
| --- | --- |
| [HActiveTrigger](../WDLang4/3044155.md) | Ré-active un trigger précédemment désactivé avec la fonction [HDésactiveTrigger](../WDLang4/3044089.md). |
| [HDécritTrigger](../WDLang4/3044074.md) | Ajoute ou modifie un trigger sur une table HFSQL. |
| [HDésactiveTrigger](../WDLang4/3044089.md) | Désactive un trigger. |
| [HDétruitTrigger](../WDLang4/3044090.md) | Détruit un trigger. |
| [HGèreTrigger](../WDLang4/3044065.md) | Active ou désactive la gestion des triggers. |
| [HListeTrigger](../WDLang4/3044231.md) | Renvoie la liste des triggers appliqués sur une ou plusieurs tables HFSQL. |
| [HTriggerEnregistrementAvant](../WDLang4/1000025873.md) | Récupère la valeur de l'enregistrement en cours avant l'exécution du ou des triggers. |




<a name="NOTE3_2"></a>


### Créer un trigger
<a name="creer_trigger_ELTPARAGRAPHE000118"></a>

Pour créer un trigger "AVANT" ou un trigger "APRÈS", utilisez la fonction [HDécritTrigger](../WDLang4/3044074.md) dans le traitement d'initialisation du projet. Le trigger peut être créé:

- Sur une ou plusieurs tables du schéma des données,

- Pour une ou plusieurs fonctions HFSQL ([HAjoute](../WDLang4/3044147.md), [HModifie](../WDLang4/3044042.md), [HSupprime](../WDLang4/3044018.md), [TableAjoute](../WDLang1/3074017.md), [TableAjouteLigne](../WDLang1/3074006.md), etc.).




A chaque exécution d'un trigger, la procédure WLangage associée est exécutée.

**Remarque**: Un trigger est global au projet.
<a name="NOTE3_3"></a>


### Créer une procédure exécutée par un trigger
<a name="creer_une_procedure_executee_par_trigger_ELTPARAGRAPHE000150"></a>

Une procédure (ou une procédure stockée) de type trigger ne reçoit aucun paramètre. Toutefois, un certain nombre de variables d'état HFSQL sont positionnées avant chaque appel:


|   |   |
| --- | --- |
| H.NomTable | Chaîne de caractères: Nom logique de la table dont le trigger est activé. <br><br>**Attention**: Selon le nom logique utilisé par l'application, la valeur de la variable **H.NomTable** peut être différente (utilisation d'alias par exemple). Il est conseillé d'utiliser: <br><br>- MonTable.NomDécrit pour connaître le nom logique de la table manipulée (sans prendre en compte les alias). <br><br>- MonFichier.NomPhysique pour connaître le nom physique de la table manipulée.  <br><br><br> |
| H.Action | Caractère initialisé à "A" pour un trigger Avant, "P" pour un trigger après. |
| H.FonctionTrigger | Chaîne de caractères: Nom de la fonction HFSQL qui a déclenché le trigger. <br><br><br>	<B><B><B><B>Avertissement</B></B></B></B><br><br>	 La variable **H.FonctionTrigger** est dépréciée au profit de la variable **H.NuméroFonctionTrigger**. L'information donnée par la variable est indépendante de la langue utilisée pour l'exécution de l'application.<br>
 |
| H.NuméroFonctionTrigger | Constante permettant de connaître la fonction qui a déclenché le trigger: <br><br>- *htrgHAjoute*: La fonction qui a déclenché le trigger est [HAjoute](../WDLang4/3044147.md). <br><br>- *htrgHEcrit*: La fonction qui a déclenché le trigger est [HEcrit](../WDLang4/3044092.md). <br><br>- *htrgHModifie*: La fonction qui a déclenché le trigger est [HModifie](../WDLang4/3044042.md). <br><br>- *htrgHRaye*: La fonction qui a déclenché le trigger est [HRaye](../WDLang4/3044121.md). <br><br>- *htrgHSupprime*: La fonction qui a déclenché le trigger est [HSupprime](../WDLang4/3044018.md). <br><br><br> |
| H.AFaire | Pendant l'exécution d'un trigger avant:<br><br>- annulation de l'exécution de la fonction HFSQL en cours en affectant **"A"** à la variable d'état HFSQL: H.AFaire = "A". Dans ce cas, l'action n'est pas effectuée et la fonction (HAjoute, HModifie, etc.) renvoie <u><u><u><u>Vrai</u></u></u></u> (pas d'erreur).<br><br>- annulation de l'exécution de la fonction HFSQL en cours en affectant **"E"** à la variable d'état HFSQL: H.AFaire = "E". Dans ce cas, l'action n'est pas effectuée et la fonction (HAjoute, HModifie, etc.) renvoie <u><u><u><u>Faux</u></u></u></u>. Le message d'erreur est le suivant: "L'action sur la table XXX a été interrompue par le trigger".<br><br><br> |


**Remarque**: Dans le cas où un trigger "AVANT" et un trigger "APRÈS" sont associés à une fonction HFSQL, si le trigger "AVANT" annule l'exécution de la fonction HFSQL (en positionnant H.AFaire à "A") le trigger "APRÈS" n'est pas déclenché.

Le mot-clé [MonFichier](../Motscles/1511019.md) permet de connaître et de manipuler dans le code de la procédure le nom de la table sur laquelle le trigger a été déclenché. Dans le cas d'un trigger "APRES", si la commande HFSQL ne s'est pas exécutée correctement, la procédure associée au trigger n'est pas exécutée.
<a name="NOTE3_4"></a>


### Tests automatiques et triggers
<a name="tests_automatiques_triggers_ELTPARAGRAPHE000162"></a>

Si des tests automatiques déclenchent des triggers utilisant des boîtes de dialogue (fonctions [OuiNon](../WDLang1/3021005.md), [Confirmer](../WDLang1/3021007.md), etc.), il est nécessaire de désactiver ces boîtes de dialogue pendant l'exécution du test grâce à la fonction [EnModeTestAutomatique](../WDLang1/3014027.md). 
<a name="NOTE3_5"></a>


### Triggers et alias de tables
<a name="triggers_alias_tables_ELTPARAGRAPHE000178"></a>

Les triggers peuvent être définis sur des alias de tables. 

- L'alias doit avoir été décrit avant d'appeler la fonction [HDécritTrigger](../WDLang4/3044074.md).

- Le nom de l'alias doit être donné explicitement dans la fonction [HDécritTrigger](../WDLang4/3044074.md).
