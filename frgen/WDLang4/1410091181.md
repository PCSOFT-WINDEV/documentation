
## hPolitiqueSécurité (Type de variable)

***En anglais : hSecurityPolicy***
			
				



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Le type **hPolitiqueSécurité** permet de connaître et de définir toutes les caractéristiques avancées d'une politique de sécurité des mots de passe mise en place pour un serveur HFSQL Client/Serveur. Les caractéristiques de cette politique de sécurité peuvent être définies et modifiées à l'aide de différentes propriétés WLangage. 

Pour manipuler les données d'une base HFSQL Client/Serveur, les utilisateurs s'identifient via un login et un mot de passe. 
La politique de gestion des mots de passe permet de définir aussi bien la taille de ces mots de passe que leur complexité ou encore leur mode de renouvellement (changement de mot de passe obligatoire tous les mois par exemple). 
Cette politique peut être définie et modifiée par programmation ou via le Centre de Contrôle HFSQL. Pour plus de détails, consultez [Politique de gestion des mots de passe](../WDLang4/1000017425.md). 

**Remarque**: Pour plus de détails sur la déclaration de ce type de variable et l'utilisation des propriétés WLangage, consultez [Déclaration d'une variable](../Motscles/1514032.md).

## Propriétés


### Propriétés spécifiques à la description des variables de type hPolitiqueSécurité
<a name="proprietes_specifiques_description_des_variables_type_hpolitiquesecurite_ELTPARAGRAPHE000040"></a>

Les propriétés suivantes peuvent être utilisées pour manipuler une politique de sécurité:

| Nom de la propriété | Type manipulé | Effet |
| --- | --- | --- |
| DuréeBlocage | Durée | Durée (en minutes) du blocage après X tentatives qui échouent. Le nombre de tentatives est déterminé par la propriété **NbTentativesAvantBlocage**. |
| MdpComplexité | Constante de type Entier | Permet de définir la complexité attendue pour le mot de passe: <br><br>- *hMdpFaible*: N'importe quel mot de passe est accepté. Seule la taille minimale est vérifiée (propriété **MdpTailleMinimale**).  <br><br>- *hMdpMoyen*: Le mot de passe doit contenir au moins une majuscule et une minuscule.  La taille minimale est également vérifiée (propriété **MdpTailleMinimale**).  <br><br>- *hMdpFort*: Le mot de passe doit contenir au moins une majuscule, une minuscule, un chiffre et un caractère spécial. La taille minimale est également vérifiée (propriété **MdpTailleMinimale**). <br><br><br> |
| MdpDuréeDeValidité | Entier | Durée de validité du mot de passe exprimée en jours. Cette durée est prise en compte à partir de la dernière date de modification du mot de passe.<br><br>Par défaut, aucune durée de validité n'est définie: cette propriété vaut 0. <br><br>**Remarques**: <br><br>- Dans les [variables de gestion des utilisateurs](../WDLang4/3044315.md), la variable **HUtilisateur.DuréeDeValidité** permet également de définir la durée de validité du mot de passe. Si cette valeur est renseignée, c'est la durée minimale qui est appliquée. <br><br>- De même, si dans le Centre de Contrôle HFSQL, une durée de validité du mot de passe a été définie dans les caractéristiques de l'utilisateur, c'est la durée minimale qui est appliquée. <br><br><br> |
| MdpDuréeDeValiditéMinimale | Entier | Permet de définir la durée minimale de validité d'un mot de passe. Il est ainsi possible d'éviter de changer le mot de passe trop souvent en une journée. Cette propriété est exprimée en jours. <br><br>Par défaut, aucune durée minimale n'est définie: cette propriété vaut 0. |
| MdpPériodeRéutilisationInterdite | Entier | Période (exprimée en jours) interdite pour la réutilisation d'un ancien mot de passe. |
| MdpTailleMinimale | Entier | Taille minimale du mot de passe. |
| NbHistorique | Entier | Nombre de mots de passe conservés dans l'historique par utilisateur. Ces mots de passe ne doivent pas être réutilisés. <br>Par exemple, s'il est interdit d'utiliser les 5 derniers mots de passe, cette propriété vaut 5.  |
| NbTentativesAvantBlocage | Entier | Nombre de tentatives d'authentifications incorrectes avant blocage du compte. La durée de blocage est définie par la propriété **DuréeBlocage**. <br><br>Après 3 tentatives infructueuses, l'authentification est automatiquement ralentie de 1 seconde. <br><br>Si au bout de 30 minutes, le nombre de tentatives spécifié n'a pas été effectué, le décompte des tentatives repart à 0. <br><br>Conseil: Ne pas utiliser sur un serveur public, sinon il y a risque de blocage de tous les utilisateurs. Cette propriété est conseillé en LAN et déconseillée sur un serveur public. <br><br>Cas particulier pour un cluster: Le nombre de tentatives de blocage est spécifiée par noeud. La connexion à un cluster se connectant aléatoirement à un noeud, le nombre de tentatives maximum avant blocage est égal à: <br><pre><code>NbTentativesAvantBlocage x Nombre de noeuds</code></pre><br><br><br> |
| RalentirAChaqueTentative | Booléen | <br><br>- <u><u><u>Vrai</u></u></u>: ajoute un "sleep" lorsqu'il y a plusieurs tentatives de connexion successives qui échouent (permet d'éviter les attaques de type "brute force"). Ce "sleep" est effectif au bout de 10 connexions. <br><br>- <u><u><u>Faux</u></u></u> (valeur par défaut) dans le cas contraire. <br><br><br><br><br> |


<a name="NOTE0"></a>

## Remarques


- Blocage d'un compte utilisateur: 

	- Il est possible de débloquer un compte utilisateur via la fonction [HPolitiqueSécuritéDébloqueCompte](../WDLang4/1410091235.md). 

	- Un redémarrage du serveur débloque tous les comptes (y compris les comptes "super-utilisateur"). 

	- En cas de blocage du compte d'un compte "Super-utilisateur", il est nécessaire de se connecter à la machine physique, puis de se connecter au serveur avec "localhost" et le login. Le blocage est alors levé.
