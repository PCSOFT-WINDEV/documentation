


## Mettre en place la journalisation dans une application
			



<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Présentation
<a name="presentation_ELTTEXTE000457"></a>
Que votre application utilise des tables HFSQL Classic ou HFSQL Client/Serveur, il est possible de mettre en place la journalisation sur ces tables.

**Pour mettre en place la journalisation des tables de votre application**, il est nécessaire de:

1. Définir le type de journalisation à effectuer.

2. Définir la journalisation au niveau des tables.

3. Définir la journalisation au niveau des rubriques.




Les fichiers créés par la journalisation dépendent du type d'accès à vos tables (HFSQL Classic ou HFSQL Client/Serveur).

Les tables journalées pourront ensuite être manipulées avec l'outil WDLog ou par programmation.

## Mettre en place la journalisation
<a name="mettre_place_journalisation_ELTTEXTE000511"></a>


### Définir la journalisation au niveau des tables
<a name="definir_journalisation_niveau_des_tables_ELTPARAGRAPHE000133"></a>

La mise en place de la journalisation sur les tables HFSQL Classic ou Client/Serveur est réalisée sous l'éditeur de schémas des données.

Pour mettre en place la journalisation sur une table décrite dans le schéma des données:

1. Réalisez une sauvegarde des tables dans leur état actuel avec l'outil [WDLog](../WDJournal/3516012.md).

2. Sous l'éditeur de schémas des données, affichez la description de la table voulue:

	- Sélectionnez la table sous l'éditeur. 

	- Sélectionnez l'option "Description de la table" du menu contextuel.




3. Dans l'onglet "Divers" sélectionnez le type de journal à gérer pour cette table.

4. Selon l'option sélectionnée, précisez si nécessaire le répertoire des différents fichiers créés par la journalisation.


![HFSQL Classic](https://doc.pcsoft.fr/ext/images/us/HF.png) Remarques: 

- **Attention: les fichiers JournalIdentification et JournalOperation sont toujours présents dans le même répertoire**. Par défaut, ces fichiers sont créés dans le répertoire de l'application. 
	Ce répertoire est défini dans les options du schéma des données: cliquez dans le fond du graphe du schéma des données et sélectionnez "Description du schéma des données" dans le menu contextuel.
	Ce répertoire peut être modifié au niveau de chaque table.

- **Conseil**: les fichiers journal permettent d'enregistrer les opérations effectuées sur une table pour les re-jouer sur une sauvegarde en cas de problème (disque inutilisable par exemple). Il est conseillé de sauvegarder les fichiers journal dans des répertoires (et même des disques) différents de ceux utilisés pour les tables.



<a name="NOTE3_2"></a>


### Définir la journalisation au niveau des rubriques
<a name="definir_journalisation_niveau_des_rubriques_ELTPARAGRAPHE000164"></a>

Par défaut, toutes les rubriques d'une table journalée sont automatiquement journalées. Il est cependant possible de définir:

- si certaines rubriques doivent être ou non journalées. Par exemple, si une des tables utilise une rubrique mémo pour stocker une image (information peu importante et peu sujette à modification), il est possible de ne pas journaler cette rubrique.

- si la rubrique journalée doit être une clé dans le journal. Cette option permet par exemple de retrouver simplement un enregistrement dans le journal.




Pour ne pas journaler une rubrique:

1. Affichez la description de la table.

2. Affichez la description de la rubrique voulue.

3. Dans l'onglet "Avancé", décochez l'option "Journaler la rubrique".



<a name="NOTE3_3"></a>


### Générer le schéma des données
<a name="generer_schema_des_donnees_ELTPARAGRAPHE000184"></a>

Lorsque la journalisation a été définie dans l'éditeur de schémas des données, le schéma des données peut être généré.

**Attention**: Avant d'effectuer cette opération, il est conseillé de sauvegarder les tables avec l'outil [WDLog](../WDJournal/3516012.md).
<a name="NOTE3_4"></a>


### Modification automatique des données et journalisation
<a name="modification_automatique_des_donnees_journalisation_ELTPARAGRAPHE000196"></a>

Lorsque une modification automatique des tables est effectuée sur des tables journalées:

1. Les fichiers journaux sont automatiquement sauvegardés.

2. Les fichiers journaux sont purgés.

### Fichiers créés en mode HFSQL Classic
<a name="fichiers_crees_mode_hfsql_classic_ELTPARAGRAPHE000210"></a>

Lorsqu'une table du schéma des données a été décrite avec une option de journalisation, les tables suivantes peuvent être créées:


|   |   |
| --- | --- |
| JournalOpération.Fic | Ensemble des opérations réalisées sur les tables HFSQL journalées utilisées par l'application. Une opération correspond à une fonction HFSQL. |
| JournalIdentification.Fic | Liste des emplacements physiques de toutes les tables journalées de l'application |
| \* JNL.Fic | Table créée pour chaque table journalée. Contient la valeur des enregistrements manipulés avant et après chaque opération. |


Pour plus de détails sur la structure de ces fichiers, consultez: [structure des fichiers journaux](../WDLang4/3044182.md).

**Pour paramétrer l'emplacement de ces fichiers et leur mot de passe:**

- **Fichiers JournalOpération et JournalIdentification**: Par défaut, ces fichiers sont créés dans le répertoire de l'application. Pour modifier ce répertoire:

	1. Affichez la description du schéma des données: cliquez dans le graphe du schéma des données, affichez le menu contextuel et sélectionnez l'option "Description du schéma des données". 

	2. Affichez l'onglet "Journal".

	3. Sélectionnez le répertoire du fichier et son mot de passe si nécessaire.


 Remarque: Ce répertoire peut également être modifié pour chaque table journalée (option "Description de la table" du menu contextuel, onglet "Divers"). Dans ce cas, les fichiers JournalOperation et JournalIdentification seront créés pour chaque fichier à l'emplacement spécifié.

- **Fichier \*JNL**: Par défaut ce fichier est créé dans le répertoire de l'application. Pour modifier ce répertoire: 

	1. Affichez la description de la table: option "Description de la table" du menu contextuel.

	2. Affichez l'onglet "Divers".

	3. Sélectionnez le répertoire du fichier.


 Remarque: Le mot de passe de la table \*JNL.fic sera identique au mot de passe de la table.

## WDLog: utilitaire de gestion des journaux
<a name="wdlog_utilitaire_gestion_des_journaux_ELTTEXTE000583"></a>
L'utilitaire WDLog permet de:

- Sauvegarder et restaurer vos tables

- Vérifier la cohérence d'un journal et le purger si nécessaire

- Restaurer une table à partir de son journal.

- Rechercher qui a modifié un enregistrement, à quelle date, ...




Cet utilitaire est redistribuable avec vos applications. Pour plus de détails, consultez [WDLog](../WDJournal/3516012.md).

### Deux tables ne doivent pas utiliser la même table journal
<a name="deux_tables_doivent_pas_utiliser_meme_table_journal_ELTPARAGRAPHE000393"></a>

Plusieurs cas peuvent se présenter:

- **Lors de la création d'une table**, le journal se sert des GUID pour vérifier que deux tables situées à des emplacements différents n'utilisent pas la même table journal. En effet, si plusieurs tables utilisent la même table journal, les données du journal pourraient être corrompues. 
	Si plusieurs fichiers utilisent le même fichier journal, une erreur est affichée.

- **Lors de la copie ou du déplacement d'une table**, le GUID de cette table n'est pas modifié. Dans ce cas, le moteur HFSQL détecte que l'emplacement de la table a été modifié. Un nouvel enregistrement est automatiquement ajouté dans la table **JournalIdentification** afin de noter le nouvel emplacement de la table et son GUID. Cependant, le journal n'effectue aucune vérification.
	Il appartient au développeur de s'assurer que deux copies de la même table situées à des emplacements différents n'utilisent pas la même table journal, auquel cas le contenu du journal ne correspond plus à aucune des 2 tables.

- **Lors de la substitution d'une table par une de ses sauvegardes plus anciennes**, le GUID n'est pas modifié. La journalisation ne détecte pas automatiquement cette opération. 
	Dans une telle situation, il faut supprimer le fichier JNL en même temps que sa table et éventuellement restaurer le fichier JNL sauvegardé en même temps que la sauvegarde de la table.




**Rappel**: Deux types de GUID de fichiers sont gérés par le moteur HFSQL:

- GUID de fichier défini lors de la description du fichier sous l'éditeur de schémas des données. Ce GUID est utilisé dans la gestion du .REP.

- GUID de la table défini lors de la création de la table physique. Ce GUID est utilisé dans la journalisation.
