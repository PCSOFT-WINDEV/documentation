


## Le fichier .REP
			



<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Présentation
<a name="presentation_ELTTEXTE000280"></a>
Le fichier .REP permet de conserver la liste des tables manipulées par l'application. 

Ce fichier .REP peut être manipulé par programmation grâce aux fonctions du WLangage.

<a name="NOTE2"></a>
<a name="NOTE2_1"></a>


## .REP: liste des tables
<a name="rep_liste_des_tables_ELTTEXTE000304"></a>
Le fichier &lt;MonProjet&gt;.REP est un fichier contenant la liste des tables manipulées par l'application (identifiant, nom logique et chemin complet du fichier physique).

Le GUID du schéma des données est l'identifiant unique du schéma des données lié au projet, contenant la description des tables. Cet identifiant peut être connu sous l'éditeur de schémas des données, dans la description du schéma des données (onglet "Options").

Le GUID de la table correspond à l'identifiant de la table logique. Cet identifiant peut être connu sous l'éditeur de schémas des données, dans la description de la table (onglet "Notes").<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=213&name=fichier_Rep.gif)
Ce fichier est automatiquement créé dans le répertoire de l'application et renseigné par le moteur HFSQL.

<a name="NOTE3"></a>
<a name="NOTE3_1"></a>


## A quoi sert le fichier .REP?
<a name="quoi_sert_fichier_rep_ELTTEXTE000328"></a>
Le fichier ".REP" permet de localiser facilement les tables qui ont été utilisées par l'application WINDEV ou WINDEV Mobile.

L'application WINDEV met à jour automatiquement le fichier ".REP", mais ne se sert pas (ou rarement) du fichier ".REP".

Ce fichier est utilisé par tous les outils devant manipuler les tables de l'application, et principalement par la mise à jour automatique des tables, etc.
<a name="NOTE3_2"></a>


### Mise à jour d'une application avec modification du schéma des données
<a name="mise_jour_une_application_avec_modification_schema_des_donnees_ELTPARAGRAPHE000042"></a>

Lors de la mise à jour d'une application WINDEV, la modification automatique des tables est automatiquement lancée en cas de modifications sur la structure de la base de données.

Cette procédure utilise le fichier ".REP" pour retrouver les tables physiques utilisées par l'application afin de les modifier.

Pour plus de détails, consultez: [La modification automatique des tables](../WDLang4/3044195.md)

### Écriture dans le fichier
<a name="ecriture_dans_fichier_ELTPARAGRAPHE000118"></a>

Pour écrire dans le fichier .REP, il suffit d'utiliser les fonctions de gestion de fichiers externes:

- [fOuvre](../WDLang1/3036036.md): pour ouvrir le fichier.

- [fEcritLigne](../WDLang1/3036025.md): pour écrire une nouvelle ligne dans le fichier.

- [fFerme](../WDLang1/3036027.md): pour fermer le fichier.




La structure de la ligne ajoutée doit suivre la norme suivante:


|   |   |   |   |   |   |
| --- | --- | --- | --- | --- | --- |
| **LOCALIZATION=** | GUID Fichier | *Tabulation* | Nom logique table. | *Tabulation* | Chemin de la table physique. |






|   |   |   |   |   |   |   |
| --- | --- | --- | --- | --- | --- | --- |
| **LOCALISATION_CS=** | GUID Fichier | *Tabulation* | Nom logique de la table. | *Tabulation* | Localisation physique de la table dans le serveur HFSQL. | *Tabulation* |
|   | NomServeur:Port | *Tabulation* | IPServeur:Port | *Tabulation* | Base de données |   |

**Dans une application en Unicode**, LOCALISATION_CS est remplacé par LOCALISATION_CS_UTF8: les différentes chaînes sont encodées en UTF8.

Le GUID de la table correspond à l'identifiant de la table logique. Cet identifiant peut être connu sous l'éditeur de schémas des données, dans la description de la table (onglet "Notes").

Deux propriétés du WLangage permettent de connaître le GUID d'une table et du schéma des données qui l'a créé:


|   |   |
| --- | --- |
| [GUIDAnalyse](../Proprietes/2512098.md) | Renvoie le GUID du schéma des données qui a permis de créer la table. |
| [GUIDFichier](../Proprietes/2512099.md) | Renvoie le GUID de la table défini dans le schéma des données qui a permis de créer la table. |

## Structure du fichier .REP
<a name="structure_fichier_rep_ELTTEXTE000400"></a>


### Structure du fichier .REP
<a name="structure_fichier_rep_ELTPARAGRAPHE000197"></a>

La structure du fichier .REP est la suivante:

- La première ligne comprend les informations concernant le schéma des données dans lequel les tables ont été décrites. Ce schéma des données correspond au schéma des données du projet en cours.
	La structure de cette ligne est la suivante:
	


|   |   |
| --- | --- |
| **ANALYSISGUID=** | GUID Schéma des données |


	Le GUID du schéma des données est l'identifiant unique du schéma des données lié au projet, contenant la description des tables. Cet identifiant peut être connu sous l'éditeur de schémas des données, dans la description du schéma des données (onglet "Options").

- Les lignes suivantes décrivent les différentes tables manipulées par l'application. Une ligne est créée par table physique manipulée. Cette ligne comprend les informations suivantes:
	


|   |   |   |   |   |   |
| --- | --- | --- | --- | --- | --- |
| **LOCALIZATION=** | GUID Fichier | Tabulation | Nom logique table | Tabulation | Chemin de la table physique |


	Le GUID de la table correspond à l'identifiant de la table logique. Cet identifiant peut être connu sous l'éditeur de schémas des données, dans la description de la table (onglet "Notes").
