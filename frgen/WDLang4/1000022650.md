


## &lt;Variable Connexion&gt;.CopieTable (Fonction)

***En anglais : &lt;Connection variable&gt;.CopyFile***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Effectue une copie d'une table HFSQL (tables .fic, .ndx, .ftx, .sdx et .mmo s'ils existent) :

- du serveur HFSQL sur le serveur (pour faire une sauvegarde par exemple).

- du serveur HFSQL sur le client (pour faire une sauvegarde en local par exemple).

- du client sur le serveur HFSQL (pour mettre à jour les tables par exemple).

- d'un serveur HFSQL vers un autre serveur HFSQL. 







<a name="sample_code"></a>

## Exemple

<a name="3044282_Exemple1"></a>

```wl
// Description de la connexion
MaConnexion est une Connexion
// Copie des tables du serveur vers le serveur
// avec renommage et changement de répertoire
MaConnexion.CopieFichier(".\sauvegarde\fichierclient_sov.fic", MaConnexion, ".\fichierclient.fic")
```
<a name="3044282_Exemple3"></a>

```wl
// Description de la connexion
MaConnexion est une Connexion
// Copie des tables du poste client vers le poste serveur
MaConnexion.CopieFichier("client.fic", "", "C:\Données\Client.fic")
```
<a name="3044282_Exemple4"></a>

```wl
// Description de la connexion
MaConnexion1 est une Connexion
MaConnexion2 est une Connexion
// Copie la(les) tables d'un serveur vers un autre serveur
MaConnexion1.CopieFichier("client.fic", MaConnexion2, "rep\client.fic", hSansIndex, JAUGE_MaJauge)
```

## Syntaxe

`<Résultat> = <Connexion destination>.CopieFichier(<Table destination> , <Connexion source> , <Table source> [, <Mode de copie> [, <Champ Jauge> [, <Mot de passe>]]])`
---

**`<Résultat> : (Booléen)`**



- <u><u><u><u>Vrai</u></u></u></u> si la table a été copiée,

- <u><u><u><u>Faux</u></u></u></u> en cas d'erreur. La fonction [HErreur](../WDLang4/3044088.md) permet d'identifier l'erreur.




**`<Connexion destination> : (Variable de type Connexion)`**

Nom de la variable de type [Connexion](../WDLang4/1514073.md) décrivant la connexion dans laquelle la table doit être copiée.

**`<Table destination> : (Chaîne de caractères)`**

Nom et chemin de la table destination. Si ce chemin et cette table n'existent pas sur le serveur, ils seront automatiquement créés. 
Si la table destination est sur le serveur, le chemin est relatif à la base de données.
Attention : l'extension de la table '.fic' doit être spécifiée.

**`<Connexion source> : (Chaîne de caractères ou variable de type Connexion)`**

Connexion à partir de laquelle la table doit être copiée. Cette connexion correspond : 

- soit au nom de la connexion définie sous l'éditeur de schémas des données ou grâce aux fonctions [HDécritConnexion](../WDLang4/3044205.md) ou [&lt;Variable Connexion&gt;.OuvreConnexion](../WDLang4/1000023962.md).

- soit au nom d'une variable de type [Connexion](../WDLang4/1514073.md).




**`<Table source> : (Chaîne de caractères)`**

Nom et chemin de la table source (à copier). Si la table source est sur le serveur, le chemin est relatif à la base de données.
Attention : 

- l'extension de la table '.fic' doit être spécifiée.

- le fichier '.mmo' s'il existe sera automatiquement copié.




**`<Mode de copie> : (Constante optionnelle de type Entier)`**

Mode de copie utilisée :



|   |   |
| --- | --- |
| *hCopieIndex* | Le ou les index de la table sont copiés (table NDX, table SDX et table FTX s'ils existent). |
| *hCopieSiInexistant* | Copie la table uniquement si elle n'existe pas à l'emplacement indiqué sur le poste destination. |
| *hCréeIndex* | Le ou les index de la table ne sont pas copiés (table NDX, table SDX et table FTX s'ils existent). Ils sont automatiquement re-créés sur la destination par ré-indexation. <br>Si la table est protégée par mot de passe, le paramètre &lt;Mot de passe&gt; doit être spécifié. |
| *hSansIndex* | Le ou les index de la table ne sont pas copiés (table NDX, table SDX et table FTX s'ils existent). |



**`<Champ Jauge> : (Nom de champ optionnel)`**

Nom du champ Jauge présent dans la fenêtre et permettant de voir la progression de la copie.

**`<Mot de passe> : (Chaîne de caractères optionnelle ou Chaîne secrète)`**

Mot de passe de la table (s'il existe). Ce mot de passe est nécessaire si la constante *hCréeIndex* est utilisée.
**Utilisation de chaînes secrètes** : Si vous utilisez le coffre-fort de chaînes secrètes, le type de la chaîne secrète utilisable pour ce paramètre doit être "Chaîne Ansi ou Unicode".
Pour plus de détails sur les chaînes secrètes et l'utilisation du coffre-fort, consultez [Coffre-fort de chaînes secrètes](../Editeurs/1410087353.md).

## Remarques


### Fonctionnement de la fonction &lt;Variable Connexion&gt;.CopieTable
<a name="fonctionnement_fonction_docparampagetitleshort_ELTPARAGRAPHE000361"></a>

- La table copiée est débloquée, ainsi que les enregistrements contenus dans la table.

- Si l'index n'existe pas ou si l'index est corrompu, alors l'index n'est pas copié.

- Pour copier la table, le mot de passe n'est pas nécessaire. Cependant, la table copiée reste protégée par mot de passe.

- La copie de tables vers un serveur défini comme source d'un serveur de réplication SPARE n'est pas possible. 

- Table en transaction : il est conseillé avant de copier la table de :

	- bloquer la table en lecture/écriture (fonction [&lt;Source&gt;.BloqueTable](../WDLang4/1000024196.md)).

	- annuler les transactions interrompues (fonction [&lt;Variable Connexion&gt;.TransactionAnnule](../WDLang4/1000023966.md)).






<a name="NOTE0_2"></a>


### Conditions d'utilisation
<a name="conditions_utilisation_ELTPARAGRAPHE000389"></a>

- Il est également possible de copier une table du poste client vers ce même poste client. Dans ce cas, la fonction est équivalente à la fonction [fCopieFichier](../WDLang1/3036004.md).

- Cette fonction permet d'effectuer des copies vers un serveur HFSQL (en mode Client/Serveur). Cette fonction ne peut pas être utilisée avec un serveur externe (Oracle ou autre).

- Pour toute copie d'une table HFSQL présente sur un poste local vers le serveur (ou inversement), tous les utilisateurs doivent avoir libéré préalablement cette table. Aucune connexion à la table ne doit être en cours sinon la copie échouera. Si vous n'avez pas la possibilité de débloquer ces enregistrements, utilisez alors les sauvegardes programmées du centre de contrôle HFSQL.




Sinon, pour éviter toute connexion à la table, il est possible de :

- Interdire l'accès à la base de données (fonction [&lt;Variable Connexion&gt;.InterditAccèsBaseDeDonnées](../WDLang4/1000022690.md)), 

- Déconnecter les clients (fonction [&lt;Variable Connexion&gt;.DéconnecteClient](../WDLang4/1000022652.md)),

- Effectuer la copie des tables (fonction [&lt;Variable Connexion&gt;.CopieTable](../WDLang4/1000022650.md)),

- Rétablir l'accès à la base de données (fonction [&lt;Variable Connexion&gt;.FinInterditAccèsBaseDeDonnées](../WDLang4/1000022661.md)). 




- **Cas des tables répliquées (réplication entre serveurs)** : 
	Dans le cas d'une table répliquée, la fonction **&lt;Variable Connexion&gt;.CopieTable** ne doit pas être utilisée pour copier une table vers le serveur : la copie est impossible. Par contre, il est possible de réaliser une copie d'une table du serveur vers le poste client. 

- **Cas d'un cluster HFSQL**

	- Si les tables à copier utilisent une sécurité renforcée, il est nécessaire de préciser le mot de passe de la table via le paramètre &lt;Mot de passe&gt;. Ce mot de passe est nécessaire notamment lors de la synchronisation des tables sur les différents noeuds. 

	- Pour utiliser la fonction **&lt;Variable Connexion&gt;.CopieTable** avec un cluster HFSQL, il est nécessaire que le cluster HFSQL comme l'application cliente utilisent au minimum la version 2024 Update 1. 






<a name="NOTE0_3"></a>


### Noms de tables et de répertoires sur le serveur
<a name="noms_tables_repertoires_sur_serveur_ELTPARAGRAPHE000445"></a>

- Le nom des tables (tables .fic, .ndx, .ftx, .sdx et .mmo s'ils existent) sur le serveur ne doit pas comporter d'accents.

- Sur un serveur LINUX, le nom des tables doit être en minuscules.
