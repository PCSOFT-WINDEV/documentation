


## HChangeConnexion (Fonction)

***En anglais : HChangeConnection***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Change dynamiquement la connexion associée à une table. La nouvelle connexion doit être connue et définie lors de ce changement. Cette nouvelle connexion sera utilisée lors de la prochaine ouverture de la table.

Il est ainsi possible d'importer une description de tables Oracle dans le schéma des données et d'utiliser cette description pour travailler sur des tables au format HFSQL. Pour voir de nombreux exemples de changements de connexion, consultez les exemples détaillés.

**Conseils**: 

- Pour manipuler les connexions, il est conseillé d'utiliser une variable de type [Connexion](../WDLang4/1514073.md).

- **Attention**: L'ordre d'utilisation des fonctions permettant de se connecter à une base de données HFSQL Client/Serveur est important. Consultez [Optimiser les temps de connexion aux bases HFSQL Client/Serveur](../WDLang4/9000176.md) pour plus de détails.





<a name="Exemple1"></a>
<a name="sample_code"></a>

## Exemple


```wl
// Décrire la nouvelle connexion
HDécritConnexion("MaConnexion", "", "", "Serveur_SQLServer", "dbo", hOledbSQLServer, hOLectureEcriture, "")
// Ouvrir la nouvelle connexion
HOuvreConnexion("MaConnexion")
// Indiquer que "Salaires" utilise la nouvelle connexion
HChangeConnexion("Salaires", "MaConnexion")
// Commencer le parcours de la table "Salaires" sur SQLServer
HLitPremier("Salaires")
...
// Fermer la connexion
HFermeConnexion("MaConnexion")
// Rétablir l'utilisation de la connexion sur Oracle
HChangeConnexion("Salaires", "")
// Ouvrir la table "Salaires" sur Oracle
HOuvre("Salaires")
```

<a name="XSYNTAXE"></a>
<a name="SYNTAXE1"></a>

## Syntaxe

`<Résultat> = HChangeConnexion(<Table> , <Nouvelle connexion>)`
---

**`<Résultat> : (Booléen)`**



- <u><u><u><u>Vrai</u></u></u></u> si l'opération a été réalisée, 

- <u><u><u><u>Faux</u></u></u></u> en cas de problème. La fonction [HErreurInfo](../WDLang4/3044071.md) permet d'identifier l'erreur. 




**`<Table> : (Chaîne de caractères)`**

Nom de la table (défini dans le schéma des données) pour lequel la connexion doit être changée. Cette table sera automatiquement fermée pour modifier sa connexion. 

- Si ce paramètre vaut "\*", le traitement est appliqué à toutes les tables connues, quelle que soit leur origine (HFSQL, OLE DB, Connecteur Natif, etc.). Il est ainsi possible de transformer une table HFSQL en une table OLE DB par exemple.
	Cas des projets multi-analyses: les tables des différentes analyses sont prises en compte.

- Ce paramètre peut également correspondre au nom d'un [groupe de fichiers (ou perso-dossier) défini dans le schéma des données](../Editeurs/2011003.md) (non disponible en Android et Android Widget).




**`<Nouvelle connexion> : (Chaîne de caractères ou variable de type Connexion)`**

Nouvelle connexion à utiliser. Ce paramètre peut correspondre: 

- au nom de la connexion à une base de données. Cette connexion a été définie dans l'éditeur de schémas des données ou décrite dynamiquement par la fonction [HDécritConnexion](../WDLang4/3044205.md). Si ce paramètre correspond à une chaîne vide (""), la connexion initiale est automatiquement utilisée.

- au nom de la variable de type [Connexion](../WDLang4/1514073.md) correspondant à la nouvelle connexion à utiliser. 






<a name="NOTE0"></a>
<a name="NOTE0_1"></a>

## Remarques


- La connexion doit être connue au moment de l'exécution de la fonction **HChangeConnexion**. Si la table n'est pas connue lors de l'utilisation de la fonction **HChangeConnexion**, la connexion sera changée au moment de la déclaration de la table.

- La fonction **HChangeConnexion** réalise automatiquement la fermeture de la table (fonction [HFerme](../WDLang4/3044073.md)) dont la connexion doit être modifiée.

- La fonction **HChangeConnexion** n'ouvre ni la table ni la connexion. La connexion définie par la fonction **HChangeConnexion** sera utilisée lors de la prochaine ouverture de la table.
