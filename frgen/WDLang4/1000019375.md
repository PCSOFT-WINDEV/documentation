


## HAccélèreVitesse (Fonction)

***En anglais : HAccelerateSpeed***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Réorganise la structure interne des index pour optimiser la vitesse d'accès aux données. Basée sur la fonction [HStatCalcule](../WDLang4/3044134.md), cette fonction réalise diverses statistiques sur les clés d'une table.

**Quand utiliser la fonction HAccélèreVitesse?**
Cette fonction peut être utilisée aussi souvent que désirée mais il est conseillé de l'utiliser après un ensemble d'ajouts (en général, après un ensemble d'ajouts correspondant au moins à 1 pour mille du nombre d'enregistrements de la base de données). 
**Remarque**: Pour un calcul de statistiques efficace, il est nécessaire de réaliser ce calcul sur toutes les tables (par exemple dans le cas d'une requête multitable).
**Attention**: Cette fonction ne doit pas être utilisée systématiquement dans le code d'initialisation du projet. En effet, l'optimisation de la vitesse d'accès aux données pouvant prendre du temps, les différents utilisateurs pourraient être ralentis. 

**Comment fonctionne la fonction HAccélèreVitesse?**
Les statistiques sur les clés d'une table sont utilisées lors de la pose d'un filtre, la création d'une requête ou encore la création d'une vue sur la table. Le moteur HFSQL schéma des données la condition de sélection et s'appuie ensuite sur ces statistiques pour déterminer les rubriques les plus discriminantes qui permettront d'optimiser les parcours des tables.
Les statistiques permettent d'avoir des informations sur le contenu de la table au moment de leur calcul. Après le calcul des statistiques: 

- Plus la table est modifiée, moins les statistiques sont fidèles au contenu de la table. 

- Plus la table contient d'enregistrements et moins la modification d'un enregistrement a d'impact sur les statistiques.




**Attention**: La fonction **HAccélèreVitesse** bloque la table en écriture pendant le calcul des statistiques (un parcours de la table est effectué pour chaque clé de la table).
![HFSQL Client/Serveur](https://doc.pcsoft.fr/ext/images/us/HFCS.png) Il est possible de réaliser le calcul des statistiques en tâche de fond, sans bloquer la table en écriture.
<a name="Exemple1"></a>
<a name="sample_code"></a>

## Exemple


```wl
// Réorganise la table Client sur la clé NomCli
HAccélèreVitesse(Client, NomCli)
```

<a name="XSYNTAXE"></a>
<a name="SYNTAXE1"></a>

## Syntaxe

`<Résultat> = HAccélèreVitesse([<Table> [, <Rubrique clé> [, <Optimisation>]]])`
---

**`<Résultat> : (Booléen)`**



- <u><u><u><u>Vrai</u></u></u></u> si la réorganisation des index a été effectuée, 

- <u><u><u><u>Faux</u></u></u></u> en cas de problème (table bloquée par une application par exemple). La fonction [HErreur](../WDLang4/3044088.md) permet d'identifier l'erreur.




**`<Table> : (Chaîne de caractères optionnelle)`**

Nom de la table manipulée. Si ce nom n'est pas spécifié, la fonction **HAccélèreVitesse** va manipuler la dernière table utilisée par la dernière fonction de gestion HFSQL (fonction commençant par la lettre H).
Si ce paramètre est égal à "\*" (sans préciser de rubrique), l'opération sera réalisée sur toutes les tables décrites dans le schéma des données en cours (y compris les tables décrites avec les fonctions [HDéclare](../WDLang4/3044203.md), [HDéclareExterne](../WDLang4/3044204.md), [HDécritTable](../WDLang4/3044206.md)).
**Attention**: Cette table ne doit pas être bloquée par une application.

**`<Rubrique clé> : (Chaîne de caractères optionnelle)`**

Nom de la rubrique clé permettant de réorganiser les index. Si ce nom n'est pas spécifié ou est égal à "\*", la réorganisation des index sera réalisée sur toutes les rubriques clé de la table.

**`<Optimisation> : (Constante de type Entier)`**

![HFSQL Client/Serveur](https://doc.pcsoft.fr/ext/images/us/HFCS.png) Permet d'optimiser la réorganisation des index pour des tables HFSQL Client/Serveur. 
Si ce paramètre n'est pas précisé, la table manipulée sera bloquée en écriture. 
Si ce paramètre correspond à la constante *hTâcheDeFond*, la réorganisation des index sera effectuée en tâche de fond, sans bloquer la table. 
**Important**: Ce paramètre est pris en compte uniquement pour des tables HFSQL Client/Serveur. Dans tous les autres cas, la table est automatiquement bloquée pendant le calcul des statistiques. 



<a name="NOTE0"></a>
<a name="NOTE0_1"></a>

## Remarques


- La fonction **HAccélèreVitesse** ne ferme pas la table.

- La réorganisation des index peut également être réalisée par la fonction [HRéindexe](../WDLang4/3044133.md) ou la fonction [HStatCalcule](../WDLang4/3044134.md). 

- Dans les tables HFSQL Classic ou Client/Serveur, seules les rubriques clés peuvent faire l'objet d'une réorganisation des index.

- La syntaxe **HAccélèreVitesse**(&lt;Fichier de données&gt;) est équivalente à **HAccélèreVitesse**(&lt;Fichier de données&gt;, "\*")
