


## HFSQL Client/Serveur : Paramétrage des tables sur le serveur
			



<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Présentation
<a name="presentation_ELTTEXTE000150"></a>
**Si vous modifiez une application WINDEV existante en une application HFSQL Client/Serveur**, il existe deux méthodes pour convertir les tables HFSQL Classic en tables HFSQL Client/Serveur : depuis l'éditeur de schémas des données ou depuis le Centre de Contrôle HFSQL.
Pour plus de détails sur les méthodes de conversion des tables HFSQL Classic en mode Client/Serveur, consultez [Convertir une base HFSQL Classic en HFSQL Client/Serveur](../WDLang4/9000155.md). 

**Si vous créez une application HFSQL Client/Serveur**, aucune manipulation spécifique n'est nécessaire. Les tables seront directement créées sur le serveur lors de l'appel de la fonction [HCrée](../WDLang4/3044255.md) ou [HCréeSiInexistant](../WDLang4/3044254.md).

### Noms sous un serveur Linux
<a name="noms_sous_serveur_linux_ELTPARAGRAPHE000032"></a>

Sur un serveur Linux, les noms de fichiers doivent être en minuscules et sans accent.

Ainsi, le fichier nommé "Tâches.fic" doit être renommé en "taches.fic". La fonction [HCopieTable](../WDLang4/3044282.md) permet de copier les tables en prenant en compte les spécificités de la casse des noms de tables sous Linux.
<a name="NOTE2_2"></a>


### Important
<a name="important_ELTPARAGRAPHE000044"></a>

Sous HFSQL Client/Serveur :

- La fonction [HSubstRep](../WDLang4/3044028.md) n'est pas prise en compte. En effet, cette fonction permet uniquement de substituer les répertoires des tables HFSQL Réseau.

- Si la fonction [HChangeRep](../WDLang4/3044168.md) est utilisée, il est nécessaire de spécifier un chemin relatif au répertoire de la base de données de l'application sur le serveur. Ce fonctionnement permet d'être indépendant de l'emplacement du serveur utilisé.

- Si un chemin de répertoire est spécifié dans la description du schéma des données, dans la description des tables du schéma des données ou dans la description du projet, ce chemin doit être relatif au répertoire de la base de données de l'application sur le serveur.

- Les tables accédées par un serveur HFSQL ne sont accessibles que via ce serveur. Ils ne peuvent pas êtres accédés directement par une autre application notamment à l'aide du moteur HFSQL Classic. Il est nécessaire de se connecter au serveur pour accéder à ces tables.



<a name="NOTE2_3"></a>


### Gestion des contraintes d'intégrité
<a name="gestion_des_contraintes_integrite_ELTPARAGRAPHE000062"></a>

Si vous avez modifié une application HFSQL ISAM en une application HFSQL Client/Serveur en créant les tables sur le serveur, les contraintes d'intégrité sont gérées.

Si vous avez modifié une application HFSQL ISAM en une application HFSQL Client/Serveur sans créer les tables HFSQL sur le serveur (par simple copie), les contraintes d'intégrité ne sont pas gérées.

**Pour gérer les contraintes d'intégrité dans votre application HFSQL**, plusieurs méthodes sont utilisables :

- Utiliser la fonction [HAjouteLiaison](../WDLang4/3044312.md). 

- Faire une modification automatique des tables lors de l'installation de l'application. La modification automatique des tables permet de créer les contraintes d'intégrité sur le serveur.

## Importation de structure
<a name="importation_structure_ELTTEXTE000210"></a>
Il est également possible d'importer dans un schéma des données des structures de fichiers présents sur un serveur HFSQL existant : sous le volet "Schéma des données", dans le groupe "Création", déroulez "Importer" et sélectionnez "Importer des descriptions de fichiers/tables".

## Limitations
<a name="limitations_ELTTEXTE000234"></a>
L'utilisation d'une application HFSQL Client/Serveur peut entraîner une adaptation de la gestion des tables. Pour connaître l'ensemble des spécificités à prendre en compte, consultez [Différences et limitations spécifiques à une application HFSQL Client/Serveur](../WDLang4/3044302.md).
