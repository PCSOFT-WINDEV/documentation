


## Alias sur les tables : fonction HAlias
			



<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Présentation
<a name="presentation_ELTTEXTE000220"></a>
Les alias permettent de manipuler :

- Plusieurs tables physiques ayant la même description dans le schéma des données

- Plusieurs tables logiques décrites dans le schéma des données manipulant la même table physique.




Attention : Cette page d'aide décrit la création d'un alias avec la fonction [HAlias](../WDLang4/3044176.md). A partir de la version 27, il est possible d'utiliser une variable de type [Alias](../WDLang4/1000021446.md). Ce type de variable simplifie la création et la manipulation des alias. 




### Plusieurs tables physiques avec une description logique identique
<a name="plusieurs_tables_physiques_avec_une_description_logique_identique_ELTPARAGRAPHE000035"></a>

Par exemple : Il est ainsi possible de manipuler en même temps :

- Le fichier Client2000.fic qui contient la sauvegarde des clients pour l'année 2000

- Le fichier Client.fic qui contient les références des clients pour l'année en cours




Ces deux tables ont la même description logique dans le schéma des données : la table CLIENT. Par défaut, la description du fichier CLIENT présente dans le schéma des données est liée au fichier Client.fic.<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=213&name=Alias1.gif)
Pour utiliser la table Client2000.Fic, il est nécessaire de "copier" la description de la table CLIENT du schéma des données : il suffit de créer un alias avec la fonction [HAlias](../WDLang4/3044176.md). La ligne de code correspondante est la suivante : 

```wl
HAlias(Client, Client2000)
```
<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=213&name=Alias2.gif)
La manipulation des deux tables se fera de la même façon avec les fonctions HFSQL.


### Plusieurs tables logiques reliées à une seule table physique
<a name="plusieurs_tables_logiques_reliees_une_seule_table_physique_ELTPARAGRAPHE000054"></a>

Il est possible de réaliser plusieurs recherches en parallèle sur une même table physique, ou une recherche et un filtre en parallèle sur la table.

**Exemple** : La table Client.Fic est associée à la table logique Client dans le schéma des données. Pour filtrer les enregistrements de la table Client.fic et pour parcourir en même temps la totalité des enregistrements de cette table, il est nécessaire :

- De "copier" la description de la table CLIENT dans le schéma des données : il suffit de créer un alias avec la fonction [HAlias](../WDLang4/3044176.md).

- D'associer la description de l'alias à la table physique Client.Fic (fonction [HChangeNom](../WDLang4/3044141.md)).




Remarque : Cette méthode permet de gérer plusieurs contextes HFSQL pour une même table physique.

## Manipuler les alias par programmation
<a name="manipuler_les_alias_par_programmation_ELTTEXTE000256"></a>


### Les fonctions du WLangage
<a name="les_fonctions_wlangage_ELTPARAGRAPHE000076"></a>Plusieurs fonctions permettent de manipuler les alias :



|   |   |
| --- | --- |
| [HAlias](../WDLang4/3044176.md) | Crée un alias logique d'une table (ou d'une requête) ou annule tous les alias existants. |
| [HAnnuleAlias](../WDLang4/3044149.md) | Annule un alias précédemment déclaré avec la fonction [HAlias](../WDLang4/3044176.md). |





D'autres fonctions peuvent intervenir dans la définition et la manipulation des alias :



|   |   |
| --- | --- |
| [HChangeNom](../WDLang4/3044141.md) | Modifie le nom physique d'une table. |
| [HChangeRep](../WDLang4/3044168.md) | Modifie le chemin d'accès à une table (c'est-à-dire le répertoire dans lequel la table sera manipulée). |





Remarque : Les variables de type [Alias](../WDLang4/1000021446.md) permettent de simplifier la création et la manipulation des alias.
<a name="NOTE2_2"></a>


### Créer un alias sur quoi ?
<a name="creer_alias_sur_quoi_ELTPARAGRAPHE000094"></a>

Il est possible de créer et de manipuler des alias sur les éléments suivants :

- Table décrite dans le schéma des données,

- Table décrite dynamiquement,

- Requête créée avec l'éditeur de requêtes,

- Vue HFSQL Classic,

- Alias.



<a name="NOTE2_3"></a>


### Caractéristiques d'un alias
<a name="caracteristiques_alias_ELTPARAGRAPHE000107"></a>

- **Table physique associée à un alias** : 
	Par défaut, le nom spécifié pour l'alias est attribué à la table physique correspondant à l'alias. Pour associer l'alias à une table physique de nom différent, il suffit d'utiliser les fonctions [HChangeNom](../WDLang4/3044141.md) et [HChangeRep](../WDLang4/3044168.md).

- **Mot de passe d'un alias** : 
	Par défaut, le mot de passe d'une table alias est identique au mot de passe de la table d'origine. Il est possible de modifier ce mot de passe grâce à la fonction [HPasse](../WDLang4/3044108.md). Le nom de la table utilisé dans cette fonction correspond alors au nom de l'alias.

- **Ré-indexation** : 
	Les fichiers alias peuvent être ré-indexés.

- **Modification automatique des tables** : 
	Cette opération peut être appliquée aux fichiers alias.



<a name="NOTE2_4"></a>


### Manipuler le fichier alias et ses rubriques
<a name="manipuler_fichier_alias_ses_rubriques_ELTPARAGRAPHE000134"></a>

- **Editeur de code** : Pour éviter l'erreur "Identificateur inconnu" lors de l'utilisation d'un fichier alias et de ses rubriques, il est nécessaire de définir une [source de données](../WDLang4/1514053.md) pour déclarer le nom de l'alias avant l'utilisation de la fonction [HAlias](../WDLang4/3044176.md).
	Par exemple :
	
	```wl
	Commande2000 est une Source de Données
	HAlias(Commande, Commande2000)
	```

	Attention : l'utilisation du mot-clé Externe est possible mais entraîne un ralentissement non négligeable à l'exécution.

- **Editeur de fenêtres ou de pages** : les champs et les champs Table ne peuvent pas être directement associés à des rubriques des fichiers alias. Il est nécessaire d'affecter les champs un par un par programmation. 
	Remarque : pour redéfinir par programmation les liaisons des champs, il est possible d'utiliser soit la fonction [ChampAlias](../WDLang1/3025016.md), soit la propriété [LiaisonDonnées](../Proprietes/2510060.md).



<a name="NOTE2_5"></a>


### Triggers et alias
<a name="triggers_alias_ELTPARAGRAPHE000162"></a>

Les triggers peuvent être définis sur des alias de tables. 

- L'alias doit avoir été décrit avant d'appeler la fonction [HDécritTrigger](../WDLang4/3044074.md).

- Le nom de l'alias doit être donné explicitement dans la fonction [HDécritTrigger](../WDLang4/3044074.md).
