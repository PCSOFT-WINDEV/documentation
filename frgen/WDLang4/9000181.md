
## Tables inaltérables
			

<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Présentation
<a name="presentation_ELTTEXTE000229"></a>
Cette fonctionnalité permet de signifier qu'une table ne pourra pas être modifiée après écriture. Une fois un enregistrement ajouté, cet enregistrement ne peut être ni modifié, ni supprimé.

Ce type de table est utile dans des domaines d'activité qui demandent une forte traçabilité. HFSQL signe automatiquement chaque enregistrement, et signe la table elle-même.

L'inaltérabilité des tables :

- protège d'erreurs de programmation en interdisant la modification ou la suppression (via les fonctions [HModifie](../WDLang4/3044042.md)/[HSupprime](../WDLang4/3044018.md) ou via une requête). 

- ajoute sur chaque enregistrement, un hash du contenu de l'enregistrement. Ce hash est un HMAC(SHA256) dont la clé est dérivée du mot de passe de cryptage de la table.




Remarques : 

- Pour renforcer la sécurité, il est conseillé de mettre un mot de passe sur la table inaltérable. Dans ce cas, la table ne pourra pas être créée sans connaître son mot de passe. Il sera donc impossible de supprimer et de recréer la table sans connaître ce mot de passe.

- Utilisation des tables inaltérables avec des serveurs ayant un PERC : 
	Dans ce cas, les écritures dans la table peuvent être plus lentes. Cette lenteur est amplifiée lors d'une réindexation d'une table inaltérable avec des enregistrements supprimés (cas très rare).

## Définir une table inaltérable
<a name="definir_une_table_inalterable_ELTTEXTE000253"></a>
Il est possible de définir une table HFSQL inaltérable :

- doit directement dans l'éditeur de schémas des données :

	1. Affichez la fenêtre de description de la table (par exemple, option "Description de la table" du menu contextuel). 

	2. Dans l'onglet "Options", cochez l'option "Table inaltérable (active automatiquement la sécurité renforcée)". <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=213&name=Fichiers%20de%20donn%E9es%20inalt%E9rables%20-%20HC%20N%B0001.gif&type=thumb)


	3. Validez la description de la table. Dans l'éditeur de schémas des données, la table inaltérable est représentée avec un verrou. <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=213&name=Fichiers%20de%20donn%E9es%20inalt%E9rables%20-%20HC%20N%B0002.gif)

- soit par programmation, en définissant dynamiquement une table : 

	1. Créez une variable de type [Description de fichier](../WDLang4/1514065.md). 

	2. Utilisez la propriété [Inaltérable](../Proprietes/1000023376.md) pour définir l'inaltérabilité de la table. 

	3. Utilisez la fonction [HDécritTable](../WDLang4/3044206.md) pour créer la description de la table. 







Remarques : 

- Si la table est définie inaltérable avec un mot de passe, la sécurité renforcée est automatiquement mise en place.
	Rappel : l'option "Activer la sécurité renforcée " permet de crypter les données sans stocker la clé de cryptage dans la table. Avec cette option et sans le mot de passe de la table, il est impossible de récupérer le contenu de la table.

- Si l'option "Table inaltérable" est mise en place sur une table existante, une mise à jour automatique des tables sera effectuée. La table existante sera compactée (suppression des enregistrements rayés et supprimés) lors de cette mise à jour. 
	**Attention : A partir du moment où une table est inaltérable, plus aucune modification automatique des données ne pourra être effectuée sur cette table**.

- Cette option est disponible uniquement à partir de la version 23. Pour des tables HFSQL Client/Serveur, il est nécessaire d'utiliser un moteur HFSQL C/S en version 23 (ou supérieure).

## Opérations disponibles ou non sur une table inaltérable
<a name="operations_disponibles_non_sur_une_table_inalterable_ELTTEXTE000277"></a>
Les seules opérations possibles sur une table inaltérable sont la création et l'ajout d'enregistrements. 

**Les fonctions et fonctionnalités autorisées** sont les suivantes : 

- Fonctions [HCrée](../WDLang4/3044255.md) et [HCréeSiInexistant](../WDLang4/3044254.md). 

- Fonction [HAjoute](../WDLang4/3044147.md) (hors transaction). 

- Fonction [HEcrit](../WDLang4/3044092.md) avec un numéro d'enregistrement uniquement si le numéro d'enregistrement est le suivant du dernier enregistrement (dans ce cas-là, un ajout est donc effectué). 

- Fonction [HModifie](../WDLang4/3044042.md) avec un numéro d'enregistrement uniquement si le numéro d'enregistrement est le suivant du dernier enregistrement (dans ce cas-là, un ajout est donc effectué). 

- Fonction [HEnregistre](../WDLang4/1000021375.md) précédée de la fonction [HRAZ](../WDLang4/3044118.md) (dans ce cas-là, un ajout est donc effectué). 

- Requêtes de type INSERT.




**Les fonctions et fonctionnalités interdites** sont les suivantes : 

- Fonctions [HModifie](../WDLang4/3044042.md), [HRaye](../WDLang4/3044121.md), [HEcrit](../WDLang4/3044092.md), [HEnregistre](../WDLang4/1000021375.md), [HSupprime](../WDLang4/3044018.md), [HSupprimeTout](../WDLang4/1000017331.md). 
	En effet, ces fonctions modifient le contenu des tables. 

- **Requêtes de type UPDATE et de type DELETE**. 
	En effet, ces requêtes modifient le contenu des tables. 

- **Toute modification du contenu de la table** (quel que soit le moyen utilisé). 

- **La réindexation avec compactage ou avec suppression des enregistrements endommagés**. 
	En effet, ce type de réindexation supprime tous les enregistrements non actifs ou endommagés. La table peut donc être modifiée. 

- **L'ajout dans une transaction**. 
	En effet, l'annulation de la transaction entraîne la modification de la table. 

- **La modification automatique des tables**. 
	En effet, la modification de la structure d'une table (ajout ou suppression d'une rubrique par exemple) peut modifier les données présentes dans la table. 
	Par exemple, l'ajout d'une rubrique avec une valeur par défaut va modifier tous les enregistrements en leur ajoutant cette nouvelle rubrique. De même, la suppression d'une rubrique existante supprime des informations dans les données enregistrées. L'intégrité des données n'est plus garantie.
	


Si une de ces fonctions ou fonctionnalités est utilisée, une erreur d'exécution est affichée. 

Remarque : La fonction [HVérifieInaltéré](../WDLang4/1000023377.md) permet de vérifier qu'un ou tous les enregistrements d'une table inaltérable n'ont pas été modifiés (par exemple avec un éditeur hexadécimal). Attention : Un enregistrement altéré peut être lu (si l'en-tête n'est pas altéré). 

**Comment gérer une modification automatique des données ?** 
La modification automatique des tables n'est pas autorisée. Lorsqu'une nouvelle version d'une application contient une évolution de la structure des enregistrements d'une table HFSQL inaltérable, cette version de l'application devra :

- gérer l'archivage de la table dans son ancien format,

- créer une nouvelle table avec la nouvelle structure.


**Rappel** : Une application peut consulter les données d'une table HFSQL d'une ancienne structure en utilisant la fonction [HVérifieStructure](../WDLang4/3044068.md) en mode *hCompatible*. Si le changement de la structure rend incompatible la table, il sera possible d'utiliser la table archivée dans son ancien format avec la nouvelle application après l'appel de la fonction [HDéclareExterne](../WDLang4/3044204.md).
