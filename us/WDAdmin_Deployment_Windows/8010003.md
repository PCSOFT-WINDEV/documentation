## WEBDEV Application Server
<a name="webdev_application_server_ELTTEXTE000209"></a>


### Overview
<a name="overview_ELTPARAGRAPHE000023"></a>

Starting with version 28, the WEBDEV Application Server setup allows you to: 

- Install the standard version of the WEBDEV Application Server. The full version of the WEBDEV Application server will be installed. This setup requires an activation key. 

- Install WEBDEV Application Server - 10 connections. The WEBDEV Application Server will be limited to 10 connections. 




In both cases, the WEBDEV Application Server includes a silent setup mode. In this mode, you don't need to manually validate the different steps of the wizard.

To perform this silent setup:

1. Install a web server on the server (IIS or Apache). These servers must be installed according to the specifications mentioned in the documentation.

2. Create a setup configuration file. This is an .INI file. 

3. Start the WEBDEV Application Server setup program (located in the EN32 or EN64 directory of the installation package). Use the following command line:
	
	```txt
	/Silent=<.INI file path> /LOG=<Log file path>/<LANGUAGE>
	```

	 where:
	

	- &lt;.INI file path&gt; corresponds to the path and name of the file that controls the setup.

	- &lt;Log file path&gt; corresponds to the path and full name of the file in which the setup result will be saved. This file will contain "OK" is the setup is completed, or an error message if it fails.

	- &lt;LANGUAGE&gt; corresponds to the setup language. Thus, the language selection window is not displayed: 

		- "FR" for French,

		- "US" for English,

		- "ES" for Spanish.




4. The setup goes through the following steps:

	- The setup progress bar appears. The windows that appear are automatically validated.

	- If several versions of IIS or Apache are detected, the most recent version of the Web server is used.

	- The setup is a full setup that uses the default options:

		- WDAdminWeb, WDAdminHF and WDAdminSaaS are installed (full version only).

		- the secure hosting mode for remote administration is not enabled.

		- WEBDEV hosting for sites in an earlier version is enabled.




- At the end of the setup, the log file is filled with the setup report. 




The following paragraphs present the contents of the INI files in the different cases. 


### Silent setup of WEBDEV Application Server - standard version
<a name="silent_setup_webdev_application_server_standard_version_ELTPARAGRAPHE000064"></a>

Below is the structure of the INI file used for the silent setup of the standard version of WEBDEV Application Server: 

```txt
[PILOTE_WebDep]
; Serial number
NUMSERIE=xxxxxx

; Activation key
CLEACT=xxxxxx

; Installation directory
REPINST="C:\WEBDEV 28"

; Install a standalone Application Server
MODINST=1
; or install a new cluster
; MODINST=2
; NOM_CLUSTER= <cluster name to specify in this case>
; or join a cluster
; MODINST=3
; or upgrade a node
; MODINST=4

; Deployment root directory
REPSITES=C:\Sites 

; Retrieve the settings of an Application Server 
; already installed with the same or previous version
RECUP_PARAM=1
; Retrieve SaaS settings from a previous version
RECUP_DATASAAS=1
; Migrate users, sites and web services from the previous version 
; to the most recent version found on the server
MIGREALL=1 
; Allow the deployment of sites in previous versions
ACTIV_ANT=1
; Create a Windows account to be used as WEBDEV administrator account
; Request the creation of a Windows account to be used as WEBDEV administrator account
CREATE_COMPTE_WINDOWS=1
; name of the account to be created
USER_ADMIN=<to specify>
; password of the account to be created
PWD_ADMIN=<to specify>
; Web server to use
; Install IIS
SER_WEB=FORCEIIS
; or use IIS already installed
; SER_WEB=IIS
; or use Apache already installed
; SER_WEB=APACHE
; Start OBDC driver installation (Not installed by default)
ODBC=1
; Show WEBDEV Administrator and CCHosting icons
ICO_BUREAU=1
; Show icons in the Windows application menu
ICO_DEMARRER=1

; Section for the replication server
;------------------------------------------
[RPL]
; Enable replication
RPL=1

; Section for web service used to access third-party databases
;----------------------------------------------
[SOAPDB]
; Enable SoapDB
SOAPDB=1
HTTPS= ;0 for HTTP, 1 for HTTPS
; Full access URL with http(s)
URL= 

;Section for telemetry server
;------------------------------------
[TELEM]
;Enable telemetry
TELEM=1
;Update mode 
;MAJ=0: new parameters on a clean machine (uses all the entries below)
;UPDATE=1: keep the existing configuration (no input required)
;MAJ=2: modifies the HFSQL parameters only (uses the inputs below, 
;specify LoginTLM and MotDePasseTLM again)
MAJ=0
ServeurHFSQL=<to specify> (with:<port number>)
LoginAdminHFSQL=<to specify>
MotDePasseAdminHFSQL=<to specify>
LoginHFSQL=<to specify>
MotDePasseHFSQL=<to specify>
BaseHFSQL=<to specify>
PremierJourSemaine="1"
;To specify if MAJ=2
LoginTLM=<to specify>
MotDePasseTLM=<to specify>

; Section for the WDBaaS server (GPU and Private Store)
; ---------------------------------------------------
[WDBAAS]
; Enable WDBaaS
WDBAAS=1
; Update mode 
; UPDATE=0: new settings on a clean machine (use all entries below)
; MAJ=1: keep the existing configuration (no input required)
; MAJ=2: modifies HFSQL parameters only 
; (uses the entries below, specify BaaSToken again)
MAJ=0
; TokenBaaS=<to specify only if MAJ=2>
ServeurHFSQL=<to specify> (with:<port number>)
LoginAdminHFSQL=<to specify>
MotDePasseAdminHFSQL=<to specify>
LoginHFSQL=<to specify>
MotDePasseHFSQL=<to specify>
BaseHFSQL=<to specify>
MotDePasseFichier=<to specify>
MotDePasseAdmin=<to specify>
```

### Silent setup of a WEBDEV Application Server update
<a name="silent_setup_webdev_application_server_update_ELTPARAGRAPHE000080"></a>

Below is the structure of the INI file used for the silent setup of a WEBDEV Application Server update (regardless of the setup mode, standard or 10 connections): 

```txt
[PILOTE_WebDep]
MODE_MAJ=1
```


The options used in the first setup will be preserved.

## HFSQL Client/Server server
<a name="hfsql_clientserver_server_ELTTEXTE000251"></a>
The HFSQL Client/Server server includes a silent setup mode. In this mode, you don't need to manually validate the different steps of the wizard.

To perform this silent setup:

1. Create a setup configuration file. This is an .INI file with the following structure:
	
	```txt
	[PILOTAGE] 
	Plateforme=1
	MAJ=2 
	CCHF=0
	
	[SERVEUR] 
	Server=LG2 
	Port=4912 
	Repertoire=c:\HF2 server 
	
	[MACHINE] 
	Nom=TRW1B
	```

	The parameters of this emulation file are as follows:

	- Platform: 

		- 1: Windows

		- 2: Remote Install for Windows, 

		- 3: Linux, only 1 and 2 work with this pack




- SHIFT: 

	- 1: update, 

	- 2: Installation, 

	- 3: Uninstall

2. To modify the configuration parameters, a [CONFIGURATION] section must be added with the same keywords as the .CONF of the server. For example:
	
	```txt
	[CONFIGURATION] 
	; indicates that the following parameters are taken into account (0 otherwise) 
	ModifConfig=1
	
	;parameters with their default values: 
	DBRootPATH=%%COMMONAPPDATA%%\PC SOFT\HFSQLServer_<server name specified in the SERVER section>\DB 
	NdxCacheSize=25 
	JNLRootPATH=%%COMMONAPPDATA%%\PC SOFT\HFSQLServer_<server name specified in the SERVER section>\DB\_JNL 
	JNLBackupRootPATH=%%COMMONAPPDATA%%\PC SOFT\HFSQLServer_&lt;server name specified in the SERVER section&gt;\DB\_JNLBackup 
	MoreThan2Go=1 
	ServerLogPath=%%COMMONAPPDATA%%\PC SOFT\HFSQLServer_<server name specified in the SERVER section>\Logs 
	ServerLogLevel1=0 
	ServerLogLevel2=0 
	LogConnection=0 
	ServerLogMaxFileSize=100 
	ServerLogMaxFiles=3 
	PerformacePath=%%COMMONAPPDATA%%\PC SOFT\HFSQLServer_<server name specified in the SERVER section>\Perf 
	PerformanceMaxFileSize=100 
	PerformancePeriod=0
	```

	Note: To include everything in the server directory, %%COMMONAPPDATA%%\\PC SOFT\\HFSQLServer_&lt;server name specified in the SERVEUR section&gt; must be replaced with %%EXE%%. 

3. To use this configuration file, simply launch the HFSQL Client/Server Pack with the following command line:
	
	```txt
	/Silent=<.INI file path> /LOG=<Log file path>
	```

	Note: It is also possible to pass "/DEBUG=&lt;Path to a .txt&gt;" to get execution traces.

4. On exit, an "nstall.log" is created in the server directory. This file will contain "OK" if no problems are encountered. Otherwise, it will contain error messages.
