
## WEBDEV Application Server automatic update
			

<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000161"></a>
The WEBDEV administrator (Deployment version) allows you to update the WEBDEV Application Server. 

If this option is enabled, the WEBDEV Application Server can be automatically updated as soon as a new version is available: 

- on the PC SOFT server. 

- on a custom server. 




<a name="NOTE2"></a>
<a name="NOTE2_1"></a>


## Implementation
<a name="implementation_ELTTEXTE000185"></a>


### How to?
<a name="how_ELTPARAGRAPHE000021"></a>

The WEBDEV Application Server automatic update can be configured: 

- from the WEBDEV administrator, on the "Setups" tab. 

- from the remote WEBDEV administrator. 




In "WEBDEV Application Server update", the administrator indicates whether or not WEBDEV the Application Server is up to date. If an update is available, you can immediately update the WEBDEV Application Server by clicking "Update server...". If a new major version is available, you can enter the new serial number. 

You can also set up an automatic update. In this case, the update will be performed automatically as soon as a new version is available. 

With the "Enable automatic update" option: 

- a wizard starts. The wizard suggests using: 

	- PC SOFT update server: This server contains the latest WEBDEV Application Server updates validated by the PC SOFT Quality Assurance team. 

	- a custom server. In this case, the URL of the custom update server must be specified (see next paragraph). 




- the wizard proposes to schedule the check of the update server (once a month for example). 
	Note: If a new version is available at the time of verification, the WEBDEV Application Server will be stopped and users will be disconnected for the duration of the update.. 



<a name="NOTE2_2"></a>


### Custom update server
<a name="custom_update_server_ELTPARAGRAPHE000053"></a>

You can use a custom update server for the WEBDEV Application Server. This gives you full control over the users' WEBDEV Application Server update process. You can for example validate the use of a new version before releasing it. 

To create a custom update server for WEBDEV Application Servers: 

1. Install a Web server (IIS or Apache) on the selected computer. 

2. Create the following MIME types on the Web server if they do not exist:

	- .json -> application/json

	- .sign -> application/byte-stream

	- .zip  -> application/x-compress




3. Create a directory at the root of the Web server. This directory will contain the update packages. Example: C:\\inetpub\\wwwroot\\hfsql_packages
	This directory must contain: 

	- A json file containing the names of the packages to be used according to the versions (see below). The name of this file must be "webdev_updateinfo.json".

	- The update packages (".zip" files).

	- The signature files corresponding to the packages (".sign" extension).


 These packages and their signatures are available at: [https://package.windev.com/webdev/](https://package.windev.com/webdev/). 




For example: 

- Web server for updates: srvmaj

- UNC directory containing the updates: \\\\updsrv\\webdev_packages\\

- Update URL: http://srvmaj/packs_webdev/




Example of Json file: 


```txt
{
	"pack": [
		{
			"major_version": 29,
			"language"     : "F",
			"version"      : "290076",
			"min_version": "290045",

			"pack": [
				{
					"plateform": "win32",
					"data": "srv_WB_win32_290076p"
				},
				{
					"plateform": "win64",
					"data": "srv_WB_win64_290076p"
				},
				{
					"plateform": "linux64",
					"data": "srv_WB_LX_290076p"
				}
			]
			"serial": [
				{
				"old": "P28F00000"
				"new": "P29F00000"
				"key": "R00000"
			]
		}
	]
}
```
where: 

- **major_version**: corresponds to the major version of the pack (29, etc.).. Only WEBDEV Application Servers in this version will be updated. 

- **language**: corresponds to the server language (F for French, A for English, etc.).. 

- **version**: corresponds to the WEBDEV Application Server version included in the package.. 

- **min_version** corresponds to the minimum version from which the pack can be applied. 

- **pack**: provides pack specifications. 

	- **platform**: platform corresponding to the: 

		- win32: 32-bit Windows

		- win64: 64-bit Windows

		- linux64: 64-bit Linux




- **data**: corresponds to the name of the pack. If the package is next to the json file, the extension is not required. You can use a complete URL in the following format: 
			
		```txt
		http(s)://<domain>/<path>/<File>.zip
		```
The .sign file will be searched at the following URL: 
			
		```txt
		http(s)://<domain>/<path>/<File>.sign
		```
Example: 
			
		```txt
		"https://package.windev.com/pack/wx29/install/wx290076p/WBDEP2024PACKDVD290076p.zip"
		```


- **serial**: manages major updates to WEBDEV Application Server. In this case, you need to provide some key details: 

	- **old**: application server version key to be updated. 

	- **new**: new WEBDEV Application Server key to install.

	- **key** identifier of the product to be installed.  





Note: Only one pack may be referenced, depending on the platform used by WEBDEV Application Servers.
