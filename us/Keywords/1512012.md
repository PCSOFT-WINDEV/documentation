
## &lt;AI TOOL&gt; statement

***In french: Tool IA***
				



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Allows you to declare the WLanguage procedures that can be used in an AI Chat control included in your WINDEV applications.

These procedures are called "tools". 

These tools enable the AI Chat control to perform the operations requested by the user.

**Remarks**:

- Only global procedures (present in a set of procedures) can be used as tools.  

- The &lt;AI TOOL&gt; block must be present in the procedure. It must not be placed above the procedure prototype. 

- The &lt;AI TOOL&gt; block can be in English or French. It will be interpreted in the same way by the AI model used. 



<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
PROCEDURE GetWeather(latitude is real, longitude is real, forecast_date is string = ""): JSON

<AI TOOL>
name: get_weather_forecast
description: Requests weather forecast information to an external webservice
parameters:
    latitude: latitude of the point of the weather forecast
    longitude: longitude of the point of the weather forecast
    forecast_date: date for which the forecast is required, if empty, corresponds to the next 24 hours
<END>
```

## Syntax

### Description of a global "Tool" procedure

`<AI TOOL>
   name: <Tool name>
   label: <Tool lable>
   description: <Tool description>
   parameters: <Name and description of parameters>
<END>
`
---

**`<AI TOOL>: ()`**

Indicates the start of the description for the AI model. 

**`<Tool name>: (Character string)`**

Name of the tool associated with the procedure. This name will be shared with the AI model. It can be different from the procedure name. This parameter is mandatory.  

**`<Tool label>: (Optional character string)`**

Tool label displayed in the AI Chat control when the tool is called. If this label is not specified, only the tool name will be displayed.

**`<Tool description>: (Character string)`**

Tool description in natural language (sentences and words in any language). The AI model uses this description to determine what the procedure does and when to use it.
**Important**: The length of descriptions has an impact on the quality of responses. Overly long descriptions can confuse the model, and slow down generation.

**Note**: You can combine multiple tools to solve complex requests. To specify this combination of tools, we recommend using the system prompt, rather than defining the desired processes in the tool description.  

**`<Name and description of parameters>: (Character string)`**

Name and description of procedure parameters. This description has the following format: 

```txt
parameters:
<Name parameter 1>: <Description 1> 
<Name parameter 2>: <Description 2> 
...
```
where: 

- &lt;Name parameter x&gt; corresponds to the name of the parameter present in the procedure prototype. 

- &lt;Description x&gt; corresponds to the parameter description in natural language.




**`<END>: ()`**

Indicates the end of the description.

## Remarks


### Parameter description
<a name="parameter_description_ELTPARAGRAPHE000061"></a>

- All procedure parameters must be typed.

- The return type must be JSON. If the return type is not specified in the procedure prototype, JSON is automatically used. 

- Only certain simple data types are supported:

	- Character string

	- Integer

	- Real




- Parameters with a default value will be considered optional for the AI model. The model can then decide not to pass this parameter, which will then have its default value.
	Example: 
	"addition", a tool for adding 3 real numbers, could have a default value of 0 in its last parameter. The AI model can use 
	
	```txt
	addition(a, b)
	```


- Each parameter must have a description. The type of each parameter is deduced from the prototype.





### Miscellaneous
<a name="miscellaneous_ELTPARAGRAPHE000080"></a>

- You can use any character in the strings used to describe the name, tool and parameters. Quotation marks are used as they are in the description. There is no need to enclose strings in quotation marks.

- You can use a space (or tab) to indent a parameter. You can use as many as you like, but you need at least 1. 

- Use ":" to separate parameters and descriptions. You can choose whether or not to use one or more spaces before and after ":".
