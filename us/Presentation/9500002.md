<a name="signature_numérique"></a>

	
		DIGITAL SIGNATURE BY CERTIFICATE ON A BULLET CARD
	

	
		 
	
		How it works
	

	
		Certificate-based signing using smart cards offers an additional authentication method. 
This mechanism enables documents or data to be digitally signed using a digital certificate on a bullet card. 
Some examples include health cards, professional cards, cryptographic cards, etc.. 

	




 
	
		The private key stays on the card
	

	
		This method guarantees a secure signing process: 

- The card stores a private key associated with a certificate (e.g. X.509) issued by a certificate authority.

- When signing, the card is inserted into a compatible reader (PC/SC).

- The software reads the data on the card.

- The signature is generated locally on the card, without ever exposing the private key outside the secure component.


Security is guaranteed, as the private key never leaves the card. 

	


 
	
		Programming in WLanguage
	

	
		All WLanguage signature functions, such as PDFSign , XMLSign ... work with a Certificate present on a bullet card. 
Using the CertificateList function, the application retrieves all certificates accessible on the seat, including those on an inserted bullet card. 
Simply browse this list to select the certificate issued by the smart card, represented as a Certificate variable in WLanguage. 

<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=3&name=Signature%20Carte%20A%20Puce.png)

		HOT RELOAD: DON'T LEAVE TEST MODE 
HOT RELOADING TECHNOLOGY GIVES YOU THE POWER 
ALLOWS YOU TO VIEW YOUR UI CHANGES IN REAL TIME 
REAL, WITHOUT LEAVING THE "GO"/HOT RELOAD
	

	
		 
	
		Refresh the UI in real time
	

	
		Imagine. 
You make GO of an ERP application: 
In version 2026, there's no need to close the project test: simply go to the Modifier pane displayed on the field, modify the anchoring, save the window, and presto, in your GO, the window is up to date, with the current data. 
This translates into massive time savings. 

	


 
	
		How it works
	

	
		The principle is simple: any change in a UI is immediately reflected in the windows currently running. 
The only exception: when a field property has been modified by code, this property is retained. 

	


 
	
		Edit and continue: hot code modification
	

	
		The "Hot Edit" (or "Edit and Continue") feature allows the developer to modify the source code of an application during a debugging session, without having to interrupt or restart program execution. 
This capability significantly improves productivity by reducing/restart cycles, especially when fixing bugs or adjusting business logic on the fly. 
For example, in a "step-by-step" debugging mode, we discover that an error has not been processed. Simply type in the error handling code, and continue debugging with the data already input. 

	




 
	
		4 examples
	

	
		Hot modification quickly becomes unavoidable. 
When GOing your application: 


- A PRINT button is missing? add it without leaving the GO

- When using GO on real data, some fields are too small? modify the field size directly in the window editor

- An incorrect or forgotten anchor? Go directly to the modifier

- When you call a function, the parameters passed are wrong or the code incorrect?  Modify your code directly. There's no need to redo GO and fill in all the fields to access the element under test.


It's a real time-saver!

		A Table control can contain very large lines. The height of a single line can even exceed the height of the Table control.
