


## Compile (Function)

***In french: Compile***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Dynamically compiles a procedure whose source code is supplied. The created and compiled procedure is a procedure global to the project.

Note: Functions [ExecuteCode](../WDLang1/1000019783.md) and [EvaluateExpression](../WDLang1/1000019782.md) can also be used to generate dynamically generated code. 


<a name="sample_code"></a>

## Example
<a class="notetitle" target="_blank" href="$DOC$=1000003013015&name=compile_function">See additional examples</a>
<a name="Exemple1"></a>

```wl
// Syntax 1: Dynamic compilation of a global Procedure
// Source: field in which the procedure code is entered

sResult is string 
sResultCompile is string 
sResultCompile = Compile("Dynamic_Proc", MySourceCode)
SWITCH sResultCompile
	CASE "": sResult = ExecuteProcess("Proc_dynamic", trtProcedure)
	CASE "ERR": sResult = "Compilation impossible." + RC + ErrorInfo()
	OTHER CASE: sResult = sResultCompile
END
RETURN sResult
```
<a name="Exemple2"></a>

```wl
// Syntax 2: Dynamic compilation of a global procedure
// Using the Procedure type
// Source: field in which the procedure code is entered

Formula is Procedure = Compile("Dynamic_Proc", MySourceCode)
IF ErrorOccurred = False THEN
	ExecuteProcess("Dynamic_Proc", trtProcedure)
	// Another way to execute the Procedure: Formula()
ELSE
	Info(ErrorInfo())
END
```
<a name="Exemple3"></a>

```wl
// Syntax 3: Dynamic compilation of a global procedure
// Direct use of the Procedure type
// Source: field in which the procedure code is entered

Formula is Procedure = Compile(MySourceCode)
IF ErrorOccurred = False THEN
	Formula()
ELSE
	Info(ErrorInfo())
END
```

## Syntax

### Dynamic compilation of a global procedure

`<Result> = Compile(<Procedure name> , <Source code> [, <Parameters>])`
---

**`<Result>: (Character string)`**

Compilation result:

- Empty string ("") if the compilation was successful. The procedure can be run using [ExecuteProcess](../WDLang1/3013031.md) and [Execute](../WDLang1/3013041.md) with the *trtProcedure* constant.

- ERR if a serious error has occurred: file wdxxxcpl.dll not found, &lt;Code source&gt; incorrect, no project in progress, global procedure already created, etc. [ErrorInfo](../WDLang1/3013008.md) returns the details of the error.

- An error message if a compilation error was detected. This message corresponds to the caption of the error.


![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png) This parameter is not available. This function returns no result.

**`<Procedure name>: (Character string)`**

Name of dynamic global procedure to create.

To create a local procedure, all you have to do is specify the element name. For example: "WindowName.ProcedureName". 

Warning: If the **function Compile** is called several times with the same procedure name, the last procedure created is automatically overwritten.

**`<Source code>: (Character string)`**

Source code in WLanguage of the procedure to compile dynamically. 

- If this code contains quotes, they must be doubled (see the example).

- This code may contain the call and declaration code of an internal procedure.


![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png) Source code in PHP of the procedure to compile dynamically. If this code contains quotes, they must be doubled.

### Dynamic compilation of a global procedure associated with a Procedure variable

- with the [Execute](../WDLang1/3013041.md) function. 

- via a call to the [Procedure](../Motscles/1000018907.md) variable.

To create a local procedure, all you have to do is specify the element name. For example: "WindowName.ProcedureName". 

If **Compile** is called several times with the same procedure name, the last created procedure is automatically overwritten.  

**`<Source code>: (Character string)`**

Source code in WLanguage of the procedure to compile dynamically. 

- If this code contains quotes, they must be doubled (see the example).

- This code may contain the call and declaration code of an internal procedure.

## Remarks


### Using the dynamic procedure
<a name="using_the_dynamic_procedure_ELTPARAGRAPHE000218"></a>

- **If you are using the first syntax**, to use your dynamic procedures, all you have to do is run the procedure via [ExecuteProcess](../WDLang1/3013031.md) or [Execute](../WDLang1/3013041.md).
	Another solution (not recommended): before executing the function **Compile FUNCTION**function, declare the procedure name to the WLanguage compiler using the [EXTERN](../Motscles/1511013.md) keyword and use the procedure directly.

- **If you are using the second syntax**, to use your dynamic procedures, all you have to do is start the procedure: 

	- using [ExecuteProcess](../WDLang1/3013031.md) or [Execute](../WDLang1/3013041.md).

	- via a direct call to the [Procedure](../Motscles/1000018907.md) variable. 




- **If you are using the third syntax**, to use your dynamic procedures, all you have to do is run the procedure via a direct call to the [Procedure](../Motscles/1000018907.md) variable. A procedure that is dynamically compiled can take parameters. Example: 





```wl
MySourceCode is string = [
PROCEDURE AddXandY(aa, bb)
RETURN aa + bb
]
MyProc is procedure = Compile(MySourceCode)
Trace(MyProc(2, 3))
```

<a name="NOTE0_2"></a>


### Dynamic code
<a name="dynamic_code_ELTPARAGRAPHE000262"></a>

**Structures** can be used in dynamic code.

**Constants cannot be used** in dynamic code (defined with the [CONSTANT](../Motscles/1514012.md) keyword).

When using constants in a code, all the occurrences of the constants are replaced with their value during the compilation in the editor but the correspondence between the name of constants and their value is not "embedded" in the application. Therefore, the dynamic compilation cannot use the constants.

Let's see two alternatives:

- Solution 1: Use variables instead of constants. 
	The code: 
	
	```wl
	CONSTANT
		CST_Name = 1
	END
	```

	becomes for example
	
	```wl
	CST_Name is int = 1
	```


- 2nd solution: In the string containing the code to be dynamically compiled, simply replace the name of the constant with its value: 
	
	```wl
	sCode is string
	sCode = [
	Info(CST_Name)
	]
	
	// Replace the name of the constant by its value
	sCode = Replace(sCode, "CST_Name", CST_Name, WholeWord + IgnoreCase)
	
	// The code can be compiled now
	IF Compile("DynProc", sCode) <> "" THEN
		Error("Dynamic procedure compilation error: ", ...
			ErrorInfo())
	ELSE
		// Then it can be run
		WHEN EXCEPTION IN 
			ExecuteProcess("DynProc", trtProcedure)
		DO
			Error("Dynamic procedure execution error: ", ...
				ExceptionInfo())
		END
	END
	```




<a name="NOTE0_3"></a>


### Parameters of a query
<a name="parameters_query_ELTPARAGRAPHE000293"></a>

If the source code used for the dynamic compilation runs a query with parameters ([HExecuteQuery](../WDLang4/3044080.md)), the parameters expected by the query must necessarily be specified in [HExecuteQuery](../WDLang4/3044080.md).

For example, you must use:


```wl
HExecuteQuery("MyQuery", hQueryDefault, "Doe")
```
instead of:


```wl
MyQuery.CustomerName = "Doe"
HExecuteQuery("MyQuery", hQueryDefault)
```





<a name="NOTE0_4"></a>


### Fields in HFSQL functions
<a name="fields_hfsql_functions_ELTPARAGRAPHE000314"></a>

If the source code used for dynamic compilation executes an HFSQL function requiring the name of a field as a parameter, this name must be given in the form of a string enclosed in quotation marks. For example, the code to use for the [HReadSeekFirst](../WDLang4/3044036.md) function is as follows:

```wl
HReadSeekFirst(Item, "ItemCode", "SearchValue")
```
instead of:


```wl
HReadSeekFirst(Item, ItemCode, "SearchValue")
```

<a name="NOTE0_5"></a>


### Deploying of an application that uses Compile
<a name="deploying_application_that_uses_docparampagetitleshort_ELTPARAGRAPHE000329"></a>

When deploying an application that uses**Compile** (when creating the executable or deploying the site), you must specify all the libraries of the WINDEV/WEBDEV/WINDEV Mobile framework used by the code that is dynamically compiled. Indeed, this code being compiled dynamically, WINDEV, WEBDEV and WINDEV Mobile do not detect the framework libraries used.

### Limitations
<a name="limitations_ELTPARAGRAPHE000341"></a>

- If a project window (page) uses a local procedure with the name &lt;Nom de la procédure&gt;, calls to &lt;Nom de la Procédure&gt; from a WLanguage event in the window (page) will always execute the local procedure.

- If a &lt;Nom de la procédure&gt; global procedure already exists, dynamic compilation of a &lt;Nom de la procédure&gt; procedure will generate an error. 

- By default, overloading the WLanguage functions is ignored during the dynamic compilation. 
	For example, if [Trace](../WDLang1/3013050.md) has been overloaded, the WLanguage function (not the overloaded function) will be called in a code that is dynamically compiled. To force the use of the overloaded function during the dynamic compilation, the name of the function must be preceded by the "Extern" keyword.

- The enumerations and the combinations are not available in dynamic compilation.
