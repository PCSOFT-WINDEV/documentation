


## fExtractPath (Function)

***In french: fExtraitChemin***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Returns the different elements of a path: drive, directories, name and extension of the file.

sFilePath = "C:\MyDirectories\File.doc"

// sResFileName corresponds to "File"

// Retrieve the disk and path of the file

## Syntax

`<Result> = fExtractPath(<File path> , <Path section to extract>)`
---

**`<Result>: (Character string)`**



- Requested path section, 

- Empty string ("") if an error occurred. To get more details on the error, use [ErrorInfo](../WDLang1/3013008.md) with the *errMessage* constant.




**`<File path>: (Character string)`**

Name and full or relative path of the file (up to 260 characters). A UNC path can be used. The existence of &lt;File path&gt; is not checked by **fExtractPath**. If the path does not end with a "\\" character, the last element is considered as being a file.
![Windows](https://doc.pcsoft.fr/ext/images/us/WINDOWS.png)![Linux](https://doc.pcsoft.fr/ext/images/us/LX.png) This parameter can be in Ansi or Unicode format.![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![Android Widget ](https://doc.pcsoft.fr/ext/images/us/ANDROIDWIDGET.png) This parameter can correspond to a full path or a path relative to the current directory (returned by [fCurrentDir](../WDLang1/3036022.md)). This parameter is case-sensitive. 
**Reminder**: In Android, the file system is read-only on the device and on the emulator. An application can only write to its installation directory or one of its subdirectories, as well as to the external memory (SDCard).

![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png)![IOS Widget](https://doc.pcsoft.fr/ext/images/us/WIDGETIOS.png)![Mac Catalyst](https://doc.pcsoft.fr/ext/images/us/CATALYST.png) This parameter can correspond to a full path or a path relative to the current directory (returned by [fCurrentDir](../WDLang1/3036022.md)). This parameter is case-sensitive. 
**Reminder** Under iPhone/iPad, on both the device and the emulator, the file system is read-only. An application can only write to its installation directory or one of its subdirectories.

**`<Path section to extract>: (Constant or combination of constants)`**

Section of file path to extract:


|   |   |
| --- | --- |
| *fDirectory* | Different file directories (the file name and extension are not returned). |
| *fDrive* | Drive name.<br>![Linux](https://doc.pcsoft.fr/ext/images/us/LX.png)![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![Android Widget ](https://doc.pcsoft.fr/ext/images/us/ANDROIDWIDGET.png)![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png)![IOS Widget](https://doc.pcsoft.fr/ext/images/us/WIDGETIOS.png)![Mac Catalyst](https://doc.pcsoft.fr/ext/images/us/CATALYST.png) This constant is not available. |
| *fExtension* | File extension, preceded by "." |
| *fFile* | File name (without extension). |

### Example of extracted path
<a name="example_extracted_path_ELTPARAGRAPHE000115"></a>

If the path specified is "C:\\Temp\\Data\\File.txt", **fExtractPath** returns:

- *fExtension* .txt

- *fFile*: File

- *f* directory: \\Temp\\Data\\

- *fDisque*: C:

- *fFile*+*fExtension*: File.txt

- *fDirectory*+*fFile*: \\Temp\\Data\\File

- etc.
