


## CoordinateEditorToScreen (Function)

***In french: CoordonnéeEditeurVersEcran***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Converts a size or a position specified in the reference dpi in the editor (160 dpi) to the native dpi of screen on the device where the application is run. 

This function is mainly used to perform a positioning at pixel level.

![WEBDEV - Server code](https://doc.pcsoft.fr/ext/images/us/WBS.png)![Windows](https://doc.pcsoft.fr/ext/images/us/WINDOWS.png) This function is available only to simplify the Webification of WINDEV projects.

<a name="sample_code"></a>

## Example


```wl
EmulateMouse(WIN_Test.IMG_Circuit, emLeftClick, ...
	CoordinateEditorToScreen(68), CoordinateEditorToScreen(43))
EmulateMouse(WIN_Test.IMG_Circuit, emLeftClick, ...
	CoordinateEditorToScreen(259), CoordinateEditorToScreen(45))
EmulateMouse(WIN_Test.IMG_Circuit, emLeftClick, ...
		CoordinateEditorToScreen(161), CoordinateEditorToScreen(139))
EmulateMouse(WIN_Test.BTN_OK, emLeftClick
```

<a name="XSYNTAXE"></a>

## Syntax
<a name="SYNTAXE1"></a>

`<Result> = CoordinateEditorToScreen(<Value>)`
---

**`<Result>: (Integer)`**

Conversion result: converted size or position in the device's native screen dpi.
![WEBDEV - Server code](https://doc.pcsoft.fr/ext/images/us/WBS.png) This parameter always corresponds to &lt;Value&gt;.

**`<Value>: (Integer)`**

Value to convert: size or position given in the reference dpi under the editor (160 dpi).

## Remarks


- ![WINDEV Mobile](https://doc.pcsoft.fr/ext/images/us/WM.png) Under the editor, the sizes and positions of Android or iPhone window fields always correspond to a 160 dpi (dot per inch) screen.

- ![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![Android Widget ](https://doc.pcsoft.fr/ext/images/us/ANDROIDWIDGET.png)![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png)![IOS Widget](https://doc.pcsoft.fr/ext/images/us/WIDGETIOS.png)![Mac Catalyst](https://doc.pcsoft.fr/ext/images/us/CATALYST.png) When running the application, these sizes and positions are automatically converted according to the native dpi of the screen on the host device.  This allows you to get a WYSIWYG rendering regardless of the device dpi.
	For example, if a control is 100x100 in the editor, at runtime it will be 150x150 on a 240 dpi screen, 200x200 on a 320 dpi screen, etc.

- [CoordinateScreenToEditor](../WDLang1/1000021276.md) makes the opposite conversion, i.e., go from the native dpi of the device where the application is run to the reference dpi in the editor (160 dpi).

- **CoordinateEditorToScreen** must not be used with the drawing functions. Indeed, the DPI of the device may differ from the scale factor used by the drawing functions.
