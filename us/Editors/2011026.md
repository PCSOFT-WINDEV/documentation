## Types of items
<a name="types_items_ELTTEXTE000359"></a>
The different types of items proposed in the data model editor are as follows:<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=3&name=TypeRubrique%20-%20HC%20N%B0001.gif)


| Type | Used to store: |
| --- | --- |
| Text | alphanumeric characters<br><br>- **String** a string of up to 65,535 characters. This character string is in Ansi format.<br><br>- **Text memo** a character string of up to 4 GB. RTF is supported. This text memo is in Ansi format.<br><br>- **Character**: a single character (initialized by a binary 0, Caract(0)).<br><br>- **Unicode** A string in Unicode format.<br><br>- **Unicode text memo** a character string of up to 4 GB. This text memo is in Unicode format.<br><br><br> |
| Numeric | a numeric value<br><br>- **1-byte signed integer** value between -128 and 127<br><br>- **2-byte signed integer** value between -32.768 and 32.767<br><br>- **4-byte signed integer** value between <br>	-2.147.483.648 and 2.147.483.647<br><br>- **8-byte signed integer** value between -9.223.372.036.854.775.808 and 9.223.372.036.854.775.807<br><br>- **1-byte unsigned integer** value between 0 and 255<br><br>- **2-byte unsigned integer** value between 0 and 65.535<br><br>- **Unsigned integer on 4 bytes** value between 0 and 4.294.967.296<br><br>- **8-byte unsigned integer**: value between 0 and 18.446.744.073.709.551.615<br><br>- **Real on 4 bytes** value between -3.4e+38 and +3.4e+38<br><br>- **8-byte real** value between -1.79e+308 and +1.79e+308<br><br>- **Decimal**(Numerical WLanguage): a decimal can have up to 38 significant digits.<br><br><br> |
| Currency | a currency<br>A currency can contain up to 24 significant digits (up to 18 digits for the integer part and up to 6 digits for the decimal part) and it can take a value between -604 462 909 807 314 587,353 087 and +604 462 909 807 314 587,353 087. |
| Date | a date or a duration<br><br>- **Date (YYYYMMDD)**: a date in YYYYMMDD format (dates between 01/01/0001 and 31/12/9999)<br><br>- **Date and Time**: a date-time (between 01/01/0001 at 00:00 and 31/12/9999 at 23:59). The precision is up to the millisecond.<br><br>- **Duration**: a duration in milliseconds (between <br>	-9.223.372.036.854.775.808 and 9.223.372.036.854.775.807).<br><br><br> |
| Time | a time<br><br>- **Time (HH)**: Time between 00H and 23H<br><br>- **Time (HHMM)**: Time between 00H00 and 23H59. The precision is up to the minute.<br><br>- **Time (HHMMSS)**: Time between 00H00min00ss and 23H59min59ss. The precision is up to the second.<br><br>- **Time (HHMMSSCC)**: Time between 00H00min00ss00cs and 23H59min59ss59cs. The precision is up to the tenth of a second.<br><br><br>**Tip**: To keep time accurate to one hundredth of a second, use the "Date and Time" type. |
| Boolean | a boolean (1: True and 0: False) |
| Sound, image, binary, ... | a binary file or string<br><br>- **Image (binary memo)**: an image file<br><br>- **Sound (binary memo)**: a sound file<br><br>- **OLE (binary memo)**: an OLE file<br><br>- **Another binary memo** all file types<br><br>- **Binary string**: a string in binary format<br><br><br> |
| Check Box | a value associated with a Check Box control<br><br>- **Switch** a Boolean (1: True and 0: False)<br><br>- **1-byte unsigned integer** a value between 0 and 255<br><br><br> |
| Radio Button, List Box, Combo Box | a value associated with a Radio Button control, a List Box control or a Combo Box control. <br><br>You have the ability to select the following sub-type: <br><br>- **1-byte integer** an index corresponding to a list of values. The value of this index ranges from -128 to 127<br><br>- **2-byte integer** an index corresponding to a list of values. The value of this index ranges from -32.768 to 32.767<br><br>- **4-byte integer** an index corresponding to a list of values. The value of this index is between <br>	-2.147.483.648 and 2.147.483.647<br><br>- **1-byte unsigned integer** an index corresponding to a list of values. The value of this index ranges from 0 to 255<br><br><br> |
| Automatic ID | the identifier of each record in the data file. <br>Its value is automatically updated by the engine of the HFSQL database.<br><br>- **Automation identifier (4 bytes)** Automatic identifier: the identifier for each record (value between 0 and 2,147,483,647)<br>	This type corresponds to the "Identifier" type of WINDEV 5.5<br><br>- **Automatic identifier (8 bytes)** Automatic identifier: the identifier for each record (value between 0 and 9.223.372.036.854.775.807)<br><br>- **Automatic UUID (128 bits)** each record identifier corresponds to a 128-bit UUID. In this case, the UUID is used to obtain a non-sequential unique identifier.<br><br>- **Automatic UUID (256 bits)** each record identifier corresponds to a 256-bit UUID. In this case, the UUID is used to obtain a non-sequential unique identifier.<br><br><br><br><br>Note: The same record can have an automatic UUID and an automatic Identifier (for example, to simplify the migration of an existing record). |
| XML | an XML character string (4 GB maximum). This string is stored as a text memo. |
| Full-text index | the different elements of the full-text index. The full-text index can include text items or text memo items.<br><br>For more details on how to create a full-text index in the analysis, see [Search and full-text index](../WDLang4/3044375.md). |
| Enumeration, Combination | <br><br>- Enumeration: an integer value among the possible values defined in the enumeration associated with the field.<br><br>- Combination: an integer value representing a combination of the possible values defined in the combination associated with the item.<br><br><br><br><br>For details on how to create an Enumeration or Combination item, see [Enumeration and Combination items](../Editeurs/9500222.md). |
| Calculated item / Formula | a character string in SQL language representing a calculation formula. The formula can use SQL functions and/or WLanguage functions (WL.). Only the formula is stored, the value is calculated when accessing the record in read-only.<br><br>For example, calculate age from the DateBirth field in the data file. The value will be calculated in the data file directly. <br><br><pre><code>CAST(TO_CHAR(SYSDATE,'YYYY') AS int)<br>	- CAST(TO_CHAR(datenaissance,'YYYY') AS int)</code></pre><br><br><br>However, it is possible to store the calculated value in the data file so as not to repeat the calculation.<br><br>It's possible to store the formula in Unicode: the calculation will be faster, but the space occupied by the formula will be larger.<br><br>If the record is modified, the calculation formula is re-run in order to update the buffer of the data file with the new value.<br><br>Caution: NULL handling complies with the SQL standard. For example, if an expression adds the NULL value to a value, the result corresponds to the NULL value. <br><br>![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![Android Widget ](https://doc.pcsoft.fr/ext/images/us/ANDROIDWIDGET.png) Only calculated fields containing SQL functions can be used.. Items calculated with "WLanguage functions" instructions are not available on Android. Their value cannot be read. |
| Timestamp | a DateTime or a Date or a Time representing the creation date of the record or the date of the last modification performed on the record.<br><br>You can choose to: <br><br>- whether the creation date or the last modification date must be saved.<br><br>- whether the local time or the UTC time must be used.<br><br><br><br><br>This item type is also called "Automatic DateTime item". |
| UUID | a UUID. A UUID (Universal Unique IDentifier) is a random number deemed unique. A UUID is useful to easily and reliably identify any element.<br><br>You can choose to: <br><br>- a 128-bit UUID. This type of UUID item complies with the 128-bit RFC 4122 standard. Only the 128-bit UUID is standardized.<br><br>- a 256-bit UUID. <br><br><br><br><br>To manage an automatic identifier of type UUID (automatically initialized by HFSQL), it is necessary to use an item of type "Identifier", with the "Automatic UUID" subtype. <br><br>Note: The main advantage of the UUID is that it enables anonymization and pseudonymization, which is useful for GDPR compliance. The UUID also allows you to manage cryptocurrency identifiers. |
| JSON | a JSON string. This item type can contain NULL, an empty string or a valid JSON. JSON is automatically verified when the record is written. <br><br>This item type is used with JSON SQL functions in particular. |
| Password | a string used as a password. <br><br>The character string contained in this field is "salted" and "chopped". The result of these operations is stored in the item, as well as the salt and the type of algorithm used. It is not possible to reconstruct the original password using this data..  <br><br>This password cannot be displayed to the user.<br><br>You can choose to: <br><br>- the key derivation function,<br><br>- the hash algorithm,<br><br>- the number of iterations,<br><br>- the output length. <br><br><br><br><br> For more details, see [Type of field: Secure password](../Editeurs/9500235.md). |
| Geometric data | geometric data, represented on an Euclidean plane. It can correspond to one of the following subtypes: <br><br>- 2-dimensional stitch,<br><br>- 2D Linestring,<br><br>- 2D Polygon,<br><br>- 2D MultiPoint,<br><br>- 2D MultiLinestring,<br><br>- 2D MultiPolygon.<br><br><br><br><br>This item type can be a spatial key. <br><br>For more details, see [Managing spatial data in HFSQL databases](../WDLang4/1410090447.md). |
| Geographic data | geographic data, using geographic coordinates (latitude and longitude). It can correspond to one of the following subtypes: <br><br>- Geographic Point,<br><br>- Geographic Linestring,<br><br>- Geographic Polygon,<br><br>- Geographic MultiPoint, <br><br>- Geographic MultiLinestring, <br><br>- Geographic MultiPolygon.<br><br><br><br><br>This item type can be a spatial key. <br><br>For more details, see [Managing spatial data in HFSQL databases](../WDLang4/1410090447.md). |
| Any type of geometric or geographic data | geometric or geographic data. In this case, the data corresponds to a geometry (defined in 2D or geographic coordinates). <br><br>For more details, see [Managing spatial data in HFSQL databases](../WDLang4/1410090447.md). |


**Note** Unicode fields are managed by the wdxxxuni.dll library. This library is not available in WINDEV Mobile.


### Array items
<a name="array_items_ELTPARAGRAPHE000287"></a>

Some field types can correspond to an array: the contents of the field will be indexed.

To define an Array item: 

1. Create an item. The field types that can correspond to an array are: Text, Numeric, Monetary, Date, Time, Boolean, Switch. 

2. In the item description: 

	- Check "Array" and specify the array dimension. 
			Warning: The size of the array is fixed. The corresponding space is reserved even if the item is not filled.

	- The actual item size is displayed.




3. Specify (if necessary) the default values of each array element. 

4. Confirm. 




**Remarks**: 

- The first index starts at 1. 

- The syntax for manipulating array fields is as follows: &lt;Nom fichier de données&gt;.&lt;Nom rubrique&gt;[&lt;Indice&gt;]

- Warning: This type of heading is retained for compatibility purposes. Most of SQL databases do not support this item type.
