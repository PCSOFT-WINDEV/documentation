


## WEBDEV site deployment: Deployment profile
			



<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000215"></a>
The setup program creation wizard allows you to select the deployment profile to use. This profile contains the parameters of the application server as well as the parameters for site deployment.

You can:

- choose a profile that was created beforehand (when updating a site for example). In this case, the information regarding the profile is automatically taken into account. Simply validate this information.  

- create a new profile (during a first setup for example).

- choose no profile. In this case, the parameters of the deployment profile will be specified when installing the site (setup via package or via physical media).




For an update, you have the ability to create new profiles (in most cases, one profile per server) and to select them for the update. The site will be deployed on all the selected servers: 

- If the site is already installed on the server, the wizard will perform an update.

- If the site is not installed on the server, the server will perform a new setup.




**Note** If installation fails on one of the servers, installation continues as normal on the other servers.

## Application server settings' step
<a name="application_server_settings_step_ELTTEXTE000239"></a>


### Entering information on the application server
<a name="entering_information_the_application_server_ELTPARAGRAPHE000033"></a>

The following information must be entered: <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=3&name=D%E9ploiement%20-%20HC%20N%B0001.gif&type=thumb)


- Address: Server address, corresponding to the machine name accessible via the network, an IP address or an Internet address.
	In the case of an installation on a WEBDEV Cluster, you must indicate the address of the proxy associated with the cluster. 

- Account and password: Characteristics of the deployment account. The account and password have been defined in the Hosting Control Center, by the host).


Note: The account name may be preceded by the domain name to avoid confusion. For example: "mycomputer\\test" or "mydomain\\test".

Several buttons are also available: 

- "Test parameters" allows you to establish a connection with the Web server and to check that all the information entered is correct.

- Via "Advanced parameters", you can:

	- Define the server parameters. 

	- Define site parameters. 

	- Specify installation file transfer mode (FTP or HTTP)
			Note: HTTP is the default mode from version 25). 

	- Specify the setup commands. 


 For more details, see [Advanced parameters](#NOTE4_1).

- "Export server parameters" allows you to create an XML file with the server parameters. By default, this file is created in the "\\Personal\\WEBDEV servers" subdirectory of the installation directory of WEBDEV. Therefore, the information regarding a server can be transmitted from a project to another one. The parameters can be imported via the "Import the parameters of a server" button.

## Step "Site Deployment Settings"
<a name="step_site_deployment_settings_ELTTEXTE000263"></a>
Then, the wizard allows you to enter the deployment parameters of the site. <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=3&name=D%E9ploiement%20-%20HC%20N%B0003.gif&type=thumb)
The following information must be entered: 

- **Deployment profile name**. 
	This name will be given to the deployment profile in order to easily find it (when updating the site for example).

- **Public name of site on application server**. 
	By default, this name corresponds to the name of the project. You can use a different name. This enables you to deploy several instances of the same project on the same server by giving them different site names. For example, the "REWALI" project can be deployed on a Web server:

	- under the name REWALI: this site is intended for the X1 travel agency.

	- under the name RESA: this site is intended for the X2 travel agency.


 It is possible to specify whether the site should be defined as the default site on the server. In this case, the site will be defined as the default application for the virtual server and will be accessible directly from the server address. 
	Note: There can be only one default application. 

- **Associated domain**.
	This parameter must be filled in the case where the name of the server used for deployment is different from the domain name used to access it. The domain name will be used in the construction of the SiteMap file and in the connection URLs. The SiteMap file is a file used by Google for referencing.

- **Location of data files**.
	Specifies the subdirectory containing data files in HFSQL Classic format. The name of this subdirectory is linked to the site name. It corresponds to the name of the directory where the data files of the site are installed. This directory is a subdirectory of the data directory assigned by the host. This directory name should be modified only if several sites share the same data files.




**Note** If you have entered this information in the advanced settings, it is automatically retrieved.

## Validation
<a name="validation_ELTTEXTE000287"></a>
If you have chosen to deploy the WEBDEV site on a remote WEBDEV Application Server, when validating the site's deployment parameters, WEBDEV attempts to connect to the indicated Web server (and to the indicated FTP server if deployment is carried out via FTP).

An error message is displayed if a problem occurs. For more details on the various errors, and how to resolve them, see: [Error when performing a setup by FTP](../Editeurs/2028057.md).

## Advanced parameters
<a name="advanced_parameters_ELTTEXTE000311"></a>
The advanced parameters allow you to specify the characteristics of the deployment profile used: <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=3&name=D%E9ploiement%20-%20HC%20N%B0002.gif&type=thumb)


- **Name of deployment profile**. This name will be given to the deployment profile in order to easily find it (when updating the site for example).

- **Application server settings** ("General" tab): 
	Application server address, deployment account and password. These parameters are those entered in the "Application server parameters" step.

- **Site parameters** ("General" tab): 

	- **Public name of site on application server**. 
			By default, this name corresponds to the name of the project. You can use a different name. This enables you to deploy several instances of the same project on the same server by giving them different site names. For example, the "REWALI" project can be deployed on a Web server:

		- under the name REWALI: this site is intended for the X1 travel agency.

		- under the name RESA: this site is intended for the X2 travel agency.


 It is possible to specify whether the site should be defined as the default site on the server. In this case, the site will be defined as the default application for the virtual server and will be accessible directly from the server address. 
			Note: There can be only one default application. 

- **Domain**.
			This parameter must be filled in the case where the name of the server used for deployment is different from the domain name used to access it. The domain name will be used in the construction of the SiteMap file and in the connection URLs. The SiteMap file is a file used by Google for referencing.

- **Directory containing HFSQL Classic data files**.
			The name of this subdirectory is linked to the site name. It corresponds to the name of the directory where the data files of the site are installed. This directory is a subdirectory of the data directory assigned by the host. This directory name should be modified only if several sites share the same data files.

- **Language management** You can specify whether the site is to be deployed in all languages or only in certain languages (selectable). 

- **Installation file transfer** ("Advanced" tab):

	- Select transfer mode: HTTP or FTP.
			 When transferring by FTP, you can specify: 

		- The address of the FTP server, 

		- FTP mode: active or passive FTP




- Installation commands ("Advanced" tab): 

	- **Use HTTPS protocol (an SSL certificate must be installed on the Web server)**
						If this option is checked, an SSL certificate must be installed on the web server. If this certificate is not signed by a trusted authority, a warning message will be displayed during the deployment. To avoid displaying this message, check "Ignore the security warnings from HTTPS certificates".

	- **Use a proxy server for the HTTP and HTTPS connections**. If this option is checked, you can specify the characteristics of the proxy server to be used: address, user name and password and proxy port.
