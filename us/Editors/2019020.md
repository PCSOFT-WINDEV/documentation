


## Test mode settings
			



<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000297"></a>
The test of the entire project simulates how the site or the application is started (e.g. via the executable for a WINDEV application). This makes it possible to test the entire site or application, even if its development is not complete yet. When a problem occurs during the execution of the project, you can start the debugger to identify and fix the problem.

To define the different test mode options, go to the "Project" tab, "Test mode" group, expand "Test mode" and select "Test mode settings" (Ctrl + Shift + F9).
<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=3&name=Param%E8trage_test%20-%20HC%20N%B0001.gif)


A series of settings allows you to:

- [Specify a command line](#NOTE3_1).

- [Manage secret string vaults](#NOTE3b_1). 
	

- ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) [Use a specific execution directory](#NOTE3_3).

- ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) [Use a specific manifest for testing](#NOTE3_4).

- ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) [Test a project using the rights granted to another user](#NOTE3_5). This setting is used to check the operating mode of the application by simulating the UAC mechanism in Windows Vista.

- ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) [Specify debugging options](#NOTE3_6).




**Note**: The test of a project can be run regardless of the current element in the editor.

## Test mode settings: Command line
<a name="test_mode_settings_command_line_ELTTEXTE000321"></a>


### Command line
<a name="command_line_ELTPARAGRAPHE000071"></a>

To test a project using a command line, simply specify this command line in the test mode settings window. 

1. Open the test mode settings window. To do so, go to the "Project" tab, "Test mode" group, expand "Test mode" and select "Test mode settings" (Ctrl + Shift + F9).

2. Type the command line.

	- The **custom command line** corresponds to custom parameters used to run the project test. 

	- The **common command line** corresponds to common parameters used to run the project test. These parameters are saved in the project and they are taken into account when the project is shared via the SCM. 


 The command line used during the test is displayed (concatenation of common and custom command lines).


The different elements of the command line will be passed as parameters to the current program.

**Reminder**: You can get the value of these parameters using the [CommandLine](../WDLang1/3013051.md) function.

<a name="vaults_ELTPARAGRAPHE000113"></a>

### Runtime directory
<a name="runtime_directory_ELTPARAGRAPHE000132"></a>

WINDEV allows you to run the project test in a directory other than the "EXE" directory of the project. Therefore, the test is run in conditions close to the ones found on the end-user computers.

By default, the data files used are those present in the directories specified:

- in the project description. For more details, see [Project description: Data files tab](../Editeurs/2030052.md). 

- in the description of the User Groupware if the User Groupware is used by the application. For more details, see [User Groupware (WINDEV and WEBDEV): Options and settings](../Editeurs/1000021153.md). 




To change the application execution directory for test mode:

1. Click the "Runtime directory" tab. 

2. Check "Run test mode in the actual runtime directory".

3. Select the desired runtime directory.

4. Click the "Copy the files" button. For each data file, you can choose the directory into which this file must be copied:

	- a directory proposed by default:

		- ***&lt;RuntimeDir&gt;***: Standard application execution directory. This is the same directory as the one selected in the "Runtime directory" tab.

		- ***&lt;DirUserData&gt;***: Standard application data directory for a specific user. In Windows XP/Vista, this directory has the following format: "C:\\Documents and Settings\\&lt;User&gt;\\Application Data\\&lt;Company Name&gt;\\&lt;Application Name&gt;".

		- ***&lt;DirCommonData&gt;***: Standard application data directory for all the users of a single computer. In Windows XP/Vista, this directory has the following format: "C:\\Documents and Settings\\All Users\\Application Data\\&lt;Company Name&gt;\\&lt;Application Name&gt;".

		- ***&lt;DirUserGlobal&gt;***: Standard data directory shared by several applications for a specific user. In Windows XP/Vista, this directory has the following format: "C:\\Documents and Settings\\&lt;User&gt;\\Application Data".

		- ***&lt;DirCommonGlobal&gt;***: Standard data directory shared by several applications for all the users of a single computer. In Windows XP/Vista, this directory has the following format: "C:\\Documents and Settings\\All Users\\Application Data".




- in a directory selected via the picker ([...] option).

### Vista manifest
<a name="vista_manifest_ELTPARAGRAPHE000178"></a>

If Windows Vista (or later) is your operating system, WINDEV allows you to run the test of your application by using a manifest. This manifest can be included in the executable of your project when creating the executable.

Using a manifest allows you to specify the level of rights required to run the application.

The available manifests are as follows:

- No manifest

- No privileges

- Maximum user privileges

- Administrator privileges

- Like in generation. This option allows you to automatically reuse the manifest characteristics specified during the last generation of application.




For more details on the different manifests, see [Choosing a manifest for Vista](../Editeurs/2025013.md).

### Other user account
<a name="other_user_account_ELTPARAGRAPHE000204"></a>

WINDEV allows you to run the test of the project in a directory by using a user account different from the current one. This allows you to run the test of the project by using rights other than the rights granted to the user currently connected.

Indeed, in most cases, you are the administrator of your computer when developing an application. In most cases, the users of your applications are standard users. This operating mode is even truer in Windows Vista.

WINDEV allows you to run the test of your applications as a standard user: you can quickly identify all your applications problems due to invalid rights, and therefore correct your applications if necessary.

**Note**: It is recommended to combine this option with:

- the use of a runtime directory. For Windows Vista, the runtime directory and the data directory must correspond to the Vista standards.

- the use of a manifest (if your development computer runs on XP).




**Note**: **You can only manage rights on disks using NTFS.**. For the FAT32 file systems, the management of rights is not taken into account.

**To run the tests by using another user account**: 

1. Create (if necessary) one or more users on your computer. New users can be created from the control panel of Windows ("User accounts").  

2. In the "Other user account" tab, specify the user details including name, password and domain.

3. The next application test will be run with this user.




Note: you cannot use a Administrator manifest with a local user that belongs to the administrator group.

### Debug options
<a name="debug_options_ELTPARAGRAPHE000234"></a>

WINDEV allows you to configure the debugging options specific to the test mode. 

The available options are as follows: 

- Ignore timers: This option is used to disable the timers during the debugging. 

- Stop on exceptions, errors or unchecked assertions. In this case, in debugging mode: 

	- the error window is not displayed, 

	- the debugger is directly positioned on the corresponding line of code. 




- Trace project: This option launches the project in "step-by-step" mode. 


These options are also available in the "Debugger" pane of the ribbon, during the test mode.
