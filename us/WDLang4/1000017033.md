


## HDescribeServerTrigger (Function)

***In french: HDécritTriggerServeur***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Adds or modifies a server trigger. A server trigger is a stored procedure automatically called by the HFSQL engine whenever an HFSQL function is run.  

**Note** Server trigger manipulation functions are advanced functions. The server triggers can be created directly in the data model editor. For more details, see [Server triggers](../WDLang4/3044369.md).




<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
// Create a data file
IF HCreation(Cedex) = False THEN
	Error(HErrorInfo())
ELSE
	Info("Data file created")
END
// Change data file directory
IF HChangeDir(Cedex, ".\FRANCE\") = False THEN Error(HErrorInfo())

// Create a trigger on an HFSQL Client/Server data file
IF HDescribeServerTrigger("CNX_TEST", "TriggerTEST", "ProcedureTEST", hTriggerAfter, ...
	"Cedex", "HAdd, HModify") = False THEN Error(HErrorInfo())
// Add records
Cedex.ZipCode = "30000"
Cedex.City = "NIMES"
HAdd(Cedex)
Cedex.ZipCode = "34000"
Cedex.City = "MONTPELLIER"
HAdd(Cedex)
```

## Syntax

### Describing a server trigger (logical files)

`<Result> = HDescribeServerTrigger(<Trigger> , <Stored procedure> , <Type of trigger> , <Logical HFSQL Client/Server files> [, <List of HFSQL functions>])`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the operation was performed, 

- <u><u><u><u>False</u></u></u></u> if a problem occurs. [HErrorInfo](../WDLang4/3044071.md) is used to identify the error.




**`<Trigger>: (Character string)`**

Name of the trigger to create. This name will be used to handle the trigger in the functions for managing server triggers.

**`<Stored procedure>: (Procedure name)`**

Name of the WLanguage stored procedure that will be run when activating the trigger. This procedure accepts no parameter.

**`<Type of trigger>: (Integer constant)`**

Indicates the type of trigger.


|   |   |
| --- | --- |
| *hTriggerAfter* | The stored procedure is run after the HFSQL function. |
| *hTriggerBefore* | The stored procedure is run before the HFSQL function. |



**`<Logical HFSQL Client/Server files>: (Character string)`**

Logical name of one or more HFSQL Client/Server data files. To specify several names, the names of the data files must be separated by a comma (",").

**`<List of HFSQL functions>: (Optional character string)`**

Name of one or more HFSQL or TableXXX functions on which the trigger must be implemented. To specify several names of functions, the names of functions must be separated by a comma (","). You have the ability to define triggers on the following functions:

- [HModify](../WDLang4/3044042.md), 

- [HAdd](../WDLang4/3044147.md)

- [HDelete](../WDLang4/3044018.md)

- [HWrite](../WDLang4/3044092.md)

- [HCross](../WDLang4/3044121.md)


Triggers are also run on INSERT queries (trigger of [HAdd](../WDLang4/3044147.md)), UPDATE queries (trigger of [HModify](../WDLang4/3044042.md)) and DELETE queries (trigger of [HDelete](../WDLang4/3044018.md)).  


<a name="SYNTAXE2"></a>

### Describing a server trigger on the physical files associated with a connection

`<Result> = HDescribeServerTrigger(<Connection> , <Trigger> , <Stored procedure> , <Type of trigger> [, <Physical HFSQL Client/Server files> [, <List of HFSQL functions>]])`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the operation was performed, 

- <u><u><u><u>False</u></u></u></u> if a problem occurs. [HError](../WDLang4/3044088.md) is used to identify the error.




**`<Connection>: (Character string or Connection variable)`**

Connection to use. This connection corresponds to: 

- the name of the connection defined in the data model editor or with [HDescribeConnection](../WDLang4/3044205.md) or [HOpenConnection](../WDLang4/3044107.md).

- the name of a variable of type [Connection](../WDLang4/1514073.md).




**`<Trigger>: (Character string)`**

Name of the trigger to create. This name will be used to handle the trigger in the functions for managing server triggers.

**`<Stored procedure>: (Procedure name)`**

Name of the WLanguage stored procedure that will be run when activating the trigger. This procedure accepts no parameter.

**`<Type of trigger>: (Integer constant)`**

Type of trigger to create: 


|   |   |
| --- | --- |
| *hTriggerAfter* | The stored procedure is run after the HFSQL function |
| *hTriggerBefore* | The stored procedure is run before the HFSQL function |



**`<Physical HFSQL Client/Server files>: (Optional character string)`**

Physical name of one or more HFSQL Client/Server data files associated with the connection ("CUSTOMER.FIC" for example). To specify several names, the names of the data files must be separated by a comma (","). If this parameter is not specified or is an empty string (""), the trigger will be enabled on all the data files of the database.

**`<List of HFSQL functions>: (Optional character string)`**

Name of one or more HFSQL or TableXXX functions on which the trigger must be implemented. To specify several names of functions, the names of functions must be separated by a comma (","). You have the ability to define triggers on the following functions:  

- [HModify](../WDLang4/3044042.md),  

- [HAdd](../WDLang4/3044147.md)

- [HDelete](../WDLang4/3044018.md)

- [HWrite](../WDLang4/3044092.md)

- [HCross](../WDLang4/3044121.md)


Triggers are also run on INSERT queries (trigger of [HAdd](../WDLang4/3044147.md)), UPDATE queries (trigger of [HModify](../WDLang4/3044042.md)) and DELETE queries (trigger of [HDelete](../WDLang4/3044018.md)).

## Remarks


### Triggers of the same type
<a name="triggers_the_same_type_ELTPARAGRAPHE000270"></a>

If several triggers of the same type are defined on the same data file for the same operation, these triggers will be run according to the alphabetical order of their names.
<a name="NOTE0_2"></a>


### Trigger on the functions for manipulating Table controls
<a name="trigger_the_functions_for_manipulating_table_controls_ELTPARAGRAPHE000279"></a>

The table field manipulation functions ([TableAdd](../WDLang1/3074017.md), [TableAddLine](../WDLang1/3074006.md), [TableDelete](../WDLang1/3074032.md), [TableModify](../WDLang1/3074019.md), etc. ) implicitly use the following HFSQL functions: [HAdd](../WDLang4/3044147.md), [HDelete](../WDLang4/3044018.md) and [HModify](../WDLang4/3044042.md).

When using one of these functions for manipulating Table controls, if a trigger is defined for the corresponding HFSQL function, the trigger is automatically activated.
<a name="NOTE0_3"></a>


### Variables used to manage the triggers
<a name="variables_used_manage_the_triggers_ELTPARAGRAPHE000311"></a>

A procedure (or stored procedure) of the trigger type receives no parameters. However, some HFSQL state variables are positioned before each call:


|   |   |
| --- | --- |
| H.FileName | Character string: Logical name of the data file for which the trigger is activated. <br><br>**Warning** Depending on the logical name used by the application, the value of the variable **H.FileName** variable may be different (using aliases, for example). It is recommended to use: <br><br>- MyFile.DescribedName to find out the logical name of the data file being manipulated (without taking aliases into account). <br><br>- MyFile.PhysicalName to find out the physical name of the data file being manipulated.  <br><br><br> |
| H.Action | Character initialized to "A" for a Before trigger and to "P" for an After trigger. |
| H.TriggerFunction | String: Name of the HFSQL function that triggered the trigger. <br><br><br>	<B><B><B><B>Warning</B></B></B></B><br><br>	 The Variable **H.FunctionTrigger** is deprecated in favour of the variable **H.FunctionTriggerNumber**. The information given by the Variable is independent of the language used to run the application.<br>
 |
| H.TriggerFunctionNumber | Constant used to identify the function that triggered the trigger: <br><br>- *htrgHAjoute* The function that triggered the trigger is [HAdd](../WDLang4/3044147.md). <br><br>- *htrgHEcrit* The function that triggered the trigger is [HWrite](../WDLang4/3044092.md). <br><br>- *htrgHModifies* The function that triggered the trigger is [HModify](../WDLang4/3044042.md). <br><br>- *htrgHRaye* The function that triggered the trigger is [HCross](../WDLang4/3044121.md). <br><br>- *htrgHSuppresses* The function that triggered the trigger is [HDelete](../WDLang4/3044018.md). <br><br><br> |
| H.ToDo | During the execution of a before trigger:<br><br>- cancelling the execution of the current HFSQL function by assigning **"A"** to the HFSQL state variable: H.ToDo = "A". In this case, the action is not performed and the function (HAdd, HModify, etc.) returns <u><u><u><u>True</u></u></u></u> (no error).<br><br>- cancelling the execution of the ongoing HFSQL function by assigning **"E"** to the HFSQL state variable: H.AFaire = "E". In this case, the action is not performed and the function (HAdd, HModify, etc.) returns <u><u><u><u>False</u></u></u></u>. The error message reads: "Action on data file XXX has been interrupted by the trigger".<br><br><br> |


**Note** In the case where a "BEFORE" and an "AFTER" trigger are associated with an HFSQL function, if the "BEFORE" trigger cancels the execution of the HFSQL function (by setting H.AFaire to "A"), the "AFTER" trigger is not triggered.
