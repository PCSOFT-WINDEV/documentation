


## &lt;Source&gt;.First (Function)

***In french: &lt;Source&gt;.Premier***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Sets the position on the first record of a data file according to the specified browse item. **The record is not read**.
The number of the current record is modified only when it is returned by [&lt;Source&gt;.RecNum](../WDLang4/1000025041.md). For functions handling the current record number by default (functions [&lt;Source&gt;.Delete](../WDLang4/1000025071.md), [&lt;Source&gt;.Read](../WDLang4/1000025019.md), [&lt;Source&gt;.Modify](../WDLang4/1000025038.md), ...), the value of this number is not updated: you must use the [&lt;Source&gt;.RecNum](../WDLang4/1000025041.md)() function. For example: do not: 

```wl
Customer.Delete()
```
but 

```wl
Customer.Delete(Customer.RecNum())
```

Values in the browse item are read in ascending order (for more details, see the remarks).

Warning: **The record loaded into memory is not modified.** HFSQL variables (e.g. Customer.Name, i.e. the field *Name* field of the *Client*) are not updated.

In most cases, **&lt;Source&gt;.First** is used to set the position in the data file in order to perform a read loop with [&lt;Source&gt;.Next](../WDLang4/1000025070.md).

Several cases may occur after the call to **&lt;Source&gt;.First**:

- the data file is empty or there is no record corresponding to the filter (defined by function [&lt;Source&gt;.Filter](../WDLang4/1000024960.md)): function [&lt;Source&gt;.Out](../WDLang4/1000024605.md) returns <u><u><u>True</u></u></u>.

- the function attempts to block a record already blocked in play mode: function [HErrorLock](../WDLang4/3044099.md) returns <u><u><u>True</u></u></u> and function [&lt;Source&gt;.Out](../WDLang4/1000024605.md) returns <u><u><u>True</u></u></u>.
	![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) JDBC access: lock management is not supported for databases that are accessed through JDBC. 





<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
Customer.First(Name)
WHILE Customer.Out() = False
	// Process the record
	Customer.Next(Name)
END
```

## Syntax

`<Result> = <Source>.First([<Search key item> [, <Options>]])`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the position was set,

- <u><u><u><u>False</u></u></u></u> if an error occurs. This problem can be caused by:

	- or a positioning problem (empty data file, etc.): function [&lt;Source&gt;.Found](../WDLang4/1000025076.md) returns <u><u><u><u>False</u></u></u></u> and function [HError](../WDLang4/3044088.md) returns 0.

	- an error: [HError](../WDLang4/3044088.md) returns an integer other than 0. [HErrorInfo](../WDLang4/3044071.md) returns more details.







**`<Source>: (Type corresponding to the specified source)`**

Name of the data file used. 

**`<Search key item>: (Optional character string)`**

Name of the key item used to loop through the data file. If this name is not specified, **&lt;Source&gt;.First** will use the last browse item used on this data file by the last HFSQL management function (function starting with "H"). If this item does not exist, the best browse item is automatically used.

**`<Options>: (Optional constant)`**

Configures the lock set on the record selected by **&lt;Source&gt;.First**:


|   |   |
| --- | --- |
| *hKeepFilter* | The filter set by [&lt;Source&gt;.Filter](../WDLang4/1000024960.md) will be taken into account, even if the search key is not optimized for the filter. Reminder: [&lt;Source&gt;.Filter](../WDLang4/1000024960.md) returns the optimized search key for the filter. <br>**Caution**: In this case, on large data files, performance problems may occur..<br>![Hyper File 5.5](https://doc.pcsoft.fr/ext/images/us/HF55.png) This variable cannot be used. |
| *hLockNo* | No blocking: the Record can be played back or modified by another application.<br>![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) JDBC access: This constant is not available. |
| *hLockReadWrite* | Read/write lock: the selected record can neither be read nor modified by another application.<br>![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png) Lock in write mode: the selected record can be read by another application, but cannot be modified by another application. Equivalent to *hLockWrite*.<br>![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) JDBC access: This constant is not available. |
| *hLockWrite* | Lock in write mode: the selected record can be read by another application, but cannot be modified by another application.<br>![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) JDBC access: This constant is not available. |
| *hNoRefresh* | ![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png) The table or query content will not be refreshed. All the saved positions are stored.  If this parameter is not specified, function **&lt;Source&gt;.First** resets the browse for the specified item: the contents of the table or query are refreshed with data from the OLE DB database.. All the saved positions are lost. The position will be restored according to the value of best item. <br>Note: Routes and positions saved on other browse items are never assigned. |

![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) JDBC access: lock management is not supported for databases that are accessed through JDBC.![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png)![Native Connectors (Native Accesses)](https://doc.pcsoft.fr/ext/images/us/AN.png) The lock options will have no effect if the locks are not supported by the OLE DB provider or by the Native Connector.![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png) The lock mode specified by **&lt;Source&gt;.First** will remain effective during the calls to [&lt;Source&gt;.Previous](../WDLang4/1000025047.md) and [&lt;Source&gt;.Next](../WDLang4/1000025070.md).

To change the lock mode, use:

- [&lt;Source&gt;.SeekFirst](../WDLang4/1000025055.md) or [&lt;Source&gt;.SeekLast](../WDLang4/1000025054.md),

- **&lt;Source&gt;.First** or [&lt;Source&gt;.Last](../WDLang4/1000024217.md).

- [&lt;Source&gt;.LockRecNum](../WDLang4/1000024197.md) or [&lt;Source&gt;.UnlockRecNum](../WDLang4/1000024212.md).


![Native Connectors (Native Accesses)](https://doc.pcsoft.fr/ext/images/us/AN.png) Oracle: a different blocking mode can be specified for each Record. However, if a transaction was started by [SQLTransaction](../WDLang4/3072029.md) before setting the lock, the lock will only be released at the end of the transaction ([SQLTransaction](../WDLang4/3072029.md) associated with *<u><u><u><u>sqlCommit</u></u></u></u>* or *<u><u><u><u>sqlRollback</u></u></u></u>*).![Hyper File 5.5](https://doc.pcsoft.fr/ext/images/us/HF55.png) The lock options are ignored. Use the lock functions ([&lt;Source&gt;.LockRecNum](../WDLang4/1000024197.md)) kept for backward compatibility.

## Remarks


### Read operation based on a key
<a name="read_operation_based_key_ELTPARAGRAPHE000491"></a>

**&lt;Source&gt;.First** positions on the record with the smallest key value.

The sort order taken into account is the one specified in the analysis for this key.

If duplicates are found, **&lt;Source&gt;.First** sets the position on the first "duplicate" record according to the sequence of record numbers.

### Checking password
<a name="checking_password_ELTPARAGRAPHE000511"></a>

If **&lt;Source&gt;.First** is the first function that handles the specified data file, the password is checked when opening the data file.

If the password is incorrect, [HErrorPassword](../WDLang4/3044082.md) returns <u><u><u><u>True</u></u></u></u> and [&lt;Source&gt;.Out](../WDLang4/1000024605.md) returns <u><u><u><u>True</u></u></u></u>.
<a name="NOTE0_3"></a>


### Miscellaneous
<a name="miscellaneous_ELTPARAGRAPHE000541"></a>

- [&lt;Source&gt;.RecNum](../WDLang4/1000025041.md) returns the current record number.

- [&lt;Source&gt;.ChangeKey](../WDLang4/1000024198.md) changes the search key while keeping the position on the current record.



<a name="NOTE0_4"></a>


### Comparison between [&lt;Source&gt;.ReadFirst](../WDLang4/1000025022.md) and &lt;Source&gt;.First
<a name="comparison_between_readfirstwdlang41000025022md_and_docparampagetitleshort_ELTPARAGRAPHE000560"></a>

The function **&lt;Source&gt;.First** function does not play the Record: the **&lt;Source&gt;.First** is therefore faster than function [&lt;Source&gt;.ReadFirst](../WDLang4/1000025022.md).

### Locks
<a name="locks_ELTPARAGRAPHE000587"></a>

By default (&lt;Options&gt; not specified), the record is not locked.

If a lock is requested (*hLockWrite* or *hLockReadWrite* constant), the position will be set on the record only if it is not already locked.
