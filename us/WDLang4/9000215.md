
## Automatic data masking
			

<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000321"></a>
Data masking is a process that transforms the data in an item that will be displayed to the user. This data can be partially or totally masked: the data will not be visible "in clear". 

Data masking helps you prevent sensitive data exposure by hiding it from certain users. Data masking also makes it possible to secure information and prevent it from spreading. By masking a data file, you will replace all personal data. For example:

- replace last names with XXX[..]XXX.

- replace city names with numbers (1, 2, 3, 4, 5) to calculate statistics on the number of inhabitants without being able to identify the cities.




There are **two types of data masking**:

- static anonymization, which is irreversible: the data is permanently lost.

- dynamic data masking. This anonymization is performed on-the-fly by the database server: it is therefore reversible. Initial data is accessible depending the user privileges.




Both types of data masking are useful, but each in a specific context.

- **In a statically anonymized data file**personal data no longer exists: the data file therefore falls outside the scope of the GDPR. The data file can then be processed, stored and transmitted without restriction.

- **In the case of dynamic anonymization**personal data still exists: the data file is therefore still subject to the GDPR (e.g. with regard to retention periods).

## Implementation in WINDEV, WEBDEV and WINDEV Mobile
<a name="implementation_windev_webdev_and_windev_mobile_ELTTEXTE000345"></a>


### Use conditions
<a name="use_conditions_ELTPARAGRAPHE000037"></a>

Data masking can only be implemented in applications that use HFSQL data files in Client/Server mode. 
<a name="NOTE2_2"></a>


### Principle
<a name="principle_ELTPARAGRAPHE000044"></a>

Applying data masking on an item consists in: 

- defining data masking rules ("masks"). A rule defines the data masking mode used and its characteristics. These rules can be implemented: 

	- in [the data model editor](#NOTE3_1), for each desired item. 

	- via [SQL statements](#NOTE5_1).


 Please note: Only one rule can be defined per section.. It is not possible to combine several rules. 

- defining data masking user privileges. Users can be allowed or prevented from viewing masked items. These privileges can be defined: 

	- [in the HFSQL Control Center](#NOTE4_2). 

	- [programmatically, using HFSQL functions](#NOTE4_3). 

	- [programmatically, using SQL statements](#NOTE5_1). 







By default, the field will be dynamically anonymized for all users. To allow a user or group of users to view an item, you need to grant them data unmasking permissions.

**For static anonymization** (irreversible) anonymization, simply make a backup of the database or the data file. The saving mode of anonymized fields is managed by the Property **Anonymization** property of the [hBackupDescription](../WDLang4/1000017455.md) type variable.

## Implementation in the analysis
<a name="implementation_the_analysis_ELTTEXTE000375"></a>


### Modifying the analysis
<a name="modifying_the_analysis_ELTPARAGRAPHE000085"></a>

To mask an item in a data file:

1. In the data model editor, select the relevant data file. 

2. In the context menu of the data file, select "Description of fields". 

3. Select the item you want to mask.  

4. Go to the "Data mask" tab. <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=3&name=Anonymisation%20-%20HC%20N%B0001.gif)
"No rule (the item is not masked)" is selected by default. 

5. Select and configure the desired rule: 

	- random text (lorem ipsum), to generate several random words,

	- a constant value (to be defined),

	- noise (a variation of plus or minus x %) for integer values,

	- a value returned by a stored procedure, for a specific data mask (for example, to mask a section of code while preserving part of the data),

	- partial scrambling, to keep some characters at the beginning and end of values, but replacing the rest with a given character.




6. Confirm changes in the description window of items. 

7. Generate the analysis and run the automatic data modification. 




Remarks: 

- The [MaskingRule](../Proprietes/1410090333.md) property gets the data masking rule defined for a given item. This rule is in SQL format. 

- To find out which fields have been anonymized and the rule used, in the "Analysis" pane, in the "Analysis" group, pull down "Maintenance" and select "List of fields with anonymization rule". 







### Enabling data file encryption
<a name="enabling_data_file_encryption_ELTPARAGRAPHE000123"></a>

When using automatic data masking, it is advisable to enable data file encryption. This ensures that data remains unusable, even in the event of unauthorized access to the server or to a backup. 

To enable data file encryption in data model editor: 

1. Select the data file. 

2. In the context menu, select "Data file description". 

3. Go to the "Details" tab, "Data protection" section and specify the desired encryption mode for the data file, index file and/or memo file. 
	The encryption algorithm to be used by default is RC5 (16 rounds).


Note: For even greater security, check "Enable enhanced security".

## Defining user permissions
<a name="defining_user_permissions_ELTTEXTE000405"></a>
To define which users can access actual (non-masked) data values, simply grant specific permissions.

Viewing permissions can be set at different levels:

- for the database,

- for the data file, 

- for the item.




Data unmasking (and other) permissions for an item can be set:

- from the HFSQL Control Center, 

- programmatically.



<a name="NOTE4_2"></a>


### HFSQL Control Center
<a name="hfsql_control_center_ELTPARAGRAPHE000159"></a>

To grant permissions at the database or data file level, simply click "Manage rights" in the HFSQL Control Center ribbon. <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=3&name=Anonymisation%20-%20HC%20N%B0003%201.gif)


To grant permissions at the item level, simply click the "lock" icon of the item in the "Description" tab. <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=3&name=Anonymisation%20-%20HC%20N%B0003.gif)
In the window that appears, you can change the permissions set on the item. <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=3&name=Anonymisation%20-%20HC%20N%B0004.gif)

<a name="NOTE4_3"></a>


### Programming
<a name="programming_ELTPARAGRAPHE000172"></a>

To change permissions programmatically, you can use a series of WLanguage functions ([HModifyItemRights](../WDLang4/1410089918.md), [HModifyFileRights](../WDLang4/3044327.md), etc.).


```wl
// Allow "MARK" to unmask data:
// - all items from all files in the "DataMasking" database
HModifyDatabaseRights(ctMyConnection, "MARK", hRightsUnmask, hAllowed, "DataMasking")
// - all the items of the "Address"
HModifyFileRights(ctMyConnection, "MARK", hRightsUnmask, hAllowed, "DataMasking", "Address")
// - only the "PostalCode" item in the "Address" file
HModifyItemRights(ctMyConnection, "MARK", hRightsUnmask, hAllowed, "DataMasking", "Address", "PostalCode")
```


Note: When data is anonymized in the application UI, it may be useful to inform users that this display is normal and requires advanced rights. Simply use the WLanguage HInfoXXXRights functions to determine which permissions have been granted and display indications where necessary.


```wl
// Checks if the permission has been granted at the data file level
IF HInfoFileRights(gctConnection, sUser, hRightsUnmask, 
		DATABASE_NAME, Address, hEffective) = hForbidden THEN
	RETURN False
END
```

## Managing data masking with SQL statements
<a name="managing_data_masking_with_sql_statements_ELTTEXTE000441"></a>
The following SQL statements can be used to manage data masking: 

- **ADD MASKED** Combined with SQL command [ALTER TABLE](../Editeurs/2034001.md), creates an anonymizing mask for a field in a file. 

- **DROP MASKED** Combined with SQL command [ALTER TABLE](../Editeurs/2034001.md), deletes an anonymizing mask for a field in a file. 

- [GRANT](../Editeurs/2034001.md): Enables a data mask. 

- [REVOKE](../Editeurs/2034001.md): Disables a data mask.

## Anonymization: features and limitations
<a name="anonymization_features_and_limitations_ELTTEXTE000465"></a>
When data masking is enabled for an item: 

- Unmasking permissions are required to: 

	- use [HReadSeek](../WDLang4/3044050.md) on a masked key item.

	- use a SQL query with a WHERE condition on a masked item.

	- use an SQL query with a reference to a masked item in the ORDER BY clause.

	- use [HBackup](../WDLang4/1000017081.md) and [HCopyFile](../WDLang4/3044282.md) with data files. 

	- use data file replication.




- Function [HCopyRecord](../WDLang4/3044261.md): original values cannot be recovered. Masked values are buffered in the new record.

- You can apply data masks to key or non-key items. However, it is not possible to apply a mask to composite key items.

- If you apply a data mask to an item of type array, this mask applies to all the elements of the array.

- Materialized view: 

	- Unmasking permissions are required to define a materialized view on a file.

	- Even if unmasking permissions are granted, items remain masked in the materialized view.

	- Regardless of the masking/unmasking permissions, it is not possible to create a materialized view with masked calculated items.




- Even if unmasking permissions are granted, it is not possible to make backup copies of files containing masked items.





### Adding and modifying records (HFSQL functions)
<a name="adding_and_modifying_records_hfsql_functions_ELTPARAGRAPHE000248"></a>

- When adding a new record with [HAdd](../WDLang4/3044147.md) or [HSave](../WDLang4/1000021375.md), items are initialized either with their default value, or with the specified value. Data masks are not applied.

- When modifying a record with [HModify](../WDLang4/3044042.md) or [HSave](../WDLang4/1000021375.md), only masked items on which the user has unmasking permissions will be modified.





### INSERT and UPDATE SQL queries
<a name="insert_and_update_sql_queries_ELTPARAGRAPHE000266"></a>

- In an INSERT SQL query, items without values are initialized with the default value defined in the analysis. Items with values are automatically initialized without applying the data mask.

- In an UPDATE SQL query, items with values are automatically initialized without applying the data mask.




Note: When using the RETURNING function, there are 2 possibilities:

- If the item is masked and has values in the SQL query, the mask will not be applied to the returned value.

- If the item is masked and does not have values in the SQL query, the mask will be applied to the returned value.
