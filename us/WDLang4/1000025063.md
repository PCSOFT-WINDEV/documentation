


## &lt;Source&gt;.Security (Function)

***In french: &lt;Source&gt;.Sécurité***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Enables or disables the automatic security mechanism on one or more data files.


<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
Customer.Security(False) // Disables the protection mechanism
Customer.Security(True) // Enables the protection mechanism
```

<a name="XSYNTAXE"></a>
<a name="SYNTAXE1"></a>

## Syntax

`<Result> = <Source>.Security(<Security level>)`
---

**`<Result>: (Integer)`**

Former security level (before running **&lt;Source&gt;.Security**).

**`<Source>: (Type corresponding to the specified source)`**

Name of the data file used.

**`<Security level>: (Integer or boolean)`**

Requested security level:

- 0 or <u><u><u><u>False</u></u></u></u> (default): Safety mechanism disabled. Data is written to data files at the highest speed possible.

- 1 or <u><u><u><u>True</u></u></u></u>: Security mechanism activated: writing speed is slower than with the HSecurity(0) option, but security is guaranteed when writing to data files.

- 2: Maximum security mechanism: Data file writing speed is slower than with the HSecurity(1) option..

<a name="NOTE0_1"></a>

## Remarks


### &lt;Source&gt;.Security and HFlush functions
<a name="docparampagetitleshort_and_hflush_functions_ELTPARAGRAPHE000214"></a>

**&lt;Source&gt;.Security** and [&lt;Source&gt;.Flush](../WDLang4/1000024981.md) can both be used to force a physical write operation on disk.

However:

- **&lt;Source&gt;.Security** forces the data file(s) to be written. The HFSQL engine automatically performs the write operation. The data files are not closed during this write operation. This results in slower write speeds.

- [&lt;Source&gt;.Flush](../WDLang4/1000024981.md) forces a write operation to the data files when it is called. The data files are closed and then re-opened during this write operation. The write operation is not slowed down.
