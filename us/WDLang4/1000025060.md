


## &lt;Source&gt;.Index (Function)

***In french: &lt;Source&gt;.Réindexe***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Rebuilds the file index (".NDX" file). You can also reindex: 

- full-text indexes (".FTX" files),

- spatial indexes (".SDX" files). 


A data file can be reindexed even when it is accessed by one or more applications. For more details, see remarks.

![HFSQL Client/Server](https://doc.pcsoft.fr/ext/images/us/HFCS.png) Client/Server HFSQL data files can be reindexed asynchronously using [&lt;HFSQL connection&gt;.ReindexAsynchronous](../WDLang4/1410091221.md). 


**Reminder**: Reindexing reorganizes indexes and can free up space left when records are deleted. After reindexing, the access to indexes is optimized. Reindexing a data file can become necessary further to the loss or modification of the index file. [&lt;Source&gt;.CheckIndex](../WDLang4/1000025078.md) is used to regularly check the status of the index file.

<a name="sample_code"></a>

## Example


```wl
IF AFile.Index(hNdxNormal) = True THEN
	TABLE_MyTable.Display(taStart)
END
```

## Syntax

`<Result> = <Source>.Index([<Mode> [, <Progress Bar> [, <Density rate>]]])`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the reindex operation was successfully performed,

- <u><u><u><u>False</u></u></u></u> otherwise. [HError](../WDLang4/3044088.md) returns more details about the problem.




**`<Source>: (Type corresponding to the specified source)`**

Name of the data file used. 

**`<Mode>: (Optional Integer constant (or combination of constants))`**

Reindexing configuration:


|   |   |
| --- | --- |
| *hChangeCharset* | Reindexing with change of character set.<br>The new character set defined by [ChangeCharset](../WDLang1/3054001.md) will be taken into account during the reindexing. Sorts, searches or other types of operations performed on string keys (strings, characters, date and time) will use the new character set. |
| *hFTX* | Reindexing of full-text indexes. |
| *hMmoCompact* | Compression and defragmentation of "Mmo" files.<br><br>**Caution**: This constant cannot be combined with the *hNdxCompact*, *hCheckMemo*, *hFTX*, *hSDX*, *hNdxNormal* or *hNdxDelete* constants. |
| *hNdxCompact* | Reindexing with compression: Only active records are preserved. All the other records are permanently deleted. The space left by the deleted records is deleted from the data file and the index (".FIC" and ".NDX" files, respectively).<br>Note: If one or more records are in a transaction, compression is automatically disabled. |
| *hNdxMinimal* | Reindexing while taking into account only corrupted keys. This parameter is ignored if the *hNdxDelete* or *hNdxCompact* constant are enabled. |
| *hNdxSilent* | Reindexing without display. |
| *hNdxNormal*<br>(default value) | Standard reindexing (with statistics and without compression).<br>Statistics help optimize queries and filters (see the Notes). Only active records are taken into account for calculating statistics. |
| *hNdxNoStat* | Reindexing without calculating statistics. This constant saves space by reducing the index file size.<br>**Note**: Statistics are important to achieve acceptable execution times when using queries, conditional filters and views with conditions. |
| *hNdxDelete* | Reindex and delete damaged records. |
| *hSDX* | Reindexing of spatial indexes. |
| *hBackgroundTask* | ![HFSQL Client/Server](https://doc.pcsoft.fr/ext/images/us/HFCS.png) Reindexing in the background. Applications are not locked during reindexing.<br><br>This feature is available in Client/Server mode only. |
| *hCheckMemo* | Standard reindexing with verification of Memo items and correction if necessary (can be used to retrieve damaged memos). <br><br>![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png)![WEBDEV - Server code](https://doc.pcsoft.fr/ext/images/us/WBS.png) Note: You can regularly check the status of memos before reindexing them, using [&lt;Source&gt;.CheckMemo](../WDLang4/1000025079.md). |



**`<Progress Bar>: (Optional control or window name, or optional integer)`**



- Name of the window in which the progress bar will be displayed, 

- Name of the Progress Bar control that displays the reindexing progress,

- Handle of the window that displays the progress bar.


![WEBDEV - Server code](https://doc.pcsoft.fr/ext/images/us/WBS.png) This parameter is ignored.

**`<Density rate>: (Integer between 1 and 100)`**

Density rate of indexes. This rate is set to 60 by default.

## Remarks


### Use conditions
<a name="use_conditions_ELTPARAGRAPHE000391"></a>

- **&lt;Source&gt;.Index** reindexes an xBase file.

- **&lt;Source&gt;.Index** is used to reindex data files in a cluster. In this case: 

	- Reindexing is performed on the node to which the user is connected. 

	- Only zero-downtime reindexing is available (*hBackgroundTask* constant).

### Automatic reindexing
<a name="automatic_reindexing_ELTPARAGRAPHE000413"></a>

It may be necessary to reindex a data file if the index file has been lost or damaged. An automatic reindexing can be implemented for the data files.

To implement an automatic reindex operation, you must:

- configure the value of the [H.AutoIndexingLimit](../WDLang4/3044024.md) variable. 
	Indeed, if the data file contains less than **H.AutoIndexingLimit** records, the reindex operation is automatically performed if an index error occurs. 
	The H.AutoIndexingLimit variable is set to 10000 by default. The automatic reindex operation is disabled if this variable is set to 0.

- configure the value of the [H.VisibleAutoIndexing](../WDLang4/3044070.md) variable. 
	If this value is set to <u><u><u><u>True</u></u></u></u> (default value), a window is automatically displayed as long as the automatic reindex operation is not completed. This window contains a progress bar used to track the progress of the current reindexing. This window can be customized. For more details, see [HFSQL error handling help](../WDLang4/3044188.md). 
	Any applications that manipulate data in the data file (read or write) will be temporarily stopped/blocked until reindexing is complete.
	![HFSQL Client/Server](https://doc.pcsoft.fr/ext/images/us/HFCS.png) If the *hBackgroundTask* constant is used, the reindexing process is run in the background and the applications that use the data file are not stopped. 




If an error occurs during the automatic reindex operation (lock error on the data file or on the record for example), the automatic reindex operation is stopped and a fatal error (corrupted index) is displayed. This operating mode is similar to the one without automatic reindexing.

Remarks:

- During the automatic reindexing, the reindex operation is performed in normal mode (*hNdxNormal* constant).

- Automatic reindexing is not available for Hyper File 5.5 data files.

- If an automatic reindexing is performed, the applications that use the data files currently reindexed are temporarily locked. A message appears, indicating that the data file is under maintenance.

- Once reindexing is completed, the current HFSQL context is automatically restored (except for reindexing with memo item verification).

### "Zero-downtime" reindexing
<a name="zerodowntime_reindexing_ELTPARAGRAPHE000466"></a>

A data file can be reindexed even when it is accessed by one or more applications.

Any applications that manipulate data in the data file (read or write) will be temporarily stopped/blocked until reindexing is complete.
![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) A window is displayed, indicating that the data file is currently reindexed (also called reorganization). This window is displayed during reindexing and cannot be closed. A progress bar indicates the status of reindex operation.<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=3&name=HF_Reindexation.gif)
You can customize this window or don't allow it to open again. For more details, see [HFSQL error handling help](../WDLang4/3044188.md).

To avoid flickering issues, the indexing window is displayed only if the reindexing process takes more than 2 seconds. In this case, this window is displayed after 0.7 seconds.

**Note**: "Hot" reindexing is not available if records are locked for read or write operations in the data file to be reindexed. If records are locked in write mode only, zero-downtime reindexing can still be performed.
![HFSQL Client/Server](https://doc.pcsoft.fr/ext/images/us/HFCS.png) If the *hBackgroundTask* constant is used, the reindexing process is run in the background and the applications that use the data file are not stopped. 
<a name="NOTE0_4"></a>


### Calculating statistics
<a name="calculating_statistics_ELTPARAGRAPHE000495"></a>

Statistics help optimize queries and filters in the data file. Only active records are taken into account for calculating statistics. [&lt;Source&gt;.StatCalculate](../WDLang4/1000025064.md) also returns the results of this calculation.

**Note**: For optimal results, this calculation must include all data files (e.g. multi-file query).
<a name="NOTE0_5"></a>


### Directory of temporary files
<a name="directory_temporary_files_ELTPARAGRAPHE000512"></a>

Temporary files can be created during reindexing. By default, these files are created in the Windows temporary directory or in the current directory if there is not enough space.

The [H.TemporaryDirectory](../WDLang4/3044381.md) variable allows you to configure the directory used to save these temporary files. This variable is recommended when reindexing large data files.
![HFSQL Client/Server](https://doc.pcsoft.fr/ext/images/us/HFCS.png) The directory used to store temporary files on the server can be defined as follows: 

- in the [HFConf.INI](../WDLang4/3044345.md) file. 

- using the [&lt;Connection variable&gt;.SetServer](../WDLang4/1000022664.md) function. 



<a name="NOTE0_6"></a>


### Managing non-Latin character sets
<a name="managing_nonlatin_character_sets_ELTPARAGRAPHE000543"></a>

To modify the character set used for the searches, the sorts:

1. Specify the character set to use with [ChangeCharset](../WDLang1/3054001.md).

2. Reindex the data file with **&lt;Source&gt;.Index**. Use the *hChangeCharset* constant to use the character set specified by [ChangeCharset](../WDLang1/3054001.md).


For more details, see [Managing specific character sets in the data files](../WDLang1/3054017.md).
<a name="NOTE0_7"></a>


### Access rights to the data file
<a name="access_rights_the_data_file_ELTPARAGRAPHE000569"></a>

Reindexing recreates the data file on disk. In an allocation system that manages permissions at file level (NTFS, etc.), the reindexed data file will have the permissions of the directory to which it belongs.

If the data file had different rights from those of the folder before reindexing, you must redefine them in Windows after reindexing.
<a name="NOTE0_8"></a>


### Special case: Data files corrupted after a reboot or a fatal error
<a name="special_case_data_files_corrupted_after_reboot_fatal_error_ELTPARAGRAPHE000581"></a>

Some data files may be corrupted when the computer reboots unexpectedly. In this case, the data files contain invalid data (unreadable characters for example). To fix this problem:

1. Perform a reindexing with deletion.

2. Free all records held by a transaction with [&lt;Source&gt;.TransactionFree](../WDLang4/1000025074.md).

3. Delete the incorrect records with WDMAP.
