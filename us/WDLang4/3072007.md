


## SQLExec (Function)

***In french: SQLExec***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Names and runs an SQL query.

**Attention** The function **SQLExec** function does not start the memory result retrieval process. The result is retrieved on the first call to one of the following functions: [SQLFirst](../WDLang4/3072017.md), [SQLTable](../WDLang4/3072031.md) or [SQLFetch](../WDLang4/3072011.md).

**Note** To manipulate a binary memo in a query, use the keyword ***WDMemoBinary*** keyword in your query text (for details, see [remarks](#NOTE0_5)).

```wl
// Connect to the database
// (SQLConnect or SQLConnectWS functions)

// Run the query and retrieve the result line by line 
i is int = 0
SQLExec("SELECT LASTNAME, FIRSTNAME, EXTENSION, PHOTO FROM CUSTOMER", "QRY1")
WHILE SQLFetch("QRY1") = 0 // There is still another line to read
	i++
	// Retrieve the data
	LASTNAME[i] = SQLGetCol("QRY1", 1)
	FIRSTNAME[i] = SQLGetCol("QRY1", 2)
	EXTENSION[i] = SQLGetCol("QRY1", 3)
	{"IMAGE"+i} = SQLGetMemo("QRY1", 4)
END
SQLClose("QRY1")

// Disconnect (SQLDisconnect)
```

## Syntax

### Running an SQL query

`<Result> = SQLExec(<SQL query text> , <Query name>)`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the query was executed,

- <u><u><u><u>False</u></u></u></u> otherwise. If the query was not run, the error message can be returned by the SQL.MesError variable once [SQLInfo](../WDLang4/3072028.md) has been run.




**`<SQL query text>: (Character string)`**

SQL code of query to run.

**`<Query name>: (Character string)`**

Name associated with the query text. Corresponds to:

- the logical query name.

- the name and full path of query (".WDR" file).


![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) The query name corresponds to the logical query name only. 


<a name="SYNTAXE2"></a>
![WEBDEV - Browser code](https://doc.pcsoft.fr/ext/images/us/WBN.png) 
### Running an SQL query in browser code

`<Result> = SQLExec(<SQL query text> , <Query name> [, <WLanguage procedure>])`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the query was executed,

- <u><u><u><u>False</u></u></u></u> otherwise. Query execution is asynchronous: the function requests execution of the query, then the current processing continues without retrieving the query result. 
	The result of **SQLExec** can only be used to manage the connection problems. We advise you to check the proper query execution in the &lt;Procedure name&gt; procedure. 




**`<SQL query text>: (Character string)`**

SQL code of query to run.

**`<Query name>: (Character string)`**

Name associated with the query text. 

**`<WLanguage procedure>: (Procedure name)`**

Name of WLanguage procedure to run during the execution of the SQL query. 
 
This procedure can be a browser procedure global to the project or a browser procedure local to the page that contains the code currently run. This procedure has the following format: 

```txt
PROCEDURE <Procedure name>(<Query name>)
```

where &lt;Query name&gt; is the name of query currently run. 

This procedure is started at the end of real query execution (regardless of the query result). This browser procedure is used to:  

- check the proper execution of the query. [SQLInfo](../WDLang4/3072028.md) is automatically run during the call to the procedure. Therefore, all the SQL variables are positioned. If an error occurred, SQL.Error will differ from "00000". The error message is returned by the SQL.MesError variable.

- browse the query result. 


If new queries are run in this procedure (to add records for example), you can: 

- use the same procedure: the parameter of this procedure is used to find out the query currently run. 

- use a different browser procedure to test the result of these new queries.

## Remarks


### Running the query
<a name="running_the_query_ELTPARAGRAPHE000160"></a>

The information regarding the query execution is returned by [SQLInfo](../WDLang4/3072028.md). The SQL.NbCol variable contains the number of columns found in the query result.

Once it was run and processed, the query must be freed by [SQLClose](../WDLang4/3072015.md).
<a name="NOTE0_2"></a>


### Retrieving the query result
<a name="retrieving_the_query_result_ELTPARAGRAPHE000175"></a>

Then, the query result can be:

- Transferred into a table or into a list box ([SQLTable](../WDLang4/3072031.md)).

- Transferred into controls or variables ([SQLAssociate](../WDLang4/3072004.md)).

- Retrieved line by line ([SQLFetch](../WDLang4/3072011.md)).

### Managing text memos
<a name="managing_text_memos_ELTPARAGRAPHE000206"></a>In the &lt;Query text&gt; parameter, a text memo is used like a text variable. For example:


```wl
// Query with condition on a text memo whose value is "Good customer" 
QueryText = "SELECT CUSTNAME FROM CUSTOMER WHERE CUSTOMERMEMO = 'Good customer'"
SQLExec(QueryText, "QRY1")
```

### Managing binary memos
<a name="managing_binary_memos_ELTPARAGRAPHE000217"></a>

To write a binary memo in a table (using an SQL UPDATE or INSERT command), the following syntax must be used in the text of the query:

- 
	```txt
	{WDBinaryMemo('<FileName>' [, 'File'])}
	```

	where: 

	- File (default value) indicates that the memo is a binary memo (coming from a file). 

	- WDBinaryMemo is a reserved word. 

	- &lt;FileName&gt; is the physical name of a file. 
			![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![Android Widget ](https://doc.pcsoft.fr/ext/images/us/ANDROIDWIDGET.png)![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png)![IOS Widget](https://doc.pcsoft.fr/ext/images/us/WIDGETIOS.png)![Mac Catalyst](https://doc.pcsoft.fr/ext/images/us/CATALYST.png) **Access to third-party databases via a web service** The file path corresponds to a path local to the application running the web service (i.e. a path on the mobile device). 




- 
	```txt
	{WDBinaryMemo('<FileName>' [, 'TextFile'])}
	```
 where: 

	- TextFile indicates that the memo is a text memo (coming from a file).

	- WDBinaryMemo is a reserved word.

	- &lt;FileName&gt; is the physical name of a file. 
			![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![Android Widget ](https://doc.pcsoft.fr/ext/images/us/ANDROIDWIDGET.png)![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png)![IOS Widget](https://doc.pcsoft.fr/ext/images/us/WIDGETIOS.png)![Mac Catalyst](https://doc.pcsoft.fr/ext/images/us/CATALYST.png) **Access to third-party databases via a web service** The file path corresponds to a path local to the application running the web service (i.e. a path on the mobile device). 







For example:


```wl
// Insert the C:\PHOTO\SMITH.BMP file into a binary memo
QueryText = "INSERT INTO CUSTOMER VALUES ('SMITH', 'John'," + ... 
	"{WDBinaryMemo('C:\PHOTO\SMITH.BMP')})"
SQLExec(QueryText, "QRY1")
// Insert the C:\DOC\LETTER.TXT file into a text memo
QueryText = "INSERT INTO CUSTOMER VALUES ('THOMPSON', 'Christopher'," + ... 
	"{WDBinaryMemo('C:\DOC\LETTER.TXT', 'TextFile')})"
SQLExec(QueryText, "QRY1")
```

**Note** Inserting binary memos into an HFSQL data file using SQL functions is not possible and will result in an error. The error message is as follows: "Query cannot be initialized. Character {WDMemBinary( unexpected".

### SQL query (SQLExec or queries created in the query editor)
<a name="sql_query_docparampagetitleshort_queries_created_the_query_editor_ELTPARAGRAPHE000258"></a>

When using the SQL DELETE, INSERT or UPDATE statements, no integrity check and no duplicate check are performed on an HFSQL database. This feature is not available in this version.

**Solution**: Use HFSQL functions ([HDelete](../WDLang4/3044018.md), [HAdd](../WDLang4/3044147.md) or [HModify](../WDLang4/3044042.md)) on your data files. The integrity check and the duplicate check will be automatically performed.

**Remarque**: The [HExecuteQuery](../WDLang4/3044080.md) and [HExecuteSQLQuery](../WDLang4/3044084.md) functions are used to check the integrity and duplicates of an HFSQL database.

### Comparison with the syntax of HExecuteSQLQuery
<a name="comparison_with_the_syntax_hexecutesqlquery_ELTPARAGRAPHE000288"></a>

[HExecuteSQLQuery](../WDLang4/3044084.md) can also be used to run an SQL query. The parameters of these two functions are identical, but their order is Reverse: the [HExecuteSQLQuery](../WDLang4/3044084.md) function specifies the query name first, followed by the query text (using the same standard as all HFSQL functions).

The syntax of **SQLExec** is kept for backward compatibility.
<a name="NOTE0_71"></a>


### SQLExec and threads
<a name="docparampagetitleshort_and_threads_ELTPARAGRAPHE000304"></a>

When executing the **SQLExec FUNCTION** in a secondary thread, the connection used must be made in the same thread: the connection cannot be made in the main thread (project or window). The connection established by [SQLConnect](../WDLang4/3072005.md) is not shared in the other threads.

### Limitations in PHP
<a name="limitations_php_ELTPARAGRAPHE000319"></a>

- The binary memos cannot be handled in this version. The query is run on a MySQL database.

- The multiple queries are not supported. For example: 
	
	```txt
	DROP TABLE TEST ;
	CREATE TABLE TEST (`IDTEST` INTEGER  PRIMARY KEY ,
	`recipient` VARCHAR(50)  NOT NULL ,
	`testname` VARCHAR(50)  NOT NULL ,`PRODUCTNAME` VARCHAR(50)  NOT NULL );
	```
