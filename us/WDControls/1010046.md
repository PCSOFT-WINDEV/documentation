
## Autofill in Edit controls
			

<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000119"></a>
Autofill is a standard feature available in most mobile applications. With the user's consent, this feature can store information such as user names, passwords and addresses, and automatically use them when requested by an application. 

Now, you can configure Edit controls in applications developed WINDEV Mobile to support this feature. 

Remarks: 

- There are multiple autofill services, both on Android and iOS devices (Dashlane, LastPass, etc.). Users can select their preferred service in the device settings. 

- Depending on the service, more or less elements are managed. Some services only handle "username/password" pairs. Other services manage numerous types of information.

## How to?
<a name="how_ELTTEXTE000143"></a>


### Settings in the window editor
<a name="settings_the_window_editor_ELTPARAGRAPHE000023"></a>

The autofill options of an Edit control can be found in the "General" tab of the description window, in the "Autofill" field. 

By default, when an Edit control is created in a mobile window, the autofill option is set to "Automatic". You can: <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=3&name=Saisie_automatique%20-%20HC%20N%B0001.gif&type=thumb)


- use automatic mode. 

- not use autofill. 

- use specific information for the autofill feature. If the service supports this type of information, a suggestion will be automatically shown to the user. 





### Defining settings programmatically
<a name="defining_settings_programmatically_ELTPARAGRAPHE000035"></a>

The [Autofill](../Proprietes/1410090515.md) property is used to identify and configure the autofill mode of the Edit control. 


### Autofill mode characteristics
<a name="autofill_mode_characteristics_ELTPARAGRAPHE000043"></a>

This mode automatically fills: 

- password fields (if the Edit control is of type "Password"). 

- phone number fields (if the Edit control uses a "Phone number" input mask). 

- email address fields (if the Edit control uses an "Email" input mask). 

- postal code fields (if the Edit control uses a "Postal code" input mask). 

- credit card fields (if the Edit control uses an Amex or Visa "Credit card" input mask).


For all other cases, if the end user uses Google's autofill, this service applies a heuristic to determine the type of data to be filled in (based on text, type of control, etc.). 


### Special case: Reading SMSes
<a name="special_case_reading_smses_ELTPARAGRAPHE000056"></a>

Many applications use a one-time code sent by SMS to authenticate users. The code is sent to the phone and the application can read the SMS directly. 
The implementation of this feature is different in Android and iOS. For more details, see [Generating and receiving a one-time code](../WDLang3/1410090676.md). 




### Limitations
<a name="limitations_ELTPARAGRAPHE000067"></a>

- ![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png) Autofill is only available from Android 8 onwards. Autofill options are ignored in previous versions. 

- In a single window, any given type of data can be used in only one control.
