


## Project Management Hub settings
			



<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000287"></a>
The Project Management Hub allows you to configure:

- [The data used to display the schedule](../CCSuivi/3540706.md) (holidays, working days, ...). This information is specific to each contributor.

- The parameters specific to the configuration of the Project Management Hub. This information affects:

	- The location of data files.

	- The time management help.

	- The personal options.

	- The "Don't show again" dialog boxes.

	- The management of links.

	- The reproduction of incidents.

	- The messaging.

	- The settings reserved to administrators.







To configure the Project Management Hub, expand ![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=3&name=CC_Suivi_Configuration%20-%20HC%20N%B0001.gif) and select "Options".

## Location of data files
<a name="location_data_files_ELTTEXTE000311"></a>
This option allows you to specify the physical location of the data files used by the Project Management Hub and by the different Control Centers provided with WINDEV, WEBDEV and WINDEV Mobile. Indeed, the different Control Centers share the same database.

You have the ability to use one of the following databases:

- HFSQL Classic.

- HFSQL Client/Server.

- on a PCSCloud platform (paid solution). For more details on PCSCloud, see [Cloud for HFSQL databases](https://pcscloud.net/UK/cloud_applications.awp).

- an SCMDrive database (paid solution). For more details on PCSCloud, see [SCMDrive](https://pcscloud-drive.net/UK/SCMDrive/index.awp).




For more details on the use of an HFSQL Client/Server database, see [Using the Control Centers in HFSQL Client/Server mode](../CCSuivi/3540712.md).

## Time management help
<a name="time_management_help_ELTTEXTE000335"></a>
The Project Management Hub allows you to configure and enable time management help. For more details, see [Time management](../CCSuivi/3540711.md).

**To enable the time management help**, select "Enable time management help". All the options specific to time management become available:

- ***Task change***: Default action when changing from one task to another.. You can automatically lock the current task, or ask for confirmation.

- ***Ask to confirm current task***: These options define how often the task confirmation request is displayed.. The current task confirmation window is displayed: 

	- on a regular basis (default: 60 minutes)

	- after a period of inactivity, for example. no keyboard and mouse actions (default: 10 minutes)


 If there is no confirmation, the "task wheel" is displayed. This task wheel allows you to select the current task, indicate an interruption or select another task.
	"Ask for confirmation each time a project is opened" is also used to request a confirmation of the current task each time a project is opened in WINDEV, WEBDEV or WINDEV Mobile. This option is useful when several tasks are linked to projects, windows, ...

- ***Task wheel options***: List of the various interruption tasks available. These tasks are specified in the Project Management Hub. Only the first eight interruption tasks will be displayed in the task wheel.




**Note**: These settings are also available directly in WINDEV, WEBDEV and WINDEV Mobile. On the "Project" tab, click "Other actions", expand "Time management" and select "Time management options".

## Personal options
<a name="personal_options_ELTTEXTE000359"></a>
Personal options apply to the Project Management Hub configuration for the currently user.

The available options are as follows:

- ***Request password at startup***. If this option is checked, a window is displayed when starting the Project Management Hub in order to identify the user.

- ***Start at Windows startup***. If this option is checked, the Project Management Hub will be automatically started when the Windows session is opened. Then, the Project Management Hub is minimized in the taskbar of Windows. The identification window will be displayed if "Request the password at startup" is checked.

- ***Automatically import user feedback in the background*** . This option is used to automatically import the user feedback in the background. This option is set to "Never" by default. The user feedback can be imported every week for example when starting the Project Management Hub.

- ***Show task completion window when the task is completed***. If this option is checked, a window used to enter a comment is displayed when a task is completed.

- ***Ignore documentation tasks associated with requirements***. This option is used to display the schedules while ignoring the documentation tasks.

## Managing links
<a name="managing_links_ELTTEXTE000407"></a>
This parameter is used to manage the "Incident/Requirement" links and the "Incident/Task" links: 

- "Incident/Requirement" link: When creating an incident with a current task associated with a requirement, the Project Management Hub can do the following:

	- Ask whether the incident must be associated with the task.  

	- Associate the incident with the task automatically.

	- No action. 




- "Incident/Requirement" link: When fixing an incident linked to a non-completed task, the Project Management Hub can do one of the following:

	- Ask whether the current task must be ended. 

	- End the task automatically. 

	- No action.

## Incident reproduction
<a name="incident_reproduction_ELTTEXTE000431"></a>
This parameter is used to manage the installation directory of the elements for reproducing incidents. You can configure: 

- The path to the local directory where attachments are saved. 

- The maximum number of incident attachments in the directory. If this number is exceeded, the oldest attachments are automatically deleted. 

- Maximum size of the attachment installation directory. If this size is exceeded, the oldest attachments are automatically deleted. 

- The automatic deletion of the attachment when the incident is fixed or archived.

## Messaging
<a name="messaging_ELTTEXTE000455"></a>
By default, Project Management Hub messages are sent using WDBAL. 

Each user can select the type of automated messages they want to receive. For example, users can choose to receive an automated message when there is a new incident in a requirement they are associated with. 

If "Receive an email copy of messages sent by the Control Center, Source Code Manager (SCM) the Software Factory" is checked, messages will also be sent by email. The email address will be the one specified in Administrator options, in the accounts used for sending and receiving emails.

## Administrator options
<a name="administrator_options_ELTTEXTE000479"></a>
In the Project Management Hub, administrators have specific rights and can perform specific operations (ADMIN is both the default username and password). In this window, you can configure:

- [the trust coefficients assigned to each contributor](../CCSuivi/3540704.md).

- ***guest mode*** support. If the guest mode is allowed, the login window will propose the "Guest" mode. This option allows a contributor not listed in the Project Management Hub to view the schedule, task list, etc. This option is not available if an HFSQL Client/Server database is used.

- the ***email account used for user feedback***. This account is the global account used for all spools of user feedback. A specific account can also be defined to manage the feedback of each application. For the global account, you have the ability to specify:

	- the POP3 server used, its port, the user account and the associated password.

	- the SMTP server used, its port, the user account and the associated password.




- the process of ***incidents***. You can: 

	- Allow contributors to edit incidents. This means they will be able to add comments. 

	- Set the maximum size of attachments (per incident). 

	- Clear the incident attachments located in the Control Centers database. 




- the messaging options: 

	- You can define the recipients of automated messages sent by the Project Management Hub when:

		- Creating an incident. 

		- Fixing an incident. 

		- Archiving an incident. 

		- Flagging an incident as priority incident. 




- You also have the ability to define the suffix used in the emails sent. 

- You have the ability to define the accounts used to send and receive emails.
