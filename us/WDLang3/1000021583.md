
## geoTrackingEnable (Function)

***In french: géoSuiviActive***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Enables the management of location tracking in a WINDEV Mobile application.
<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
// Enable the push notifications
geoTrackingEnable(ValidateTrackingActivation)
```

```wl
// Manage location tracking
PROCEDURE ValidateTrackingActivation(bTrackingEnabled is boolean, cError is string)
IF NOT bTrackingEnabled THEN
	Error(cError)
	RETURN
END

STC_Loc = "Location enabled"
```

## Syntax
<a name="SYNTAXE1"></a>

`geoTrackingEnable(<WLanguage procedure>)`
---

**`<WLanguage procedure>: (Procedure name)`**

Name of WLanguage procedure called: 

- when the deactivation was performed, 

- if an error occurs: 

	- ![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png)![IOS Widget](https://doc.pcsoft.fr/ext/images/us/WIDGETIOS.png)![Mac Catalyst](https://doc.pcsoft.fr/ext/images/us/CATALYST.png) activation request refused by the user.

	- ![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png) erreur while accessing the Google Play Services.





This procedure has the following format: 

```txt
PROCEDURE <Procedure name>(<Tracking enabled> is boolean, <Error> is string)
```


- &lt;Tracking enabled&gt; is a boolean indicating whether tracking is enabled (<u><u><u><u>True</u></u></u></u>) or not (<u><u><u><u>False</u></u></u></u>). 

- &lt;Error&gt; is a character string corresponding to the text of the activation error. This parameter is initialized only if &lt;Tracking enabled&gt; is set to <u><u><u><u>False</u></u></u></u>.

## Remarks


### Remarks
<a name="remarks_ELTPARAGRAPHE000061"></a>

- This function is asynchronous. 

- ![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png)![IOS Widget](https://doc.pcsoft.fr/ext/images/us/WIDGETIOS.png)![Mac Catalyst](https://doc.pcsoft.fr/ext/images/us/CATALYST.png) This function can be used only if the location rights have been granted to the application. These rights are enabled during the generation.

- ![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png) Starting with Android 8, to reduce the applications' battery usage, the system drastically limits the frequency for receiving device locations when the application is running in the background. For more details, see [https://developer.android.com/about/versions/oreo/background-location-limits](https://developer.android.com/about/versions/oreo/background-location-limits). 





![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![Android Widget ](https://doc.pcsoft.fr/ext/images/us/ANDROIDWIDGET.png) 

### Required permissions
<a name="required_permissions_ELTPARAGRAPHE000078"></a>

**Android 11 specific case**: 
This function requires the ACCESS_BACKGROUND_LOCATION permission to access the device's location. 
This permission allows using the function when the application is in the background.

If the application needs to use background location:

- Manually add the "ACCESS_BACKGROUND_LOCATION" permission in the Android application generation wizard. 

- Explicitly request background location permission with [PermissionRequest](../WDLang3/1410087423.md). For example: 
	
	```wl
	PermissionRequest(permBackgroundLocation, Callback)
	INTERNAL PROCEDURE Callback(p is Permission)
		IF p.Granted THEN
			// Functions that require background location access can be used
		END
	END
	```



A window allows users to: 

- allow access to the device location while the application is in the background,

- allow access to the location only while the application is in use,

- deny access to the location. The user can also change these permissions at any time in the Android settings.  



Remarks: 

- Follow Google's guidelines for applications that require background location access. For more details, see [https://support.google.com/googleplay/android-developer/answer/9799150](https://support.google.com/googleplay/android-developer/answer/9799150). If these conditions are not met (especially user information requirements), applications may not be accepted for publication on Google Play. 

- The background location permission should only be requested if the location permission has been granted. Otherwise, [PermissionRequest](../WDLang3/1410087423.md) will fail.

- If the option chosen by the user for the background location access request is more restrictive than the option chosen for the location access request, the application will be automatically restarted. 

- On devices running Android 10 or earlier, if location permission has been granted to the application, the background location permission will be granted without displaying a window.
