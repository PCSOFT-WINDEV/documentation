
## NearbyShareWaitForConnection (Function)

***In french: PartageProximitéAttendConnexion***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Makes the device visible to nearby devices in discovery mode (via [NearbyShareDiscoverDevice](../WDLang3/1410090648.md)) and waits for their connection request.
<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
// Each time the connection wait check box is changed
CBOX_Wait_connection.State = Grayed
IF CBOX_Wait_connection THEN
	NearbyShareWaitForConnection(gsDeviceName, CallbackResult, CallbackRequestConnection, 
		CallbackConnection, gnTopology)
ELSE
	NearbyShareStopWaiting()
	CBOX_Wait_connection.State = Active
END
	INTERNAL PROCEDURE CallbackResult(bResult is boolean)
		IF bResult THEN
			CBOX_Wait_connection.State = Active
		ELSE
			Info("Search or connection request failed: " + CR + ErrorInfo())
		END
	END
```

<a name="XSYNTAXE"></a>

## Syntax
<a name="SYNTAXE1"></a>

`NearbyShareWaitForConnection(<Device name> , <Result procedure> , <Connection request procedure> , <Notification procedure> [, <Topology>])`
---

**`<Device name>: (Character string)`**

Advertising device name. This name will be received by the nearby device as a parameter of the procedure passed to [NearbyShareWaitForConnection](../WDLang3/1410090655.md). This procedure is executed when the advertiser is discovered by the nearby device.

**`<Result procedure>: (Procedure name)`**

Name of the WLanguage procedure ("callback") called when the device starts advertising. For more details on this procedure, see [Parameters of the procedure used by NearbyShareWaitForConnection (Result)](../WDLang3/1410090662.md).

**`<Connection request procedure>: (Procedure name)`**

Name of the WLanguage procedure ("callback") executed when a nearby device requests a connection.
In the code of this procedure, the request can be accepted ([NearbyShareAcceptConnection](../WDLang3/1410090646.md)) or rejected ([NearbyShareRejectConnection](../WDLang3/1410090651.md)). For more details on this procedure, see [Parameters of the procedure used by NearbyShareWaitForConnection (Request)](../WDLang3/1410090658.md).

**`<Notification procedure>: (Procedure name)`**

Name of the WLanguage procedure ("callback") called to notify the nearby device connection status.

For more details on this procedure, see [Parameters of the procedure used by NearbyShareWaitForConnection (Notification)](../WDLang3/1410090665.md).

**`<Topology>: (Optional Integer constant)`**

Connection topology. 
The topology defines the connection constraints between devices and the data sharing technology implemented (Wi-Fi Direct, Bluetooth, BTLE).
This parameter can correspond to one of the following constants: 



|   |   |
| --- | --- |
| *nsCluster* | Cluster topology between nearby devices. <br><br>In this topology, each device can connect to several devices and/or accept connections from several devices. Each device can act either as an "advertiser", which can accept incoming connections from N other devices, or as a "discoverer", which can initiate an outgoing connection to a single device. <br><br><br><br>This topology is suitable for multidirectional data exchanges that do not involve large volumes of data. <br><br><br><br>This topology uses Bluetooth 5.0. |
|  *nsPointToPoint*<br>(Default value) | Topology for "one-to-one" connections where each device can only connect to one other device at a time.  This allows for the highest bandwidth possible.<br><br>This topology is ideal for applications that need to exchange large amounts of data, such as file transfers.<br><br><br><br>This topology uses Bluetooth 5.0 and Wi-Fi Direct. |
| *nsStar* | Topology intended for applications that distribute information from a centralized point.<br><br>At any time, each device can act either as an "advertiser", which can accept incoming connections from N other devices, or as a "discoverer", which can initiate an outgoing connection to a single device. Once the connection has been established, the devices retain their role until the connection is terminated. <br><br><br><br>This topology is ideal for situations where a single device is streaming bandwidth-intensive content to multiple devices (e.g. video streaming). <br><br><br><br>This topology uses Bluetooth 5.0 and Wi-Fi Direct. |

<a name="NOTE0_1"></a>

## Remarks


- Advertising (waiting for a connection) can consume significant network resources. Therefore, it is recommended to stop advertising as soon as the connection between devices is established. 

- Once the device stops advertising, it is still possible to send data to connected devices. 

- To stop advertising, use [NearbyShareStopWaiting](../WDLang3/1410090647.md).
