
## Nearby sharing (Android)
			

<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000159"></a>
This feature, available on Android, lets you exchange data between two or more nearby devices. This exchange takes place in real time, even in airplane mode, without a network connection.

Nearby devices are detected using Bluetooth (therefore, within Bluetooth range). The connection is then made via Bluetooth, Bluetooth Low Energy or Wi-Fi Direct.

On Android, there are 3 sharing modes:

- point-to-point.

- star (1 to N).

- cluster (each device can both send and receive data). 




Here are a few use cases:

- photo or video exchange.

- customer information sharing.

- quiz during a business meeting.

- coach-to-student program sharing at a training session.

- collaborative whiteboard.

## Implementing nearby sharing
<a name="implementing_nearby_sharing_ELTTEXTE000183"></a>


### How it works
<a name="how_works_ELTPARAGRAPHE000032"></a>

In nearby sharing, devices are considered as advertisers and discoverers. 

- The advertiser is the device that announces it is ready to receive a connection. 

- The discoverer is the device that searches for nearby devices ready to exchange data. 



<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=3&name=Partage%20proximit%E9.gif)


Here is how it works: 

1. The advertiser announces itself and waits for a connection request ([NearbyShareWaitForConnection](../WDLang3/1410090655.md)). 

2. The discoverer starts searching for nearby devices ([NearbyShareDiscoverDevice](../WDLang3/1410090648.md)). 

3. When the discoverer finds the desired advertiser, it requests a connection ([NearbyShareRequestConnection](../WDLang3/1410090650.md)). 

4. The advertiser can: 

	- Accept the connection request ([NearbyShareAcceptConnection](../WDLang3/1410090646.md)). 

	- Reject the connection request ([NearbyShareRejectConnection](../WDLang3/1410090651.md)). 




5. The connection request must be accepted by both the advertiser and the discoverer. Once accepted, the connection is authenticated using a token. 

6. The connection is established. You can: 

	- exchange data ([NearbyShareSend](../WDLang3/1410090653.md)).

	- exchange files ([NearbyShareSendFile](../WDLang3/1410090654.md)).
			Recipients are informed of incoming data, modifications, cancellations and transfer failures. 
			Both devices can simultaneously send and receive data. 




7. Once the transfer is completed, the connection is closed. 




Several WLanguage functions are available for this purpose. For more details, see [Nearby sharing functions](../WDLang3/1410090833.md). 


### Strategies
<a name="strategies_ELTPARAGRAPHE000088"></a>

Strategies define the network topology. There are several strategies. You can choose the best one depending on the intended use case: 

- **"Cluster"**: 
	In this topology, each device can connect to several devices and/or accept connections from several devices. Each device can be both a discoverer and an advertiser. 
	This topology is suitable for multidirectional data exchanges that do not involve large volumes of data. 
	This topology uses Bluetooth 5.0. 

- **"Star"**: 
	This strategy is intended for applications that distribute information from a centralized point, or "hub". At any time, each device can act either as a "hub" (advertiser that can accept incoming connections from N other devices), or as a "spoke" (discoverer that can initiate an outgoing connection to a single device). Once the connection has been established, the devices retain their role until the connection is terminated. 
	This topology is ideal for situations where a single device is streaming bandwidth-intensive content to multiple devices (e.g. video streaming). 
	This topology uses Bluetooth 5.0 and Wi-Fi Direct.

- **"Point-to-point"**: 
	This strategy enables "one-to-one" connections, where each device can only connect to one other device at a time. This allows for the highest bandwidth possible. 
	This topology is ideal for applications that need to exchange large amounts of data, such as file transfers. 
	This topology uses Bluetooth 5.0 and Wi-Fi Direct.
