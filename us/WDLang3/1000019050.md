


## &lt;zipArchive variable&gt;.AddFile (Function)

***In french: &lt;Variable zipArchive&gt;.AjouteFichier***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Automatically adds and compresses any type of file into a CAB, ZIP, WDZ, 7z, TAR, gzip or TGZ (TAR.GZ) archive. 
This function cannot be used with RAR archives.

Remarks: 

- To add files located in a directory, use [&lt;zipArchive variable&gt;.AddDirectory](../WDLang3/1000019078.md).

- To optimize the addition of files into ZIP, WDZ and 7Z archives, add the files between the [&lt;zipArchive variable&gt;.StartAddingFile](../WDLang3/1410091280.md) and [&lt;zipArchive variable&gt;.EndAddingFile](../WDLang3/1410091281.md) functions. 
	









<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
MyArchive is zipArchive
ResCreate is int
ResAddFile is int
// Create the archive 
ResCreate = MyArchive.Create("C:\Temp\Archive.zip")
IF ResCreate = 0 THEN
	// Add a file into an archive
	ResAddFile = MyArchive.AddFile(...
			"C:\MyDirectory\MyFiles\File.pdf", zipDrive)
END
// Display an error message if the file was not added
IF ResAddFile <> 0 THEN 
	Error(zipMsgError(ResAddFile))
END
```

## Syntax

### Adding a file and preserving parts of the file path

`<Result> = <Archive>.AddFile(<File path> [, <Path section to keep> [, <Progress>]])`
---

**`<Result>: (Integer)`**



- 0 if the file has been added, 

- an error code (value greater than 0) otherwise. For more details on these error codes, see the remarks.




**`<Archive>: (zipArchive variable)`**

Name of a variable of type [zipArchive](../WDLang3/1000018679.md) corresponding to the archive in which the file must be added.

**`<File path>: (Character string)`**

Path of the file to be added to the archive (260 characters maximum, 90 maximum for TAR, gzip or TGZ (TAR.GZ) archives). This path can be a full path or a path relative to the current directory. Wildcard characters (\*,?) are not allowed in the file name.
This file must not exceed 4 GB. Otherwise, an error occurs.

**`<Path section to keep>: (Optional constant)`**

Indicates the section of the file path that will be kept in the archive:


|   |   |
| --- | --- |
| *zipDirectory*<br>(Default value) | Keeps the different directories of the file path as well as the file name and extension. For example: \\Directory\\Files\\FileName.pdf |
| *zipDrive* | Keeps the full and absolute file path (name of disk, name of directories, file name and file extension). For example: C:\\Directory\\Files\\FileName.pdf<br>**ZIP format**: This constant has no effect.<br>**7z format**: This constant and *zipDirectory* will have the same effect.<br><br>![Linux](https://doc.pcsoft.fr/ext/images/us/LX.png)![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png)![IOS Widget](https://doc.pcsoft.fr/ext/images/us/WIDGETIOS.png)![Mac Catalyst](https://doc.pcsoft.fr/ext/images/us/CATALYST.png) This constant is not available as there is no drive root.![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![Android Widget ](https://doc.pcsoft.fr/ext/images/us/ANDROIDWIDGET.png)![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) This constant will have the same effect as *zipDirectory*. |
| *zipNone* | Keeps the file name and extension. For example: FileName.pdf |


**If you are using an archive in .CAB format**, only the *zipNone* constant is taken into account. Indeed, the .CAB format cannot be used to save the paths inside the archive.

**`<Progress>: (Control name or procedure name)`**

Progress bar management mode. This parameter can correspond to: 

- ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png)![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png)![Mac Catalyst](https://doc.pcsoft.fr/ext/images/us/CATALYST.png) the name of a Progress Bar control in a window. The progress bar will display the addition and compression progress of the file being managed.  

- the name of a WLanguage procedure. For more details on this procedure, see [Parameters of the procedure used by &lt;zipArchive variable&gt;.AddFile](../WDLang3/1000025730.md). 




**If you use a TAR, gzip or TGZ (TAR.GZ) archive**, the progress bar is refreshed only after the file is added. 

![WEBDEV - Server code](https://doc.pcsoft.fr/ext/images/us/WBS.png) This procedure must be executed on the server side.

![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) This parameter is not available.

## Remarks


### Use condition
<a name="use_condition_ELTPARAGRAPHE000629"></a>

You can add files to an archive if:

- The archive exists (archives are created using [&lt;zipArchive variable&gt;.Create](../WDLang3/1000019160.md)).

- The archive is accessible in read/write mode.

- The archive is a single-part archive.

- The size of the file is less than 4 GB.




**Caution**: 

- **CAB archives**: Files must be added immediately after the archive is created. This format cannot be used to add files to an existing archive.  

- **7z archives**: The archive is fully compressed each time **&lt;zipArchive variable&gt;.AddFile** is called. This function is recommended when adding a single file. If several files must be added into the archive, use [&lt;zipArchive variable&gt;.AddFileList](../WDLang3/1000019159.md) or [&lt;zipArchive variable&gt;.AddDirectory](../WDLang3/1000019078.md). 




Maximum number of files allowed:

- in a WDZ file: 232-1.

- in a ZIP file: 65535. 

- in a CAB file: 65535. 


Reminder: 

- ![Linux](https://doc.pcsoft.fr/ext/images/us/LX.png)![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png)![IOS Widget](https://doc.pcsoft.fr/ext/images/us/WIDGETIOS.png)![Mac Catalyst](https://doc.pcsoft.fr/ext/images/us/CATALYST.png) Only ZIP, TAR, gzip and TGZ (TAR.GZ) archives are available.

- ![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![Android Widget ](https://doc.pcsoft.fr/ext/images/us/ANDROIDWIDGET.png) The CAB format is not available.



<a name="NOTE0_2"></a>


### Compression level of ZIP or 7z archives
<a name="compression_level_zip_7z_archives_ELTPARAGRAPHE000714"></a>

The files added into an archive in ZIP or 7z format are compressed by default. You can change the compression level of files added to an archive using function [zipCompressionLevel](../WDLang3/3082054.md).
<a name="NOTE0_3"></a>


### Error codes
<a name="error_codes_ELTPARAGRAPHE000727"></a>

The following error codes are returned:

- 1: The path passed as parameter does not exist.

- 2: Access denied: The user does not have sufficient rights or the file is in use.. If the file to insert is an HFSQL data file, it must be closed by the following code:
	
	```wl
	HClose(FileName)
	Multitask() // Waits for the effective file closing
	```


- 3: The archive is corrupted.

- 4: The path does not exist in the archive.

- 5: Unable to write to the archive.

- 7: The file already exists in the archive.

- 8: An archive cannot be added to itself. For example, "MyArchive" cannot be added to "MyArchive".




The message corresponding to the error code is returned by [zipMsgError](../WDLang3/3082034.md).
<a name="NOTE0_4"></a>


### Adding a file that already exists in the archive
<a name="adding_file_that_already_exists_the_archive_ELTPARAGRAPHE000752"></a>

Adding a file already present in an archive causes an error. A file is identified according to the path saved in the archive. Therefore, you cannot add two files with the same name and the same relative path to an archive.

For example, the *zipNone* constant cannot be used to add two files with the same but coming from different directories.
<a name="NOTE0_5"></a>


### Index of files in the archive
<a name="index_files_the_archive_ELTPARAGRAPHE000764"></a>

When a file is added to an archive, an index is automatically assigned to that file. This index corresponds to the order in which the files are added to the archive. To select a file in the archive, you can use:

- the index of the element (this index is returned by [&lt;zipArchive variable&gt;.FindFile](../WDLang3/1000026330.md)).

- or the path of the element saved in the archive.
