


## zipDeleteFileList (Function)

***In french: zipSupprimeListeFichier***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Deletes a list of files from an archive. This function is faster than [zipDeleteFile](../WDLang3/3082041.md) run for each file.

<a name="sample_code"></a>

## Example

![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png)![WEBDEV - Server code](https://doc.pcsoft.fr/ext/images/us/WBS.png)![Reports and Queries](https://doc.pcsoft.fr/ext/images/us/ER.png)![User code (UMC)](https://doc.pcsoft.fr/ext/images/us/MCU.png)![Ajax](https://doc.pcsoft.fr/ext/images/us/AJAX.png) 
```wl
MyArchive is zipArchive
// Create the archive
ResOpen = zipOpen(MyArchive, "C:\Temp\Archive.zip")

IF ResOpen = 0 THEN
	...
	// Delete "File.doc" and "MyDoc.pdf"
	ResDelete = zipDeleteFileList(MyArchive, "File.doc" + CR + "MyDoc.PDF")
	...
END
```

## Syntax

`<Result> = zipDeleteFileList(<Archive> , <Path of the files to delete> [, <Progress bar management>])`
---

**`<Result>: (Integer)`**



- 0 if the files have been deleted,

- An error code (value greater than 0) otherwise. The message corresponding to the error code is returned by [zipMsgError](../WDLang3/3082034.md).




**`<Archive>: (Character string or zipArchive variable)`**

Name of the archive to be used.
This name can correspond to:

- an archive name defined with [zipOpen](../WDLang3/3082044.md) or [zipCreate](../WDLang3/3082003.md).

- the name of a variable of type [zipArchive](../WDLang3/1000018679.md). 
	![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) [zipArchive](../WDLang3/1000018679.md) variables are not available in Java.




**`<Path of the files to delete>: (Character string)`**

Stored path of the file that must be deleted from the archive. The paths are separated by CR characters (Carriage Return).  

**`<Progress bar management>: (Optional character string)`**

Progress bar management mode. This parameter can correspond to: 

- ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png)![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png)![Mac Catalyst](https://doc.pcsoft.fr/ext/images/us/CATALYST.png) the name of a Progress Bar control found in a window. The progress bar will display the progress of file deletion.  

- the name of a WLanguage procedure. This procedure has the following format: 
	
	```txt
	<Procedure name> (<Current file>, <Progress percentage>)
	```

	where: 

	- &lt;Current file&gt; corresponds to the name of the file currently processed. 

	- &lt;Progress percentage&gt; corresponds to the progress percentage of the file list being deleted from the archive. 







**If you're working with an archive in gzip, TAR or TGZ (TAR.GZ)**format, the ProgressBar is updated only when the file has been added.

![WEBDEV - Server code](https://doc.pcsoft.fr/ext/images/us/WBS.png) The procedure must be a server procedure.

## Remarks


### Use conditions
<a name="use_conditions_ELTPARAGRAPHE000143"></a>

The files can be deleted from an archive if:

- The archive exists (archives are created using [zipCreate](../WDLang3/3082003.md)).

- The archive is accessible in read/write.

- The archive is a single-part archive.




**Caution**: 

- **Archives in RAR** format: This function is not available. 

- **Archives in CAB** format: This function is not available.  

- **Archives in gzip, TAR and TGZ format (TAR.GZ)**: This function is not available.  

- **Archives in 7z** format: The archive is fully compressed each time the **function is called zipDeleteFileList**.

### Error codes
<a name="error_codes_ELTPARAGRAPHE000172"></a>

The following error codes are returned:

- 2: Access denied: user does not have sufficient rights.

- 3: The archive is corrupt.

- 4: The path does not exist in the archive.

- 5: Unable to write to archive.



<a name="NOTE0_3"></a>


### Index of files in the archive
<a name="index_files_the_archive_ELTPARAGRAPHE000186"></a>

Once the files have been deleted, the indexes of the remaining files are modified. The indexes of the files after the deleted file are automatically decremented by 1.
<a name="NOTE0_4"></a>


### Stored path
<a name="stored_path_ELTPARAGRAPHE000195"></a>

The table below presents the paths stored in the archive according to:

- the access path to the file,

- the path section to store.




The current directory is: "C:\\Temp".


|   |   |   |   |   |
| --- | --- | --- | --- | --- |
| **zipAddFile** | **File location** | *zipNone* | *zipDirectory* | *zipDrive* |
| zipAddFile("Archi",<br>"File.txt") | C:\\Temp\\File.txt | File.txt | File.txt | File.txt |
| zipAddFile("Archi",<br>"Data\\File.txt") | C:\\Temp\\Data\\File.txt | File.txt | Data\\File.txt | Data\\File.txt |
| zipAddFile("Archi",<br>"D:\\Data\\File.txt") | D:\\Data\\File.txt | File.txt | Data\\File.txt | D:\\Data\\File.txt |


**Remark**: If the constant *zipDisk* is used, WDZ format memorizes the full path of the file (including drive letter), whereas ZIP format does not memorize the drive letter.
