## Overview
<a name="overview_ELTTEXTE000156"></a>
The Microsoft Graph API enables you to interact programmatically with Microsoft 365 services (Outlook, OneDrive, Teams etc.).

Below are the Microsoft prerequisites and settings for calling this API in WLanguage.

<a name="NOTE2_1"></a>


## Creating an Azure account
<a name="creating_azure_account_ELTTEXTE000180"></a>
To use Microsoft Graph APIs, you need a Microsoft developer account.

If necessary, visit [https://portal.azure.com/](https://portal.azure.com/) to create an account.

## Declaring an application
<a name="declaring_application_ELTTEXTE000204"></a>
To register an application in Azure:

1. Open the Azure portal. 

2. Go to "Microsoft Entra ID".
	Tip: To quickly find a section in the Azure, use the search box at the top of the web page.

3. In the left-hand menu, expand "Manage", then select "App registrations".

4. Click "New registration".

5. On the registration page:

	- Enter the application name.

	- Select the supported account types.
			For example, to access accounts only in a given organizational directory, select "Accounts in this organizational directory only".




6. To implement OAuth authentication, you need to provide a redirect URL:

	- in platform, always select "Web",

	- in the URL field, in the case of a WINDEV or WINDEV Mobile application, choose a URL with a format such as "http://localhost:9874". You can use any port number. Simply specify this number in the code of the application.
			**Important**: For a WEBDEV site, the URL should have the following format:
			"http(s)://localhost/WD310AWP/WD310Awp.exe/OAUTH2_RETURN".




7. Confirm by clicking "Register" at the bottom of the page.

## Getting the ClientID and ClientSecret
<a name="getting_the_clientid_and_clientsecret_ELTTEXTE000228"></a>
To implement OAuth authentication in WLanguage, you need the **ClientID** and the **ClientSecret** of the application. This information can be found in the Azure portal.

**Getting the ClientID**:

- Once the application has been registered, an overview page is displayed.

- Copy the value from "Application (client) ID". This is the ClientID required by WLanguage.


Note: To find this information for an existing application, enter the application name in the search box. In the results that appear, under "Microsoft Entra ID", select the result identified as "Application"

**Creating the ClientSecret**:

- In the left-hand menu, expand "Manage" and select "Certificates & secrets". 

- Click "New client secret". An "Add a client secret" section appears.

- Enter a name for the secret and choose a validity period. The recommended value is 180 days (6 months). This means the client secret must be renewed every 6 months. 
	You can also choose a validity period longer than the average frequency of your application updates. This means your users will always be up to date with a valid secret.

- Click "Add" to create the client secret

- Copy the secret immediately. It is displayed only once. This value is required by WLanguage.

## Getting the Tenant ID
<a name="getting_the_tenant_ELTTEXTE000252"></a>
You also need to get the "Tenant ID". This is the identifier that represents the organization.
This identifier can also be found in the Azure portal. Simply search for "Tenant ID" and select "Microsoft Entra ID".

## Consent screen
<a name="consent_screen_ELTTEXTE000276"></a>
A Microsoft consent request is shown to users during the authentication process.

By default, this request is shown to each user when they log in for the first time.

To avoid this, you can grant permissions for your entire "Entra ID". This translates into a streamlined authentication process, without consent requests and without the need for error handling processes. These settings must be defined on the Azure portal.

In the left-hand menu of the registered application, click "API permissions" then "Add a permission".
A wizard starts:

- Select "Microsoft Graph", then "Delegated permissions".

- Find and select the permission you want to add (e.g., "Mail.ReadBasic" to read emails).

- Click "Add permissions" to confirm.

- Then, click "Grant admin consent". All the permissions for all members of your EntraID directory will then be automatically granted.
