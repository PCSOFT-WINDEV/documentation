


## &lt;sshSession variable&gt;.Command (Function)

***In french: &lt;Variable sshSession&gt;.Commande***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Sends a command to an SSH server. The session is automatically started and closed as soon as the command is sent.


<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
cMySession is sshSession
cMySession.Address = "127.0.0.1"
cMySession.Port = 22
cMySession.User = "login"
cMySession.UserPassword = "pass"
nExitCode is int
sOutput is ANSI string
sOutputErr is ANSI string
(nExitCode, sOutput, sOutputErr) = cMySession.Command(EDT_Command)
IF ErrorOccurred THEN
	Error(ErrorInfo(errFullDetails))
	RETURN
END
EDT_ExitCode = nExitCode
EDT_StdOut = UTF8ToString(sOutput)
EDT_StdErr = UTF8ToString(sOutputErr)
```

```wl
cMySession1 is sshSession
cMySession1.Address = "127.0.0.1"
cMySession1.User = "login"
cMySession1.UserPassword = "pass"

bufDataSent is Buffer = 'It's [%TimeToString(TimeSys, "HH:mm:SS")%]'
nExitCode is int
sOutput is ANSI string
sOutputErr is ANSI string
	
// Execute a Linux script that stores sent data in a file 
// then displays the file contents on standard output
(nExitCode, sOutput, sOutputErr) = cMySession1.Command(...
	"echo $(</dev/stdin) > data_sent.txt; cat data_sent.txt", bufDataSent)
Trace(sOutput) //Displays the content of bufStandardInput
```

<a name="XSYNTAXE"></a>

## Syntax
<a name="SYNTAXE1"></a>

`(<Result>, <Data received>, <Data if error>) = <SSH session>.Command(<Command> [, <Data to send>])`
---

**`<Result>: (Integer)`**

Exit code of the command.

**`<Data received>: (Buffer)`**

Data received from the server.

**`<Data if error>: (Buffer)`**

Data received from the server if an error occurs.

**`<SSH session>: (sshSession variable)`**

Name of the [sshSession](../WDLang3/1000021157.md) variable corresponding to the SSH session on which the command must be run.

**`<Command>: (Character string)`**

Command that must be sent to the SSH server.

**`<Data to send>: (Optional buffer)`**

Data that must be sent to the server. This data can be read in the standard input (stdin).

## Remarks


### Keeping SSH sessions alive
<a name="keeping_ssh_sessions_alive_ELTPARAGRAPHE000214"></a>

You can keep SSH sessions alive (**KeepAliveInterval** property of the [sshSession](../WDLang3/1000021157.md) variable). This method consists in sending two requests to the server at given intervals, in order to keep the connection alive and to check that the server is still responding. The **KeepAliveInterval** property sets the duration between these two requests.  

If the SSH server shuts down unexpectedly while a long command initiated by **&lt;sshSession variable&gt;.Command** is being executed, the keep alive functionality can detect the loss of connection between the application and the server.
