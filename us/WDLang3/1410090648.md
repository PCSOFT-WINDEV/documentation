
## NearbyShareDiscoverDevice (Function)

***In french: PartageProximitéRechercheAppareil***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Discovers nearby devices that have advertised themselves and are waiting to connect ("advertisers").
<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
// Code of the check box used to start discovering nearby devices
CBOX_Discover.State = Grayed
IF CBOX_Discover THEN
	NearbyShareDiscoverDevice(CallbackResult, CallbackDiscover, gnTopology)
ELSE
	NearbyShareStopDiscovery()
	CBOX_Discover.State = Active
END
		INTERNAL PROCEDURE CallbackResult(bResult is boolean)
			IF bResult THEN
				CBOX_Discover.State = Active
			ELSE
				Info("Search or connection request failed: " + CR + ErrorInfo())
			END
		END
```

```wl
PROCEDURE CallbackDiscover(bDiscover is boolean, sDeviceID is string, sDeviceName is string)
IF bDiscover THEN
	ToastDisplay("Device discovered: " + sDeviceName)
ELSE
	ToastDisplay("Device unavailable: " + sDeviceName)
END
```

<a name="XSYNTAXE"></a>

## Syntax
<a name="SYNTAXE1"></a>

`NearbyShareDiscoverDevice(<Result procedure> , <Discovery procedure> [, <Topology>])`
---

**`<Result procedure>: (Procedure name)`**

Name of the WLanguage procedure ("callback") executed to notify if the device started the discovery of nearby advertisers. 
For more details on this procedure, see [Parameters of the procedure used by NearbyShareDiscoverDevice (Result)](../WDLang3/1410090663.md). 

**`<Discovery procedure>: (Procedure name)`**

Name of the WLanguage procedure ("callback") called when a new nearby device is discovered, or when a previously discovered device is no longer available.
The connection request should be written in the code of this procedure ([NearbyShareRequestConnection](../WDLang3/1410090650.md)).
For more details on this procedure, see [Parameters of the procedure used by NearbyShareDiscoverDevice (Discovery)](../WDLang3/1410090664.md). 

**`<Topology>: (Optional Integer constant)`**

Connection topology. 
The topology defines the connection constraints between devices and the data sharing technology implemented (Wi-Fi Direct, Bluetooth, BTLE).
This parameter can correspond to one of the following constants: 



|   |   |
| --- | --- |
| *nsCluster* | Cluster topology between nearby devices. <br><br>In this topology, each device can connect to several devices and/or accept connections from several devices. Each device can act either as an "advertiser", which can accept incoming connections from N other devices, or as a "discoverer", which can initiate an outgoing connection to a single device. <br><br><br><br>This topology is suitable for multidirectional data exchanges that do not involve large volumes of data. <br><br><br><br>This topology uses Bluetooth 5.0. |
|  *nsPointToPoint*<br>(Default value) | Topology for "one-to-one" connections where each device can only connect to one other device at a time.  This allows for the highest bandwidth possible.<br><br>This topology is ideal for applications that need to exchange large amounts of data, such as file transfers.<br><br><br><br>This topology uses Bluetooth 5.0 and Wi-Fi Direct. |
| *nsStar* | Topology intended for applications that distribute information from a centralized point.<br><br>At any time, each device can act either as an "advertiser", which can accept incoming connections from N other devices, or as a "discoverer", which can initiate an outgoing connection to a single device. Once the connection has been established, the devices retain their role until the connection is terminated. <br><br><br><br>This topology is ideal for situations where a single device is streaming bandwidth-intensive content to multiple devices (e.g. video streaming). <br><br><br><br>This topology uses Bluetooth 5.0 and Wi-Fi Direct. |

## Remarks


- To send a connection request to the discovered device, use [NearbyShareRequestConnection](../WDLang3/1410090650.md). 

- Discovering nearby devices can consume significant network resources. Therefore, it is recommended to stop discovery as soon as the connection between devices is established. 

- Once the device stops discovery, it is still possible to send data to connected devices

- To stop discovery, use [NearbyShareStopDiscovery](../WDLang3/1410090649.md).
