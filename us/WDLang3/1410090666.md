
## Parameters of the procedure used by NearbyShareRequestConnection (Request)



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
WLanguage procedure ("callback") called by [NearbyShareRequestConnection](../WDLang3/1410090650.md) executed when the nearby device receives the connection request.

In the code of this procedure, the request can be accepted ([NearbyShareAcceptConnection](../WDLang3/1410090646.md)) or rejected ([NearbyShareRejectConnection](../WDLang3/1410090651.md)).
<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
NearbyShareRequestConnection(gSelectedDevice.ID, ...
	gsDeviceName, CallbackRequestConnection, CallbackConnection)
```



```wl
PROCEDURE CallbackRequestConnection(sDeviceID is string, sDeviceName is string, sToken is string)
Info([
	ID: [%sDeviceID%]
	Name: [%sDeviceName%]
])
```



```wl
PROCEDURE CallbackConnection(sDeviceID is string, nStatus is int)
SWITCH nStatus
	CASE nsConnectionRejected
		ToastDisplay("The connection request has been rejected.")
	CASE nsConnected
		ToastDisplay(StringBuild("Connected to %1.", sDeviceID)
	CASE nsDisconnected
		ToastDisplay("Disconnected.")
	CASE nsConnectionFailed
		ToastDisplay("Connection failed." + ErrorInfo())
END
```

## Syntax
<a name="SYNTAXE1"></a>

`NearbyShareRequestConnection_Callback_Request(<Device identifier> , <Device name> , <Authentication token>)`
---

**`<Device identifier>: (Character string)`**

Identifier of the nearby device that received the connection request.

**`<Device name>: (Character string)`**

Name of the nearby device that received the connection request. 
This name corresponds to the device name passed to [NearbyShareWaitForConnection](../WDLang3/1410090655.md).

**`<Authentication token>: (Character string)`**

Short, random character string that allows users to confirm that they are connecting to the right device.

## Remarks


### Authentication tokens
<a name="authentication_tokens_ELTPARAGRAPHE000053"></a>

Both devices receive the same token. These tokens must be verified programmatically. 

A common practice is to display the token on both devices and ask users to compare and confirm manually (e.g., Bluetooth pairing).

[NearbyShareAcceptConnection](../WDLang3/1410090646.md) allows you to open a dialog box with the authentication token. The connection request can then be accepted or rejected.
