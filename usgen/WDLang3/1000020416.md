
## NFCReadTag (Function)

***In french: NFCLitTag***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Starts reading an NFC tag or enables the detection of NFC tags for the current window.


<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
// Read an NFC tag in blocking mode
tag is nfcTag
tag = NFCReadTag()
IF NOT ErrorOccurred THEN
	Info(StringBuild("Reading an NFC tag of %1 type", tag..Type))
	FOR EACH data of tag.Data
		SWITCH data.Type
			CASE nfcText
				Info(data.Content)
			CASE nfcURI
				IF StringStartsWith(data.Content, "http") THEN
					BrowserRunApp(data.Content)
				END	
			CASE nfcMedia
				IF data.MIMEType ~= "image/png" THEN
					fSaveBuffer(CompleteDir(SysDirStorageCard()) + "image.png", data.Content)
				END				
		END
	END
END
```


<a name="Exemple2"></a>

```wl
// Read an NFC tag in non-blocking mode
IF NOT NFCReadTag(ReadNFCTag) THEN
	Error("Failure starting the NFC detection.", ErrorInfo())
END
INTERNAL PROCEDURE ReadNFCTag(tag is nfcTag)
	Info(StringBuild("A NFC tag of %1 type was detected.", tag.Type))
	// Stop detection
	RETURN True
END
```

## Syntax
<a name="SYNTAXE1"></a>
![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png) 
### Reading an NFC tag in blocking mode

`<Result> = NFCReadTag()`
---

**`<Result>: (nfcTag variable)`**

[nfcTag](../WDLang3/1000020411.md) variable initialized with the information read in the NFC tag. 

If an error occurs, the [ErrorOccurred](../WDLang1/3087001.md) variable is set to <u><u><u><u>True</u></u></u></u>. To get more details on the error, use [ErrorInfo](../WDLang1/3013008.md).


<a name="SYNTAXE2"></a>

### Reading an NFC tag in non-locking mode

`<Result> = NFCReadTag(<WLanguage procedure>)`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if NFC tag detection has been enabled,

- <u><u><u><u>False</u></u></u></u> otherwise. If an error occurs, the [ErrorOccurred](../WDLang1/3087001.md) variable is set to <u><u><u><u>True</u></u></u></u>. To get more details on the error, use [ErrorInfo](../WDLang1/3013008.md).




**`<WLanguage procedure>: (Procedure name)`**

Name of the WLanguage procedure ("callback") called when an NFC tag was read. This procedure has the following format: 


```txt
PROCEDURE <Procedure Name> (<Tag>)
```


where &lt;Tag&gt; is a [nfcTag](../WDLang3/1000020411.md) variable containing the information read in the NFC tag. 

Remarks:

- The parameters of this procedure are optional. There is no need to pass parameters to this procedure. Indeed, these parameters are automatically filled during each call.

- If the procedure returns <u><u><u><u>True</u></u></u></u>, the detection of NFC tags will be automatically stopped after the reading. 

- If the procedure returns <u><u><u><u>False</u></u></u></u> or if it returns no value, the detection will remain active as long as the window in which the procedure was triggered is not closed.

<a name="NOTE0_1"></a>

## Remarks
![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png) 

### Use in blocking mode (Syntax 1)
<a name="use_blocking_mode_syntax_1_ELTPARAGRAPHE000107"></a>

The call to **NFCReadTag** automatically opens a window to prompt the users to hold their devices closer to another NFC-enabled device. This window will be automatically closed: 

- when the sending is over 

- if the user cancels the sending by pressing the Back key of the device. 
	Note: To customize the message displayed in this window, use [NextTitle](../WDLang1/3038043.md) before calling **NFCReadTag**. 



<a name="NOTE0_2"></a>


### Use in non-blocking mode (Syntax 2)
<a name="use_nonblocking_mode_syntax_2_ELTPARAGRAPHE000126"></a>

The call to **NFCReadTag** starts detecting the NFC tags for the current window at the time of the call.

The detection will be active when this window is displayed in the foreground of the application. 

When the window is closed, the detection is stopped and will have to be restarted by calling **NFCReadTag**. 

A fatal error will occur if there is no current window when **NFCReadTag** is called.
<a name="NOTE0_3"></a>


### Other notes
<a name="other_notes_ELTPARAGRAPHE000145"></a>

- The NFC functions cannot be used in the simulator or in the emulator.

- ![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png) The NFC functions are only available in read-only mode.







<a name="NOTE0_4"></a>


### Required permissions 
<a name="required_permissions_ELTPARAGRAPHE000158"></a>

This function changes the permissions required by the application. 

Required permissions:  

- NFC: Allows applications to perform I/O operations over NFC.

- VIBRATE: Allows access to the vibrator.



<a name="NOTE0_5"></a>
![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png) 

### AppID required
<a name="appid_required_ELTPARAGRAPHE000174"></a>

Calling this function modifies the AppIDs of the application in the Apple developer account. It is necessary to activate the "NFC Tag Reading" App ID.. 
<a name="NOTE0_6"></a>
![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![Android Widget ](https://doc.pcsoft.fr/ext/images/us/ANDROIDWIDGET.png) 

### Application in the background: Specific case from Android 10
<a name="application_the_background_specific_case_from_android_10_ELTPARAGRAPHE000345"></a>

Starting with Android 10, it is no longer possible to open a window when the application is in the background. 

**NFCReadTag** can open a window. If this function is used while the application is in the background, a fatal error will occur. 

Tips: 

- It is possible to determine if the application is in the background using [InBackgroundMode](../WDLang1/1000023457.md). 

- If an application needs to interact with the user while it is in the background, the solution is to display a notification (via the [Notification](../WDLang3/1000019441.md) type). The application will be brought back to the foreground when the notification is clicked, if the **ActivateApplication** property is set to <u><u><u><u>True</u></u></u></u>. You can also open a window from the procedure passed to the **ActionClick** property.




For more details, see [Android 10: Behavior of applications in the background](../Editeurs/9000195.md).
