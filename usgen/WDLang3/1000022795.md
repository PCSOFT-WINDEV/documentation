
## WDTestRest: REST web service test tool
			

<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000169"></a>
WDTestRest is used to test the calls to an HTTP REST web service or to run a Web API accessible by HTTP. 

This tool is automatically launched when a REST web service is tested from the WINDEV or WEBDEV editor. The methods of the web service are automatically listed. 

**Remarks**: 

- The following methods are supported: HTTP GET, POST, PUT, PATCH, DELETE, COPY and HEAD.

- WDTestRest supports the HTTP and OAuth authentication systems.

- You can manage the headers sent as well as the ones received at runtime.

- The content of requests can be customized, in "Form-Data", "URLEncoded" or binary format.

- WINDEV and WEBDEV must be installed.

## Using WDTestRest
<a name="using_wdtestrest_ELTTEXTE000193"></a>
WTestRest allows you to: 

- [Define URL parameters](#NOTE2_2).

- [Define headers](#NOTE2_3).

- [Send content](#NOTE2_4). 

- [Define the authentication mode](#NOTE2_5). 

- [Send the request](#NOTE2_6). 

- [Manage a history](#NOTE2_7). 



<a name="NOTE2_2"></a>


### URL parameters
<a name="url_parameters_ELTPARAGRAPHE000050"></a>

You have the ability to specify the URL parameters ("Parameters" button):

- To add a parameter, type its name and its possible value.

- To delete a parameter, click the "-" button associated with the parameter.

- To modify a parameter, type the new values in the relevant controls.

- To reorder the parameters, click and hold the "" button of a given parameter, then drag it to the desired position and release. Release the left mouse button when it's done.



<a name="NOTE2_3"></a>


### Headers
<a name="headers_ELTPARAGRAPHE000062"></a>

In the "Headers" pane, you can manage the headers that will be sent with the request.

You can manage headers the same way you manage URL parameters.

You can also manage the content of headers manually, via the "Bulk edit" button.
Note: in this case, data must respect the format of HTTP headers.
<a name="NOTE2_4"></a>


### Content
<a name="content_ELTPARAGRAPHE000075"></a>

All requests, except GET, can convey content.

This content can correspond to form data, binary data, etc.

In the "Content" pane, expand the "Type" combo box and choose the type of content to be sent. The interface will adapt to your choice.

For the forms ("form-data" or "urlencoded"), the edit of data is performed like the edit of headers and URL parameters.
<a name="NOTE2_5"></a>


### Authentication
<a name="authentication_ELTPARAGRAPHE000088"></a>

WDTestRest handles basic HTTP authentication, with the username and password to be sent during the request.

You also have the ability to use the OAuth 2 authentication.

WDTestRest asks you to specify the OAuth connection information and it allows you to get the access token ("token") that will be used to run the request.

Note: You can keep OAuth authentication data for future calls by selecting "Store token".
<a name="NOTE2_6"></a>


### Send
<a name="send_ELTPARAGRAPHE000101"></a>

Once the parameters of the request have been defined, click "Send" to send them to the specified URL.

At the end of request execution, the result is displayed at the bottom of window:

- HTTP content (the response),

- cookies,

- headers. 




Each pane is used to see the data received. XML and JSON codes can be formatted as required.

To get the WLanguage code corresponding to the call to the request, click the button "Generate the WL code".
<a name="NOTE2_7"></a>


### History
<a name="history_ELTPARAGRAPHE000118"></a>

Whenever sending an HTTP request, WDTestRest stores the full setting (URL, parameters, headers, content, etc.) in a history.

This history, accessible from the WDTestRest button, is used to re-run the previous requests.
