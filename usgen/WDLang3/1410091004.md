
## REST web service: Creating entry points

## Creating entry points
<a name="creating_entry_points_ELTTEXTE000371"></a>
The REST web service entry point creation wizard opens: 

- when creating a new REST web service description. 

- on the "REST web service" tab, "Entry points" group, by clicking "New". <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Webservice_REST%20-%20HC%20N%B0009%202.gif)

	Note: The "REST web service" tab only appears when you open a REST web service description in the editor. 




The entry point creation wizard lets you select the creation method:

- [Method 1: Manual creation of entry points](#REST_Methode1). 

- [Method 2: Automatic creation of entry points from the description of a table (present in the database schema)](#REST_Methode2).

- [Method 3: Automatic creation of entry points from a set of procedures](#REST_Methode3).

<a name="REST_Methode1"></a>


## Method 1: Manual creation of an entry point
<a name="method_1_manual_creation_entry_point_ELTTEXTE000395"></a>
To manually create an entry point: 

1. In the wizard, select "Create an entry point". 

2. Go to the next step.

3. Specify the global WLanguage procedure associated with the entry point. This procedure can be created or selected from existing global procedures. <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Webservice_REST%20-%20HC%20N%B0003.gif&type=thumb)


4. Go to the next step. 

5. Choose the HTTP method according to the desired action (GET, PUT, etc.). <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Webservice_REST%20-%20HC%20N%B0004.gif&type=thumb)


6. Go to the next step. 

7. Define the resource (or URL section) corresponding to the entry point. This resource can include static elements or variable elements (parameters).<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Webservice_REST%20-%20HC%20N%B0005.gif&type=thumb)
For more details on the resource, see [Resource structure](#NOTE6_1).. 

8. Go to the next step. 

9. Define the request and response format. JSON is the standard format in REST web services, but other formats are also available. 

	- The **request format** indicates how the data passed in the REST call is formatted. <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Webservice_REST%20-%20HC%20N%B0006.gif&type=thumb)
This format can be as follows: 

		- HTML form,

		- JSON,

		- XML,

		- Text (MIME "Text/Plain" type),

		- Binary (for images, for example),

		- Variable (must be specified programmatically with [WebserviceReadMIMEType](../WDLang3/1000022680.md)).




- **Automatic deserialization**: The data passed as parameters to POST, PUT or PATCH requests can be automatically deserialized in a parameter of the procedure associated with the entry point:<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Webservice_REST%20-%20HC%20N%B0007.gif&type=thumb)

10. Go to the next step. 

11. Type the entry point description (free text). 

12. Confirm. 




The description of the different entry points is displayed in the editor. <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Webservice_REST%20-%20HC%20N%B0009.gif&type=thumb)

## Method 2: Automatic creation of entry points to access a table
<a name="method_2_automatic_creation_entry_points_access_table_ELTTEXTE000428"></a>
To automatically create entry points and procedures for a table in the database schema:

1. In the wizard, select "Create entry points to access tables". 

2. Select the table for which you want to define the entry points.<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=WebService_Rest_fichier%20-%20HC%20N%B0003.gif&type=thumb)


3. Go to the next step.

4. Select the items that will be exposed in the web service. <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=WebService_Rest_fichier%20-%20HC%20N%B0004.gif&type=thumb)
These items can be accessed in read and/or write mode via the REST web service entry points.

5. Go to the next step.

6. Select the key that will be used to access the record in the table to be read, modified or deleted. <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=WebService_Rest_fichier%20-%20HC%20N%B0005.gif&type=thumb)


7. Go to the next step.

8. Select the format used to exchange data when calling the entry points of the REST web service. 3 formats are available: <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=WebService_Rest_fichier%20-%20HC%20N%B0006.gif&type=thumb)


	- JSON (UTF-8): Data sent or returned is in JSON format.

- JSON (UTF-8) ([HRecordToJSON](../WDLang4/1000021909.md)): Data is formatted in an intermediate object created with [HRecordToJSON](../WDLang4/1000021909.md).

- XML: Data sent or returned is in XML format.

9. Go to the next step.

10. Select the list of entry points that will be generated when creating the REST web service. <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=WebService_Rest_fichier%20-%20HC%20N%B0007.gif&type=thumb)
By default, all types of entry points are generated: 

	- Creation: Add a record into the table.

	- Read: Find and read a record in a table.

	- Modification: Update a record in the table.

	- Deletion: Delete a record from the table.

	- Read all records: Read all records in the table.




11. Go to the next step.

12. It's done. The wizard generates the object-oriented (OOP) source code and the REST web service with all entry points.  The created class contains:

	- the declaration of members representing the items of the record being manipulated (MAPPING).

	- the declaration of methods representing the different REST web service entry points. A method for each entry point of REST web service.

	- a **sCreation** method for the Creation entry point.

	- a **sRead** method for the Read entry point.

	- a **sModification** method for the Modification entry point.

	- a **Deletion** method for the Deletion entry point.

	- a **sReadAll** method for the Read All Records entry point.

## Method 3: Creation of entry points from a class or set of procedures
<a name="method_3_creation_entry_points_from_class_set_procedures_ELTTEXTE000452"></a>
To automatically create entry points from a class or set of procedures:  

1. In the wizard, select "Create entry points from the procedures of a set". 

2. Select the set of procedures or the class associated with the entry point. <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=WebServiceRest_cr%E9er_proc%20-%20HC%20N%B0002.gif&type=thumb)


3. Go to the next step. 

4. Select the procedures or methods that will be exposed by the REST web service. The resource associated with each procedure or method will be automatically initialized according to the name of the procedure and its parameters. <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=WebServiceRest_cr%E9er_proc%20-%20HC%20N%B0003.gif&type=thumb)

	Specify the HTTP method for each selected procedure. 

5. Go to the next step. 

6. Define the request and response format. JSON is the standard format in REST web services, but other formats are also available. 

	- The **request format** indicates how the data passed in the REST call is formatted. <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=WebServiceRest_cr%E9er_proc%20-%20HC%20N%B0005.gif&type=thumb)
This format can be as follows: 

		- HTML form,

		- JSON,

		- XML,

		- Text (MIME "Text/Plain" type),

		- Binary (for images, for example),

		- Variable (must be specified programmatically with [WebserviceReadMIMEType](../WDLang3/1000022680.md)).




- The **response format** indicates how the data retrieved from a REST call is formatted. <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=WebServiceRest_cr%E9er_proc%20-%20HC%20N%B0006.gif&type=thumb)
This format can be as follows: 

	- None,

	- JSON,

	- XML,

	- Text (MIME "Text/Plain" type),

	- Binary (for images, for example),

	- Variable (must be specified programmatically with [WebserviceWriteMIMEType](../WDLang3/1000022681.md)).

	- Chunked: Data must be returned using [WebServiceSendChunk](../WDLang3/1410091271.md). The response format must be specified programmatically using [WebserviceWriteMIMEType](../WDLang3/1000022681.md).
						

7. Finish the wizard. 




The description of the different entry points is displayed in the editor. <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Webservice_REST%20-%20HC%20N%B0009.gif&type=thumb)

## Remarks
<a name="remarks_ELTTEXTE000485"></a>


### Resource structure (or URL section)
<a name="resource_structure_url_section_ELTPARAGRAPHE000254"></a>

The resource is made of: 

- static elements.

- variables elements.

- common parameters (optional).




The **static elements** represent the objects used. For example, "/Customers" to handle customers. 
In the resource creation wizard, a static element corresponds to a "Fixed component". 

The **variable elements** identify the resources used (a customer number, an order number, etc.). For example, "/Customers/{CustNum}" identifies the customer using a customer number. 

- In the URL creation wizard, a variable element corresponds to: 

	- a variable component defined by a procedure parameter. This component is automatically retrieved in the parameters of the associated WLanguage procedure. 

	- a variable component retrieved programmatically with [WebserviceParameter](../WDLang3/1000022786.md).  




- A variable element is represented by the following syntax: "{Variable component name}".
	For example, "/Customers/10" allows you to manage customers with an identifier set to 10. 

- It is quite common to pass variables elements in the URL when calling a REST function. 

- Each variable component (retrieved programmatically) of the resource corresponds to a parameter passed to the WLanguage procedure associated with the entry point.

- A variable element is represented by a name when defining the address of the entry point in the editor. **For a variable component retrieved programmatically, this name must be identical to the name of the parameter in the WLanguage procedure associated with the entry point**. 
	At runtime, the value passed in the resource (URL) will be retrieved and placed in the variable. This name is case sensitive. Therefore, it is very important to use the same name in the procedure and in the resource (or vice versa), otherwise a runtime error occurs.

<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Webservice-REST.gif)
You can combine several static and variable elements. For example:

- "/Customers/{CustomerID}/Invoices" to retrieve the invoices of a customer identified by their customer ID. 

- "/Suppliers/{SupID}/Products/{ProdRef}" to retrieve the product identified by "ProdRef" for the supplier identified by "SupID". 





To change the common parameters, go to the "REST web service" tab, "Options" group, and select "Description". <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Webservice_REST%20-%20HC%20N%B0010.gif)


In the "Common components" tab of the REST webservice description window, you can define a part of the resource that is common to all entry points. Therefore, there is no need to systematically copy this resource section to each entry point. The modification is performed at a single location.

**Tip**: You can use common parameters to manage different versions of the REST web service. For example, you can use a common parameter named "V1". When creating another version of the web service, simply change "V1" to "V2" to change the resource (URL) of all entry points.

### Status codes in the code of procedures
<a name="status_codes_the_code_procedures_ELTPARAGRAPHE000303"></a>

The code of WLanguage procedures used for REST web services must manage reports indicating whether or not the function has been executed successfully.

In a REST web service, execution reports are returned using HTTP response status codes. HTTP response codes are divided into different categories: 

- 2xx codes correspond to successful actions.

- 3xx codes correspond to redirection errors.

- 4xx codes correspond to client errors (incorrect HTTP method, incorrect data format sent, etc.).

- 5xx codes correspond to server errors (WLanguage procedure internal error, etc.).


The response code is returned by [WebserviceWriteHTTPCode](../WDLang3/1000022785.md).

Examples of response codes used:

- Create a customer using the POST method. If the request was successful, return code 201.

- Delete a customer using the DELETE method. If the request fails due to an integrity error returned by the database, return code 500 with a message explaining the error. 

- Find a product by passing a reference as parameter via the GET method. If the request was successful, return code 200.

- Find a product by passing a reference as parameter via the GET method. If the request fails because the reference does not exist, return code 404.
