


## zipExtractFile (Function)

***In french: zipExtraitFichier***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Extracts a file from an archive and automatically decompresses it to a physical location or in memory.


	<B><B><B>Warning</B></B></B>

	 This method of extracting files from an archive can be relatively slow. To extract multiple files, use functions [zipExtractAll](../WDLang3/3082011.md) or [zipExtractDirectory](../WDLang3/1000025518.md).

## Syntax

### Extracting a file identified by its index

`<Result> = zipExtractFile(<Archive> , <File index> [, <File destination> [, <Progress>]])`
---

**`<Result>: (Integer or buffer)`**



- 0 if the file was extracted,

- An error code (value greater than 0) otherwise. For more details on these error codes, see the [Remarks](#NOTE0_1).


When extracting "in memory", corresponds to the buffer containing the extracted file.

**`<Archive>: (Character string or zipArchive variable)`**

Name of the archive to be used.
This name can correspond to:

- an archive name defined with [zipOpen](../WDLang3/3082044.md) or [zipCreate](../WDLang3/3082003.md).

- the name of a variable of type [zipArchive](../WDLang3/1000018679.md). 
	![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) [zipArchive](../WDLang3/1000018679.md) variables are not available in Java.




**`<File index>: (Integer)`**

Index of file to extract from the archive.  [zipFindFile](../WDLang3/3082002.md) returns this index. 

**`<File destination>: (Optional character string or constant)`**

Destination path of extracted file:

- Optional character string: The file is extracted to the specified path, to which the file's memorized tree structure is added (the disk is not preserved). The specified path is created if it does not exist.

- Optional constant:
	


|   |   |
| --- | --- |
| *zipDirectory*<br>(Default value) | Extraction into the current directory while restoring the tree structure of file (if it was stored). |
| *zipDrive* | Extraction:<br><br>	- to the initial file location if it was stored and if the drive exists.<br><br>	- while restoring the tree structure of the file on the current drive if the drive or the stored directory does not exist.<br><br>	- into the current directory if only the file name and extension have been stored.<br><br><br>![Linux](https://doc.pcsoft.fr/ext/images/us/LX.png)![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png)![IOS Widget](https://doc.pcsoft.fr/ext/images/us/WIDGETIOS.png)![Mac Catalyst](https://doc.pcsoft.fr/ext/images/us/CATALYST.png) This constant is not available. The directories have no root.<br>![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![Android Widget ](https://doc.pcsoft.fr/ext/images/us/ANDROIDWIDGET.png)![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) This constant and *zipDirectory* will have the same effect.<br>**Archives in format 7z**: This constant will have the same effect as the *constant zipDirectory*. |
| *zipInMemory* | Extracts the file in memory. The file content is directly returned by the function. It can be assigned to a Buffer variable for example.<br>This feature is available for ZIP and WDZ archives only. |
| *zipNone* | Extraction into the current directory without restoring the tree structure of file (if it was stored). |






**`<Progress>: (Control name or procedure name)`**

Progress bar management mode. This parameter can correspond to: 

- ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png)![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png)![Mac Catalyst](https://doc.pcsoft.fr/ext/images/us/CATALYST.png) the name of a Progress Bar control found in a window. The progress bar will display the progress of file extraction.  

- the name of a WLanguage procedure. This procedure has the following format: 
	
	```txt
	<Procedure name> (<Current file>, <Progress percentage>)
	```

	where: 

	- &lt;Current file&gt; corresponds to the name of the file currently processed. 

	- &lt;Progress percentage&gt; corresponds to the progress percentage of the file being extracted from the archive. 







Please note: The ProgressBar is only updated at the end of file extraction for: 

- TAR, gzip or TGZ (TAR.GZ),

- RAR, 

- CAB.

## Remarks


### Error codes
<a name="error_codes_ELTPARAGRAPHE000328"></a>

The following error codes are returned:

- 1: Path passed as parameter does not exist.

- 2: Access denied: user does not have sufficient rights.

- 3: The archive is corrupt.

- 4: The path does not exist in the archive.

- 6: Sub-archive files are not in order (case of extraction from a multi-part archive).

- 21: The password specified is not correct.




The message corresponding to the error code is returned by [zipMsgError](../WDLang3/3082034.md).
Reminder: 

- ![Linux](https://doc.pcsoft.fr/ext/images/us/LX.png)![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png)![IOS Widget](https://doc.pcsoft.fr/ext/images/us/WIDGETIOS.png)![Mac Catalyst](https://doc.pcsoft.fr/ext/images/us/CATALYST.png) Only archives in ZIP, TAR, gzip and TGZ (TAR.GZ) formats are available.

- ![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![Android Widget ](https://doc.pcsoft.fr/ext/images/us/ANDROIDWIDGET.png)![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) Only ZIP archives are available.

- RAR is supported up to and including version 4.



<a name="NOTE0_2"></a>


### Extracted file
<a name="extracted_file_ELTPARAGRAPHE000358"></a>

The extracted file is not deleted from the archive. To delete one file or all the files from the archive, use [zipDeleteFile](../WDLang3/3082041.md) or [zipDeleteAll](../WDLang3/3082051.md).

### Extraction and password
<a name="extraction_and_password_ELTPARAGRAPHE000375"></a>

If the file is not encrypted and if [zipPassword](../WDLang3/3082053.md) was used:

- Archive in WDZ format: The file is still extracted.

- Archive in ZIP format: An error appears.



<a name="NOTE0_4"></a>


### Index of files in the archive
<a name="index_files_the_archive_ELTPARAGRAPHE000390"></a>

When a file is added into an archive, an index is automatically assigned to the file. This index corresponds to the order in which the files are included in the archive. To select a file in the archive, you can use:

- the index of the element (the index of an element is returned by [zipFindFile](../WDLang3/3082002.md)).

- the stored path of the element.



<a name="NOTE0_5"></a>


### Stored path
<a name="stored_path_ELTPARAGRAPHE000405"></a>

The table below presents the paths stored in the archive according to:

- the access path to the file,

- the stored path section.




The current directory is: "C:\\Temp".


|   |   |   |   |   |
| --- | --- | --- | --- | --- |
| **zipAddFile** | **File location** | *zipNone* | *zipDirectory* | *zipDrive* |
| zipAddFile("Archi",...<br>"File.txt") | C:\\Temp\\File.txt | File.txt | File.txt | File.txt |
| zipAddFile("Archi",...<br>"Data\\File.txt") | C:\\Temp\\Data\\File.txt | File.txt | Data\\File.txt | Data\\File.txt |
| zipAddFile("Archi",...<br>"D:\\Data\\File.txt") | D:\\Data\\File.txt | File.txt | Data\\File.txt | D:\\Data\\File.txt |


**Remark**: If the constant *zipDisk* is used: 

- the WDZ format stores the full path of the file (including the drive letter). 

- the ZIP format does not store the drive letter.

- the 7z format stores the directories only.
