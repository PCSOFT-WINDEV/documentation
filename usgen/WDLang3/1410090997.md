
## Secure REST web service
			

<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000135"></a>
WINDEV and WEBDEV allow you to create REST web services and secure access with OAuth tokens.

Here's how it works: <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=WB-Webservice-Securise.gif)


To access certain web services, an access token is required.
Users must therefore obtain the token to call those web services.
OAuth is a standard protocol that allows them to obtain this token.
Reminder: OAuth lets you manage access authorizations.
This token is provided by an authentication server, using the OAuth protocol.

## Creating a secure REST web service
<a name="creating_secure_rest_web_service_ELTTEXTE000159"></a>
To create a secure REST web service, simply follow these steps:

1. Create the REST web service. For more details, see [Creating and using a REST web service](../WDLang3/1000022792.md). 

2. Define the authentication (OpenID Connect) or authorization (OAuth 2.0) servers. 

3. Define scopes when using OAuth 2.0. 

4. Associate scopes with entry points. 





### Defining authorizations
<a name="defining_authorizations_ELTPARAGRAPHE000040"></a>

To define the authorizations associated with a REST web service:

1. If necessary, open the REST web service in the REST web service editor.  

2. To open the REST web service description, go to the "REST web service" tab, "Options" group and click "Description".

3. Click the "Authorization" tab of the description window. 




**Defining trusted servers**
First of all, you need to enter the details of the user authentication or authorization servers. 
To define authentication (OpenID Connect) or authorization (OAuth 2.0) servers: 

- Click "+"  at the top of the window to add as many servers as required. 

- Specify the characteristics of each server: <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=WebServiceRest_S%E9curis%E9%20-%20HC%20N%B0004.gif)


	- Server address,

- Token validation key **or** introspection URL provided by the server. Only one of these elements is required.


Token validation key (signature verification). 
The key depends on the signature used by the server: 

- "HS256"/"HS384"/"HS512" signatures: A secret key is used (shared with the server). The key is a binary value generally in hexadecimal format. 

- "RS256"/"RS384"/"RS512" signatures: The server's public key is used. The key is a string. It is generally represented as a multiline text starting with -----BEGIN PUBLIC KEY-----





**Defining scopes**
In the lower section of the window, you can enter the list of scopes that may be required to address a web service entry point. 
<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=WebServiceRest_S%E9curis%E9%20-%20HC%20N%B0005.gif)

To associate scopes with entry points, simply click "Scopes" for each entry point and select the required scopes.  
<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=WebServiceRest_S%E9curis%E9%20-%20HC%20N%B0006.gif)


Note: If no permission is selected, the entry point can be used without any particular restrictions.
