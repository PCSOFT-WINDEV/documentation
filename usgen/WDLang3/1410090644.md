
## WLanguage procedure called by NearbyShareAcceptConnection (Data reception)



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
WLanguage procedure ("callback") called by [NearbyShareAcceptConnection](../WDLang3/1410090646.md) when the entire file (or buffer) is received. This procedure provides information on the type and content of data transferred. 
<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
NearbyShareAcceptConnection(gsNearbyDeviceID, ReceptionCallback, ProgressCallback)
	INTERNAL PROCEDURE ReceptionCallback(sDeviceID is string, nTransferID is 8-byte int, 
					nType is int, data)
		STC_Received_message_information = [
			Message received from the following device: [%sDeviceID%]
			Transfer ID: [%nTransfertID%]
		]
		SWITCH nType
			CASE nsBuffer
				sMessage is string = data
				EDT_Message_received = sMessage
				EDT_Message_received.State = Inactive
			CASE nsFile
				BTN_Open_file_received.State = Active
				gsFileReceived = data
			END
	END
	INTERNAL PROCEDURE ProgressCallback(sDeviceID is string, nTransferID is 8-byte int, 
		nState is int, nSizeReceived is 8-byte int, 
		nTotalSize is 8-byte int)
		Message is string
		SWITCH nState
			CASE nsInProgress
				Message = [
						Transfer in progress: 
						[%Round(nSizeReceived / nTotalSize * 100, 2)%]% 
						of data was sent.
						]
				ToastDisplay(Message)
			CASE nsCompleted
				Message = [
					Data transfer completed: 
					[%Round(nSizeReceived / nTotalSize * 100, 2)%]% 
					of data was sent.
					]
				ToastDisplay(Message)
			CASE nsError
				ToastDisplay("Transfer error" + CR + ErrorInfo())
			CASE nsCanceled
				ToastDisplay("Data transfer canceled")
		END
	END
```

<a name="XSYNTAXE"></a>

## Syntax
<a name="SYNTAXE1"></a>

`NearbyShareAcceptConnection_Callback_Reception(<Sending device ID> , <Transfer ID> , <Type> , <Data received>)`
---

**`<Sending device ID>: (Character string)`**

Identifier of the sending nearby device.

**`<Transfer ID>: (Integer)`**

Identifier of the current transfer.

**`<Type>: (Integer constant)`**

Type of data received. This parameter can correspond to one of the following constants: 



|   |   |
| --- | --- |
| *nsBuffer* | The data received is a binary buffer.  |
| *nsFile* | The data received corresponds to a file. In this case, &lt;Data received&gt; corresponds to the path of the file received. |



**`<Data received>: (Variant)`**

Data received. The type of this parameter depends on the type of data received (string or binary buffer, corresponding to the path of the file received).
