


## Migrating the Private Store to another server
			



<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000146"></a>
Private Stores group together application and site installations within an organization.
If you need to migrate a Private Store to a new server, you can preserve its configuration.
Here is how to do it in 6 steps.

<a name="NOTE2"></a>


## Procedure to follow
<a name="procedure_follow_ELTTEXTE000170"></a>
<a name="NOTE1_2"></a>


### 1. HFSQL server for the Private Store
<a name="1_hfsql_server_for_the_private_store_ELTPARAGRAPHE000023"></a>

The Private Store requires two elements to run:

- an HFSQL server,

- an Application Server hosting BaaS solutions.




If the HFSQL server used by the Private Store is hosted on the same machine as the Application Server that hosts BaaS solutions, it is necessary to back up this HFSQL server. This makes it possible to restore it on the new machine.

If the HFSQL server used by the Private Store is hosted on another machine, go directly to **step 4**.
<a name="NOTE1_3"></a>


### 2. HFSQL server backup
<a name="2_hfsql_server_backup_ELTPARAGRAPHE000037"></a>

To back up the HFSQL Client/Server used by the Private Store, use the HFSQL Control Center:

1. Open the HFSQL Control Center. 

2. Select the HFSQL server in the tree structure on the left.

3. In the ribbon, go to the "Backups" tab, and click "New backup". 

4. For the contents of the backup, select "All server contents (all databases, including system database)".



<a name="NOTE1_4"></a>


### 3. Restore the HFSQL backup
<a name="3_restore_the_hfsql_backup_ELTPARAGRAPHE000049"></a>

On the new server machine:

1. Install an HFSQL server.
	The HFSQL server installation is available in WINDEV's "Install\\HFSQL Server" subdirectory.

2. Open the HFSQL Control Center. 

3. Go to the "Backups" tab and click "Restore".



<a name="NOTE1_5"></a>


### 4. Install the Application Server with BaaS solutions
<a name="4_install_the_application_server_with_baas_solutions_ELTPARAGRAPHE000062"></a>

On the new server machine: 

1. Install an Application Server with BaaS solutions. For more details, see [Installing BaaS solutions](../WDLang3/1000021311.md). 

2. In "WDBaaS: HFSQL server", generally, the HFSQL Client/Server connection parameters are those used previously and can remain unchanged. This is because either the HFSQL server was hosted on the old machine and was backed up and restored (steps 2 and 3), or it is hosted on a third-party machine and requires no changes. 



<a name="NOTE1_6"></a>


### 5. Access token
<a name="5_access_token_ELTPARAGRAPHE000075"></a>

Deploying WINDEV Mobile applications to the Private Store requires an access token.

This token is provided after installing the Application Server that hosts BaaS solutions. Therefore, installing a new BaaS server modifies this access token.

To keep the old token:

1. On the old server machine, locate the BaaS server configuration file ("GPUConnection.default.xml").

2. Copy the content of the &lt;token&gt; tag. 

3. On the new machine, open the BaaS server configuration file and paste this content.




**Note**: Depending on the version of the BaaS Server, the "GPUConnection.default.xml" file may be located in:

- the "C:\\ProgramData\\WDBaaS" directory,

- the account root directory: "C:\\sites\\Data_WDBaaS\\". This root directory is specified in the WEBDEV Hosting Control Center.



<a name="NOTE1_7"></a>


### 6. Last step: Network settings
<a name="6_last_step_network_settings_ELTPARAGRAPHE000095"></a>

- **If the server was used in an Intranet via its machine name or IP address**, stop the old server and reconfigure the new one so that it has the same name and/or address.
	

- **In the case of an Internet server**, you can either stop the old server and reconfigure the new one so that it responds to the same address as the previous one, or modify the configuration of the domain that accesses the server to go to the address of the new server.
