


## zipAddFileList (Function)

***In french: zipAjouteListeFichier***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Automatically adds and compresses a list of files into a ZIP, CAB, WDZ, 7z, TAR, gzip or TGZ (TAR.GZ) archive. This function is faster than [zipAddFile](../WDLang3/3082008.md) run for each file.

## Example

![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png)![WEBDEV - Server code](https://doc.pcsoft.fr/ext/images/us/WBS.png)![Reports and Queries](https://doc.pcsoft.fr/ext/images/us/ER.png)![User code (UMC)](https://doc.pcsoft.fr/ext/images/us/MCU.png)![Ajax](https://doc.pcsoft.fr/ext/images/us/AJAX.png) 
```wl
// Create an archive and add an element
// With progress bar displayed in a Progress Bar control 
MyArchive is zipArchive
NumZipErr is int

NumZipErr = zipCreate(MyArchive,"C:\Doc\Archive\ArchiveFile.zip")
IF NumZipErr = 0 THEN
	NumZipErr = zipAddFileList(MyArchive, "C:\doc\Image\House.BMP" + CR +  ...
			"C:\My Projects\WDStock\WDStock.wdp", zipDrive, PROGBAR_Progress)
	IF NumZipErr <> 0 THEN
		Error(zipMsgError(NumZipErr))
	END
	zipClose(MyArchive)
ELSE
	Error(zipMsgError(NumZipErr))
END
```

## Syntax

### Adding a list of files separated by carriage returns (CR)

`<Result> = zipAddFileList(<Archive> , <Path of files to add> [, <Path section to store> [, <Progress>]])`
---

**`<Result>: (Integer)`**



- 0 if the file list has been added,

- An error code (value greater than 0) otherwise. For more details on these error codes, see the [Remarks](#NOTE0_2).




**`<Archive>: (Character string or zipArchive variable)`**

Name of the archive into which the files will be added.
This name can correspond to:

- an archive name defined with [zipOpen](../WDLang3/3082044.md) or [zipCreate](../WDLang3/3082003.md).

- the name of a variable of type [zipArchive](../WDLang3/1000018679.md). 
	![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) [zipArchive](../WDLang3/1000018679.md) variables are not available in Java.




**`<Path of files to add>: (Character string)`**

Name and path of files to be added to the archive, separated by carriage returns (CR). These paths can be full paths or paths relative to the current directory. The length of each path must not exceed 260 characters.
The size of each file must not exceed 4 GB. Otherwise, an error occurs.
You cannot use wildcard characters. 
![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png)![Reports and Queries](https://doc.pcsoft.fr/ext/images/us/ER.png)![User code (UMC)](https://doc.pcsoft.fr/ext/images/us/MCU.png) This parameter has the following format: 

```txt
<File path> [ + TAB + <Path to store> ] + RC
```
If a path is specified, adding the file will be equivalent to calling [zipAddFile](../WDLang3/3082008.md) followed by [zipChangePath](../WDLang3/3082027.md).

**`<Path section to store>: (Optional constant)`**

Indicates the file path section to be stored in the archive. This parameter is only taken into account for files for which &lt;Path to store&gt; was not specified. 


|   |   |
| --- | --- |
| *zipDirectory* | Stores the different directories that are part of the path, as well as the file name and extension. For example: \\Directory\\Files\\FileName.pdf |
| *zipDrive*<br>(Default value) | Stores the full and absolute path of the file (disk, directories, file name and extension). For example: C:\\Directory\\Files\\FileName.pdf<br>**ZIP format**: This constant has no effect.<br>**7z format**: This constant and *zipDirectory* will have the same effect.<br><br>![Linux](https://doc.pcsoft.fr/ext/images/us/LX.png)![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png)![IOS Widget](https://doc.pcsoft.fr/ext/images/us/WIDGETIOS.png)![Mac Catalyst](https://doc.pcsoft.fr/ext/images/us/CATALYST.png) This constant is not available as there is no drive root.![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![Android Widget ](https://doc.pcsoft.fr/ext/images/us/ANDROIDWIDGET.png)![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) This constant will have the same effect as *zipDirectory*. |
| *zipNone* | Stores the file name and extension. For example: FileName.pdf |


**If you are using an archive in .CAB format**, only the *zipNone* constant is taken into account. The .CAB format does not allow you to store paths in the archive file.

**`<Progress>: (Control name or procedure name)`**

Progress bar management mode. This parameter can correspond to: 

- ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png)![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png)![Mac Catalyst](https://doc.pcsoft.fr/ext/images/us/CATALYST.png) the name of a Progress Bar control in a window. The progress bar shows the file addition and compression progress status.

- the name of a WLanguage procedure. For more details on this procedure, see [Parameters of the procedure used by zipAddFileList](../WDLang3/1000025731.md). 




**If you use a TAR, gzip or TGZ (TAR.GZ) archive**, the progress bar is refreshed only after each file is added. 

![WEBDEV - Server code](https://doc.pcsoft.fr/ext/images/us/WBS.png) This procedure must be executed on the server side.![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) This parameter is not available.

## Remarks


### Use condition
<a name="use_condition_ELTPARAGRAPHE000291"></a>

You can add files to an archive if:

- The archive exists (archives are created using [zipCreate](../WDLang3/3082003.md)).

- The archive is accessible in read/write mode.

- The archive is a single-part archive.

- The size of the file is less than 4 GB.




**Caution**:

- The full path of each file is stored in the archives in ZIP or WDZ format.

- **CAB archives**: Files must be added immediately after the archive is created. This format does not allow adding files to an existing archive.

- **RAR archives**: This function is not available.

- **7z archives**: The archive is fully compressed each time **zipAddFileList** is called. 




Maximum number of files allowed:

- in a WDZ file: 232-1.

- in a ZIP file: 65535. 

- in a CAB file: 65535. 


Reminder: 

- ![Linux](https://doc.pcsoft.fr/ext/images/us/LX.png)![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png)![IOS Widget](https://doc.pcsoft.fr/ext/images/us/WIDGETIOS.png)![Mac Catalyst](https://doc.pcsoft.fr/ext/images/us/CATALYST.png) Only ZIP, TAR, gzip and TGZ (TAR.GZ) archives are available.

- ![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) Only ZIP archives are available.

- ![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![Android Widget ](https://doc.pcsoft.fr/ext/images/us/ANDROIDWIDGET.png) The CAB format is not available. 



<a name="NOTE0_2"></a>


### Compression level
<a name="compression_level_ELTPARAGRAPHE000362"></a>

The files added into a zip archive are compressed by default. You can change the compression level of files added to an archive using function [zipCompressionLevel](../WDLang3/3082054.md).
<a name="NOTE0_3"></a>


### Error codes
<a name="error_codes_ELTPARAGRAPHE000374"></a>

The following error codes are returned:

- 1: The path passed as parameter does not exist.

- 2: Access denied: The user does not have sufficient rights or the file is in use.. If the table to insert is an HFSQL table, it must be closed by the following code: 
	
	```txt
	HClose(<File name>)
	Multitask(<Timeout>) // Waits until the file is closed
	```


- 3: The archive is corrupted.

- 4: The path does not exist in the archive.

- 5: Unable to write to the archive.

- 7: The file already exists in the archive.

- 8: An archive cannot be added to itself. For example, "MyArchive" cannot be added to "MyArchive".




The message corresponding to the error code is returned by [zipMsgError](../WDLang3/3082034.md).
<a name="NOTE0_4"></a>


### Adding a file that already exists in the archive
<a name="adding_file_that_already_exists_the_archive_ELTPARAGRAPHE000398"></a>

Adding a file already present in an archive causes an error. A file is identified by its stored path. Therefore, you cannot add two files with the same name and the same relative path to an archive.
<a name="NOTE0_5"></a>


### Index of files in the archive
<a name="index_files_the_archive_ELTPARAGRAPHE000407"></a>

When a file is added to an archive, an index is automatically assigned to that file. This index corresponds to the order in which the files are added to the archive. To select a file in the archive, you can use:

- The index of the element (this index is returned by [zipFindFile](../WDLang3/3082002.md)).

- The stored path of the element.
