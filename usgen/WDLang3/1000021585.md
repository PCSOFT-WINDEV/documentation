
## geoTrackingProcedure (Function)

***In french: géoSuiviProcédure***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Defines the WLanguage procedure that will be called when the location of the user changes. 

**Caution**: 

- Before using this function, [geoTrackingEnable](../WDLang3/1000021583.md) must be used to enable location tracking. 

- To be run in the background, this function must be called in the "Initialization" event associated with the project. For more details, see [Remarks](#NOTE0_1).



<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
// -- Project initialization (REQUIRED to run the function in the background)
geoTrackingProcedure(TrackingProcedure)
```

```wl
// Implement the TrackingProcedure procedure
PROCEDURE TrackingProcedure(mLocation is geoPosition)
// Send the location to the server
SendServer(mLocation)
```

<a name="XSYNTAXE"></a>

## Syntax
<a name="SYNTAXE1"></a>

`<Result> = geoTrackingProcedure(<WLanguage procedure>)`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the location tracking system is available,

- <u><u><u><u>False</u></u></u></u> if the location tracking system is not available. To get more details on the error, use [ErrorInfo](../WDLang1/3013008.md). 




**`<WLanguage procedure>: (Procedure name)`**

Name of WLanguage procedure called when the location of the user changes. 

This procedure has the following format: 

```txt
PROCEDURE <Procedure name>(<Location> is geoPosition)
```


In this code, &lt;Location&gt; is a [geoPosition](../WDLang3/1000019191.md) variable corresponding to the current location of the user. 

This procedure must be a global procedure of application.

<a name="NOTE0_1"></a>

## Remarks


### Specific features
<a name="specific_features_ELTPARAGRAPHE000066"></a>

- **geoTrackingProcedure** must be called in the project initialization code. Indeed, the WLanguage procedure can be called just after the initialization, for a clock in background mode for example.

- If the application is in stand-by mode, it is automatically restarted when a location is received.

- ![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png)![IOS Widget](https://doc.pcsoft.fr/ext/images/us/WIDGETIOS.png)![Mac Catalyst](https://doc.pcsoft.fr/ext/images/us/CATALYST.png) **geoTrackingProcedure** can be used in the background. It is recommended not to access the interface or open windows in the WLanguage procedure, since iOS does not allow accessing the interface when the application is in the background. 



<a name="NOTE0_2"></a>


### Low location accuracy
<a name="low_location_accuracy_ELTPARAGRAPHE000081"></a>

Caution: Low precision tracking. The events are sent only if significant changes of location occur and at time intervals exceeding several minutes. For information, the sending conditions per platform are as follows: 

- ![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png)![IOS Widget](https://doc.pcsoft.fr/ext/images/us/WIDGETIOS.png)![Mac Catalyst](https://doc.pcsoft.fr/ext/images/us/CATALYST.png) The events regarding the change of location are not sent if the location did not change by more than 500 meters, or if the time interval is less than 5 minutes (December 2014). 

- ![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png) Location change events are sent at intervals that range from 30 seconds to 10 minutes, depending on the distance between locations.


For a more precise tracking, you must use [GPSFollowMovement](../WDLang3/1000019206.md). However, this function: 

- requires the application to be started,

- ![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png) requires the application to be in the foreground,

- consumes more battery.
