


## HTTP server response procedure parameters



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
WLanguage procedure ("callback") called by [HTTPSend](../WDLang3/1000021183.md) or [HTTPSendAsynchronous](../WDLang3/1410091208.md) when the HTTP server responds. 
<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
cMyRequest is httpRequest
cMyRequest.URL = "http://www.mysite.com/api/streamdata"
cMyRequest.ProcedureHeader = Procedure(cMyHeader is httpResponse) {
	IF cMyHeader.StatusCode = 200 THEN Trace("Request sent.")
}
cMyRequest.ProcedureData = Procedure(bufChunk is Buffer) {
	Trace("Processing [%size(bufChunk)%] bytes of data")
}
INTERNAL PROCEDURE procEnd(cMyResponse is httpResponse)
	Trace("HTTP request completed")
END
HTTPSendAsynchronous(cMyRequest, procEnd)
```

<a name="XSYNTAXE"></a>

## Syntax
<a name="SYNTAXE1"></a>

`SendAsynchronous_Callback(<Response>)`
---

**`<Response>: (httpResponse variable)`**

[httpResponse](../WDLang3/1000021165.md) variable containing the response received from the HTTP server.

## Remarks


### Error handling
<a name="error_handling_ELTPARAGRAPHE000039"></a>

To handle errors in this procedure:

- The [ErrorOccurred](../WDLang1/3087001.md) variable and the [ErrorInfo](../WDLang1/3013008.md) function can be used to determine if the server is unreachable.  

- The **StatusCode** property of the [httpResponse](../WDLang3/1000021165.md) variable is used to get the server's response and detect any errors. By default, 200 indicates that the request has been accepted. Other HTTP codes will indicate errors, if any.





### Chunked mode: Query response is retrieved in chunks
<a name="chunked_mode_query_response_retrieved_chunks_ELTPARAGRAPHE000056"></a>

If the HTTP server returns a chunked request, it is possible to define how to retrieve the data by specifying the following in the httpRequest variable:

- A procedure to read the header (**ProcedureHeader** property). 

- A procedure to retrieve the data (**ProcedureData** property). 




In this case, the callback procedure called by [HTTPSend](../WDLang3/1000021183.md) or [HTTPSendAsynchronous](../WDLang3/1410091208.md) retrieves the server's response via a variable of type [httpResponse](../WDLang3/1000021165.md). 

Remarks: 

- If the **ProcedureData** property is specified in the request sent, the **httpResponse.Content** property will be empty.

- The header received in this callback can be larger than the one received at the beginning. The header may contain specific information related to the chunked trailer. 





### Security error in a secure transaction
<a name="security_error_secure_transaction_ELTPARAGRAPHE000216"></a>

During a secure transaction, the request may fail due to security errors:

- invalid certificate or certificate issued by an unknown organization.

- the name of the site specified in the certificate does not correspond to a server.

- invalid or expired certificate date.

- redirection to a non-secure server.




These errors are returned by [ErrorInfo](../WDLang1/3013008.md).

If one of these errors occurs, you can re-run the request while ignoring the errors. To do so, simply modify the **IgnoreError** property of the [httpRequest](../WDLang3/1000021158.md) variable:

| Error returned by [ErrorInfo](../WDLang1/3013008.md)<br>  (with the *errCode* constant) |   | Description |
| --- | --- | --- |
| *httpErrorInvalidCertificate*<br>Invalid certificate or certificate coming from an unknown company. | *httpIgnoreInvalidCertificate* | Ignores the certificate. |
| *httpErrorInvalidCertificateName*<br>The site name specified in the certificate does not correspond to a server. | *httpIgnoreInvalidCertificateName* | Ignores the site name specified in the certificate. |
| *httpErrorExpiredCertificate*<br>Invalid or expired certificate date. | *httpIgnoreExpiredCertificate* | Ignores the certificate date. |
|   | *httpIgnoreDeprecated* | Ignores errors related to the use of deprecated algorithms (e.g. SHA-1 certificate signature). |
| *httpErrorRedirectToHTTP*<br>Redirection to a non-secure server. | *httpIgnoreRedirectToHTTP* | The redirection to a non-secure server is allowed. |
| *httpIgnoreRedirectToHTTPS*<br>Redirection to a secure server. | *httpIgnoreRedirectToHTTPS* | The redirection to a secure server is allowed. |
|   | *httpIgnoreUnsafeRenegotiation* | Ignores the error indicating that the server does not support secure renegotiation (RFC 5746). |
|   | *httpIgnoreRevocation* | The certificate found in the list of revoked certificates is not checked. |


Remarks: 

- When the HTTP queries are run in several threads, the **HTTP.IgnoreError** variable has a specific value for each thread.

- ![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![Android Widget ](https://doc.pcsoft.fr/ext/images/us/ANDROIDWIDGET.png) The following errors are handled: *httpIgnoreExpiredCertificate*, *httpIgnoreInvalidCertificate*, *httpIgnoreInvalidCertificateName*, *httpIgnoreRevocation*, *httpIgnoreRedirection*.
