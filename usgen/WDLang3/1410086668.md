## Overview
<a name="overview_ELTTEXTE000246"></a>
The Private Store website allows you to manage the different BaaS aolutions: 

- Private Store. 

- User Groupware. 

- OAuth server. 




The Private Store site can be accessed from any browser, using the following address: http(s)://&lt;PCSCloud server or platform&gt;/WDBaaS".

From this site, users can download and install the various applications available in the Private Store:

- Windows applications,

- Mobile applications,


They can also open websites accessible from the Private Store. 

Users can log in to the Private Store site to access the applications for which they have specific user rights. 

When an administrator logs in to the Private Store, they can access all administration options via the "Administration" button. The administration site contains:

- The Private Store general options, which can be accessed via a menu at the top of the page. General options are organized into different tabs:

	- [Applications](#NOTE2_1),

	- [Users and groups](#NOTE3_1),

	- [OAuth 2.0 server](#NOTE4_1),

	- [SMTP settings](#NOTE5_1),

	- [Options](#NOTE6_1). 




- The different applications in the Private Store, on the left. You can click the name of an application to see its options.

## Applications
<a name="applications_ELTTEXTE000270"></a>
The "Applications" tab allows you to manage all the applications and websites accessible from the Private Store. These applications can use the User Groupware via BaaS solutions. 

**1. Publishing applications in the Private Store** 


- WINDEV applications can be installed in the Private Store via their setup program. 
	For more details, see [Private Store for WINDEV applications](../Editeurs/9000203.md). 

- You can add websites to the portal by clicking the button next to "Applications": ![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Baas_admin_btn.gif). Select "New link to a website". 

- You can add mobile applications to the Private Store by clicking the button next to "Applications" ![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Baas_admin_btn.gif). Select "New mobile application". 




**2. Features for applications in the Private Store**
For applications available in the Private Store, the "Private Store" tab allows you to:

- Define the owner(s). 

- Define keyword(s) to find the application in the Private Store. 

- Get the reference version number of the application and the minimum version required. 
	To force an application update for all users, simply click the triangle icon next to the version number. The triangle turns completely black, indicating that it is the minimum version required. 
	You can also determine if the application has been downloaded.

- Transform a public application into a private application. This allows you to define download rights:

	- Download available to everyone.

	- Download available only to logged-in users.

	- Download available only to some users or groups.




- See the list of available versions, including the one available for download. 




**3. Features for sites in the Private Store**
For sites listed in the Private Store, the "Private Store" tab allows you to:

- Define the owner(s). 

- Define keyword(s) to find the site in the Private Store. 

- Transform a public site into a private site. It is then possible to define the visibility of the site:

	- Everyone can view the site.

	- Only logged-in users can view the site.

	- Only certain users or groups can view the site.








### Applications that use the User Groupware
<a name="applications_that_use_the_user_groupware_ELTPARAGRAPHE000101"></a>

If the application uses the User Groupware via BaaS solutions, other tabs are available:

- Rights management: Allows you to define user and user group rights to various application elements. 

- Statistics: Allows you to view the history of connections to the application for a user or group over a given period. 

- Import: Allows you to import tables from the standard User Groupware into User Groupware BaaS solutions. 

- OAuth / OpenID: Allows you to define the required settings for automated login via Google, Salesforce, Microsoft, etc. For each login mode, you must specify the credentials provided when you registered your application on the chosen platform.

## Users and groups
<a name="users_and_groups_ELTTEXTE000300"></a>
The "Users and groups" tab allows you to define which users can access the Private Store and the available applications. 

You can also manage users programmatically using [WLanguage administration functions](../WDLang3/1410091358.md). The "Enable WLanguage administration functions" link opens the WLanguage functions setup page. 

1. Enter login credentials. These credentials are used to get a Client ID and a Client Secret. 

2. Indicate the permissions to be granted:

	- Create users only. 

	- Read user information only.

	- All (read, create, modify, delete).





The connection code with the identifier created to use WLanguage functions is automatically generated. You can then copy this code into the application that uses WLanguage user management functions.  

Note: These steps allow you to quickly create OAuth 2.0 credentials. Authorizations can also be managed via the "OAuth 2.0 server" tab.

## OAuth 2.0 server
<a name="oauth_20_server_ELTTEXTE000333"></a>
The "OAuth 2.0 server" tab allows you to create OAuth 2.0 credentials and/or APIs for web services.


### Creating OAuth 2.0 credentials
<a name="creating_oauth_20_credentials_ELTPARAGRAPHE000357"></a>

To create OAuth 2.0 credentials: 

1. Click the "Create your first OAuth 2.0 credentials" link (or click the "Add credentials" button in the "OAuth 2.0 credentials" tab if you have already created credentials). 

2. The OAuth 2.0 credential configuration page appears. This page has 2 tabs: 

	- General options: Allows you to define the parameters of the credentials to be created. 

	- Login page: Defines the user login page (when a "User" token is used). 


 By default, new tokens are created as User tokens. They can be transformed into Application tokens.  

3. The characteristics of the credentials are automatically generated in the "General options" tab. These include Client ID, Client Secret and creation date. 

4. Complete the details of the credentials: 

	- Name of credentials. This name will simplify the search in the list of credentials. 

	- Connection authorization. If the credentials are active, they can be used for testing and production purposes

	- One or more redirect URLs. By default: http://localhost:9874

	- Token lifetime (10 days by default). 

	- Optional description. 

	- Indicate whether the new token is a user token or an application token. 
			In the case of a user token, you can define the login page. 

	- Indicate whether SSO is available for these credentials. 




5. Copy the Client ID and Client Secret information, as they will be required in the client application when a token is requested. 

6. Click "Save" to create the credentials. A summary page appears with the various URLs required to request a token from the client application.







### Creating APIs for web services
<a name="creating_apis_for_web_services_ELTPARAGRAPHE000384"></a>

You can associate OAuth credentials with a REST API. To access a REST API, users will need to provide a token. Only a valid token can be used to access the API.

To define APIs for web services: 

1. Click the "Create your first API for web services" link (or click the "Add an API" button in the "APIs for web services" tab if you have already created APIs). 

2. Enter the details of the API entry point: 

	- Name

	- API URL, 

	- Optional description. 




3. Add the necessary scopes. 
	Note: Scopes are described in APIs. They are used to filter functionalities according to the credentials. 

4. Click "Save" to create the API.

5. Click the "OAuth 2.0 credentials" tab. 

6. Edit the OAuth 2.0 credentials you want to associate with the API. 

7. Click the "APIs" tab. 

8. Select the APIs to which the client application will have access. 

9. Click "Save". 







### Scopes
<a name="scopes_ELTPARAGRAPHE000408"></a>

OAuth 2.0 scopes are a mechanism to limit an application's access to a user's account. Applications can request one or multiple "scopes". This information is presented to the user in a consent screen, and the access token issued to the application will be limited to the scopes granted.

By default, the following scopes are supported for connections via OpenID: 

- "openid": verifies user identity. 

- "profile": gets the user's name. 

- "email": gets the user's email address. 


These scopes are returned by [OpenIDReadIdentity](../WDLang3/1000023573.md). 

You can add other scopes. 

You can specify the desired scopes using the **Scope** property of [OpenIDParameters](../WDLang3/1000023561.md) and [OAuth2Parameters](../WDLang3/1000022212.md) variables. The "Source" property of [OpenIDIdentity](../WDLang3/1000023567.md) variables can also be used to get the value of these scopes. Simply search for the value in the corresponding JSON file. 


WDBaaS now includes a new API (web service secured with an OAuth token) for managing users registered on the server.

The configuration of the API (permissions/scopes for adding, editing, deleting, etc. users, etc.) can be easily configured from the WDBaaS administration interface.

To configure this API:

1. Select the "OAuth 2.0 server" tab. 

2. Select the desired OAuth 2.0 credentials. 

3. In the description, select the "APIs" tab. 

4. Edit "User management (administration)". 

5. Specify the user permissions:

	- wdbaas:users:create: Create users. 

	- wdbaas:users:delete: Delete users. 

	- wdbaas:users:read: Read user information. 

	- wdbaas:users:readwrite: Read and write user information. 

	- wdbaas:users:update: Update users. 




6. Confirm. 




Simply provide the client application with the credentials (ClientID and Client Secret) to access the API via the [AuthIdentify](../WDLang3/1000022219.md) WLanguage function.

## Options
<a name="options_ELTTEXTE000488"></a>
The "Options" tab contains all the options for customizing and configuring the Private Store:

- Private Store page: You can customize the Private Store label, which appears in the site banner (default label: "Application catalog"). You can also display a "Featured applications" section. 

- Add Windows applications: Allows or prevents users from adding applications to Private Store (you can also configure this option for each user).

- Automatically delete old application versions: Allows you to specify the maximum number of versions to keep. 

- Proxy (optional): Allows you to specify a URL to generate download QRCodes. 

- Manage user accounts: Allows you to specify account creation rights (all users, none or only some users). Users can also come from an LDAP directory (via a secure connection if required).

- User activation mode: Accounts can be activated automatically or by email.

- Two-factor authentication: Two-factor authentication can be mandatory or be enabled by the user. You can create a message prompting the user to contact an administrator if they cannot get the code.

- reCAPTCHA key: Allows you to specify the reCAPTCHA v3 details (available in Google's Admin console).

- Reset User Groupware and Private Store connection token for development environment: When the Application Server was installed, a connection token was supplied. You can generate this token again in case of loss.
