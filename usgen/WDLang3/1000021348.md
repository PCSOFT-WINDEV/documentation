
## CheckUserIDentity (Function)

***In french: VérifieIdentitéUtilisateur***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Checks the identity of the current user using biometric authentication.

If the authentication is available, a message asks the user to log in. Then, the WLanguage authentication procedure is called.

**Note**: This function only verifies the user's identity via the data stored on the mobile phone. It is not possible to capture the user's fingerprint. 

**Remarks**: 

- ![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png)![IOS Widget](https://doc.pcsoft.fr/ext/images/us/WIDGETIOS.png)![Mac Catalyst](https://doc.pcsoft.fr/ext/images/us/CATALYST.png) This function is available from iOS version 8.0. The project must be compiled with Xcode 6 (or later). This function is using: 

	- the "Touch ID" feature of iPhones 5S and later versions. 

	- the "Facial recognition" feature of iPhone X.




- ![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png) This feature is available from Android 6.0 (api level 23).

## Example


```wl
CheckUserIDentity("Check the identity for unlocking", Authentication)

	// Check procedure
	INTERNAL PROCEDURE Authentication(nStatus is int, sErrorMessage is string)
		
		SWITCH nStatus
			CASE cuiAuthenticated
				// Authentication OK.
			CASE cuiAuthenticationFailure		
				Error("Authentication failed: " + sErrorMessage)
				// Try again.
				CheckUserIDentity("Check the identity for unlocking", Authentication)		
			CASE cuiCustomAuthentication,cuiAuthenticationUnavailable				
				// Password required in this case.
				pwd is string
				SWITCH Input("Enter your password: ", pwd)
					CASE 1: // OK
						IF pwd ="1234" THEN
							// Authentication OK.
						ELSE
							Error("Incorrect password")
							// Try again.
							CheckUserIDentity("Check the identity for unlocking", Authentication)
						END
					CASE 0: // Cancel
						Close()
				END
		END
	END
```

## Syntax
<a name="SYNTAXE1"></a>

`CheckUserIDentity(<Message> , <WLanguage procedure> [, <Button caption>])`
---

**`<Message>: (Character string)`**

Message that will be displayed to the user. 
![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png)![IOS Widget](https://doc.pcsoft.fr/ext/images/us/WIDGETIOS.png)![Mac Catalyst](https://doc.pcsoft.fr/ext/images/us/CATALYST.png) 

- If this string is a multiline string, only the first line will be visible in the authentication popup.

- This parameter is ignored during a facial recognition.




**`<WLanguage procedure>: (Procedure name)`**

Name of the WLanguage procedure ("callback") called once the user authentication is complete. This procedure has the following format:

```txt
PROCEDURE <Procedure name> (<Status>, <Error message>)
```


where: 

- &lt;Status&gt; is an integer constant indicating the authentication status:
	


|   |   |
| --- | --- |
| *cuiAuthenticated* | The user has successfully authenticated. |
| *cuiAuthenticationFailure* | Authentication failed. |
| *cuiAuthenticationUnavailable* | Authentication is not available or was disabled by the user. |
| *cuiCustomAuthentication* | The user has requested authentication using a password. The application must implement a manual authentication process |



- &lt;Error message&gt; is a character string containing the system error message in case of authentication failure (*cuiAuthenticationFailure* constant). Otherwise, this parameter corresponds to an empty string.




**`<Button caption>: (Optional character string)`**

Default caption of the authentication button (displayed on the password entry button). This button is used to log in without biometric verification. This button is displayed as soon as the first failure occurs.

### Application in the background: Specific case from Android 10
<a name="application_the_background_specific_case_from_android_10_ELTPARAGRAPHE000216"></a>

Starting with Android 10, it is no longer possible to open a window when the application is in the background. 

**CheckUserIDentity** can open a window. If this function is used while the application is in the background, a fatal error will occur. 

Tips: 

- It is possible to determine if the application is in the background using [InBackgroundMode](../WDLang1/1000023457.md). 

- If an application needs to interact with the user while it is in the background, the solution is to display a notification (via the [Notification](../WDLang3/1000019441.md) type). The application will be brought back to the foreground when the notification is clicked, if the **ActivateApplication** property is set to <u><u><u><u>True</u></u></u></u>. You can also open a window from the procedure passed to the **ActionClick** property.




For more details, see [Android 10: Behavior of applications in the background](../Editeurs/9000195.md).
