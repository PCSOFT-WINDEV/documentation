


## FTPDeleteFile (Function)

***In french: FTPSupprimeFichier***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Deletes a file from an FTP server (File Transfer Protocol).


<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example
<a class="notetitle" target="_blank" href="$DOC$=1000003040010&name=ftpdeletefile_function">See additional examples</a>

```wl
// Connect the current computer to the FTP server
ConnectionNumber = FTPConnect("192.54.12.8")

// Delete the "/Documents/File.DOC" file from the FTP server
ResDelete = FTPDeleteFile(ConnectionNumber, "/Documents/Files.DOC")
```

## Syntax

`<Result> = FTPDeleteFile(<FTP connection> , <File to delete>)`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the file was deleted,

- <u><u><u><u>False</u></u></u></u> otherwise. To get more details on the error, use [ErrorInfo](../WDLang1/3013008.md) with the *errMessage* constant.




**`<FTP connection>: (Integer or ftpConnection variable)`**



- Connection identifier, returned by [FTPConnect](../WDLang3/3040016.md).
	![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png) This parameter is a Variant parameter.

- Name of the [ftpConnection](../WDLang3/1410090869.md) variable that corresponds to the FTP connection used.
	

![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png) Not available.




**`<File to delete>: (Character string)`**

Name and full or relative path of the file to be deleted. The different parts of the path are separated by "slashes" ("/").

## Remarks
<a name="NOTE0_2"></a>


### Timeout
<a name="timeout_ELTPARAGRAPHE000296"></a>

By default, all the FTP functions fail if the FTP server does not respond within 20 seconds. This time can be modified: 

- when connecting to the FTP server with [FTPConnect](../WDLang3/3040016.md) (&lt;Timeout&gt; parameter).

- when defining the parameters of the [ftpConnection](../WDLang3/1410090869.md) variable (**Timeout** property).
	



<a name="NOTE0_4"></a>


### Rights of users
<a name="rights_users_ELTPARAGRAPHE000336"></a>

Only a user who has read rights on the FTP server can get information about the files or the directories located on an FTP server. In most cases, the read rights are granted to the "anonymous" users.
<a name="NOTE0_5"></a>


### Relative and absolute path
<a name="relative_and_absolute_path_ELTPARAGRAPHE000346"></a>

The notions of relative path and absolute path are very important in an FTP application.

- A path beginning with a slash is considered an **absolute path**. This path is relative to the root of the FTP server (server-specific parameter).
	ex: /pub/user/JULIA

- If the path does not begin with a slash, it is considered a **relative path**, i.e. the path relative to the current directory. This current directory can be obtained or changed using [FTPCurrentDir](../WDLang3/3040003.md).




When connecting to an FTP site, the initial directory (the "base directory" of the user) is not necessarily found at the root of the FTP server. Therefore, we recommend that you use relative paths.
