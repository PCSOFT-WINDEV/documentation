


## inAppListPurchase (Function)

***In french: inAppListeAchat***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Returns the list: 

- of application products purchased by the user and not consumed.

- of active subscriptions for the user.




![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png) This function is now available for iPhone/iPad applications.
<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
// Retrieve the list of purchases for the user 
inAppListPurchase(ListPurchase, inAppPurchaseID)
```

```wl
PROCEDURE ListPurchase(bSuccess is boolean, sPurchaseList is string)
	IF NOT bSuccess THEN
		ToastDisplay(ErrorInfo())
	ELSE
		// Browses the purchases performed
		FOR EACH STRING sPurchaseInfo OF sPurchaseList SEPARATED BY CR
			// Retrieves the product identifier
			sProductID is string = ExtractString(sPurchaseInfo, 1, TAB)
			// Retrieves the purchase identifier
			sPurchaseID is string = ExtractString(sPurchaseInfo, 2, TAB)
			// Consumes the product if necessary
			IF sProductID = "PRODUCT_ID" THEN
				inAppConsumeProduct(sProductID, ConsumeProduct)	
			END
		END
	END
END
```

```wl
PROCEDURE ConsumeProduct(nSuccess is boolean)
	IF NOT bSuccess THEN
		ToastDisplay(ErrorInfo())
	ELSE
		// Consume the product in the application
		...
	END
END
```

## Syntax
<a name="SYNTAXE1"></a>

`<Result> = inAppListPurchase(<Procedure> [, <Type of information>])`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the purchase list retrieval request has been carried out,

- <u><u><u><u>False</u></u></u></u> otherwise. To get more details on the error, use [ErrorInfo](../WDLang1/3013008.md).




**`<Procedure>: (Character string)`**

Name of the WLanguage procedure ("callback") executed when the list of purchases is received. For more details on this procedure, see [Parameters of the procedure used by inAppListPurchase](../WDLang3/1000024809.md). 

**`<Type of information>: (Optional Integer constant)`**

Additional information that will be returned for each listed purchase (in addition to the product identifier): 


|   |   |
| --- | --- |
| *inAppAutoRenewal* | <br><br>- 1 if the subscription is automatically renewed at the next invoicing date. <br><br>- 0 if the subscription was canceled by the user or if the purchase does not correspond to a subscription. <br><br><br>![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png) Information not available. Always corresponds to 0. |
| *inAppOrderID* | Number of the order corresponding to the purchase. |
| *inAppPurchaseDate* | Purchase date in YYYYMMDD format.<br><br>In the case of a subscription: subscription date.<br>For renewals: initial subscription date (not renewal date).  |
| *inAppPurchaseID* | Identifier of purchase. <br><br>![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png) This identifier is used in [inAppConsumeProduct](../WDLang3/1000020880.md) to consume a product that was purchased.<br><br>![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png) This identifier has the same value as the one obtained with the *inAppOrderID* constant. |
| *inAppSubscriptionEndDate* | End date of subscription in YYYYMMDD format.<br><br>![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png) Information not available. Always corresponds to empty string ("").<br> If the subscription was canceled by the user, this subscription will be listed by **inAppListPurchase** until the next invoicing date and the access to the subscription will be lost at this time (see [Managing subscriptions](#NOTE0_2)). |

## Remarks


### Special cases
<a name="special_cases_ELTPARAGRAPHE000124"></a>

- ![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png) When a product is consumed ([inAppConsumeProduct](../WDLang3/1000020880.md)), it is no longer displayed in the list returned by **inAppListPurchase** and it can be purchased again by the user ([inAppPurchaseProduct](../WDLang3/1000020873.md)).

- **inAppListPurchase** has no effect if it is run from the simulator or emulator.


![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png) At consumable product is always consumed when it is purchased and therefore if will never appear in the result of **inAppListPurchase**.
<a name="NOTE0_2"></a>


### Managing subscriptions
<a name="managing_subscriptions_ELTPARAGRAPHE000152"></a>

![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png) In Android: 

- If a subscription is listed by **inAppListPurchase**, the user must be able to access the subscription content. 

- If the subscription was canceled by the user, this subscription will be listed by **inAppListPurchase** until the next invoicing date and the access to the subscription will be lost at this time. You can allow the user to renew his subscription from the application ([inAppPurchaseProduct](../WDLang3/1000020873.md)).


![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png) In iOS: 

- The subscription is valid between the purchase date and the end date of subscription. 

- An expired subscription can be returned by **inAppListPurchase**. It is up to the application to decide which content remains accessible at the end of a subscription.
