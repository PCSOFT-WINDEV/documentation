
## Deployment via physical media (DVD, etc.)
			

<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000426"></a>
To deploy a WEBDEV website or a SOAP/REST web service via physical media, you must: 

- Step 1: Check the server configuration.

- Step 2: Install the WEBDEV site on the server.

- Step 3: Configure the access rights on the server.




<a name="NOTE2"></a>
<a name="NOTE2_1"></a>


## Step 1: Check server configuration
<a name="step_1_check_server_configuration_ELTTEXTE000450"></a>
**To install a site developed with WEBDEV on an Internet server** (at a hosting provider for example), the following elements must be installed on the server:

- a Windows 32-bit or 64-bit operating system (a Server version is recommended).

- the TCP/IP network protocol.

- a Web server, used to make the WEBDEV websites accessible. If no Web server is installed, the setup by physical media can automatically install the Apache server (if this one was included when creating the setup on the development computer).

- the WEBDEV 2026 application server. If the application server is not found, the setup by physical media can automatically install an application server limited to 10 connections (if this one was included when creating the setup on the development computer).




To get fast response time, a powerful computer must be used for the Internet server.

**To avoid a drop in the system performance**, the total number of connections to all dynamic WEBDEV websites or to a dynamic WEBDEV website must be limited:

- by the site developer, in the WEBDEV website programmatically.

- by the server administrator in the different local or remote administration tools provided with WEBDEV 2026 application server.

- by the site manager, in the remote WEBDEV administrator.

## Step 2: Installing a dynamic WEBDEV site by physical media (Windows server only)
<a name="step_2_installing_dynamic_webdev_site_physical_media_windows_server_only_ELTTEXTE000474"></a>
To install a dynamic WEBDEV website on a Web server:

1. Run **INSTALL.EXE** (supplied with the site setup) on the Web server.
	**Important** If you are updating an existing site, you must first:

	- block the site via the WEBDEV administrator. Uncheck "Enabled" in the "Sites" tab.

	- disconnect all Web users from the site.


[Special Case: a WEBDEV site with the same name is already installed on the server](../WDAdminDeploiement/3539055.md)

2. Choose the setup language: a setup wizard launches. Click "Next" to continue.
	Note: The setup language only affects the setup wizard (it does not affect the site installed).

3. Select the WEBDEV account that will be associated with the site. If no account is suitable, create a new account ("WEBDEV account" button).

4. The setup automatically detects whether one or more of the following **Internet servers** are installed on the computer:

	- **IIS Version 7 to 10 (Microsoft Internet Information Server)**: Microsoft server supplied with Windows and Windows Server.

	- **Apache Version 2.x** free Web server provided by the Apache Software Foundation.


 Three cases may occur:

- **Case 1: your Web server does not appear in this list**: select "Other server".. You will have to configure the server manually.

- **Case 2: your Web server appears in the list but grayed out**: this means it has not been detected (rare case). You will have to configure the server manually.

- **Case 3: Your web server can be selected directly**. In this case, select your server.
			You can request the generation of a configuration file so that you can run the configuration later. The configuration file can be modified before it is run. Depending on the selected server, the extension of configuration file will be .reg, .conf or something else.

5. Select the installation directory:

	- for the files of the site: HTML pages, ...

	- for the tables of the site


 The paths corresponding to the selected WEBDEV account are automatically proposed:

- **&lt;site&gt;** corresponds to the website installation directory defined in the account.

- **&lt;webservice&gt;** corresponds to the SOAP web service installation directory defined in the account.

- **&lt;rest&gt;** corresponds to the REST web service installation directory defined in the account.

- **&lt;data&gt;** corresponds to the data file installation directory defined in the account.

- **&lt;webroot&gt;** indicates the root directory of the computer's web server. Depending on the selected web server, the root directory is detected and displayed. If the root directory of the web server does not appear, you can type it in the gray area or find it via the "…" button.
			**Caution**: If the area is already filled, don't make any changes.

6. Choose to generate the statistical files. If this option is selected, the site manager or the web service manager will be able to directly see the traffic statistics regarding the site or the SOAP/REST web service. In this case, specify the directory for generating the statistical file. The default directory is a subdirectory of the directory that contains the tables of the website or web service.
	**Note**: This option can also be modified directly in the WEBDEV administrator or in the remote administrator.

7. Update tables (optional step, for a site update only).
	To update the tables associated with the WEBDEV website or with the web service, choose to run the automatic modification of tables.
	Contact the site or web service provider if you don't know whether this update must be performed or not.
	**Warning** no site or web service using these tables should be running. Use the WEBDEV administrator to check that no connection is in progress and stop the sites: uncheck "Enabled" in the "Sites" tab (or "Enabled" in the "Webservices" tab).

8. For a site: specify the URL (Internet address) where the site is available in order to build the SiteMap file. This file is used by the search engines to better reference your site. The address to specify is the home address of your site.
	For example: if your site is available at "http://www.monsite.fr/index.awp", you should enter www.monsite.fr as the search Engine Optimization URL.
	For a web service: specify the URL (Internet address) where the web service file (.AWWS file) is accessible. This address will be used to build the web service import file (WDSL file) required to import your web service into a project in order to use it.

9. If your site uses the "User Groupware" feature, you can specify the location of the tables used. For more details, see the WEBDEV documentation

10. Install an ODBC driver for HFSQL if programs not developed with WEBDEV must access the HFSQL tables of the site that will be installed (optional step).

11. The setup summary is displayed:

	- Click "Previous" if you want to modify some options.

	- Click "Next" to start the setup.




12. The setup is completed:

	- Click on the suggested address to test the WEBDEV website locally. This option can be used only if the web server was automatically configured. The "Clipboard" option is used to retrieve this address.

	- Click "Finish" to exit the setup.




13. **Web server configuration** If the Web server has not been configured automatically, there are two possible scenarios:

	- Case 1: Your server has been detected and a configuration file has been generated. You can view, edit and run this file.

	- Case 2: your server has not been detected: consult [configuration of Web servers](../WDAdminDeploiement/3539043.md).




14. Unlock the sites that may be locked via the WEBDEV administrator.

15. Test WEBDEV website from the WEBDEV administrator with the "Test page" option ("Advanced" tab) or by using the link supplied at the end of setup.
	**Note** WEBDEV administrator (WD310ADMIN.EXE) must be running in the background at all times. It can be installed as service. For more details about the local WEBDEV administration tool, see "[WEBDEV administrator](../WDAdmin/3539021.md)".

## Step 3: Configure the access rights on the server
<a name="step_3_configure_the_access_rights_the_server_ELTTEXTE000498"></a>


### Overview
<a name="overview_ELTPARAGRAPHE000130"></a>

If you are using a NTFS file system, you must configure the access rights to the server in order to use a WEBDEV website or a web service. These access rights are used to grant specific authorizations: authorization to write into the file transfer directory, ...

Reminder: Access rights are configured automatically via WEBDEV Account Manager.

**Attention** Although WEBDEV 2026 will assist you as best it can, remote installation requires "expert" level server configuration. This area is NOT directly related to WEBDEV. These settings cannot be defined by a novice.

You must have a minimum knowledge of this area or have knowledgeable help.



If you want to use these advanced features, plan to spend the required time for installing them and for configuring them. This setting depends on several parameters not related to PC SOFT and to WEBDEV.




### Access rights required to use a WEBDEV website or a SOAP/REST web service
<a name="access_rights_required_use_webdev_website_soaprest_web_service_ELTPARAGRAPHE000150"></a>

The access rights are configured in relation to the Windows account that is running the AWP manager.

In Windows, it is in most cases the "Internet guest" account named IUSR_ComputerName.

In Linux, it is the account that owns the library (.WDL file for a dynamic WEBDEV website or for a REST web service, .AWP file for an AWP site and .AWWS file for a SOAP web service).

This account must be able to:

- Read files from the site or web service directory (SOAP or REST).

- Read and write to the site or web service data directory (SOAP or REST).




To identify the Windows account that runs the AWP protocol, see [Identifying the account that runs the AWP protocol](../NonDocumente/3539022.md).




### Summary table about the necessary rights
<a name="summary_table_about_the_necessary_rights_ELTPARAGRAPHE000170"></a>

The following user groups are used in this table:

- WWUSR: Group of WEBDEV users (It is the set of Windows/Linux accounts used for FTP)

- IUSR: Group of anonymous Internet users (it is the set of accounts running the AWP protocol on each virtual server of computer). For example: on a Windows computer running IIS with a single virtual server, it is the IUSR_ComputerName account.

- LOGIN: a member of the WWUSR group.




**NTFS rights**

| Directory | User | Necessary rights |
| --- | --- | --- |
| WEBDEV directory | WWUSR and IUSR  | Read + Execution |
| Subdirectory of account files | WWUSR | Read + Write |
|   | IUSR | Read |
| AWP subdirectory | WWUSR and IUSR | Read + Execution |
| FTP directory of LOGIN user | LOGIN | Full control |
| Directory of sites and web services of LOGIN user | LOGIN | Full control |
|   | IUSR | Read + List |
| Data directory of LOGIN user | LOGIN | Full control |
|   | IUSR | Read + Write + List |
| Temporary directory of system | WWUSR and IUSR | Read + Write + List + Modification |
| File of the metabase (c:\\winnt\\system32\\inetserv\\metabase.bin) | WWUSR | Read + Write |
|   | IUSR | Read |
| Directory of SaaS data | IUSR | Read + Write |
