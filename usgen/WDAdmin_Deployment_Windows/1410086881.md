
## Creating/Configuring a WEBDEV deployment account 
			

<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000162"></a>
We recommend that you use WEBDEV Account Manager to create and configure a WEBDEV account, especially in a configuration of the following type:

- Windows Server 2008/2012/2022,

- IIS Web server, 

- IIS FTP server.




This is recommended especially for shared hosting or for hosting that requires multiple WEBDEV accounts.

When the WEBDEV Application Server is installed, a Windows account is created or defined as administrator of the WEBDEV Application Server. This user has all the rights (administration, deployment, statistics).

To configure the different characteristics of this user or define a specific user to deploy your websites, use WEBDEV Account Manager.

WEBDEV Account Manager automatically performs the following configuration tasks: 

- Creating a deployment account. 

- Creating the different directories (folders) used to host the deployed elements.

- Assigning the necessary rights to the created account on the created directories.

- Creating a new specific virtual Web server (optional).

- Creation of an FTP alias (for an installation via FTP).




If you do not use IIS as a Web server, WEBDEV Account Manager will not perform all the necessary steps, you will need to define some settings manually.

## Using WEBDEV Account Manager

### Configuring WEBDEV Account Manager
<a name="configuring_webdev_account_manager_ELTPARAGRAPHE000036"></a>

First, you need to configure WEBDEV Account Manager. Here is a typical configuration example:

**Directory configuration**
In the "Hosting parameters" group, **click on "Directories "**: <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Configuration%20CCH%E9bergement%20Livre%20-%20HC%20N%B0001.gif&type=thumb)


- The directory containing all the elements deployed by WEBDEV sites: "C:\\Hébergement WEBDEV\\".. There will be one subdirectory per WEBDEV account and another subdirectory per site. Example: "C:\\WEBDEV hosting\\USER_WEBDEV\\".

- The name of the subdirectory for dynamic sites (corresponds to fRepExe() when running a site): **"sites "**. This directory will contain the libraries (.wdl) of the sites, the _WEB sub-directories, the .awl, .awp pages, ... There will be one subdirectory per site. Example: "C:\\WEBDEV hosting\\USER_WEBDEV\\sites\\FirstWEBDEVSite\\".

- SOAP Webservices subdirectory name (corresponds to fRepExe() when running a WebserviceSOAP): **"WebservicesSOAP "**. This directory will contain the SOAP web services (.awws). There will be one subdirectory per web service. Example: "C:\\WEBDEV hosting\\USER_WEBDEV\\SOAPwebservice\\FirstSOAPWebService\\".

- REST Webservices subdirectory name (corresponds to fRepExe() when running a REST Webservice): **"WebservicesREST "**. This directory will contain the REST web services (.WDL). There will be one subdirectory per web service. Example: "C:\\WEBDEV hosting\\USER_WEBDEV\\RESTwebservice\\FirstRESTWebService\\".

- The name of the data subdirectory (corresponds to fRepDonnées() at runtime): **"Data "**
	This is the directory in which HFSQL Classic (.fic) data files, .ini files, PDF files, etc. will be stored. There will be one subdirectory for each site and/or web service.. Example: "C:\\WEBDEV hosting\\USER_WEBDEV\\Data\\FirstWEBDEVSite\\".

- The name of the subdirectory for static sites: **"wwwroot "**
	This directory will be set as the root of the website, the root of the virtual website. 


With the above-mentioned parameters, all elements of a WEBDEV user "USER_WEBDEV" with a base folder "C:\\WEBDEV Hosting\\" will be deployed in a tree structure such as: <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Deploie_win_Hebergement2.gif&type=thumb)


Click the "Apply" button to save the modifications.

**OS accounts**
In the "Hosting parameters" group, click "OS accounts". <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Configuration%20CCH%E9bergement%20Livre%20-%20HC%20N%B0002.gif&type=thumb)


- Specify: 

	- The group of Windows accounts that will be used for administration purposes, and to perform the installations, including the FTP installation, if necessary

	- The group of Windows accounts in which the sites will operate: (Guests) 




- Click the "Apply" button found at the bottom of window to save the modifications.




**Account limits**
You can set two limits on a user account:

- the maximum number of connections assigned to the account. This number of connections must be distributed between the different WEBDEV sites of the account.

- the number of sites associated with an account.




To set the limits: 

- In the "Hosting parameters" group, click "Limits": <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=P6_Configuration%20CCH%E9bergement%20-%20HC%20N%B0003.jpg&type=thumb)


- Specify:

	- The maximum number of connections that will be shared between sites (0 = unlimited),

	- If the number of sites associated with an account must be limited, etc.





Click "Apply" at the bottom of the window to save the changes.

### Creating a deployment account with WEBDEV Account Manager
<a name="creating_deployment_account_with_webdev_account_manager_ELTPARAGRAPHE000094"></a>

To create a deployment account in WEBDEV Account Manager:

1. Open WEBDEV Account Manager from the Windows Start menu.

2. In the "Users" group, click "New user". The user creation wizard starts. Simply follow the different steps.
	Note: If necessary, WEBDEV Account Manager will prompt you to define an administration group. In this example, answer "Yes" to the question "Continue without this group?". 

3. You can: 

	- Create a Windows account. This account will be used for deploying and configuring your websites. 

	- Use an existing Windows account. 




4. If you are creating a Windows account, enter the username and password (you can also generate the password. In this case, don't forget to write it down!).<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=P6_Configuration%20CCH%E9bergement%20-%20HC%20N%B0005.jpg&type=thumb)
Proceed to the next step of the wizard.

5. The wizard prompts you to select the specific WEBDEV options associated with the account: <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=P6_Configuration%20CCH%E9bergement%20-%20HC%20N%B0006.jpg&type=thumb)
The (optional) options are: 

	- This account is a WEBDEV administrator account. It will make it possible to configure other user accounts via the remote administrator.

	- Leave account inactive when created. In this case, this account cannot be used to deploy or update sites. Likewise, this account won't allow you to use the remote administrator. 




6. Go to the next step.

7. The wizard suggests a Windows account to run the applications. Proceed to the next step of the wizard. 

8. Enter the user details. Go to the next step.

9. The directories of the user account are defined automatically according to the data specified in the server configuration.<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=P6_Configuration%20CCH%E9bergement%20-%20HC%20N%B0008.jpg&type=thumb)


10. Go to the next step.

11. Specify the maximum number of connections allowed for the account and, if necessary, the maximum number of sites that can be installed.

12. Select or specify the parameters of the HFSQL Client/Server server that must be associated with the user account.

13. The next step of the wizard includes virtual websites. 

	- If you choose to create a new virtual website, simply enter the DNS name that will point to this site (the DNS must also be configured).

	- If you choose to use an existing virtual website, its configuration will be replaced.
			Note: The root directory of the virtual site will change. If sites (developed in WEBDEV or not) are already operating on this same virtual Web server, they may be impacted. You may have to restore the initial root directory (c:\\inetpub\\wwwroot\\ by default).




14. Go to the next step.

15. In this step you can specify whether FTP access and deployment should be allowed for the user. This step is not necessary for HTTP deployments. 

16. Go to the next step.

17. The wizard is finished. Check all choices. You can uncheck the operations you don't want the wizard to perform for you.

18. Finish the wizard. Your server is now ready to receive WEBDEV websites.

## Special case
<a name="special_case_ELTTEXTE000255"></a>


### Linux server
<a name="linux_server_ELTPARAGRAPHE000105"></a>

When using a Linux server, it is necessary to: 

1. Create a WEBDEV user account with the WEBDEV Account Manager.

2. Associate the WEBDEV user account with an existing system account of the same name via the Remote WEBDEV administrator.





### Apache server on Windows
<a name="apache_server_windows_ELTPARAGRAPHE000113"></a>

When using an Apache server on Windows, it is necessary to create a WEBDEV user account with WEBDEV Account Manager.
