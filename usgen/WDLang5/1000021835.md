


## FBStartSession (Function)

***In french: FBOuvreSession***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Used to authenticate and log in to Faceboook.

![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png)![IOS Widget](https://doc.pcsoft.fr/ext/images/us/WIDGETIOS.png)![Mac Catalyst](https://doc.pcsoft.fr/ext/images/us/CATALYST.png) This function is not available in the simulator.

![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png) **Note**: This feature is available up to Android 11. Starting with Android 12, this function causes a fatal error. 
We advise you to: 

- use [SysAndroidVersion](../WDLang1/1000019785.md) to test the Android version used.

- use [AuthIdentify](../WDLang3/1000022219.md) to manage Facebook authentication.

## Example


```wl
MySession is fbSession
MySession.AppID = "1702546803104741"
MySession.AppSecret = "badf00ddeadbeefbadc0deoff1ce8ecd"
MySession.Permission = [fbInfoProfile, fbEmail]
IF FBStartSession(MySession) THEN
	Info("Connected")
END
```

### Asynchronous authentication

`FBStartSession(<Session> , <WLanguage procedure>)`
---

**`<Session>: (fbSession variable)`**

Name of the [fbSession](../WDLang5/1000021851.md) variable corresponding to the connection to initialize. 

**`<WLanguage procedure>: (Procedure name)`**

Name of the WLanguage procedure ("callback") called during the connection. This procedure has the following format: 

```txt
<Procedure name>(Connection, Session)
```
 where: 

- &lt;Connection&gt; is set to: 

	- <u><u><u><u>True</u></u></u></u> if the connection was established,

	- <u><u><u><u>False</u></u></u></u> otherwise. 




- &lt;Session&gt; is a variable of type [fbSession](../WDLang5/1000021851.md) that corresponds to the initialized connection.

## Remarks


### Starting the session
<a name="starting_the_session_ELTPARAGRAPHE000125"></a>

- **FBStartSession** authenticates users on a Facebook server. This function initializes the connection with the server and must be called before any interaction with Facebook.

- ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) A login window appears automatically.

- ![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png)![IOS Widget](https://doc.pcsoft.fr/ext/images/us/WIDGETIOS.png)![Mac Catalyst](https://doc.pcsoft.fr/ext/images/us/CATALYST.png) The function uses the Facebook account entered by the user on the phone (if it is specified). 

- ![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png) A single session can be started at a time. If **FBStartSession** is called while a session is already open, the previous session will be closed.

- The **FBStartSession** function must only be called from the main the thread of the application.



<a name="NOTE0_2"></a>
![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png) 

### Characteristics of the session
<a name="characteristics_the_session_ELTPARAGRAPHE000152"></a>

The "public_profile" permission is always required when starting a Facebook session. If this permission was not specified in the list of permissions for the [fbSession](../WDLang5/1000021851.md) variable passed as parameter to **FBStartSession**, it will be automatically requested.
<a name="NOTE0_3"></a>


### Closing the session
<a name="closing_the_session_ELTPARAGRAPHE000166"></a>

An open Facebook session is persistent and will remain open:

- until the application is closed. 

- until [FBStopSession](../WDLang5/1000021836.md) is called.



<a name="NOTE0_4"></a>
![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) 

### Incompatibility between the IE ActiveX (and oAuth2) and the use .NET assemblies
<a name="incompatibility_between_the_activex_and_oauth2_and_the_use_net_assemblies_ELTPARAGRAPHE000184"></a>

When an HTML control is used in WINDEV, this control uses the "Microsoft Web browser" ActiveX system. ActiveX is also used by WINDEV for all OAuth2 authentications (Facebook, Twitter, Google, etc.) that require a validation for the connection via HTML code.

If you use an HTML control (or OAuth2 authentication) and a ".Net" assembly in the same project, you may encounter a compatibility issue between Microsoft .NET layers and the ActiveX framework.

An API can be used to manage both technologies. To do so, write the following line of code in the initialization code of the project or in the initialization code of a class or global procedure if the ".Net" object is initialized in a class or in a set of procedures:


```wl
// Used to manage the cohabitation between IE ActiveX and .NET
API("OLE32", "CoInitializeEx", Null, 2)
```

### Application in the background: Specific case from Android 10
<a name="application_the_background_specific_case_from_android_10_ELTPARAGRAPHE000351"></a>

Starting with Android 10, it is no longer possible to open a window when the application is in the background. 

**FBStartSession** can open a window. If this function is used while the application is in the background, a fatal error will occur. 

Tips: 

- It is possible to determine if the application is in the background using [InBackgroundMode](../WDLang1/1000023457.md). 

- If an application needs to interact with the user while it is in the background, the solution is to display a notification (via the [Notification](../WDLang3/1000019441.md) type). The application will be brought back to the foreground when the notification is clicked, if the **ActivateApplication** property is set to <u><u><u><u>True</u></u></u></u>. You can also open a window from the procedure passed to the **ActionClick** property.




For more details, see [Android 10: Behavior of applications in the background](../Editeurs/9000195.md).
