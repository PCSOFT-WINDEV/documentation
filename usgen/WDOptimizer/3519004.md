


## WDOptimizer: Index optimization
			



<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000247"></a>


### WDOptimizer includes multiple modes to optimize indexes:
<a name="wdoptimizer_includes_multiple_modes_optimize_indexes_ELTPARAGRAPHE000011"></a>

***1. Check indexes*** Checks consistency between index and tables.

***2. Optimize index speed (Recalculate statistics)*** Optimize indexes by calculating index statistics. These statistics are used to optimize the filters, the queries and the HFSQL views. 
Note: The more the table is modified, the less the statistics reflect the content of the HFSQL table.. The more records the table contains, the less the modification of a single record impacts the overall statistics.

***3. Reconstruct indexes*** Optimize access to table records and recalculate statistics. All the crossed records are automatically deleted.

***4. Rebuild indexes and memos*** Optimizes the entire table, its indexes and memos.

***5. Revise and compress indexes and memos*** Optimize the entire table, index and memos. The memos will be compressed. Advanced options are available ("Options for compressing the memos").
Remarks: 

- The table is created again. The last write date of the last record (returned by [HRecordDate](../WDLang4/3044338.md)) is set to the current date.

- Timestamp items are also modified and are set to the date and time at which the optimization is performed. 




**Remarks**:

- Apart from option 2, all the optimization modes lock the tables during the optimization. The users are informed that the table is currently under maintenance.

- Once the reindexing is performed, the current HFSQL context is restored (except if the option for compressing memos was chosen).

## How to?
<a name="how_ELTTEXTE000271"></a>


### Optimizing the indexes of a table
<a name="optimizing_the_indexes_table_ELTPARAGRAPHE000043"></a>

To optimize the indexes of a table:

1. Start WDOptimizer:

	- Directly from WINDEV, WEBDEV or WINDEV Mobile: in the "Tools" pane, in the "Database" group, click on "WDOptimizer".

	- run "WDOptimizer.EXE" directly.




2. Select the tables to process. You can: 

	- Drag and Drop the tables from the explorer to WDOptimizer. Dropped tables automatically appear in the list. 

	- add one or more tables using the "Add a table" button. 

	- add the tables found in a directory via the "Add a folder" button. 
			To process the sub-directories, select "When adding a directory, include the files of all the sub-directories". 




3. Select the tables to process and indicate (if necessary) the password of each table. 
	Note: If the password is identical for all tables, check the "Use the same password for all tables" option. 

4. Click the "Optimize indexes" or "Optimize indexes of selected files" button and choose the desired option.

### Advanced reindexing mode
<a name="advanced_reindexing_mode_ELTPARAGRAPHE000095"></a>

These options are taken into account for the reindexing operations from type 1 to type 4:

- **Delete inactive records (deleted or crossed records)**
	If this option is selected, the crossed records are permanently deleted.
	**Reminder**: When a record is crossed, it is logically deleted and may be recovered at a later date. The record is still found in the table. Deleting the crossed records deletes these records permanently and optimizes the size of the table.

- **Delete damaged records**
	If this option is checked, the damaged records are automatically deleted.

- **Reindex without locking the client computers**
	If this option is checked, the reindexing operation is performed in background task and the client applications are not stopped. 
	**Note**: This option is only taken into account for HFSQL Client/Server tables. 

- **Density of the index**
	Corresponds to the density rate of the indexes. This rate is set to 80 by default. 
	A higher rate increases the density of the index and reduces its size. In this case, the browses, searches, filters and queries are faster. Adding and modifying records may take longer. 
	A smaller rate reduces the density of the index and increases its size. In this case, iterations, searches, filters and queries will be slower. Adding and modifying records will be faster. 
	Note: This parameter can only be used on HFSQL Classic or Client/Server tables.

- **Charset**
	The character set of the table is kept by default. However, a reindexing operation can be performed by changing the character set of the table. In this case, the new character set will be taken into account during the reindex operation. Sorts, searches, etc. on string keys (strings, characters, date and time) will be performed according to this character set.



<a name="NOTE3_3"></a>


### Options for compressing the memos
<a name="options_for_compressing_the_memos_ELTPARAGRAPHE000148"></a>

These options are taken into account during the revision with compression of indexes and memos (option 5):

- **Keep crossed records**
	If this option is selected, the crossed records are kept. Otherwise, they are permanently deleted.

- **Try to retrieve data from memo if damaged**
	If this option is selected, WDOptimizer tries to retrieve the memo. Otherwise, the damaged records are retrieved without the associated memo. 
	**Attention** Memo recovery may be partial. Check your tables.



<a name="NOTE3_4"></a>


### Options
<a name="options_ELTPARAGRAPHE000172"></a>

These options simplify management of the list of tables to be re-indexed:

- **Use the same password for all tables**
	If this option is selected, the same password is used for all the tables. All you have to do is specify the password in the "Password" column of the first table found in the list.
	If this option is unchecked, the password will have to be specified in the "Password" column of the table for each table.

- **When adding a directory, include the files found in all the subdirectories**
	If this option is selected, the tables found in the sub-directories are automatically added.



<a name="NOTE3_5"></a>


### Access rights to the table
<a name="access_rights_the_table_ELTPARAGRAPHE000196"></a>

The optimization triggers the recreation of the table on disk. 

Check the rights of the optimized table. These rights may differ from those of the original table. In this case, they must be redefined in Windows after the optimization.
