


## &lt;Source&gt;.LockFile (Function)

***In french: &lt;Source&gt;.BloqueFichier***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Locks a table and restricts the access to this table for all other sites or applications. Then, the table can be unlocked by [&lt;Source&gt;.UnlockFile](../WDLang4/1000024211.md).

Several cases may occur after the call to **&lt;Source&gt;.LockFile**:

- A table record is already blocked by another application: blocking cannot be performed.

- The table is already blocked by another application: blocking cannot be performed.




[HErrorLock](../WDLang4/3044099.md) returns <u><u><u>True</u></u></u> if a lock problem occurs.

<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
// Lock the CUSTOMER table
IF Customer.LockFile(hLockReadWrite) = False THEN
	IF HErrorLock() = True THEN
		Error("Operation not allowed")
	END
END
// Process on table ...
...
// Restore access to table
Customer.UnlockFile()
```

<a name="SYNTAXE1"></a>

## Syntax

`<Result> = <Source>.LockFile([<Lock>])`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the lock was performed, 

- <u><u><u><u>False</u></u></u></u> if a problem occurred (the file is already locked for example). [HError](../WDLang4/3044088.md) is used to identify the error.




**`<Source>: (Type corresponding to the specified source)`**

Name of the table used. 

**`<Lock>: (Optional integer constant)`**

Used to define the type of lock performed on the table:



|   |   |
| --- | --- |
| *hLockNo* | No effect |
| *hLockReadWrite* | Read/Write Lock: the records in the table can neither be read nor modified by another application. No lock on the table can be defined by another application. |
| *hLockWrite*<br>(default value) | Lock in write mode: records in the table can be read by another application but cannot be modified by another application. No lock on the table can be defined by another application. |


![Hyper File 5.5](https://doc.pcsoft.fr/ext/images/us/HF55.png) &lt;Lock&gt; is ignored.![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![Android Widget ](https://doc.pcsoft.fr/ext/images/us/ANDROIDWIDGET.png)![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) The management of locks is performed on the HFSQL Client/Server tables only.

## Remarks


### Setting the type of lock for a table
<a name="setting_the_type_lock_for_table_ELTPARAGRAPHE000269"></a>

To modify the type of lock applied to a table, call **&lt;Source&gt;.LockFile** and specify the requested type of lock. There is no need to unlock the table beforehand.
<a name="NOTE0_2"></a>


### Effect of lock mode
<a name="effect_lock_mode_ELTPARAGRAPHE000281"></a>

If the table lock mode is set to *hModeMono* (see [&lt;Source&gt;.Mode](../WDLang4/1000025037.md)), **&lt;Source&gt;.LockFile** has no effect.
<a name="NOTE0_3"></a>


### Lock failure
<a name="lock_failure_ELTPARAGRAPHE000298"></a>

If the table (or one of its records) is already locked, the lock request is retried [H.NbRetry](../WDLang4/3044075.md) times (50 by default).

If the table cannot be locked after ***H.NbRetry*** attempts, [HErrorLock](../WDLang4/3044099.md) returns <u><u><u><u>True</u></u></u></u>.
