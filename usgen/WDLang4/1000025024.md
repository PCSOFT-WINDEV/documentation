


## &lt;Source&gt;.ReadSeekLast (Function)

***In french: &lt;Source&gt;.LitRechercheDernier***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Positions on the last record of a table whose value for a specific item is less than or equal to a sought value (exact-match search). The record is read and the corresponding HFSQL variables are updated.

In most cases, **&lt;Source&gt;.ReadSeekLast** sets the position in the table to loop through the records that match a condition. [&lt;Source&gt;.ReadPrevious](../WDLang4/1000025021.md) is used to read the previous record corresponding to the condition.

Several cases may occur after the call to **&lt;Source&gt;.ReadSeekLast**:

- a record matching the condition is found, blocked (if necessary) and loaded into memory. [&lt;Source&gt;.Found](../WDLang4/1000025076.md) returns <u><u><u>True</u></u></u>.
	![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png) The management of locks is not available.
	![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) JDBC access: lock management is not supported for databases that are accessed through JDBC.




- the table is empty or no record matches the condition. The read operation cannot continue and [&lt;Source&gt;.Out](../WDLang4/1000024605.md) returns <u><u><u>True</u></u></u>.




- the function tries to lock a record that has already been locked. The read operation cannot continue, [HErrorLock](../WDLang4/3044099.md) is set to <u><u><u>True</u></u></u> and [&lt;Source&gt;.Out](../WDLang4/1000024605.md) returns <u><u><u>True</u></u></u>.
	![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png) The management of locks is not available.
	![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) JDBC access: lock management is not supported for databases that are accessed through JDBC.




This function can be used with the tables, HFSQL views or queries.

Note: The search criteria can be removed using [&lt;Source&gt;.CancelSeek](../WDLang4/1000024193.md).


<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
// Find the last record for which 
// the Customer name is MOORE
Customer.ReadSeekLast(NAME, "MOORE")
```
<a name="Exemple2"></a>
<a name="3044034_Exemple2"></a>

```wl
// Find all the customers whose turnover is less than a specific value 
Customer.ReadSeekLast(Turnover, X)
WHILE NOT Customer.Out()
	AddCustomerList()
	Customer.ReadPrevious(Turnover)
END
```

## Syntax

`<Result> = <Source>.ReadSeekLast(<Item> , <Search value> [, <Options>])`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the record was found (corresponds to the value of [&lt;Source&gt;.Found](../WDLang4/1000025076.md)). 

- <u><u><u><u>False</u></u></u></u> if a problem occurs. This problem can be caused by:

	- a positioning problem (empty table, etc.). In this case, [&lt;Source&gt;.Found](../WDLang4/1000025076.md) returns <u><u><u><u>False</u></u></u></u> and [HError](../WDLang4/3044088.md) returns 0.

	- an error. In this case, [HError](../WDLang4/3044088.md) returns an integer other than 0. [HErrorInfo](../WDLang4/3044071.md) returns more details.







**`<Source>: (Type corresponding to the specified source)`**

Name of table, HFSQL view or query used.

**`<Item>: (Character string)`**

Name of item on which the search will be performed. This item can be a search key or not.
![Hyper File 5.5](https://doc.pcsoft.fr/ext/images/us/HF55.png) The search can only be performed on a key item.

**`<Search value>: (Type corresponding to the value)`**

Value of the sought item.

**`<Options>: (Optional constant (or combination of constants))`**

Used to configure:

- the lock mode applied to the sought record.

- the type of search performed.

## Remarks


### Generic search/Exact-match search
<a name="generic_searchexactmatch_search_ELTPARAGRAPHE000534"></a>

- **Generic search** (mainly used on Character string items): ***Finds all records beginning with the specified value***. 
	For example: If you search for "Smith" in the NAME item, all records whose Name item starts with "Smith" will match the search. Therefore, the record that contains "Smither" will match the search ([&lt;Source&gt;.Found](../WDLang4/1000025076.md) returns <u><u><u><u>True</u></u></u></u>).
	**Note**: For backward compatibility with version 5.5, the generic search of an empty string ("") is equivalent to the use of [&lt;Source&gt;.ReadLast](../WDLang4/1000025020.md).

- **Exact-match search**: ***Finds all records exactly matching the specified value***. 
	For example: When an exact-match search is performed on "Smith" (for the NAME item), [&lt;Source&gt;.Found](../WDLang4/1000025076.md) returns <u><u><u><u>True</u></u></u></u> only for records whose item exactly matches "Smith".

- **Examples of searches on the CUSTOMER table sorted by name:**

<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=hlitrechpremier.gif)



|   |   |   |   |   |   |
| --- | --- | --- | --- | --- | --- |

| Davon |   | 6 | True | False | Davon exists.<br>The beginning of table was not reached yet. |

| Bernard |   | The record was not found (no move). | False | True | Bernard does not exist.<br>Sets the position to the first lower value (this value does not exist). The beginning of the table is reached. |

### Search performed on a key item or on a non-key item
<a name="search_performed_key_item_nonkey_item_ELTPARAGRAPHE000654"></a>

The search can be performed on a key item or a non-key item.

If the search is performed on a key item:

- the search is fast and the result is sorted.

- if the iteration is continued by [&lt;Source&gt;.ReadPrevious](../WDLang4/1000025021.md), the next records will correspond to the values less than or equal to the search value. In this case, [&lt;Source&gt;.Out](../WDLang4/1000024605.md) must be checked after each read operation to find out whether the beginning of the file has been reached.




If the search is performed on a non-key item:

- the selected item will appear in red in the code editor and a warning will appear in the ["Compilation error" pane](../Editeurs/2027031.md).
	**Note**: The [automatic completion](../Editeurs/2013001.md) only offers the key items.

- if the iteration is continued by [&lt;Source&gt;.ReadPrevious](../WDLang4/1000025021.md), the next records will correspond to the values equal to the search value.



<a name="NOTE0_3"></a>


### Performing a search on a composite key
<a name="performing_search_composite_key_ELTPARAGRAPHE000697"></a>

Several methods can be used to perform a search on a composite key:

- Using a list of values.

- Use the [&lt;Source&gt;.BuildKeyValue](../WDLang4/1000024205.md) function.




**1. Using a list of values**

The following syntax is used to perform a search on a composite key:


```txt
HReadSeekLast(<File name>, <Name of composite key>, 
	[<Search value of first element of composite key>, 
	<Search value of first element of composite key>, ...])
```
Example:

```wl
// Find the record
Customer.ReadSeekLast(LastName_FirstName, ["MOORE","Vince"])
```

**2. Using [&lt;Source&gt;.BuildKeyValue](../WDLang4/1000024205.md)**

Example:

```wl
bufSoughtVal is Buffer = Customer.BuildKeyValue(LastName_FirstName, sLastName, sFirstName)
Customer.ReadSeekLast(LastName_FirstName, bufSoughtVal)
WHILE Customer.Found()
	Customer.Delete()
	Customer.Previous(LastName_FirstName)
END
```
![Hyper File 5.5](https://doc.pcsoft.fr/ext/images/us/HF55.png) To perform generic searches on a composite key, all the components of composite key must be Text components. Otherwise, an exact-match search is performed.
<a name="NOTE0_4"></a>


### Search and filter
<a name="search_and_filter_ELTPARAGRAPHE000746"></a>

If a filter is enabled ([&lt;Source&gt;.Filter](../WDLang4/1000024960.md)), the filter is taken into account by the search only if the key used is identical.

To apply this filter in the rest of the iteration (even if the search key is not optimized for the filter), use the *hKeepFilter* constant.
![Hyper File 5.5](https://doc.pcsoft.fr/ext/images/us/HF55.png) If a filter is enabled, the filter is ignored by the search.
<a name="NOTE0_5"></a>


### Search on an array item
<a name="search_array_item_ELTPARAGRAPHE000766"></a>

The search is performed on the first array element (element with index 1). To perform a search on the other array elements, use the filters or queries.
<a name="NOTE0_6"></a>


### Looping through records that match a condition
<a name="looping_through_records_that_match_condition_ELTPARAGRAPHE000776"></a>

In most cases, **&lt;Source&gt;.ReadSeekLast** sets the position in the table to loop through the records that match a condition. [&lt;Source&gt;.ReadNext](../WDLang4/1000025035.md) and [&lt;Source&gt;.ReadPrevious](../WDLang4/1000025021.md) are used to read the next and previous matching records.

To ignore the search while going to the next or previous record, use one of the following functions:

- [&lt;Source&gt;.CancelSeek](../WDLang4/1000024193.md)

- [&lt;Source&gt;.ReadLast](../WDLang4/1000025020.md)

- [&lt;Source&gt;.ReadFirst](../WDLang4/1000025022.md)

### Locks
<a name="locks_ELTPARAGRAPHE000830"></a>

The locks apply only when a record was found.

By default (no lock mode specified in &lt;Options&gt;), the record is not locked.

If a lock is erquested (*hLockWrite* or *hLockReadWrite* constant), the record will be read only if this record is not already locked.

Reminder: a locked record can be unlocked by  [&lt;Source&gt;.UnlockRecNum](../WDLang4/1000024212.md).

![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png)![Native Connectors (Native Accesses)](https://doc.pcsoft.fr/ext/images/us/AN.png) Lock options will have no effect if the OLE DB provider or Native Connector (also called Native Access) does not support locks.
