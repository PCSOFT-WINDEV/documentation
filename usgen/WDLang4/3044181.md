


## Implementing the log process in an application
			



<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000457"></a>
Regardless of the tables used by your application (HFSQL Classic or HFSQL Client/Server), the log process can be implemented on these tables.

**To implement logging for your application's tables**you need to:

1. Define the type of log process to perform.

2. Define the log process for the tables.

3. Define the log process for the items.




The files created by the log process depend on the type of access to your tables (HFSQL Classic or HFSQL Client/Server).

The log tables can then be manipulated using the WDLog tool or by programming.

## Implementing the log process
<a name="implementing_the_log_process_ELTTEXTE000511"></a>


### Defining the log process for the tables
<a name="defining_the_log_process_for_the_tables_ELTPARAGRAPHE000133"></a>

The log process on HFSQL Classic or Client/Server tables is implemented in the data model editor.

To implement the log process on a table described in the database schema:

1. Make a backup copy of the tables in their current status with [WDLog](../WDJournal/3516012.md).

2. In the data model editor, open the description of the desired table:

	- Select the table in the editor. 

	- Select "Description of table" in the context menu.




3. On the "Miscellaneous" tab, select the type of log to manage for this table.

4. Depending on the selected option, specify (if necessary) the directory of the different files created by the log process.


![HFSQL Classic](https://doc.pcsoft.fr/ext/images/us/HF.png) Remarks: 

- **Note: the JournalIdentification and JournalOperation files are always located in the same**directory. . By default, these files are created in the directory of the application. 
	This directory is defined in the database schema options: click on the database schema graph background and select "Database schema description" from the context menu.
	This directory can be modified for each table.

- **Tip** Log files are used to record operations performed on a table, so that they can be replayed on a backup in the event of a problem (e.g. unusable disk). We recommend that you save the log files in directories (and even disks) different from the ones used for the tables.



<a name="NOTE3_2"></a>


### Defining the log process for the items
<a name="defining_the_log_process_for_the_items_ELTPARAGRAPHE000164"></a>

By default, all fields in a log file are automatically logged. You have the ability to define:

- whether some items must be logged or not. For example, if one of the tables uses a memo item to store an image (information not that important and that does not change very often), you have the ability not log this item.

- whether the logged item must be a key in the log. This option allows you to easily retrieve a record in the log.




To avoid implementing a log on an item:

1. Display the file description.

2. Display the description of requested item.

3. On the "Advanced" tab, uncheck "Log item".



<a name="NOTE3_3"></a>


### Generating the database schema
<a name="generating_the_database_schema_ELTPARAGRAPHE000184"></a>

Once the log process was defined in the table model editor, the database schema can be generated.

**Caution**: Before performing this operation, we recommend you back up your tables with [WDLog](../WDJournal/3516012.md).

### Automatic data modification and log process
<a name="automatic_data_modification_and_log_process_ELTPARAGRAPHE000196"></a>

When the automatic table modification is performed on logged tables:

1. The log files are automatically saved.

2. The log files are flushed.

### Files created in HFSQL Classic mode
<a name="files_created_hfsql_classic_mode_ELTPARAGRAPHE000210"></a>

When a database schema table has been described with a logging option, the following tables can be created:


|   |   |
| --- | --- |
| JournalOperation.Fic | List of all the operations performed on the logged HFSQL tables used by the application. An operation corresponds to an HFSQL function. |
| JournalIdentification.Fic | List of physical locations of all application log tables |
| \* JNL.Fic | File created for each log table. Contains the value of records used before and after each operation. |


For more details on the structure of these files, see: [structure of log files](../WDLang4/3044182.md).

**To configure the location of these files and their password:**

- **LogOperation and LogIdentification** files: By default, these files are created in the application directory. To modify this directory:

	1. Display the database schema description: click on the database schema graph, display the context menu and select "Database schema description". 

	2. Go to the "Log" tab.

	3. Select the file directory and its password if necessary.


 Note: This directory can also be modified for each table logged (option "Table description" in the context menu, "Miscellaneous" tab). In this case, the JournalOperation and JournalIdentification files will be created for each file at the specified location.

- **\*JNL** file: By default, this file is created in the application directory.. To modify this directory: 

	1. Display the table description: "Table description" option in the context menu.

	2. Go to the "Miscellaneous" tab.

	3. Select the file directory.


 Note: The password for the \*JNL.fic file will be identical to the password for the table.

### Two tables must not use the same log file
<a name="two_tables_must_not_use_the_same_log_file_ELTPARAGRAPHE000393"></a>

Several cases may occur:

- **When creating a table**, the log uses the GUIDs to check whether two tables found at different locations do not use the same log file. Indeed, the table found in the log could be corrupted if the same log table is used by several tables. 
	An error is displayed if the same log file is used by several files.

- **When copying or moving a table**, the GUID of this file is not modified. In this case, the HFSQL engine detects that the location of the table was modified. A new record is automatically added into the **JournalIdentification** file in order to specify the new location of the table and its GUID. However, no check is performed by the log.
	The developer should make sure that two copies of the same table found at different locations do not use the same log file, in which case the content of the log file would not correspond to any of the two tables.

- **When a table is replaced with one of its earlier backups**, the GUID is not modified. This operation is not automatically detected by the log process. 
	In such situation, you must delete the JNL file at the same time as its table and eventually restore the JNL file saved at the time as the table.




**Reminder** Two types of file GUIDs are managed by the HFSQL engine:

- File GUID defined when the file was described in the data model editor. This GUID is used to manage the .REP.

- File GUID defined when creating the physical table. This GUID is used in the log process.
