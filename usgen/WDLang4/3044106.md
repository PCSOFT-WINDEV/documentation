


## HOpenAnalysis (Function)

***In french: HOuvreAnalyse***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Opens a database schema in HFSQL Classic format. This allows you to access the tables defined in the database schema as well as their structure.

**Please note** Only one database schema can be opened at any given time using the function **HOpenAnalysis**. 

- If a database schema was already open when the function was called, it is automatically closed along with the associated tables. 

- To open several database schemas simultaneously, open the main database schema with **HOpenAnalysis** and additional database schemas with [HOpenComplementaryAnalysis](../WDLang4/1410090082.md). 


**Warning** When using the **HOpenAnalysis FUNCTION**function, the current HFSQL context is automatically reset. The following operations are automatically performed:

- All opened tables are closed.

- All existing HFSQL views are deleted.

- All existing queries are deleted.

- All the declarations made with [HDeclareExternal](../WDLang4/3044204.md) and [HDescribeFile](../WDLang4/3044206.md) are deleted.





<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
// Open the SALESMGT database schema
HOpenAnalysis("C:\SALESMGT\SALESMGT.WDD", "Password")
```

## Syntax

`<Result> = HOpenAnalysis(<WDD file path> [, <Password>])`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the database schema was opened,

- <u><u><u><u>False</u></u></u></u> otherwise. [HError](../WDLang4/3044088.md) returns more details about the problem.




**`<WDD file path>: (Character string)`**

Full path of the ".WDD" file of the database schema. This file contains the description of the database schema to be opened.

![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png)![WEBDEV - Server code](https://doc.pcsoft.fr/ext/images/us/WBS.png) If only the drive and the name of the database schema are specified, the database schema is searched for in the current directory of the specified drive. 
If neither the drive, nor the database schema path are specified, the database schema is searched for in the current directory of the current disk.
The &lt;Unit&gt;:&lt;database schema name&gt; syntax is used to search for the database schema in the current directory of the specified drive. 

**`<Password>: (Optional string or Secret string)`**



- Database schema password, defined in the data model editor. 

- Empty string ("") if no password is associated with the database schema.
	**Secret strings**: If you use the secret string vault, the type of secret string used for this parameter must be "ANSI or Unicode string".
	To learn more about secret strings and how to use the vault, see [Secret string vault](../Editeurs/1410087353.md).

## Remarks


### Starting an application associated with a database schema
<a name="starting_application_associated_with_database_schema_ELTPARAGRAPHE000092"></a>

- When starting an application, the database schema associated with this application is automatically opened. The database schema is searched for in the main library of the application, then in the directory of the application. 
	To make sure the database schema is found, we advise you to include the database schema in the main library of the application.

- If **HOpenAnalysis** is called by an application associated with a database schema, this function:

	- has no effect if the path of the specified database schema corresponds to the path of the database schema associated with the application.

	- returns <u><u><u><u>False</u></u></u></u> if the path of the specified database schema does not exist. In this case, the application keeps working with the current database schema.

	- opens the database schema and returns <u><u><u><u>True</u></u></u></u> if the specified database schema exists and if it is valid.






<a name="NOTE0_2"></a>


### Starting an application not associated with a database schema
<a name="starting_application_not_associated_with_database_schema_ELTPARAGRAPHE000116"></a>

When an application that is not associated with a database schema is started, no database schema is automatically opened. In this case, you need to use **HOpenAnalysis**.

The database schema opened by **HOpenAnalysis** is searched:

- first, in the main library of the application according to its full physical name.

- then, on the current disk.



<a name="NOTE0_3"></a>


### Opening a database schema that is already open
<a name="opening_database_schema_that_already_open_ELTPARAGRAPHE000132"></a>

If the database schema you are trying to open with **HOpenAnalysis** is already open, **HOpenAnalysis** has no effect.
<a name="NOTE0_5"></a>


### Database schema version supported by HOpenAnalysis
<a name="database_schema_version_supported_docparampagetitleshort_ELTPARAGRAPHE000143"></a>

**HOpenAnalysis cannot be used to open Hyper File 5.5 database schemas (and earlier versions). Only HFSQL Classic database schemas can be opened.**

To use **HOpenAnalysis** on Hyper File 5.5 tables, you must use the " .WDD" file in an HFSQL Classic database schema containing tables Hyper File 5.5 tables. In this case, the ".WDD" file of the source WINDEV 5.5 database schema must necessarily be found in the directory of the executable.

**You can also use [HDeclare](../WDLang4/3044203.md) to directly handle a Hyper File 5.5 file.**
