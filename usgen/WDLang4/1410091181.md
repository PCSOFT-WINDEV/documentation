
## hSecurityPolicy (Variable type)

***In french: hPolitiqueSécurité***
			
				



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
The **hSecurityPolicy** type gets and sets all the advanced characteristics of a password security policy implemented on a server in HFSQL Client/Server mode. You can define and change the characteristics of this security policy using different WLanguage properties. 

To manipulate data in an HFSQL Client/Server database, users need to authenticate using login credentials. 
You can now implement a password security policy to define how long and how complex passwords should be, and how often they should be renewed (e.g. passwords must be changed every month). 
This policy can be defined and modified programmatically, or via the HFSQL Control Center. For more details, see [Password management policy](../WDLang4/1000017425.md). 

**Note**: For more details on the declaration of this type of variable and the use of WLanguage properties, see [Declaring a variable](../Motscles/1514032.md).

## Properties


### Properties specific to hSecurityPolicy variables
<a name="properties_specific_hsecuritypolicy_variables_ELTPARAGRAPHE000040"></a>

The following properties can be used to manage a security policy:

| Property name | Type used | Effect |
| --- | --- | --- |
| LockTime | Duration | Lockout period (in minutes) after a given number of failed attempts. The number of attempts is determined by the **FailedLoginAttempts** property. |
| FailedLoginAttempts | Integer | Number of failed login attempts before locking out a user. The lockout time is defined by the **LockTime** property. <br><br>After 3 failed attempts, authentication is automatically delayed by 1 second. <br><br>If the specified number of attempts has not been reached within 30 minutes, the count is reset to 0. <br><br>Tip: Do not use this property on a public server, as it may block all users. This property is recommended for LANs and not for public servers. <br><br>Special case for a cluster: The number of failed attempts before lockout is specified per node. Since the connection is established with a node at random, the maximum number of failed login attempts before lockout is:<br><pre><code>FailedLoginAttempts x Number of nodes</code></pre><br><br><br> |
| PasswordComplexity | Integer constant | Sets the expected password complexity:<br><br>- *hPasswordLow*: Any password is accepted. Only the minimum length is checked (**PasswordMinimumLength** property).  <br><br>- *hPasswordMedium*: The password must contain at least one uppercase and one lowercase letter.  Minimum length is also checked (**PasswordMinimumLength** property).  <br><br>- *hPasswordStrong*: The password must contain at least one digit, one uppercase, one lowercase and one special character. Minimum length is also checked (**PasswordMinimumLength** property). <br><br><br> |
| PasswordHistory | Integer | Number of passwords stored in the history per user. These passwords must not be reused. <br>For example, to prevent users from using the last 5 passwords, the property must be set to 5.  |
| PasswordLifetime | Integer | Validity period of password (in days). This validity period is taken into account from the date of last password modification.<br><br>By default, no validity period is defined. The property is set to 0. <br><br>**Remarks**:<br><br>- In the [user management variables](../WDLang4/3044315.md), the **HUser.ValidityPeriod** variable is also used to define the password validity period. If this value is specified, the minimum duration is applied. <br><br>- Likewise, if a password validity period has been defined in the user details in the HFSQL Control Center, the minimum validity period is applied. <br><br><br> |
| PasswordMinimumLength | Integer | Minimum password length. |
| PasswordMinimunLifetime | Integer | Sets the minimum password validity period. For example, this prevents users from having to change their password too often in a single day. This property is expressed in days. <br><br>By default, no minimum duration is defined. The property is set to 0. |
| PasswordReuseTime | Integer | Number of days that must pass before a previous password can be reused. |
| SlowDownEachAttempt | Boolean | <br><br>- <u><u><u>True</u></u></u>: Adds a delay when there are successive failed login attempts, preventing "brute force" attacks. This delay is applied after 10 attempts. <br><br>- <u><u><u>False</u></u></u> (default value) otherwise. <br><br><br><br><br> |


<a name="NOTE0"></a>

## Remarks


- User lockout:

	- You can unlock a user account with [HSecurityPolicyUnlockAccount](../WDLang4/1410091235.md). 

	- A server restart unlocks all accounts (including "superuser" accounts). 

	- If a "Superuser" account is locked out, it is necessary to connect to the physical machine, then to connect to the server using "localhost" and the login credentials. This will allow access again.
