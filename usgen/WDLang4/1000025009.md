
## &lt;Source&gt;.JSONToRecord (Function)

***In french: &lt;Source&gt;.JSONVersEnregistrement***

<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Imports JSON data into the current record.
<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
let sString1 = "{ ""FirstName"":""Tintin"", ""FirstName"":[""Milou"", ""IDEFIX""] }"
let b1 = Customer.JSONToRecord(sString1)
IF ErrorOccurred = True THEN
```

<a name="XSYNTAXE"></a>

## Syntax
<a name="SYNTAXE1"></a>

`<Result> = <Table>.JSONToRecord(<JSON data> [, <List of destination items> [, <List of JSON keys to import>]])`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if no problems were encountered during the import process,

- <u><u><u><u>False</u></u></u></u> otherwise. [HErrorInfo](../WDLang4/3044071.md) returns more details about the problem.




**`<Table>: (Optional character string)`**

Name of the HFSQL table used. JSON data is imported into the current record.

**`<JSON data>: (JSON string or variable)`**

JSON data to be converted to record. This data can correspond to a JSON string or to a [JSON](../WDLang1/1000023611.md) variable.

**`<List of destination items>: (Optional character string)`**

Names of items in the table into which the JSON data is to be imported. These names can be delimited by simple quotes and separated by commas or carriage returns (CR). 
Items of type Composite key, Binary Memo and Binary are ignored. 
Items not included in this list will be initialized with the default value defined in the database schema. 
If this parameter is not specified or is an empty string (""), all items are imported (except compound keys, binary items and binary memos) in the order in which they were created in the physical file.

**`<List of JSON keys to import>: (Optional character string)`**

List of keys associated with the JSON values to be imported. 
If this parameter is not specified or is an empty string (""), the values associated with all JSON keys are imported.
If there is no JSON data for one given item in the table, a non-fatal error is returned.



<a name="NOTE0"></a>
<a name="NOTE0_1"></a>

## Remarks


### Type of import
<a name="type_import_ELTPARAGRAPHE000206"></a>

If the list of JSON keys is specified, all "JSON values" whose key names are identical to the names of the items in the table will be imported.

The table defined in the database schema contains the following items: ITEM1, ITEM2, etc. The JSON table should therefore have the following structure:


```txt
{"File":
	{
		"ITEM1":Data of ITEM1,
		"ITEM2":Data of ITEM2,
		...
		}
}
```
JSON keys that do not exist in the database schema or are not specified in the list of items will be ignored during the import.

If the list of JSON keys is not specified, the values of the JSON keys are imported into the items of the HFSQL table that have the same name as the JSON keys.
<a name="NOTE0_2"></a>


### Encoding
<a name="encoding_ELTPARAGRAPHE000223"></a>

The encoding used corresponds to the JSON standard: 

- 7-bit ASCII encoding, i.e. the first 128 characters, unaccented characters,

- JSON encoding for other characters: "\\u" followed by the character code in 4-byte hexadecimal format. 




For example, the "é" character (ASCII code 233, hexadecimal code E9) would be encoded as "\\u00E9".
