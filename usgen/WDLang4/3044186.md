


## REP files
			



<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000280"></a>
REP files contain the list of tables handled by the application. 

This .REP file can be used in programming by the WLanguage functions.

<a name="NOTE2"></a>
<a name="NOTE2_1"></a>


## .REP: list of tables
<a name="rep_list_tables_ELTTEXTE000304"></a>
The file &lt;MonProjet&gt;.REP file contains a list of tables handled by the application (identifier, logical name and full path of the physical file).

The GUID of the database schema is the unique identifier of the database schema linked to the project, containing the description of the tables. This identifier can be found in the data model editor, in the database schema description ("Options" tab).

The GUID of the table corresponds to the identifier of the logical table. This identifier can be found in the data model editor, in the description of the table ("Notes" tab).<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=fichier_Rep.gif)
This file is automatically created in the application directory and is populated by the HFSQL engine.

<a name="NOTE3"></a>
<a name="NOTE3_1"></a>


## What are REP files for?
<a name="what_are_rep_files_for_ELTTEXTE000328"></a>
".REP" files allow you to easily locate the tables used by the WINDEV or WINDEV Mobile application.

The WINDEV application automatically updates the ".REP" file but it rarely uses the ".REP" file.

This file is used by all the tools that handle the tables of the application, and mainly by the automatic update of the tables, etc.
<a name="NOTE3_2"></a>


### Example: Updating an application while modifying the database schema
<a name="example_updating_application_while_modifying_the_database_schema_ELTPARAGRAPHE000042"></a>

When updating a WINDEV application, the automatic table modification is automatically started if the structure of the database is modified.

This procedure uses the ".REP" table to find and modify the physical tables used by the application.

For more details, see [The automatic modification of tables](../WDLang4/3044195.md)

### Writing into the file
<a name="writing_into_the_file_ELTPARAGRAPHE000118"></a>

To write into the .REP file, all you have to do is use the functions for managing the external files:

- [fOpen](../WDLang1/3036036.md): to open the file.

- [fWriteLine](../WDLang1/3036025.md): to write a new line into the file.

- [fClose](../WDLang1/3036027.md): to close the file.




The structure of the added line must be as follows:


|   |   |   |   |   |   |
| --- | --- | --- | --- | --- | --- |
| **LOCALIZATION=** | File GUID | *Tabulation* | Logical name of table. | *Tabulation* | Path of physical table. |






|   |   |   |   |   |   |   |
| --- | --- | --- | --- | --- | --- | --- |
| **LOCALIZATION_CS=** | File GUID | *Tabulation* | Logical name of the table. | *Tabulation* | Physical location of the table in the HFSQL server. | *Tabulation* |
|   | ServerName:Port | *Tabulation* | ServerIP:Port | *Tabulation* | Database |   |

**In a Unicode**LOCALISATION_CS is replaced by LOCALISATION_CS_UTF8: the various strings are encoded in UTF8.

The GUID of the table corresponds to the identifier of the logical table. This identifier can be found in the data model editor, in the description of the table ("Notes" tab).

Two WLanguage properties return the GUID of a table and the GUID of the database schema that created it:


|   |   |
| --- | --- |
| [GUIDAnalysis](../Proprietes/2512098.md) | Returns the GUID of the database schema that was used to create the table. |
| [GUIDFile](../Proprietes/2512099.md) | Returns the GUID of the table defined in the database schema that created the table. |

## Structure of .REP file
<a name="structure_rep_file_ELTTEXTE000400"></a>


### Structure of .REP file
<a name="structure_rep_file_ELTPARAGRAPHE000197"></a>

The .REP file has the following structure:

- The first line contains the information regarding the database schema in which the tables have been described. This database schema corresponds to the database schema of the current project.
	The structure of this line is as follows:
	


|   |   |
| --- | --- |
| **ANALYSISGUID=** | Database schema GUID |


	The GUID of the database schema is the unique identifier of the database schema linked to the project, containing the description of the tables. This identifier can be found in the data model editor, in the database schema description ("Options" tab).

- The following lines describe the different tables handled by the application. A line is created for each physical table handled. This line contains the following information:
	


|   |   |   |   |   |   |
| --- | --- | --- | --- | --- | --- |
| **LOCALIZATION=** | File GUID | Tabulation | Logical name of table | Tabulation | Path of physical table |


	The GUID of the table corresponds to the identifier of the logical table. This identifier can be found in the data model editor, in the description of the table ("Notes" tab).
