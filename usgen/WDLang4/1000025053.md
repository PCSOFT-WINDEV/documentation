


## &lt;Source&gt;.Seek (Function)

***In french: &lt;Source&gt;.Recherche***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
The number of the current record is modified only when it is returned by [&lt;Source&gt;.RecNum](../WDLang4/1000025041.md). For functions handling the current record number by default (functions [&lt;Source&gt;.Delete](../WDLang4/1000025071.md), [&lt;Source&gt;.Read](../WDLang4/1000025019.md), [&lt;Source&gt;.Modify](../WDLang4/1000025038.md), ...), the value of this number is not updated: you must use the [&lt;Source&gt;.RecNum](../WDLang4/1000025041.md)() function. For example: do not: 

```wl
Customer.Delete()
```
but 

```wl
Customer.Delete(Customer.RecNum())
```

<a name="Exemple1"></a>

```wl
// Generic search for the first record for which 
// the postal code starts with "75"
Customer.Seek(ZC, "75")
```
<a name="sample_code"></a>

## Example

<a name="Exemple2"></a>

```wl
// Exact-match search for the first record
// for which the Customer name is Moore
// Mode 7: Text field terminated by Caract(0)
Customer.Seek(Name, "Moore" + Charact(0))

// Mode 5.5: Text field completed with spaces
Customer.Seek(Name, Complete("Moore", 30))
```

## Syntax

`<Result> = <Source>.Search(<Key item> , <Search value> [, <Options>])`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the position was set,

- <u><u><u><u>False</u></u></u></u> in the event of an error (blocking, etc.): the Record is not played. This problem can be caused by:

	- or a positioning problem (empty table, etc.): function [&lt;Source&gt;.Found](../WDLang4/1000025076.md) returns <u><u><u><u>False</u></u></u></u> and function [HError](../WDLang4/3044088.md) returns 0.

	- an error: [HError](../WDLang4/3044088.md) returns an integer other than 0. [HErrorInfo](../WDLang4/3044071.md) returns more details.







**`<Source>: (Type corresponding to the specified source)`**

Name of the HFSQL table used.

**`<Key item>: (Character string)`**

Name of key item on which the search will be performed.

**`<Search value>: (Type corresponding to the value)`**

Value of the sought item.

**`<Options>: (Optional constant (or combination of constants))`**

Configures:

- the lock mode applied to the sought record. 

- the type of iteration

- the type of search performed.





|   |   |
| --- | --- |
| *hIdentical* | Exact-match search (see the Notes). <br>A generic search is performed by default (parameter not specified). |
| *hKeepFilter* | The filter set by [&lt;Source&gt;.Filter](../WDLang4/1000024960.md) will be taken into account, even if the search key is not optimized for the filter. Reminder: [&lt;Source&gt;.Filter](../WDLang4/1000024960.md) returns the optimized search key for the filter.<br>Warning: in this case, on large tables, performance problems may occur..<br>![Hyper File 5.5](https://doc.pcsoft.fr/ext/images/us/HF55.png) This variable cannot be used. |
| *hLimitParsing* | The iteration will stop when the last searched value is found. The current record will correspond to the record found. | *hLockNo* | No blocking: the Record can be played back or modified by another application during playback. |
| *hLockReadWrite* | Read/write lock: the record being read cannot be read or modified by another application.<br>![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png) Lock in write-only. Operating mode equivalent to the *hLockWrite* constant. |
| *hLockWrite* | Write lock: the record currently read can be read by another application but it cannot be modified by another application. |

## Remarks


### Generic search/Exact-match search
<a name="generic_searchexactmatch_search_ELTPARAGRAPHE000354"></a>

A generic search or an exact-match search will be performed according to &lt;Sought value&gt;.

- **Generic search**: searches for all records beginning with the specified value
	To perform a generic search, the desired value must be specified in &lt;Sought value&gt;.

- **Case of exact-match search** In the case of an identical search: searches for all records corresponding exactly to the specified value.
	To perform an exact-match search, the size of the search argument must be exactly the same as the size of the key. The search argument must be filled with "space" characters for the text keys. To do so, use the [&lt;ANSI string&gt;.Complete](../WDLang1/1410089823.md) function.



<a name="NOTE0_2"></a>


### Space characters at the end of item
<a name="space_characters_the_end_item_ELTPARAGRAPHE000376"></a>

By default, when a record is read, trailing spaces in text fields are not removed from variables associated with the table.

In order for the space characters to be deleted, use [WithSpace](../WDLang4/3044142.md).
<a name="NOTE0_3"></a>


### Performing a search on a composite key
<a name="performing_search_composite_key_ELTPARAGRAPHE000391"></a>

Several methods can be used to perform a search on a composite key:

- Using a list of values

- Using the [&lt;Source&gt;.BuildKeyValue](../WDLang4/1000024205.md) function




**Using a list of values**
The following syntax is used to perform a search on a composite key:


```txt
HSeek(<File name>, <Name of composite key>, ...
	[<Search value of first element of composite key>, 
	<Search value of first element of composite key>, ...])
```
Example:

```wl
// Find the record
Customer.Seek(LastName_FirstName, ["MOORE","Vince"])
```
![Hyper File 5.5](https://doc.pcsoft.fr/ext/images/us/HF55.png) To perform generic searches on a composite key, all the components of composite key must be Text components. Otherwise, an exact-match search is performed.
<a name="NOTE0_4"></a>


### Search on an array item
<a name="search_array_item_ELTPARAGRAPHE000425"></a>

The search is performed on the first array element (element with index 1). To perform a search on the other array elements, use the filters or queries.
<a name="NOTE0_5"></a>


### Search and filter
<a name="search_and_filter_ELTPARAGRAPHE000435"></a>

If a filter is enabled ([&lt;Source&gt;.Filter](../WDLang4/1000024960.md)), this filter is taken into account during the search.
