


## HAccelerateSpeed (Function)

***In french: HAccélèreVitesse***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Reorganizes the internal structure of the indexes to optimize the speed for accessing the data. Based on [HStatCalculate](../WDLang4/3044134.md), this function performs several statistical calculations on the keys of a table.

**When to use HAccelerateSpeed?**
This function can be used as often as necessary but we advise you to use it after a set of additions (in most cases, after a set of additions corresponding to at least 1 per thousand of the number of records in the database). 
**Note** For an efficient statistics calculation, it is necessary to perform this calculation on all tables (e.g. in the case of a multi-table query).
**Warning** This function should not be used systematically in project initialization code. Indeed, optimizing the speed for accessing the data may take quite a long time and the users may be slowed down. 

**How does HAccelerateSpeed work?**
The statistics on the keys of a table are used when implementing a filter, when creating a query or when creating a view on the table. The HFSQL engine performs the database schema on the selection condition, then uses these statistics to define the most discriminating items that will be used to optimize iterations on tables.
The statistics are used to get information about the content of the table when they are calculated. Once the statistics have been calculated: 

- The more the table is modified, the less accurate the statistics are. 

- The more records the table contains, the less the modification of a single record impacts the overall statistics.




**Attention** The function **HAccelerateSpeed** function locks the table for writing while statistics are being calculated (the table is scanned for each key in the table).
![HFSQL Client/Server](https://doc.pcsoft.fr/ext/images/us/HFCS.png) The statistics can be calculated in background task without locking the table in write mode.

## Example


```wl
// Reorganizes the Customer table on the CustName key
HAccelerateSpeed(Customer, CustName)
```

## Syntax

`<Result> = HAccelerateSpeed([<Table> [, <Key item> [, <Optimization>]]])`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the reorganization of indexes was performed, 

- <u><u><u><u>False</u></u></u></u> if a problem occurred (table locked by an application for example). [HError](../WDLang4/3044088.md) is used to identify the error.




**`<Table>: (Optional character string)`**

Name of the table used. If this name is not specified, **HAccelerateSpeed** will use the last table used by the last HFSQL function (function starting with "H").
If this parameter is equal to "\*" (without specifying any item), the operation will be performed on all the tables described in the current database schema (including the tables described by [HDeclare](../WDLang4/3044203.md), [HDeclareExternal](../WDLang4/3044204.md), [HDescribeFile](../WDLang4/3044206.md)).
**Caution**: This table must not be blocked by an application.

**`<Key item>: (Optional character string)`**

Name of the key item used to reorganize the indexes. If this name is not specified or if it is equal to "\*", the reorganization of indexes will be performed on all the key items of the table.

**`<Optimization>: (Integer constant)`**

![HFSQL Client/Server](https://doc.pcsoft.fr/ext/images/us/HFCS.png) Optimizes index reorganization for HFSQL Client/Server tables. 
If this parameter is not specified, the table used will be locked in write mode. 
If this parameter corresponds to the *hBackgroundTask* constant, the reorganization of indexes will be performed in background task, without locking the table. 
**Important** This parameter is only taken into account for HFSQL Client/Server tables. In the other cases, the table is automatically locked while the statistics are calculated. 



<a name="NOTE0"></a>
<a name="NOTE0_1"></a>

## Remarks


- **HAccelerateSpeed** does not close the table.

- The reorganization of indexes can also be performed by [HIndex](../WDLang4/3044133.md) or by [HStatCalculate](../WDLang4/3044134.md). 

- In the HFSQL Classic or Client/Server tables, the reorganization of indexes can only be performed on the key items.

- The syntax **HAccelerateSpeed**(&lt;Data file&gt;) is equivalent to **HAccelerateSpeed**(&lt;Data file&gt;, "\*")
