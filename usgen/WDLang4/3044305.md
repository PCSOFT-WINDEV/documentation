


## HFSQL Client/Server: Setting up tables on the server
			



<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000149"></a>
**If you are modifying an existing WINDEV application into an HFSQL Client/Server application**, there are two ways to convert HFSQL Classic tables into HFSQL Client/Server tables: from the data model editor or from the HFSQL Control Center.
For details of how to convert HFSQL Classic tables to Client/Server mode, see [Converting an HFSQL Classic database into HFSQL Client/Server](../WDLang4/9000155.md). 

No specific operation is required **to create an HFSQL Client/Server application**. The tables will be created on the server during the call to [HCreation](../WDLang4/3044255.md) or [HCreationIfNotFound](../WDLang4/3044254.md).

### Names on a Linux server
<a name="names_linux_server_ELTPARAGRAPHE000032"></a>

On a Linux server, the names of tables must be written in lowercase with no accented characters.

Therefore, the file named "Tasks.fic" must be renamed to "tasks.fic". [HCopyFile](../WDLang4/3044282.md) is used to copy the tables while taking into account the specific features regarding the case of file names in Linux.
<a name="NOTE2_2"></a>


### Important
<a name="important_ELTPARAGRAPHE000044"></a>

In HFSQL Client/Server:

- [HSubstDir](../WDLang4/3044028.md) is ignored. In fact, this function only allows you to substitute the directories of Network HFSQL tables.

- If [HChangeDir](../WDLang4/3044168.md) is used, you must specify a path relative to the directory of the application database on the server. This operating mode allows you to be independent of the location of the server used.

- If a directory path is specified in the database schema description, in the description of the tables found in the database schema or in the project description, this path must be relative to the directory of the application database on the server.

- The tables accessed by an HFSQL server are accessible via this server only. They cannot be directly accessed by another application especially via the HFSQL Classic engine. A connection to the server is required to access these tables.



<a name="NOTE2_3"></a>


### Managing the integrity constraints
<a name="managing_the_integrity_constraints_ELTPARAGRAPHE000061"></a>

If an ISAM HFSQL application was modified into an HFSQL Client/Server application by creating the tables on the server, the integrity constraints are supported.

If an ISAM HFSQL application was modified into an HFSQL Client/Server application without creating the HFSQL tables on the server (by simple copy), the integrity constraints are not managed.

Several methods can be used to **manage the integrity constraints in your HFSQL application**:

- Use the [HAddLink](../WDLang4/3044312.md) function. 

- Perform the automatic modification of the tables when installing the application. The automatic modification of the tables is used to create the integrity constraints on the server.

## Importing the structures
<a name="importing_the_structures_ELTTEXTE000209"></a>
It is also possible to import file structures from an existing HFSQL server into a database schema: in the "Database schema" pane, in the "Creation" group, pull down "Import" and select "Import/table file descriptions".

## Limitations
<a name="limitations_ELTTEXTE000233"></a>
The management mode of tables may have to be adapted when using a HFSQL Client/Server application. To learn more about the specific features to be taken into account, see [Differences and limitations specific to an HFSQL Client/Server application](../WDLang4/3044302.md).
