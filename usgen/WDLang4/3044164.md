


## HChangeLogDir (Function)

***In french: HChangeRepJnl***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Modifies the location of log files corresponding to an HFSQL table (\*JNL files as well as JournalOperation and JournalIdentification files if they exist).

**Reminder** The JournalOperation and JournalIdentification files are created only:

- if the management of replication is requested for the table.

- if the management of the selected log corresponds to "Write-to-file log and history of accesses".




The \*JNL file is not created if only the log of access history is requested.

By default, the physical files corresponding to the logs are created:

- in the directory specified in the database schema ("Database Schema description", "Logging" tab).

<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=HChangeRepJNL%20-%20HC%20N%B0002.gif)


- in the specified directory when describing the table ("Table description" option in the context menu, "Logging" tab). This option is available only if the database schema directory corresponds to "&lt;Default file directory>".

<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=HChangeRepJNL%20-%20HC%20N%B0003.gif)
![HFSQL Client/Server](https://doc.pcsoft.fr/ext/images/us/HFCS.png) **The location of log files cannot be modified. This function is ignored**. The location of the log is configured in the [HFCONF.INI file](../WDLang4/3044345.md). ![Hyper File 5.5](https://doc.pcsoft.fr/ext/images/us/HF55.png) This function has no effect and it always returns <u><u><u>True</u></u></u>.

<a name="sample_code"></a>

## Example


```wl
// "Client" table is logged
HChangeLogDir(Customer, "\\MyServer\Log\JNL", "\\MyServer\Log\Operation")
...
HAdd(Customer)
// -> the "CustomerJNL" file is opened 
// in the "\\MyServer\Log\JNL" directory
//-> the "JournalOperation" and "JournalIdentification" files 
// are opened in the "\\MyServer\Log|Operation" directory
...
```

## Syntax

`<Result> = HChangeLogDir(<Table> , <JNL file location> [, <LogOperation file location> [, <Backup location>]])`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the operation was performed, 

- <u><u><u><u>False</u></u></u></u> if a problem occurs. [HErrorInfo](../WDLang4/3044071.md) is used to identify the error.




**`<Table>: (Character string)`**

Name of the table whose log must be moved. This is the logical name of the table (defined in the data model editor). 
If this parameter is equal to "\*", all the tables found in the current database schema will have their log file moved.

**`<JNL file location>: (Character string)`**

New access path to JNL file associated with the file with logs (full or relative path). 
If this parameter corresponds to an empty string (""), the current file location is not modified.

**`<LogOperation file location>: (Optional character string)`**

New path for JournalOperation file and JournalIdentification file associated with log table (full or relative path). The JournalOperation file contains all the operations performed on the logged table. 
If this parameter is not specified or is an empty string (""), the current file location is not modified.

**`<Backup location>: (Optional character string)`**

Path of backups of log files. By default, this path corresponds to: &lt;répertoire des fichiers JNL&gt;\\__JNLBackup

This path is used during the automatic table modification to archive the logs. [HHistoryModification](../WDLang4/3044344.md) will also search for change history in these files.

If this parameter corresponds to an empty string (""), the current location is not modified.

If this parameter corresponds to a relative path (and starts with a dot), the path will be relative to tables.

## Remarks


### Priority for defining the location of log files
<a name="priority_for_defining_the_location_log_files_ELTPARAGRAPHE000119"></a>

The location of log files is defined according to the following priority order:

1. Location specified when creating the log table (function [HCreation](../WDLang4/3044255.md)).

2. Location specified by **HChangeLogDir**.

3. Location specified in the database schema.

4. Location of the logged table.



<a name="NOTE0_2"></a>


### The log file exists when HChangeLogDir is used
<a name="the_log_file_exists_when_docparampagetitleshort_used_ELTPARAGRAPHE000138"></a>

If the log file already exists when the function is called **HChangeLogDir**function, this log file is no longer used: a log file is created at the specified location and associated with the logged HFSQL table.

**Using the [HDeclareExternal](../WDLang4/3044204.md) function with a journaled table** If an application uses the [HDeclareExternal](../WDLang4/3044204.md) function on a logged table, changes made by this application are recorded in the log files specified in the header of the logged HFSQL table.
<a name="NOTE0_3"></a>


### Miscellaneous
<a name="miscellaneous_ELTPARAGRAPHE000159"></a>

- If the tables are opened when the directory is modified, the tables are automatically closed.

- If the path of the log is redefined several times by **HChangeLogDir**, only the last path is used. The change is effective for all applications using the log file.



<a name="NOTE0_4"></a>


### Replication and log process
<a name="replication_and_log_process_ELTPARAGRAPHE000171"></a>

If [HInitSubscriber](../WDLang4/3044013.md) is used, the location of logs and operation tables must also be initialized (**HChangeLogDir**, [LogDirectory](../Proprietes/2512075.md) and [OperationLogDirectory](../Proprietes/2512076.md)).

**Reminder** Replication is based on logs and tables of operations in tables. The replication fails if the location of the logs and operation tables is invalid.
