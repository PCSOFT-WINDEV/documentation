
## Unalterable tables
			

<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000223"></a>
This feature is used to signal that a table cannot be modified after writing. Once a record is added, this record cannot be modified or deleted.

This type of table is useful in the fields that require strong traceability. HFSQL automatically signs each record as well as the table itself.

Inalterability of tables: 

- avoids programming errors by preventing modification or deletion (via [HModify](../WDLang4/3044042.md)/[HDelete](../WDLang4/3044018.md), or via a query). 

- adds a hash of the record content to each record. This hash is an HMAC(SHA256) whose key is derived from the table's encryption password.




Remarks: 

- To reinforce the security, we advise you to implement a password on the unalterable table. In this case, the table cannot be created without knowing the password. It will not be possible to delete and recreate the table without knowing this password.

- Use unalterable tables with PERC servers: 
	In this case, writing to the table may be slower. This slowness is amplified when reindexing an unalterable table with deleted records (very rare case).

## Defining an unalterable table
<a name="defining_unalterable_table_ELTTEXTE000247"></a>
You have the ability to define an unalterable HFSQL table:

- in the data model editor: 

	1. Open the table description window (for example, "Description of table" option in the context menu). 

	2. On the "Options" tab, check "Unalterable table (automatically enables enhanced security)". <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Fichiers%20de%20donn%E9es%20inalt%E9rables%20-%20HC%20N%B0001.gif&type=thumb)


	3. Validate the description of table. In the data model editor, the unalterable table is represented with a lock. <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Fichiers%20de%20donn%E9es%20inalt%E9rables%20-%20HC%20N%B0002.gif)

- programmatically, by defining a table dynamically:

	1. Create a variable of type [File description](../WDLang4/1514065.md). 

	2. Use the [Unalterable](../Proprietes/1000023376.md) property to define the file unalterability. 

	3. Use [HDescribeFile](../WDLang4/3044206.md) to create the file description. 







Remarks: 

- If the table is defined as being unalterable with password, the reinforced security is automatically implemented.
	Reminder: the "Enable enhanced security " option is used to encrypt data without storing the encryption key in the table. With this option and without the file password, the file content cannot be retrieved.

- If the "Unalterable table" option is set on an existing table, the tables will be updated automatically. The existing table will be compressed (deletion of crossed and deleted records) during this update. 
	**Caution: Once a table is unalterable, no further automation can be performed on it**.

- This option is available from version 23. For the HFSQL Client/Server tables, an HFSQL C/S engine in version 23 (or later) must be used.

## Operations that can be performed (or not) on an unalterable table
<a name="operations_that_can_performed_not_unalterable_table_ELTTEXTE000271"></a>
The only operations that can be performed on an unalterable table are the creation and the addition of records. 

**The authorized functions and features** are as follows: 

- [HCreation](../WDLang4/3044255.md) and [HCreationIfNotFound](../WDLang4/3044254.md). 

- [HAdd](../WDLang4/3044147.md) (outside transaction). 

- [HWrite](../WDLang4/3044092.md) with a record number only if the record number is the one that follows the last record (in this case, an addition is performed). 

- [HModify](../WDLang4/3044042.md) with a record number only if the record number is the one that follows the last record (in this case, an addition is performed). 

- [HSave](../WDLang4/1000021375.md) preceded by [HReset](../WDLang4/3044118.md) (in this case, an addition is performed). 

- INSERT queries.




**The forbidden functions and features** are as follows: 

- [HModify](../WDLang4/3044042.md), [HCross](../WDLang4/3044121.md), [HWrite](../WDLang4/3044092.md), [HSave](../WDLang4/1000021375.md), [HDelete](../WDLang4/3044018.md), [HDeleteAll](../WDLang4/1000017331.md). 
	Indeed, these functions modify the content of tables. 

- **UPDATE and DELETE queries**. 
	Indeed, these queries modify the content of tables. 

- **Any modification to the contents of the table** (by whatever means). 

- **The reindex operation with compression or deletion of damaged records**. 
	Indeed, this type of reindex operation deletes all inactive or damaged records. Therefore, the table can be modified. 

- **The addition in a transaction**. 
	Indeed, canceling a transaction triggers the modification of table. 

- **The automatic modification of tables**. 
	Indeed, modifying the structure of a table (item addition or deletion for example) can modify the data found in the table. 
	For example, adding an item with a default value will modify all records by adding this new item to them. Similarly, deleting an existing item deletes information from the saved data. The data integrity is guaranteed anymore.
	


A runtime error occurs if one of these functions or features is used. 

Note: The [HCheckUnaltered](../WDLang4/1000023377.md) function can be used to check that one or all records in an unalterable table have not been modified (e.g. with a hexadecimal editor). Warning: A corrupted record can be read (if the header is not corrupted). 

**How to manage an automatic data modification?** 
The automatic table modification is not allowed. When a new application version contain an evolution of structure of records found in an unalterable HFSQL tables, this application version will have to:

- manage the archiving of table in its earlier format,

- create a new table with the new structure.


**Reminder**: An application can consult the data in an HFSQL table of an older structure by using the [HCheckStructure](../WDLang4/3044068.md) function in *hCompatible mode.*. If the table is incompatible due to the change in structure, it will be possible to use the archived table in its old format with the new application after calling the [HDeclareExternal](../WDLang4/3044204.md) function.
