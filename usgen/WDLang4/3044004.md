


## HFlush (Function)

***In french: HForceEcriture***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Forces the operating system of the computer where the tables are found to write data onto the disk. The HFSQL context of the manipulated table is preserved (blocking, current path, etc.).

**Note** If used regularly, this function minimizes data loss caused by unexpected shutdowns of the workstation on which the tables are stored (e.g. power cuts).

![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) This function is available for HFSQL tables only. It is not available for the tables accessed by JDBC.

## Example


```wl
// Add a record in a table
// (record described through programming)
Customer.LastName = "Clark"
Customer.FirstName = "Vince"
Customer.Address = "Palm lane"
Customer.City = "San Francisco"
Customer.Zip = "94102"
Customer.Country = "USA"
HAdd(Customer)
// Forces a write operation into Customer file
HFlush(Customer)
```

<a name="XSYNTAXE"></a>
<a name="SYNTAXE1"></a>

## Syntax

`HFlush(<Table>)`
---

**`<Table>: (Character string)`**

Name of the table used. 
If this name is not specified, **HFlush** will use the last table used by the last HFSQL function (function starting with "H").
If this parameter corresponds to "\*", **HFlush** will be applied to all open tables.
**Warning** In this case, execution of the function may take a long time.
This parameter can also correspond to the name of a [group of files (or custom-folder) defined in the database schema](../Editeurs/2011003.md) (not available in Android and Android widget).

### Managing locks
<a name="managing_locks_ELTPARAGRAPHE000091"></a>

During the call to **HFlush**, the table used is closed and re-opened. If locks were implemented on this table before it was closed, these locks are automatically restored when it is re-opened. Indeed, when closing a table, the operating system deletes the locks implemented on this table.

**Remark**: We therefore advise against calling this function too often on:

- tables on which an important number of locks is implemented.

- tables on which an important number of write operations is implemented.



<a name="NOTE0_2"></a>


### HSecurity and HFlush
<a name="hsecurity_and_docparampagetitleshort_ELTPARAGRAPHE000109"></a>[HSecurity](../WDLang4/3044135.md) and **HFlush** can both be used to force a physical write operation on disk.

However:

- [HSecurity](../WDLang4/3044135.md) is used to force a write operation into the tables used during each write operation. The HFSQL engine automatically performs the write operation. The tables are not closed during this write operation. This results in slower write speeds.

- **HFlush** forces the table(s) to be written when it is called. The tables are closed and then re-opened during this write operation. The write operation is not slowed down.
