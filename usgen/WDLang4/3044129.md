


## HSeekLast (Function)

***In french: HRechercheDernier***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Sets the position on the last table record whose value for a specific item is less than or equal to a sought value. ***The record is not read***.
The number of the current record is modified only when it is returned by [HRecNum](../WDLang4/3044063.md). For functions handling the current record number by default (functions [HDelete](../WDLang4/3044018.md), [HRead](../WDLang4/3044047.md), [HModify](../WDLang4/3044042.md), ...), the value of this number is not updated: you must use the [HRecNum](../WDLang4/3044063.md)() function. For example: do not: 

```wl
HDelete(Customer)
```
but 

```wl
HDelete(Customer, HRecNum())
```

Reading is done from the smallest to the largest value of the browse item (see notes for details).

**Attention**: ***Record loaded into memory is not modified***. The HFSQL variables (for example Customer.Name, i.e. the *Name* item of the *Customer* file) are not updated.

In most cases, **HSeekLast** sets the position in the table to loop through the records that match a condition.

Several cases may occur after the call to **HSeekLast**:

- a Record corresponding to the condition has been found, blocked (if necessary) and loaded into memory: function [HFound](../WDLang4/3044104.md) returns <u><u><u>True</u></u></u>. 

- the table is empty or there is no record corresponding to the condition: function [HOut](../WDLang4/3044094.md) returns <u><u><u>True</u></u></u>.

- the function attempts to block a record already blocked in play mode: function [HErrorLock](../WDLang4/3044099.md) returns <u><u><u>True</u></u></u> and function [HOut](../WDLang4/3044094.md) returns <u><u><u>True</u></u></u>.




**Note**: the search can be cancelled by pressing [HCancelSeek](../WDLang4/3044157.md).


<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
// Find the last record for which the Customer name is Moore
HSeekLast(Customer, Name, "Moore")
```
<a name="Exemple2"></a>

```wl
// This example is used to find all the customers 
// whose turnover is less than a specific value. 
HSeekLast(Customer, Turnover, X)
WHILE NOT HOut(Customer)
	AddCustomerList()
	HPrevious(Customer, Turnover)
END
```

## Syntax

`<Result> = HSeekLast(<Table> , <Key item> , <Search value> [, <Options>])`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the position was set on the record (corresponds to the value of [HFound](../WDLang4/3044104.md)). 

- <u><u><u><u>False</u></u></u></u> if a problem occurs. This problem can be caused by:

	- or a positioning problem (empty table, etc.): function [HFound](../WDLang4/3044104.md) returns <u><u><u><u>False</u></u></u></u> and function [HError](../WDLang4/3044088.md) returns 0.

	- an error: [HError](../WDLang4/3044088.md) returns an integer other than 0. [HErrorInfo](../WDLang4/3044071.md) returns more details.







**`<Table>: (Character string)`**

Name of the HFSQL table used.

**`<Key item>: (Character string)`**

Name of key item on which the search will be performed.

**`<Search value>: (Type corresponding to the value)`**

Value of the sought item.

**`<Options>: (Optional constant (or combination of constants))`**

Configures:

- the lock mode applied to the sought record

- the type of search performed.





|   |   |
| --- | --- |
| *hGeneric* | Generic search (see the Notes)<br>An exact-match search is performed by default (constant not specified). |
| *hKeepFilter* | The filter set by [HFilter](../WDLang4/3044100.md) will be taken into account, even if the search key is not optimized for the filter. Reminder: [HFilter](../WDLang4/3044100.md) returns the optimized search key for the filter.<br>**Caution**: In this case, on large tables, performance problems may occur..<br>![Hyper File 5.5](https://doc.pcsoft.fr/ext/images/us/HF55.png) This variable cannot be used.By default, the iteration performed after **HSeekLast** ignores the filter. |
| *hLimitParsing* | The iteration will stop when the last searched value is found. The current record will correspond to this last record found.<br>[HFound](../WDLang4/3044104.md) will be set to <u><u><u><u>False</u></u></u></u> and [HOut](../WDLang4/3044094.md) will be set to <u><u><u><u>True</u></u></u></u>.<br>This constant is used to optimize the search speed in Client/Server mode. |
| *hLockNo* | No blocking: the Record can be played back or modified by another application during playback. |
| *hLockReadWrite* | Read/write blockage: the record can neither be read nor modified by another application.<br>![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png) Lock in write-only. Operating mode equivalent to the *hLockWrite* constant. |
| *hLockWrite* | Lock in write mode: the record can be read by another application, but cannot be modified by another application. |

![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) Access through JDBC: This parameter is ignored.![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png)![Native Connectors (Native Accesses)](https://doc.pcsoft.fr/ext/images/us/AN.png) The lock options will have no effect if the locks are not supported by the OLE DB provider or by the Native Connector.![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png) The lock mode specified by **HSeekLast** will remain effective during the calls to [HPrevious](../WDLang4/3044112.md) and [HNext](../WDLang4/3044027.md).

To change the lock mode, use:

- [HSeekFirst](../WDLang4/3044125.md) or **HSeekLast**,

- [HLast](../WDLang4/3044101.md) or [HFirst](../WDLang4/3044113.md).

## Remarks


### Generic search/Exact-match search
<a name="generic_searchexactmatch_search_ELTPARAGRAPHE000268"></a>

- **Generic search** (mainly for string fields): ***Finds all records beginning with the specified value***. 
	For example: When performing a generic search for the string "Martin" in the NAME field, all records whose Name field begins with "Martin" will match the search. Therefore, the record containing "Smither" will correspond to the search (**HFound** returns <u><u><u><u>True</u></u></u></u>).

- **Exact-match search**: ***Finds all records exactly matching the specified value***. 
	For example: When performing an exact-match search on the "Matin" channel for the NAME item, the function **HFound** returns <u><u><u><u>True</u></u></u></u> only for records where the field is exactly "Martin".

- Examples or searches performed on CUSTOMER file sorted by name: <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=hlitrechpremier.gif)






|   |   |   |   |   |   |
| --- | --- | --- | --- | --- | --- |
| Search value | Options | **HSeekLast** sets the position on the record | **HFound** returns | HOut returns | Explanations |
| Durand |   | 6 | True | False | Durand exists.<br>The beginning of table was not reached yet. |
| Dupuis |   | 5 | False | False | Dupuis does not exist. Positioning on the first lower value (Moore).<br>The beginning of table was not reached yet. |
| Moor | hGeneric | 5 | True | False | Moor does not exist but the search is generic, and Moore is found (among others).<br>The beginning of table was not reached yet. |
| Moor |   | The record was not found (no move) | False | False | Moor does not exist.<br>The beginning of table was not reached yet. |
| Bernard |   | The record was not found (no move) | False | True | Bernard does not exist.<br>Position on first lower value (this value does not exist): The start of the table is reached. |

### Performing a search on a composite key
<a name="performing_search_composite_key_ELTPARAGRAPHE000369"></a>

Several methods can be used to perform a search on a composite key:

- Using a list of values.

- Use the [HBuildKeyValue](../WDLang4/3044258.md) function.




**Using a list of values**

The following syntax is used to perform a search on a composite key:


```txt
HSeekLast(<File name>, <Name of composite key>, ...
	[<Search value of first element of composite key>, 
	<Search value of first element of composite key>, ...])
```
Example:

```wl
// Find the record
HSeekLast(Customer, LastName_FirstName, ["Moore", "Vince"])
```
![Hyper File 5.5](https://doc.pcsoft.fr/ext/images/us/HF55.png) To perform generic searches on a composite key, all the components of composite key must be Text components. Otherwise, an exact-match search is performed.
<a name="NOTE0_3"></a>


### Search on an array item
<a name="search_array_item_ELTPARAGRAPHE000400"></a>

The search is performed on the first array element (element with index 1). To perform a search on the other array elements, use the filters or queries.
<a name="NOTE0_4"></a>


### Search and filter
<a name="search_and_filter_ELTPARAGRAPHE000409"></a>

If a filter is enabled ([HFilter](../WDLang4/3044100.md)), the search takes the filter into account.
![Hyper File 5.5](https://doc.pcsoft.fr/ext/images/us/HF55.png) If a filter is enabled, the filter is ignored by the search.

### Locks
<a name="locks_ELTPARAGRAPHE000426"></a>

The locks apply only when a record was found.

By default (no lock mode specified in &lt;Options&gt;), the record is not locked.

If a lock is requested (*hLockWrite* or *hLockReadWrite* constant), the record will be read only if this record is not already locked.

**Reminder** A blocked Record can be unlocked by pressing [HUnlockRecNum](../WDLang4/3044194.md).

![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png)![Native Connectors (Native Accesses)](https://doc.pcsoft.fr/ext/images/us/AN.png) The lock options will have no effect if the locks are not supported by the OLE DB provider or by the Native Connector.
