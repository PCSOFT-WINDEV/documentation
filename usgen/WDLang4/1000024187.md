


## &lt;Source&gt;.Add (Function)

***In french: &lt;Source&gt;.Ajoute***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Adds: 

- the record found in memory into the table (query or view).

- ![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png)![WEBDEV - Server code](https://doc.pcsoft.fr/ext/images/us/WBS.png)![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![Android Widget ](https://doc.pcsoft.fr/ext/images/us/ANDROIDWIDGET.png) the record found in a [Record](../WDLang4/1000020962.md) variable into the table (query or view).




The indexes corresponding to all the keys used in the table are automatically updated. The possible memos are added if the management of memos is enabled ([&lt;Source&gt;.SetMemo](../WDLang4/1000024987.md)).

After the call to **&lt;Source&gt;.Add**:

- Automatic error handling is available for several types of error: Duplicate error, Integrity error, Password error, Modification conflict and status error during modification conflict, Blocking error, etc. For more details, see [HFSQL error handling help](../WDLang4/3044188.md).

- If the management of duplicates is enabled and if the table contains a unique key, [HErrorDuplicates](../WDLang4/3044077.md) returns <u><u><u>True</u></u></u> if the value of added key is not unique. The record is not added.

- The added record becomes the current record. The automatic identifier is automatically filled. By default, the current iteration is not affected.




**Note** The entire record in memory is written to the table with the values assigned to it (and failing that, the contents of the previously read record). To clear the values from the record in memory, all you have to do is use [&lt;Source&gt;.Reset](../WDLang4/1000025052.md).

## Example


```wl
// Add a record in a table
// (record described through programming)
Customer.LastName = "Clark"
Customer.FirstName = "Vince"
Customer.Address = "Palm Lane"
Customer.City = "Philadelphia"
Customer.Zip = "19101"
Customer.Country = "USA"
Customer.Add()
```

## Remarks


### Managing automatic identifiers
<a name="managing_automatic_identifiers_ELTPARAGRAPHE000703"></a>

By default, the "automatic identifier" item is automatically updated when a record is added into a table. There is no need to read the record again to find out the value of the automatic identifier. Simply use the syntax &lt;Nom Fichier de données&gt;.&lt;Nom rubrique Identifiant automatique&gt;.

The constants *hForceIdAuto* and *hFixeIdAuto constants* constants are used to modify the default behavior of the automation identifier.

For more details on automatic identifiers for new records, see [Managing the automatic identifier during an addition](../WDLang4/3044183.md).

![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![Android Widget ](https://doc.pcsoft.fr/ext/images/us/ANDROIDWIDGET.png)![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png)![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png)![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png)![Native Connectors (Native Accesses)](https://doc.pcsoft.fr/ext/images/us/AN.png) **Special case**


- **If the database generates an automatic identifier**, the HFSQL engine keeps this value. If the constants *hForceIdAuto* or *hFixeIdAuto* constants are specified, the HFSQL engine replaces the generated value with the desired value. 
	Note: the constant *hForceIdAuto* is equivalent to *hFixeIdAuto*: the automatic identifier calculated by the HFSQL engine the next time a table is added will be unique in the table.

- **If no automatic identifier is generated by the database**, the HFSQL engine generates the value and assigns it to the automatic identifier.

### Reusing the deleted or freed records
<a name="reusing_the_deleted_freed_records_ELTPARAGRAPHE000732"></a>

When adding a new record, the HFSQL engine optimizes the filling of the table. The space corresponding to the deleted or freed records is used first when a new record is added.

The crossed records are not re-used.

### Version of table after an addition
<a name="version_table_after_addition_ELTPARAGRAPHE000746"></a>

If the record was added to the table (no duplicate error and no integrity error), the version number of the table is modified. To get the version number, use [&lt;Source&gt;.Version](../WDLang4/1000025082.md).
<a name="NOTE0_4"></a>


### Adding a record into a query
<a name="adding_record_into_query_ELTPARAGRAPHE000761"></a>

Adding a record into a query can be performed:

- in the query result.

- in the tables handled by the query (*hModifyFile* constant used in [&lt;Source&gt;.ExecuteQuery](../WDLang4/1000024944.md) or [&lt;Source&gt;.ExecuteSQLQuery](../WDLang4/1000024948.md)). In this case, the *hWithFilter* constant is automatically selected.




Regardless of how the query is executed (with or without the constant *hWithFilter*constant), adding records to a query is only possible for single-file queries. The calculated items specified during the addition are ignored. They are automatically calculated.

Caution:

- No addition is allowed in a query that uses groups or aggregates.

- Integrity and duplicates are not managed by operations on multi-file queries: it is advisable to use transactions to avoid any problems.

### Adding records into a view
<a name="adding_records_into_view_ELTPARAGRAPHE000793"></a>

You have the ability to add records into a view created on tables in HFSQL Classic format. These records are added in memory only. To add them into the table linked to the view (simple view for example), you must use [&lt;Source&gt;.ViewToFile](../WDLang4/1000025084.md).
<a name="NOTE0_6"></a>


### Browsing and adding records
<a name="browsing_and_adding_records_ELTPARAGRAPHE000808"></a>

You can configure the effect of adding a record during the browse of a table (*hWriteDefault* and *hAffectBrowse* constants). The behavior of earlier versions can be kept with the *hAffectBrowse* constant.

### Slowness when adding or deleting a record for the first time in an HFSQL table
<a name="slowness_when_adding_deleting_record_for_the_first_time_hfsql_table_ELTPARAGRAPHE000824"></a>

Accessing a record in an HFSQL table for the first time may take long. To fix this problem:

- Disable antivirus scanning for ".FIC", ".NDX", ".SDX", ".STX", ".MMO" and ".REP" files.

- Disable the "Restore the system" option in Windows XP.
