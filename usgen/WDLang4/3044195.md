


## Automatic table modification
			



<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000316"></a>
The automatic table modification updates the description of tables on user computers.

If the structure of one or more tables has changed on the development seat (adding or deleting fields, modifying fields, etc.), these changes must be transferred to the user seats when the application is updated.

If the application is updated while no automatic data modification is performed, the application found on the end-user computers may:

- no longer operate properly.

- generate programming errors.




![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) **Warning**: In the case of a network update with automatic modification of tables, installation of the application update on user seats is mandatory.

**Remarks**: 

- The automatic table modification can be performed programmatically with [HModifyStructure](../WDLang4/1000019439.md). 

- ![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png) The automatic data modification can only be performed by [HModifyStructure](../WDLang4/1000019439.md).

## Performing the automatic modification of tables
<a name="performing_the_automatic_modification_tables_ELTTEXTE000376"></a>


### Development computer
<a name="development_computer_ELTPARAGRAPHE000109"></a>

The automatic table modification is systematically performed when the database schema is generated on the development computer.

**To apply the automatic modification to the tables on the end-user computers**, the automatic modification must be performed when installing the update of the application or site. The setting of this automatic modification can be done:

- by [the setup program creation wizard](../Editeurs/2028043.md).

- in [the setup editor (WDInst)](../Editeurs/2028018.md).

- using [HModifyStructure](../WDLang4/1000019439.md) in the initialization code of the project, for example.




Note: If required, automatic modification of tables can also be performed during table synchronization via [universal replication](../WDLang4/9000032.md) or [assisted replication](../WDLang4/9000045.md).
<a name="NOTE3_2"></a>
![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png)![Windows](https://doc.pcsoft.fr/ext/images/us/WINDOWS.png)![HFSQL Classic](https://doc.pcsoft.fr/ext/images/us/HF.png)![HFSQL Client/Server](https://doc.pcsoft.fr/ext/images/us/HFCS.png)![Hyper File 5.5](https://doc.pcsoft.fr/ext/images/us/HF55.png) 

### Deployment computer
<a name="deployment_computer_ELTPARAGRAPHE000145"></a>

When installing an update, the user will be able to configure the automatic modification by clicking the "Advanced" button. This button appears in the first window of the setup program. The following window is displayed:
<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=FENMODIFAUTO.GIF)


This window allows you to:

- create a report of the operations performed by the automatic data modification. If a problem occurs, this file can be given to the application manager. 
	By default, this file is named "LOGMODAUTO.TXT" and it is created in the installation directory of the application.

- list the HFSQL tables on which the automatic modification will be performed. You will have the ability to add to this list:

	- additional tables.

	- additional directories containing tables.




- specify additional directories containing tables in Hyper File 5.5 format that are not automatically found during the update.




**Remarks**:

- During the update, the tables automatically found are:

	- tables in the application installation directory.

	- tables listed in the ".REP" file. For more details, see the help about the [management of .REP files](../WDLang4/3044186.md).




- To prevent the user from accessing the options used to configure the automatic modification, the setup editor WDInst allows you to make the "Advanced" button invisible in the setup program.

## Notes
<a name="notes_ELTTEXTE000412"></a>


### Running the automatic table modification several times
<a name="running_the_automatic_table_modification_several_times_ELTPARAGRAPHE000192"></a>

The automatic modification will have no effect on the application if it is performed on data that is already updated.

### Default configuration of setup program
<a name="default_configuration_setup_program_ELTPARAGRAPHE000201"></a>

If the application is associated with a database schema, the setup program proposes to perform the automatic modification of the tables. The user can access the options used to configure the automatic modification by clicking the "Advanced" button.
<a name="NOTE4_3"></a>


### Saving tables
<a name="saving_tables_ELTPARAGRAPHE000208"></a>

The tables of the application are automatically backed up before the automatic modification is performed. The backup directories are named:

- "Save Modif Auto (&lt;DateModifAuto&gt; &lt;HeureModifAuto&gt;)" if you want automatic modification of tables in Hyper File 5.5 or HFSQL Classic format.

- "Files before conversion (&lt;DateModifAuto&gt; &lt;HeureModifAuto&gt;)" if tables are migrated from a Hyper File 5.5 to a HFSQL Classic.

### Force automatic modification of tables
<a name="force_automatic_modification_tables_ELTPARAGRAPHE000220"></a>

The automatic modification of the tables can be performed at any time on the development computer.

In some cases, automatic data modification may not be carried out correctly: tables present on a laptop not connected to the network at the time of update, faulty update, etc. In such cases, it is necessary to force automatic data modification in order to use the application. To do so, **WDModFic** must be used. For more details on this tool, see [WDModFic: Tool for automatic modification of tables](../WDLang4/3044270.md).
<a name="NOTE4_5"></a>


### Database schema shared between several applications and sites
<a name="database_schema_shared_between_several_applications_and_sites_ELTPARAGRAPHE000232"></a>

For a database schema shared between several applications or sites, after the automatic modification of tables, all the executables and sites that share the database schema must be updated. However, it is possible to authorize an application or site to use a more recent table description, using the [HCheckStructure](../WDLang4/3044068.md) function.
**"Live" modification of tables**
The modification of the tables can be performed even if applications are accessing these tables. 
During the modification of the tables, the different applications that handle the tables continue to operate.

The application will no longer operate if the modifications are not compatible (deleting a key, deleting a unique key, deleting identifiers, deleting tables or items, modifying the format of an item, ...)

During the first access to a table whose structure is not compatible, an error indicates that the structure of the table differs from the structure of the database schema.
In the case of adding fields, adding keys or adding tables, the application will continue to function normally (unless the function [HCheckStructure](../WDLang4/3044068.md) has been used with the constant *hIdentique*).


### Access rights to the table
<a name="access_rights_the_table_ELTPARAGRAPHE000258"></a>

The modification of the tables provokes the recreation of the table on disk. In an allocation system that manages rights at file level (NTFS...), the table after automatic modification will therefore have the rights of the directory to which it belongs.

Before the automatic modification, if the table had specific rights different from the rights of the folder, they must be redefined in Windows after the modification.


### Limitation
<a name="limitation_ELTPARAGRAPHE000265"></a>

The automatic table modification operates for the tables with indexes only.

Reminder: it is possible to create tables without an Index field.
