


## HCopyFile (Function)

***In french: HCopieFichier***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Copies an HFSQL table (.fic, .ndx, .ftx, .sdx and .mmo files, if any):

- from the HFSQL server to the server (to perform a backup for example).

- from the HFSQL server to the client (to perform a local backup for example).

- from the client to the HFSQL server (to update the tables for example).

- from an HFSQL server to another HFSQL server. 







<a name="sample_code"></a>

## Example
<a class="notetitle" target="_blank" href="$DOC$=1000021620&name=hcopyfile_function">See additional examples</a>
<a name="Exemple1"></a>

```wl
// Copy the tables from server to server
// while renaming and changing directory
HCopyFile(MyConnection, ".\backup\customerfile_bck.fic", MyConnection, ".\customerfile.fic")
```
<a name="Exemple2"></a>

```wl
// Copy the tables from the server to the client computer
HCopyFile("", "C:\Data\Customer.fic", MyConnection, "customer.fic")
```
<a name="Exemple3"></a>

```wl
// Copy the tables from the client computer to the server
HCopyFile(MyConnection, "customer.fic", "", "C:\Data\Customer.fic")
```
<a name="Exemple4"></a>

```wl
// Copies the table(s) from a server to another server
HCopyFile("CNT", "customer.fic", "CNT2", "dir\customer.fic", hNoIndex, PROGBAR_MyProgressBar)
```
<a name="Exemple5"></a>

```wl
// Copy the CUSTOMER table to itself (save)
sMyDestinationDirectory is string = CompleteDir(fExeDir()) + "TestDirectory"
IF NOT fDirectoryExist(sMyDestinationDirectory) THEN fMakeDir(sMyDestinationDirectory)
HCopyFile("", sMyDestinationDirectory + "CUSTOMER.FIC", "", ...
		CompleteDir(fExeDir()) + "CUSTOMER.FIC", hCopyIndex)
```

## Syntax

`<Result> = HCopyFile(<Destination connection> , <Destination table> , <Source connection> , <Source table> [, <Copy mode> [, <Progress Bar control> [, <Password>]]])`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the table was copied, 

- <u><u><u><u>False</u></u></u></u> if an error occurs. [HError](../WDLang4/3044088.md) is used to identify the error.




**`<Destination connection>: (String or Connection variable)`**

Connection to which the table must be copied. This connection corresponds to:

- the name of the connection defined in the data model editor or with [HDescribeConnection](../WDLang4/3044205.md) or [HOpenConnection](../WDLang4/3044107.md).

- the name of a variable of type [Connection](../WDLang4/1514073.md).

- the DNS of an HFSQL cluster or the node of an HFSQL cluster (for a copy to an HFSQL cluster).


If this parameter corresponds to an empty string, the destination will be the local computer. 

**`<Destination table>: (Character string)`**

Name and path of destination table. The path and this table is automatically created if they do not exist on the server. 
If the destination table is found on the server, the path is relative to the database schema.
Please provide the text you want transformed. 

**`<Source connection>: (String or Connection variable)`**

Connection from which the table must be copied. This connection corresponds to: 

- the name of the connection defined in the data model editor or with [HDescribeConnection](../WDLang4/3044205.md) or [HOpenConnection](../WDLang4/3044107.md).

- the name of a variable of type [Connection](../WDLang4/1514073.md).




**`<Source table>: (Character string)`**

Name and path of the source table (to copy). If the source table is found on the server, the path is relative to the database.
Caution: 

- the '.fic' table extension must be specified.

- the '.mmo' file, if any, will be automatically copied. 




**`<Copy mode>: (Optional Integer constant)`**

Copy mode used:



|   |   |
| --- | --- |
| *hCopyIfNotFound* | Copies the table only if it does not exist at the specified location on the destination computer. |
| *hCopyIndex* | Table indexes are copied (NDX, SDX and FTX files, if any). |
| *hCreateIndex* | Table indexes are not copied (NDX, SDX and FTX files, if any). They are automatically recreated on the destination via a reindex operation. <br>If the table is password-protected, the &lt;Password&gt; parameter must be specified. |
| *hNoIndex* | Table indexes are not copied (NDX, SDX and FTX files, if any). |



**`<Progress Bar control>: (Optional control name)`**

Name of Progress Bar control found in the window, used to show the progress of copy.

**`<Password>: (Optional string or Secret string)`**

File password (if it exists). This password is required if the *hCreateIndex* constant is used.
**Secret strings**: If you use the secret string vault, the type of secret string used for this parameter must be "ANSI or Unicode string".
To learn more about secret strings and how to use the vault, see [Secret string vault](../Editeurs/1410087353.md).

## Remarks


### Operating mode of HCopyFile
<a name="operating_mode_docparampagetitleshort_ELTPARAGRAPHE000232"></a>

- The copied table is unlocked, as well as the records found in the table.

- The index is not copied if it does not exist or if it is corrupt.

- The password is not required to copy the table. However, the copied table remains password-protected.

- It is not possible to copy tables to a source server of a SPARE replication server. 

- Transaction table: before copying the table, it is advisable to:

	- lock the table in read/write ([HLockFile](../WDLang4/3044153.md)).

	- cancel the interrupted transactions ([HTransactionCancel](../WDLang4/3044001.md)).






<a name="NOTE0_2"></a>


### Use conditions
<a name="use_conditions_ELTPARAGRAPHE000255"></a>

- You can also copy a table in the same client computer. In this case, this function is equivalent to [fCopyFile](../WDLang1/3036004.md).

- This function is used to copy files to an HFSQL server (in Client/Server mode). This function cannot be used with an external server (Oracle or other).

- To copy an HFSQL table from a local computer to the server (or vice versa), all users must first release the table. No connection to the table must be in progress, or the copy will fail. If you are unable to unlock these records, use the scheduled backups of the HFSQL Control Center.




Otherwise, to avoid any connection to the table, you can:

- Block access to the database ([HNoDatabaseAccess](../WDLang4/3044286.md)), 

- Disconnect clients ([HDisconnectClient](../WDLang4/3044339.md)),

- Copy the tables ([HCopyFile](../WDLang4/3044282.md)),

- Restore access to the database ([HEndNoDatabaseAccess](../WDLang4/3044287.md)). 




- **Replicated tables (replication between servers)**: 
	**HCopyFile** cannot not be used to copy replicated tables to the server. However, a table can be copied from the server to the client computer. 

- **HFSQL cluster**

	- If the tables to be copied use enhanced security, you need to specify the password of the table password with the &lt;Password&gt; parameter. This password is required to synchronize tables on the different nodes. 

	- To use **HCopyFile** with an HFSQL cluster, it is necessary that both the HFSQL cluster and the client application use at least version 2024 Update 1. 






<a name="NOTE0_3"></a>


### Names of tables and directories on the server
<a name="names_tables_and_directories_the_server_ELTPARAGRAPHE000302"></a>

- The names of the tables on the server (.fic, .ndx, .ftx, .sdx and .mmo files, if any) must not contain accented characters.

- On a LINUX server, the name of the tables must be written in lowercase characters.
