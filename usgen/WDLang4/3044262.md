


## Native xBase/FoxPro Connector
			



<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000276"></a>
WINDEV and WEBDEV offer a Native xBase/FoxPro Connector (or Native xBase/FoxPro Access) module. This Native Connector allows you to handle xBase/FoxPro tables from a WLanguage program without using any external driver.

**System requirements**: The following files are supplied as standard with WINDEV and WEBDEV: wd310db.dll. This file is required by the Native Connector on xBase/FoxPro files in order to operate with an HFSQL Classic database schema.

<a name="NOTE2"></a>
<a name="NOTE2_1"></a>


## Using the Native xBase/FoxPro Connector
<a name="using_the_native_xbasefoxpro_connector_ELTTEXTE000300"></a>
To use the Native xBase/FoxPro Connector in your WINDEV or WEBDEV applications: 

1. Import (if necessary) the description of the xBase/FoxPro tables into the WINDEV or WEBDEV database schema.

2. Program with the HFSQL functions of WLanguage.  




The management of xBase/FoxPro tables is similar to the management of HFSQL tables except for the cases explained in this help page.

**Remark**: Don't forget to consult [limitations regarding the use of the Native xBase/FoxPro Connector](../WDLang4/3044249.md).

<a name="NOTE3_1"></a>


## Importing the structure of tables
<a name="importing_the_structure_tables_ELTTEXTE000324"></a>


### The import steps
<a name="the_import_steps_ELTPARAGRAPHE000039"></a>

1. In the data model editor, launch the import wizard: in the "Database schema" pane, in the "Creation" group, pull down "Import" and select "Import file/table descriptions".

2. Select database type: xBase. A connection to the xBase/FoxPro database is automatically established and associated with the tables imported into the database schema. This connection will have to be used to handle the xBase/FoxPro table programmatically.

3. Specify whether the data must be kept in the current format (option required to use the Native xBase/FoxPro Connector).

4. Select the table access mode (xBase Native Connector for WINDEV) and specify the table directory.

5. Select the tables that will be imported into the WINDEV database schema. These tables can be handled through programming with the HFSQL functions of WINDEV. These tables will be displayed in blue in the data model editor.
	Note: the FoxPro databases (.dbc extensions) are not supported. Each table (.dbf extension) must be individually imported into the database schema.  

6. Validate. The tables are imported into the database schema. In the description of the tables, you will find the xBase subtype of the imported table (dBase3+, dBase4, FoxPro/FoxBase, Clipper5, Clipper87).




**Remarks**:

- An item defined as Numeric in FoxPro can be imported as currency into WINDEV and WEBDEV (if the size of the item exceeds the size of a real for example).

- The Logical items in xBase/FoxPro are imported as Text items. Indeed, for a boolean in xBase, you have the ability to specify True and False with the 'T' and 'F' strings.



<a name="NOTE3_2"></a>


### Taking into account the changes of the xBase/FoxPro tables
<a name="taking_into_account_the_changes_the_xbasefoxpro_tables_ELTPARAGRAPHE000070"></a>

To take account of changes to tables imported into the data model editor, in the "Database schema" pane, in the "Database schema" group, pull down "Synchronization" and select "Update database schema from external databases".

A wizard starts, allowing you to:

- analyze the differences for the imported tables, 

- analyze the differences for all the xBase/FoxPro tables.

## The important points regarding the programming
<a name="the_important_points_regarding_the_programming_ELTTEXTE000354"></a>


### New features for managing the xBase/FoxPro tables
<a name="new_features_for_managing_the_xbasefoxpro_tables_ELTPARAGRAPHE000096"></a>

The management of xBase/FoxPro tables is similar to the management of HFSQL tables except for the cases explained in this help page.

**New features for xBase table management since WINDEV 5.5**:

- Managing an automatic identifier.

- Ability to use [HIndex](../WDLang4/3044133.md).

- Management of expressions in [HFilter](../WDLang4/3044100.md).

- Ability to use [HChangeDir](../WDLang4/3044168.md).

- Using the native xBase access with non-Latin character sets.




**Managing FoxPro tables**:

- Support of memos in VFP format.

- All the index formats are supported (including the indexes in VFP format corresponding to the .CDX extension). The indexes are read and modified.

- Managing an automatic identifier.

- Management of expressions in [HFilter](../WDLang4/3044100.md).

- Ability to use [HChangeDir](../WDLang4/3044168.md).

- Limitation: FoxPro files cannot be reindexed.

- Limitation: it is not possible to create a FoxPro file.



<a name="NOTE4_2"></a>


### Dynamic description of an xBase table
<a name="dynamic_description_xbase_table_ELTPARAGRAPHE000136"></a>

An xBase table can be described through programming with the following functions:


|   |   |
| --- | --- |
| [HDBCreation](../WDLang4/3044171.md) | Ends the dynamic description of the table structure. The table that was just described is created on disk in the path specified in [HDBDescribeFile](../WDLang4/3044172.md). The data, memo and index files are created on disk. |
| [HDBDescribeField](../WDLang4/3044170.md) | Dynamically describes each item of the structure of an xBase table described by [HDBDescribeFile](../WDLang4/3044172.md). |
| [HDBDescribeFile](../WDLang4/3044172.md) | Dynamically describes a table in dBase 3 format (most common format). This function is used to specify the name, abbreviation and access path of the xBase table. |
| [HDBDescribeIndex](../WDLang4/3044166.md) | Dynamically describes the different index files that will be created. An index file must be described for each search key. The created index file will be in dBase 3 format. |

Example:


```wl
// Describe an xBase table with the following items:
// LASTNAME, string of 20 characters
// FIRSTNAME, string of 20 characters
// AGE, integer on 3 digits
// BALANCE, real on 10 digits and 2 decimals
// MARRIED, boolean
// DOB, date
// INFO, text memo

HDBDescribeFile("DBCUSTOMER", "CD", "C:\FILE\CUSTOMER.DBF")
HDBDescribeField("LASTNAME,C,20")
HDBDescribeField("FIRSTNAME,C,20")
HDBDescribeField("AGE,N,3,0")
HDBDescribeField("BALANCE,N,10,2")
HDBDescribeField("MARRIED,L")
HDBDescribeField("DOB,D")
HDBDescribeField("INFO,M")
HDBCreation()
```
**Note** FoxPro tables cannot be described dynamically. Only the dBase 3 format is supported.
<a name="NOTE4_3"></a>


### Opening tables described dynamically
<a name="opening_tables_described_dynamically_ELTPARAGRAPHE000175"></a>

An xBase table is not automatically opened: you must open this table with function [HDBOpen](../WDLang4/3044163.md) before using it for the first time, unless it has been created with function [HDBCreation](../WDLang4/3044171.md) (which creates and opens the table).
<a name="NOTE4_4"></a>


### Opening indexes that were described dynamically
<a name="opening_indexes_that_were_described_dynamically_ELTPARAGRAPHE000188"></a>

[HDBOpen](../WDLang4/3044163.md) opens the table but not the index files. Therefore, you must open all the necessary index files for using the table with [HDBIndex](../WDLang4/3044165.md).

If the index files are not opened, they will not be updated after a deletion, a modification or an addition.
<a name="NOTE4_5"></a>


### Links between the xBase or FoxPro tables
<a name="links_between_the_xbase_foxpro_tables_ELTPARAGRAPHE000202"></a>

The links are not automatically managed by WINDEV and WEBDEV. They must be managed programmatically. Therefore, to access a record in the linked table, you must find the corresponding record according to the link key ([HReadSeek](../WDLang4/3044050.md)).

A window displays the orders of a customer, the "ORDER" table contains the product number, the "PRODUCT" table contains the product name and number. For example, the initialization process of the window is:


```wl
// Read the orders
HReadFirst(ORDER, Ord_Date)
IF HOut() = False THEN
	// Find the corresponding product
	HReadSeek(PRODUCT, ProNum, ORDER.ProNum)
	FileToScreen()
END
```

### Using the Native xBase/FoxPro Connector with non-Latin character sets
<a name="using_the_native_xbasefoxpro_connector_with_nonlatin_character_sets_ELTPARAGRAPHE000216"></a>

To use the Native xBase Connector with non-Latin character sets, a standard OEM/ANSI conversion must be performed by the Native Connector. To do so, the following string must be specified in the extended information: 

```txt
OEMTOANSI=WINDOWS;
```


**Example**:

1. In the initialization code of the project, add the code used to modify the character set:
	
	```wl
	ChangeCharset(charsetChinese)
	```


2. Create an xBase connection:
	
	```wl
	HDescribeConnection("CntxBase", "", "", fExeDir(), "", hNativeAccessxBase, ...
			hOReadWrite, "OEMTOANSI=WINDOWS;")
	HChangeConnection("*", "CntxBase")
	```
