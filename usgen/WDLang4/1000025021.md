


## &lt;Source&gt;.ReadPrevious (Function)

***In french: &lt;Source&gt;.LitPrécédent***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Positions on the previous file record according to a browse item. The record is read and the HFSQL variables are updated (Customer.Name for example, which means the *Name* item of *Customer* file).

Values in the browse item are read in descending order (for more details, see the remarks).

Generally, **&lt;Source&gt;.ReadPrevious** sets the position in the table during a loop operation.

Several cases may occur after the call to **&lt;Source&gt;.ReadPrevious**:

- the table is empty or there is no record corresponding to the filter (defined by function [&lt;Source&gt;.Filter](../WDLang4/1000024960.md)): no read is performed and function [&lt;Source&gt;.Out](../WDLang4/1000024605.md) returns <u><u><u>True</u></u></u>.

- the function attempts to block a record already blocked for playback: no playback is performed, function [HErrorLock](../WDLang4/3044099.md) returns <u><u><u>True</u></u></u> and function [&lt;Source&gt;.Out](../WDLang4/1000024605.md) returns <u><u><u>True</u></u></u>.
	![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png) The management of locks is not available.
	![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) JDBC access: lock management is not supported for databases that are accessed through JDBC. 




This function can be used with the tables, HFSQL views, or queries.

<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
Customer.ReadLast(Name)
WHILE Customer.Out() = False
	// Process the record
	Customer.ReadPrevious(Name)
END
```

## Syntax

`<Result> = <Source>.ReadPrevious([<Browse item> [, <Options>]])`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the previous record was read,

- <u><u><u><u>False</u></u></u></u> in case of error (block, end of table, etc.): the record is not read. This problem can be caused by:

	- or a positioning problem (empty file, etc.): function [&lt;Source&gt;.Found](../WDLang4/1000025076.md) returns <u><u><u><u>False</u></u></u></u> and function [HError](../WDLang4/3044088.md) returns 0.

	- an error: [HError](../WDLang4/3044088.md) returns an integer other than 0. [HErrorInfo](../WDLang4/3044071.md) returns more details.







**`<Source>: (Type corresponding to the specified source)`**

Name of table, HFSQL view or query used. 

**`<Browse item>: (Optional character string)`**

Name of item used to loop through the table. If this name is not specified, **&lt;Source&gt;.ReadPrevious** will use:

- *In the case of a* table: the last browse item used on this table by the last HFSQL management function (function beginning with the letter H).. If this item does not exist, the best browse item is automatically used. 

- *In the case of a query* ORDER BY of the query if it exists, otherwise according to the last field used.

- *In the case of a view* In the case of a view: the view sort item (if available), otherwise on the last used sort item.




**`<Options>: (Optional constant (or combination of constants))`**

Used to configure:

- the lock set on the record read by **&lt;Source&gt;.ReadPrevious**.

- the management of duplicates. By default, all duplicates are iterated over.





|   |   |
| --- | --- |
| *hDistinct* | If duplicates are found, this constant allows you to read a single record among the duplicates. This parameter is taken into account only if the iteration is performed on a key item. |
| *hLockNo* | No blocking: the Record can be played back or modified by another application during playback. |
| *hLockReadWrite* | Read/write lock: the record being read cannot be read or modified by another application. |
| *hLockWrite* | Write lock: the record currently read can be read by another application but it cannot be modified by another application. |


![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png)![Native Connectors (Native Accesses)](https://doc.pcsoft.fr/ext/images/us/AN.png) The lock options will have no effect if the locks are not supported by the OLE DB provider or by the Native Connector.![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png) The lock options specified by **&lt;Source&gt;.ReadPrevious** will be ignored. The lock mode specified by [&lt;Source&gt;.ReadFirst](../WDLang4/1000025022.md) or [&lt;Source&gt;.ReadLast](../WDLang4/1000025020.md) will remain effective when **&lt;Source&gt;.ReadPrevious** and [&lt;Source&gt;.ReadNext](../WDLang4/1000025035.md) are called.

To change the lock mode, use:

- [&lt;Source&gt;.ReadSeekFirst](../WDLang4/1000025034.md) or [&lt;Source&gt;.ReadSeekLast](../WDLang4/1000025024.md),

- [&lt;Source&gt;.ReadFirst](../WDLang4/1000025022.md) or [&lt;Source&gt;.ReadLast](../WDLang4/1000025020.md).

- [&lt;Source&gt;.LockRecNum](../WDLang4/1000024197.md) or [&lt;Source&gt;.UnlockRecNum](../WDLang4/1000024212.md).


![Native Connectors (Native Accesses)](https://doc.pcsoft.fr/ext/images/us/AN.png)  For Native Oracle Connector, a different lock mode can be specified for each record. However, if a transaction was started by [SQLTransaction](../WDLang4/3072029.md) before setting the lock, the lock will only be released at the end of the transaction ([SQLTransaction](../WDLang4/3072029.md) with the *sqlCommit* or *sqlRollBack* constant).![Hyper File 5.5](https://doc.pcsoft.fr/ext/images/us/HF55.png) The lock options are ignored. ## Remarks


### Read operation according to a key item or not
<a name="read_operation_according_key_item_not_ELTPARAGRAPHE000412"></a>

If the item is a key, **&lt;Source&gt;.ReadPrevious** reads the record with the greatest key value. The sort order taken into account is the one specified in the database schema for this key. 

If the item is not a key, **&lt;Source&gt;.ReadPrevious** reads the previous active record. When browsing the table, the records will be sorted according to their record number. 
In this case, the selected browse item will appear in red in the code editor and a warning will be displayed in the ["Code" pane](../Editeurs/2027009.md).

**Note**: The [automatic completion](../Editeurs/2013001.md) only offers the key items.
<a name="NOTE0_2"></a>


### Looping through records that match a condition
<a name="looping_through_records_that_match_condition_ELTPARAGRAPHE000438"></a>

In most cases, [&lt;Source&gt;.ReadSeek](../WDLang4/1000025023.md), [&lt;Source&gt;.ReadSeekFirst](../WDLang4/1000025034.md) and [&lt;Source&gt;.ReadSeekLast](../WDLang4/1000025024.md) are used to position in the table to perform a browse loop among the records corresponding to a condition. [&lt;Source&gt;.ReadNext](../WDLang4/1000025035.md) and **&lt;Source&gt;.ReadPrevious** are used to read the next or previous record corresponding to the condition:

- if the item is a key, **&lt;Source&gt;.ReadPrevious** reads the previous records corresponding to the values less than or equal to the sought value.

- if the item used is not a key, **&lt;Source&gt;.ReadPrevious** will read the next records corresponding to the values equal to the sought value.




To ignore the search while going to the next or previous record, use one of the following functions:

- [&lt;Source&gt;.CancelSeek](../WDLang4/1000024193.md)

- [&lt;Source&gt;.ReadLast](../WDLang4/1000025020.md)

- [&lt;Source&gt;.ReadFirst](../WDLang4/1000025022.md)

### Locks
<a name="locks_ELTPARAGRAPHE000494"></a>

By default (&lt;Options&gt; not specified), the record is not locked.

If a lock is erquested (*hLockWrite* or *hLockReadWrite* constant), the record will be read only if this record is not already locked.

![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png)![Native Connectors (Native Accesses)](https://doc.pcsoft.fr/ext/images/us/AN.png) The lock options will have no effect if the locks are not supported by the OLE DB provider or by the Native Connector.
<a name="NOTE0_4"></a>


### Memos
<a name="memos_ELTPARAGRAPHE000510"></a>

The memos associated with the record can be automatically read (or not) when reading the record. [&lt;Source&gt;.SetMemo](../WDLang4/1000024987.md) is used to customize this automatic read operation.

If the memos are supported, the associated text memos are read when the record is read. The binary memos are read only when they are explicitly used ([&lt;Source&gt;.ExtractMemo](../WDLang4/1000024957.md)).
<a name="NOTE0_5"></a>


### Miscellaneous
<a name="miscellaneous_ELTPARAGRAPHE000532"></a>

- [&lt;Source&gt;.RecNum](../WDLang4/1000025041.md) returns the current record number.

- [&lt;Source&gt;.ChangeKey](../WDLang4/1000024198.md) changes the search key while keeping the position on the current record.

- To optimize the first iterations on a table, use [&lt;Source&gt;.Optimize](../WDLang4/1000025042.md) on this table.

- This function replaces **HReadPreviousLock** and **HReadPrevious**, which were kept for compatibility with WINDEV 5.5.
