


## FileToScreen (Function)

***In french: FichierVersEcran***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Automatically updates the controls in a window or page with:

- the values of the bound items in the current record (loaded in memory) of the table described in the data model editor. 

- the values of the bound WLanguage variables. 


This operation is performed regardless of the state of the controls (grayed, inactive or invisible).

**Remarks**:

- **FileToScreen** does not read records on the table. The value of the record loaded in memory is used to update the controls. Therefore, a record must be loaded in memory previously (with [HRead](../WDLang4/3044047.md), [HReadSeek](../WDLang4/3044050.md), [HReadFirst](../WDLang4/3044051.md), etc.).

- This function is global to the window. If it is called in an internal window, the parent window and the other internal windows will benefit from it. The mechanism is identical for the pages. 

- ![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png) Only the binding to the table items is supported. Bindings to WLanguage variables are not supported in this version.

- ![WEBDEV - Server code](https://doc.pcsoft.fr/ext/images/us/WBS.png)![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png) In WEBDEV, you can also use [FileToPage](../WDLang4/3044148.md).

<a name="sample_code"></a>

## Example


```wl
HReadSeekFirst(Customer, Name, "PAUL")
IF HFound() = True THEN
	FileToScreen()
END
// Read the record and transfer the items to the controls
HReadFirst(Customer, Name)
FileToScreen()
```

## Syntax

`FileToScreen([<Window/Page> [, <Source>]])`
---

**`<Window/Page>: (Name of window or page)`**

Name of the window or page containing the controls to be updated. 
Summary: Called when a control gains focus.
![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png) If this parameter is specified, it must correspond to the name of the current page. Otherwise, an error occurs.![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![Android Widget ](https://doc.pcsoft.fr/ext/images/us/ANDROIDWIDGET.png)![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) If this parameter is specified, it must correspond to the name of the current window. Otherwise, an error occurs.

**`<Source>: (Optional character string)`**

Name of the source the controls to be updated are bound to. This source can be:

- The name of a table. In this case, only the controls bound to the items of the table are taken into account.

- The name of a WLanguage variable. In this case, only the controls bound to the WLanguage variable are taken into account.
	Remarks: 

	- If the name of the variable is enclosed in quotes, the control will be bound to the specified variable. 

	- If the name of the variable is not enclosed in quotes, the control will be bound to the variable data (e.g., a variable containing the name of another variable).





If this name is not specified, all the window or page controls that are bound to a table described in the data model editor or to a WLanguage variable will be taken into account.

## Remarks


### Binding between a control and a WLanguage variable or between a control and a table item
<a name="binding_between_control_and_wlanguage_variable_between_control_and_table_item_ELTPARAGRAPHE000131"></a>

The binding between a control and a WLanguage variable or between a control and a table item can be determined:

- In the editor, in the control description window ("Binding" tab).

- Programmatically, with the [DataBinding](../Proprietes/2510060.md) property.



<a name="NOTE0_2"></a>


### Types of item binding
<a name="types_item_binding_ELTPARAGRAPHE000146"></a>

There are two types of bindings between a control and an item

- *direct binding*: In this case, **FileToScreen** transfers the value of the items from the record loaded in memory to the bound control, without reading any values.

- *binding by reading the records in the associated table*. 



<a name="NOTE0_3"></a>


### Miscellaneous
<a name="miscellaneous_ELTPARAGRAPHE000160"></a>

- **Auto-filled Combo Box control bound to an HFSQL table**: **FileToScreen** must not be in the "Global declarations" event of the window. The function must be in the "Initialization" event of the window.

- Space characters in HFSQL items are kept.

- **FileToScreen** updates the Image controls bound to image memo items.

- **FileToScreen** supports the NULL value. If the item content is NULL, an empty string will be displayed in the bound Edit control. To change this display mode, use [ControlError](../WDLang1/3025036.md).

- **FileToScreen** is not available on views. The values of the items must be assigned to each control.

- **Binding with "Secure Password" items**:

	- In an Edit control bound to a Password item, "\*\*\*\*\*" characters are displayed. If the Edit control is of type "Password", dots are displayed instead. 

	- The value of the "Password" item cannot be read again until the user changes the password value.

	- The value of the "Password" item can still be compared to a string (e.g., "" or "1234").
