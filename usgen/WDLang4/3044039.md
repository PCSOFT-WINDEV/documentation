


## HMode (Function)

***In french: HMode***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Changes the mode and the method for locking tables.

![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png)![Native Connectors (Native Accesses)](https://doc.pcsoft.fr/ext/images/us/AN.png) **Attention**: If the OLE DB provider or Native Connector used does not support blocking, the blocking options will have no effect.

![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) JDBC access: This function has no effect and always returns the constant *hModeMulti*.




<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
// Change the mode of all tables
HMode("*", hModeMulti)

// Make the "Customer" table inaccessible to other applications
HMode(Customer, hModeMono)
```

## Syntax

### Modifying the lock mode

`<Result> = HMode([<Table>, ] <Mode>)`
---

**`<Result>: (Integer constant)`**

Lock mode performed on the table before modification.


|   |   |
| --- | --- |
| *hModeMono* | Single-user mode: tables are completely locked for reading and writing as soon as they are opened.. This mode prevents the other applications from accessing the tables already opened by the current application. |
| *hModeMulti* | Multi-user mode: tables are not blocked when opened. The other applications can access the tables. |


![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png)![Native Connectors (Native Accesses)](https://doc.pcsoft.fr/ext/images/us/AN.png) The result always corresponds to *hModeMulti*.![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) Access via JDBC: The result always corresponds to *hModeMulti*.

**`<Table>: (Optional character string)`**

Name of the table used. If this parameter corresponds to "\*" or if it is not specified, the modifications will be applied to all the tables.

**`<Mode>: (Integer constant)`**

Lock mode that must be performed on the table. 
If only this parameter is specified, the management mode is applied to all tables.


|   |   |
| --- | --- |
| *hModeMono*<br>(default value) | **Single-user mode**: tables are completely locked for reading and writing as soon as they are opened.. This mode prevents the other applications from accessing the tables already opened by the current application. |
| *hModeMulti* | **Multi-user mode**: tables are not blocked when opened. The other applications can access the tables. |


![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png)![Native Connectors (Native Accesses)](https://doc.pcsoft.fr/ext/images/us/AN.png) The mode used is *hModeMulti*.

|   |   |

## Remarks


### Lock mode
<a name="lock_mode_ELTPARAGRAPHE000202"></a>

By default, if the current project:

- is associated with a database schema, the lock mode performed on the tables is the multi-user mode (the tables are not locked when they are opened, the other applications can access the tables).

- is not associated with a database schema, the locking mode applied to tables is single-user: tables are completely locked for reading and writing as soon as they are opened. This mode prevents the other applications from accessing the tables already opened by the current application.




To modify the lock mode used:

1. Open the project description window. To do so, go to the "Project" tab, "Project" group, and click "Description". 

2. Display the "Tables" tab.

3. Specify the lock mode that must be used ("Management mode of files").



<a name="NOTE0_2"></a>


### Changing the mode
<a name="changing_the_mode_ELTPARAGRAPHE000232"></a>

Changing the mode cancels all the current locks applied to the table. 
There is no need to close the table to change mode.
<a name="NOTE0_3"></a>


### Changing the method
<a name="changing_the_method_ELTPARAGRAPHE000243"></a>

Changing the method has no effect on the current locks applied to the table. 
There is no need to close the table to change method.
<a name="NOTE0_4"></a>


### Changing the mode and the method
<a name="changing_the_mode_and_the_method_ELTPARAGRAPHE000254"></a>

The change of mode and method is directly performed on the physical table. Therefore, this change is applied to the table and to all its aliases.
