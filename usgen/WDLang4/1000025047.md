


## &lt;Source&gt;.Previous (Function)

***In french: &lt;Source&gt;.Précédent***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Sets the position on the previous record of the table according to a browse item. **The record is not read**.

The number of the current record is modified only when it is returned by [&lt;Source&gt;.RecNum](../WDLang4/1000025041.md). For functions handling the current record number by default (functions [&lt;Source&gt;.Delete](../WDLang4/1000025071.md), [&lt;Source&gt;.Read](../WDLang4/1000025019.md), [&lt;Source&gt;.Modify](../WDLang4/1000025038.md), ...), the value of this number is not updated: you must use the [&lt;Source&gt;.RecNum](../WDLang4/1000025041.md)() function. For example: do not: 

```wl
Customer.Delete()
```
but 

```wl
Customer.Delete(Customer.RecNum())
```

Values in the browse item are read in descending order (for more details, see the remarks).

**Attention**: ***Record loaded into memory is not modified***. The HFSQL variables (for example Customer.Name, i.e. the *Name* item of the *Customer* file) are not updated.

Generally, **&lt;Source&gt;.Previous** sets the position in the table during a loop operation.

Several cases may occur after the call to **&lt;Source&gt;.Previous**:

- the table is empty or there is no record corresponding to the filter (defined by [&lt;Source&gt;.Filter](../WDLang4/1000024960.md)): function [&lt;Source&gt;.Out](../WDLang4/1000024605.md) returns <u><u><u>True</u></u></u>.

- the function attempts to block a record already blocked in play mode: function [HErrorLock](../WDLang4/3044099.md) returns <u><u><u>True</u></u></u> and function [&lt;Source&gt;.Out](../WDLang4/1000024605.md) returns <u><u><u>True</u></u></u>.
	![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) JDBC access: lock management is not supported for databases that are accessed through JDBC. 



<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
Customer.Last(Name)
WHILE Customer.Out() = False
	// Process the record
	Customer.Previous(Name)
END
```

## Syntax

`<Result> = <Source>.Previous([<Search key item> [, <Options>]])`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the position was set,

- <u><u><u><u>False</u></u></u></u> if an error occurs. This problem can be caused by:

	- or a positioning problem (empty table, etc.): function [&lt;Source&gt;.Found](../WDLang4/1000025076.md) returns <u><u><u><u>False</u></u></u></u> and [HError](../WDLang4/3044088.md) returns 0.

	- an error: [HError](../WDLang4/3044088.md) returns an integer other than 0. [HErrorInfo](../WDLang4/3044071.md) returns more details.







**`<Source>: (Type corresponding to the specified source)`**

Name of the HFSQL table used. 

**`<Search key item>: (Optional character string)`**

Name of the key item used to loop through the table. If this name is not specified, **&lt;Source&gt;.Previous** will use the last browse item used on this file by the last HFSQL management function (function starting with "H"). If this item does not exist, the best browse item is automatically used.

**`<Options>: (Optional constant)`**

Configures the lock and the management of duplicates performed on the record selected by **&lt;Source&gt;.Previous**:


|   |   |
| --- | --- |
| *hDistinct* | If there are any duplicates, sets the position on a single record of the duplicates. This parameter is taken into account only if the iteration is performed on a key item. <br>By default, all duplicates are iterated over. |
| *hLockNo* | No blocking: the Record can be played back or modified by another application. |
| *hLockReadWrite* | Lock in read/write mode: the selected record cannot be read or modified by another application. |
| *hLockWrite* | Lock in write mode: the selected record can be read by another application, but cannot be modified by another application. |


![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) Access through JDBC: This parameter is ignored.![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png)![Native Connectors (Native Accesses)](https://doc.pcsoft.fr/ext/images/us/AN.png) The lock options will have no effect if the locks are not supported by the OLE DB provider or by the Native Connector.![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png) The lock options specified by **&lt;Source&gt;.Previous** will be ignored. The lock mode specified by [&lt;Source&gt;.First](../WDLang4/1000025048.md) or [&lt;Source&gt;.Last](../WDLang4/1000024217.md) will remain effective during the calls to **&lt;Source&gt;.Previous** and [&lt;Source&gt;.Next](../WDLang4/1000025070.md).

To change the lock mode, use:

- [&lt;Source&gt;.SeekFirst](../WDLang4/1000025055.md) or [&lt;Source&gt;.SeekLast](../WDLang4/1000025054.md).

- [&lt;Source&gt;.First](../WDLang4/1000025048.md) or [&lt;Source&gt;.Last](../WDLang4/1000024217.md).

- [&lt;Source&gt;.LockRecNum](../WDLang4/1000024197.md) or [&lt;Source&gt;.UnlockRecNum](../WDLang4/1000024212.md).


![Native Connectors (Native Accesses)](https://doc.pcsoft.fr/ext/images/us/AN.png) For Native Oracle Connector, a different lock mode can be specified for each record. However, if a transaction was started by [SQLTransaction](../WDLang4/3072029.md) before setting the lock, the lock will only be released at the end of the transaction ([SQLTransaction](../WDLang4/3072029.md) with the *sqlCommit* or *sqlRollBack* constant).![Hyper File 5.5](https://doc.pcsoft.fr/ext/images/us/HF55.png) The lock options are ignored. Use the lock functions ([&lt;Source&gt;.LockRecNum](../WDLang4/1000024197.md)) kept for backward compatibility.

## Remarks


### Read operation based on a key 
<a name="read_operation_based_key_ELTPARAGRAPHE000443"></a>

**&lt;Source&gt;.Previous** sets the position on the record with the greatest key value.

The sort order taken into account is the one specified in the database schema for this key.
<a name="NOTE0_2"></a>


### Comparison between &lt;Source&gt;.Previous and [&lt;Source&gt;.ReadPrevious](../WDLang4/1000025021.md)
<a name="comparison_between_docparampagetitleshort_and_readpreviouswdlang41000025021md_ELTPARAGRAPHE000457"></a>

The function **&lt;Source&gt;.Previous** function does not play the Record: the **&lt;Source&gt;.Previous** is therefore faster than function [&lt;Source&gt;.ReadPrevious](../WDLang4/1000025021.md).

### Locks
<a name="locks_ELTPARAGRAPHE000506"></a>

By default (&lt;Options&gt; not specified), the record is not locked.

If a lock is requested (*hLockWrite* or *hLockReadWrite* constant), the position will be set on the record only if it is not already locked.
