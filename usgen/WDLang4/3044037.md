


## HReadNext (Function)

***In french: HLitSuivant***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Sets the position on the next table record according to a browse item. The record is read and the HFSQL variables are updated (Customer.Name for example, which means the *Name* item of *Customer* file).

Values in the browse item are read in ascending order (for more details, see the [remarks](#NOTE0_1)).

**HReadNext** is used to position in the table during a browse loop. This function can only be run: 

- after a function that starts a browse ([HReadFirst (Function)](../WDLang4/3044051.md) or [HSeekFirst (Function)](../WDLang4/3044125.md) for example),

- after a call to [HChangeKey (Function)](../WDLang4/3044151.md).




Several cases may occur after the call to **HReadNext**:


- the file is empty or there is no record corresponding to the filter (defined by function [HFilter](../WDLang4/3044100.md)): no reading is performed and function [HOut](../WDLang4/3044094.md) returns <u><u><u>True</u></u></u>.

- the function attempts to block a record already blocked for playback: no playback is performed, function [HErrorLock](../WDLang4/3044099.md) returns <u><u><u>True</u></u></u> and function [HOut](../WDLang4/3044094.md) returns <u><u><u>True</u></u></u>.
	
	![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png) The locks are not available in PHP.
	
	![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) JDBC access: lock management is not supported for databases that are accessed through JDBC.




This function can be used with the tables, HFSQL views, or queries.

<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
HReadFirst(Customer, Name)
WHILE HOut() = False
	// Process the record
	HReadNext(Customer, Name)
END
```

## Syntax

`<Result> = HReadNext([<Table> [, <Browse item>] [, <Options>]])`
---

**`<Result>: (Boolean)`**

Corresponds to: 

- <u><u><u><u>False</u></u></u></u> if an error occurs. In this case, [HError](../WDLang4/3044088.md) returns an integer other than 0. [HErrorInfo](../WDLang4/3044071.md) returns more details about the error. The record is not read. 

- the value of [HFound](../WDLang4/3044104.md) in the other cases (the record can be read, even if &lt;Result&gt; returns <u><u><u><u>False</u></u></u></u>). 




**`<Table>: (Optional character string)`**

Name of the table, view or query used. If this parameter is an empty string (""), **HReadNext** manipulates the last table used by the last HFSQL function (function starting with "H").

**`<Browse item>: (Optional character string)`**

Name of item used to loop through the table, view, or query. If this name is not specified, **HReadNext** will use:

- *In the case of a* table: the last browse item used on this table by the last HFSQL management function (function beginning with the letter H).. If this item does not exist, the best browse item is automatically used. 

- *In the case of a query* ORDER BY of the query if available, otherwise according to the last field used. 

- *In the case of a view* In the case of a view: the view sort item (if available), otherwise on the last used sort item.




**`<Options>: (Optional constant (or combination of constants))`**

Used to configure:

- the lock set on the record read by **HReadNext**

- the management of duplicates. By default, all duplicates are iterated over.





|   |   |
| --- | --- |
| *hDistinct* | If duplicates are found, this constant allows you to read a single record among the duplicates. This parameter is taken into account only if the iteration is performed on a key item.<br><br>![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png)![Native Connectors (Native Accesses)](https://doc.pcsoft.fr/ext/images/us/AN.png) This constant is ignored. |
| *hLockNo* | No blocking: the Record can be played back or modified by another application during playback. |
| *hLockReadWrite* | Read/write lock: the record being read cannot be read or modified by another application. |
| *hLockWrite* | Write lock: the record currently read can be read by another application but it cannot be modified by another application. |


![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) Access through JDBC: This parameter is ignored.![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png)![Native Connectors (Native Accesses)](https://doc.pcsoft.fr/ext/images/us/AN.png) Lock options will have no effect if the OLE DB provider or Native Connector (also called Native Access) does not support locks.![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png) The lock options specified by **HReadNext** will be ignored. The lock mode specified by [HReadFirst](../WDLang4/3044051.md) or [HReadLast](../WDLang4/3044140.md) will remain effective during the calls to **HReadNext** and [HReadPrevious](../WDLang4/3044048.md).

To change the lock mode, use:

- [HReadSeekFirst](../WDLang4/3044036.md) or [HReadSeekLast](../WDLang4/3044034.md),

- [HReadFirst](../WDLang4/3044051.md) or [HReadLast](../WDLang4/3044140.md).

- [HLockRecNum](../WDLang4/3044152.md) or [HUnlockRecNum](../WDLang4/3044194.md).
	![Hyper File 5.5](https://doc.pcsoft.fr/ext/images/us/HF55.png) The lock options are ignored. Use locking read functions (**HReadNextLock**) kept for backward compatibility.


![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png) &lt;Options&gt; is ignored.

## Remarks


### Read operation according to a key item or not
<a name="read_operation_according_key_item_not_ELTPARAGRAPHE000251"></a>

If the item is a key, **HReadNext** reads the record with the greatest key value. The sort order taken into account is the one specified in the database schema for this key. 

**Note** In the case of a search loop (e.g. function [HReadSeekFirst](../WDLang4/3044036.md)), when function **HReadNext** function reads the record for which the key value is greatest, the [HFound](../WDLang4/3044104.md) function lets you know whether the record corresponds to the search criterion or not.

If the item is not a key, **HReadNext** reads the next active record. When browsing the table, the records will be sorted according to their record number. 
In this case, the selected browse item will appear in red in the code editor and a warning will be displayed in the ["Code" pane](../Editeurs/2027009.md).

**Note**: The [automatic completion](../Editeurs/2013001.md) only offers the key items.
<a name="NOTE0_2"></a>


### Memos
<a name="memos_ELTPARAGRAPHE000286"></a>

The memos associated with the record can be automatically read (or not) when reading the record. [HSetMemo](../WDLang4/3044139.md) is used to customize this automatic read operation.

If the memos are supported, the associated text memos are read when the record is read. The binary memos are read only when they are explicitly used ([HExtractMemo](../WDLang4/3044072.md)).
<a name="NOTE0_3"></a>


### Looping through records that match a condition
<a name="looping_through_records_that_match_condition_ELTPARAGRAPHE000303"></a>

In most cases, [HReadSeek](../WDLang4/3044050.md), [HReadSeekFirst](../WDLang4/3044036.md), and [HReadSeekLast](../WDLang4/3044034.md) are used to position in the table to perform a browse loop among the records corresponding to a condition. **HReadNext** and [HReadPrevious](../WDLang4/3044048.md) are used to read the next or previous record corresponding to the condition:

- if the item used is a key, **HReadNext** will read the next records corresponding to the values greater than or equal to the sought value.

- if the item used is not a key, **HReadNext** will read the next records corresponding to the values equal to the sought value.




To ignore the search while going to the next or previous record, use one of the following functions:

- [HCancelSeek](../WDLang4/3044157.md)

- [HReadLast](../WDLang4/3044140.md)

- [HReadFirst](../WDLang4/3044051.md)




**Warning**: if a route is to be performed with the **function HReadNext**, the initial search (functions [HReadSeek](../WDLang4/3044050.md), [HReadSeekFirst](../WDLang4/3044036.md), [HReadSeekLast](../WDLang4/3044034.md)) must not use the *constant hLimitRoute*.
<a name="NOTE0_4"></a>


### Modifying the value of search key
<a name="modifying_the_value_search_key_ELTPARAGRAPHE000355"></a>

If the value of the browse item is modified before **HReadNext** is used, the current record can be read again by **HReadNext** in the rest of the browse.

Changing the browse item updates the file index key. This modification is taken into account when reading the next records. 

This remark is also valid when using **HReadNext** without search key a sorted query (ORDER BY).

### Locks
<a name="locks_ELTPARAGRAPHE000376"></a>

By default (&lt;Options&gt; not specified), the record is not locked.

If a lock is specified (*hLockWrite* or *hLockReadWrite* constants), the record will be read only if this record is not already locked.

![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png)![Native Connectors (Native Accesses)](https://doc.pcsoft.fr/ext/images/us/AN.png) The lock options will have no effect if the locks are not supported by the OLE DB provider or by the Native Connector.

### Miscellaneous
<a name="miscellaneous_ELTPARAGRAPHE000391"></a>

- [HRecNum](../WDLang4/3044063.md) returns the current record number.

- [HChangeKey](../WDLang4/3044151.md) changes the search key while keeping the position on the current record.

- To optimize the first iterations on a table, use [HOptimize](../WDLang4/3044005.md) on this table.
