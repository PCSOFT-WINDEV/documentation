


## HCreation (Function)

***In french: HCréation***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Creates an empty table (extension ".FIC") with index file, full-text index file, spatial index file, and memo file if required.

This function can also be used to delete all records from a table. In this case, the record in memory is not canceled. To initialize it, use [HReset](../WDLang4/3044118.md).

**Note**: It is possible to activate the automatic creation of non-existent tables in the project description (tab "Tables" in the project description, option "Automatically create the tables when they are opened"). **HCreation** is automatically used if the table does not exist when it is handled for the first time.

### Characteristics of created table
<a name="characteristics_created_table_ELTPARAGRAPHE000176"></a>

The characteristics of the created table are as follows:

- Table name:
	Physical name defined during the file description in the data model editor. This name can be modified by [HChangeName](../WDLang4/3044141.md) before creating the table.

- Directory of table:
	Directory defined during the file description in the data model editor. This directory can be changed with [HChangeDir](../WDLang4/3044168.md) and [HSubstDir](../WDLang4/3044028.md) before creating the table.

- Content of table:
	The created table is empty, which does not mean that its size is null (the table contains a header describing its structure).

- The order of items created in the physical file is the physical order of items created in the database schema (and not the logical order).




**If the table already existed**: If the table already existed (same name, same directory), this table is recreated: the table no longer contains any records. The index file and the memo file (if they exist) are also recreated. In this case, the integrity constraints are not checked.

**Warning**: The table can only be re-created if it is not being used by another application. If a file currently used must be cleared, use [HDelete](../WDLang4/3044018.md) during a browse. You can also use [HDeleteAll](../WDLang4/1000017331.md) to delete all records from a table.

### Additional files created
<a name="additional_files_created_ELTPARAGRAPHE000217"></a>

When creating a table, the following tables can be created in addition to the table:

- ***An index file*** (".NDX" extension) if one or more keys have been defined in the file description.

- ***A full-text index file*** (extension ".FTX") if one or more "Full-text index" keys have been defined in the table description.

- ***A spatial index file*** (extension ".SDX") if one or more "Spatial key" keys have been defined in the table description.

- ***A memo file*** (".MMO" extension) if one or more memo items have been defined in the file description. 

- ***A log file*** (".JNL extension). This file is created only if the corresponding option was selected during the file description.
	![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![Android Widget ](https://doc.pcsoft.fr/ext/images/us/ANDROIDWIDGET.png)![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png)![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png) This file is not created.

- **A &lt;ProjectName&gt;.REP file**. This file contains the list of tables handled by the application. This file is created (or filled) if the management of .REP is enabled ([HSetREP](../WDLang4/3044061.md)). For more details, see [.REP file](../WDLang4/3044186.md).
	![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png) This file is not created.

### Managing passwords
<a name="managing_passwords_ELTPARAGRAPHE000249"></a>

- The password can be defined:

	- when the table is created by **HCreation**.

	- before the table is created by [HPass](../WDLang4/3044108.md).




- If the table existed and if it was password protected, the table is recreated, even if the password changes or does not exist anymore.




**Attention** Password is independent of data encryption. Data encryption must be configured when describing the table in the data model editor ("Details" tab).
![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png)![Native Connectors (Native Accesses)](https://doc.pcsoft.fr/ext/images/us/AN.png) The password is not associated with a table but with a database. This password must be specified during the connection ([HConnect](../WDLang4/3044263.md)).

### Managing fatal errors when creating a table
<a name="managing_fatal_errors_when_creating_table_ELTPARAGRAPHE000275"></a>If a fatal error occurs when creating a table, it may be interesting to continue the program while checking whether the table was created or not. To do so, we recommend that you perform the following exception process:

```wl
WHEN EXCEPTION IN
	HCreation(PARENT)
DO
	Error("HFSQL error: " + HError())
ELSE
	Trace("The file is created")
END
```

### Managing non-Latin character sets 
<a name="managing_nonlatin_character_sets_ELTPARAGRAPHE000292"></a>

If the *hChangeCharset* constant is specified, the character set used in the table will be the one specified by [ChangeCharset](../WDLang1/3054001.md). Sorts, searches or other types of operations performed on string keys (strings, characters, date and time) will use the new character set.

The character set used can be modified by [HIndex](../WDLang4/3044133.md).

**Note**: The length of string fields specified in the database schema is in bytes, not characters. Depending on the character set used, you may have to increase the item size (if the characters used are coded on 2 bytes for example).

For more details, see [Managing specific character sets in the tables](../WDLang1/3054017.md).

### Replication: Range of Identifiers
<a name="replication_range_identifiers_ELTPARAGRAPHE000318"></a>

The automatic identifiers for the files of subscriber replicas are using a range of identifiers that differs from the one used by the file of master replica and by the other files of subscriber replicas.

This range of automatic identifiers is written in the header of each table (".FIC" extension).
This range is initialized:

- when creating a table (**HCreation** or [HCreationIfNotFound](../WDLang4/3044254.md)).

- via .

- when [HInitSubscriber](../WDLang4/3044013.md) is used.




For more details, see the [consequences of implementing the replication](../WDLang4/3044246.md).

### Priority for defining the location of log files
<a name="priority_for_defining_the_location_log_files_ELTPARAGRAPHE000350"></a>

The location of log files is defined according to the following priority order:

1. Location specified when creating the logged table (**HCreation**). 

2. Location specified by [HChangeLogDir](../WDLang4/3044164.md).

3. Location specified in the database schema.

4. Location of the logged table.




If another application uses [HDeclareExternal](../WDLang4/3044204.md) on a logged table, the changes made by this application are saved in the log files specified in the header of the logged HFSQL table.
![HFSQL Client/Server](https://doc.pcsoft.fr/ext/images/us/HFCS.png) The location of Log files is fixed and it cannot be modified. For more details, see [Log files in Client/Server mode](../WDLang4/3044197.md).

### Creating an existing table
<a name="creating_existing_table_ELTPARAGRAPHE000382"></a>

If the table already exists, **HCreation** tries to delete and recreate the table.

For example: Using an Oracle database

- with OLE DB provider "MSDAORA": no new table can be created. If the table already exists, the records are erased.

- with the OLE DB provider "oraOLEDB.Oracle": a new table can be created, as well as the re-creation of an existing table. However, no index or memo item can be created.




When creating a table, WINDEV and WEBDEV try to create the items in the OLE DB type corresponding to the HFSQL type. If this type is not supported, WINDEV and WEBDEV successively try all the "compatible" OLE DB types until they find a type supported by the OLE DB database.

<a name="constraints_for_referential_integrity_ELTPARAGRAPHE000402"></a>

### Managing indexes
<a name="managing_indexes_ELTPARAGRAPHE000435"></a>

**HCreation** does not return any error messages if an index cannot be added. The table is created without the index that is causing the problem. In this case, duplicates may be found in an item defined as unique key by WINDEV and WEBDEV if the external database does not support the unique keys.

### HCreation and Native SQLite Connector
<a name="docparampagetitleshort_and_native_sqlite_connector_ELTPARAGRAPHE000470"></a>

**HCreation** may fail ("database table is locked" error) if: 

- the file to create already exists.

- an iteration is in progress on another file in the same database.




This is caused by a limitation of SQLite database.
