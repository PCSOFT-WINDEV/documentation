


## HSetLog (Function)

***In french: HGèreJournal***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Enables or disables the log management for a logged table.

**Note** By default, log management is enabled for all tables described as being logged in the database schema description.
<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
// Disable log management on the Customer table
HSetLog(Customer, False)
```

<a name="XSYNTAXE"></a>
<a name="SYNTAXE1"></a>

## Syntax

`<Result> = HSetLog([<Table>, ] <Activation>)`
---

**`<Result>: (Boolean)`**

Corresponds to the former management mode of log (before the call to **HSetLog**): 

- <u><u><u><u>True</u></u></u></u> if the log management was enabled,

- <u><u><u><u>False</u></u></u></u> if the log management was disabled.




**`<Table>: (Optional character string)`**

Name of the table used. 
If this parameter is not specified or if it is equal to "\*", the new management is applied to all the tables described as being logged in the database schema.

**`<Activation>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the log management is enabled,

- <u><u><u><u>False</u></u></u></u> if this management must be disabled. 


If only this parameter is specified, the management mode is applied to all tables.

<a name="NOTE0_1"></a>

## Remarks


### Managing the log
<a name="managing_the_log_ELTPARAGRAPHE000093"></a>

The operations performed on the table after a call to the function **HSetLog** (false) function will not be logged: it will not be possible to "UNDO" these functions.

Tips:

- **If the log management must be disabled, we advise you to disable it permanently.**
	Indeed, when the log management is re-enabled on a table, the log will assume that the table has not changed since the last logged operation. Otherwise, the log may not be synchronized with the content of the table and therefore it may be useless.

- **Do not disable the log management if the read operations are logged for the table.**
	When logging a read operation, the records found BEFORE and AFTER the operations are automatically saved. 
	When logging a read operation, the record already saved is not compared to the record read. Therefore, the backup of the record read can differ from the value actually read if the record was modified while the log management was disabled.




**Warning** If the table name corresponds to "JournalOperation" or "JournalIdentification", logging of operations in these tables is stopped and the tables are closed. However, the log process will continue in the "files for record backup".
<a name="NOTE0_2"></a>


### Miscellaneous
<a name="miscellaneous_ELTPARAGRAPHE000117"></a>

- The xBase files cannot be logged.

- The call to this function on a table not defined as being logged in the database schema has no effect.

- **Interest** If a database schema is described with logging of tables, the programs manage the log files. By defining in a parameter file (managed in the program) a parameter specifying to use of logs or not, it will be possible to specify during a setup at the client site whether the tables will be logged or not, without having to recompile the programs.

- To permanently disable the log process, you must: 

	- delete the management of logs from the database schema. 

	- generate the database schema. 

	- perform an automatic application update.
