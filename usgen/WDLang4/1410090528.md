


## &lt;PolygonGeo variable&gt;.Cross (Function)

***In french: &lt;Variable PolygoneGéo&gt;.Croise***



<a name="XUse"></a>
<a name="Use"></a>
<a name="description"></a>
Determines if a geographic polygon crosses another geometry. 

It can be considered that one geometry crosses another if: 

- The interiors of geometry A and geometry B have at least one point in common.

- The interior of geometry A does not have all its points in the interior of geometry B, and vice versa. Geometry A must not contain geometry B and geometry B must not contain geometry A.

- The intersection of the interiors must have a dimension less than the maximum dimension of the input geometries.



<a name="XSYNTAX"></a>

## Syntax
<a name="SYNTAX1"></a>

`<Result> = <Geometry A>.Cross(<Geometry B>)`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if geometry A crosses geometry B,

- <u><u><u><u>False</u></u></u></u> otherwise. 


If an error occurs, the [ErrorOccurred](../WDLang1/3087001.md) variable is set to <u><u><u><u>True</u></u></u></u>. To get more details on the error, use [ErrorInfo](../WDLang1/3013008.md) with the *errMessage* constant.

**`<Geometry A>: (PolygonGeo variable)`**

Name of the [PolygonGeo](../WDLang4/1410090127.md) variable to be used.

**`<Geometry B>: (Variable containing spatial data)`**

Variable corresponding to the second geometry. This geometry can correspond to one of the following variable types:  

- [PointGeo](../WDLang4/1410090102.md).

- [Point2D](../WDLang4/1410090100.md).

- [LinestringGeo](../WDLang4/1410090128.md).

- [Linestring2D](../WDLang4/1410090109.md).

- [PolygonGeo](../WDLang4/1410090127.md).

- [Polygon2D](../WDLang4/1410090122.md).

- [MultiPointGeo](../WDLang4/1410090130.md).

- [MultiPoint2D](../WDLang4/1410090129.md).

- [MultiLinestringGeo](../WDLang4/1410090133.md).

- [MultiLinestring2D](../WDLang4/1410090131.md).

- [MultiPolygonGeo](../WDLang4/1410090136.md).

- [MultiPolygon2D](../WDLang4/1410090135.md).

## Remarks


### Examples
<a name="examples_ELTPARAGRAPHE000292"></a>

**Example 1: Crossing polygons** 
Two polygons (with a dimension of 2) whose interiors have points in common do not cross. In this case, their intersection is also a polygon, whose dimension is equal to the dimension of the two geometries (2). However, these polygons overlap and intersect.
In this case: 

- **&lt;PolygonGeo variable&gt;.Cross** returns <u><u><u><u>False</u></u></u></u>. 

- a non-fatal error is raised if two polygons are passed to **&lt;PolygonGeo variable&gt;.Cross**.




**Example 2: Linestring and polygon**: 
A linestring that passes through a polygon and has points outside the polygon, crosses the polygon. The intersection between the two geometries is a linestring, whose dimension is smaller than that of the polygon.
<a name="NOTE0_2"></a>


### Accessing spatial data using spatial indexes
<a name="accessing_spatial_data_using_spatial_indexes_ELTPARAGRAPHE000321"></a>

In a table, you can apply a filter on spatial data and loop through the table. For example, the filter can be based on the result of **&lt;PolygonGeo variable&gt;.Cross**.

It is recommended to use the following syntax to apply a filter on spatial data: 

```txt
FOR EACH File WHERE WLanguage_function(File.Spatial_item, Spatial_variable)
```

where: 

- WLanguage_function corresponds to **&lt;PolygonGeo variable&gt;.Cross**. 

- Spatial_item is a spatial item in the table. This item must: 

	- be of type "Geographic data" or "Geometric data".   

	- be defined as a "Spatial key". 




- Spatial_variable is a given spatial variable, used for comparison with the spatial item. This variable can be of type PolygonGeo, Polygon2D, etc.   




Note: The "FOR EACH File" syntax is available but not recommended, as it doesn't use spatial indexes and is therefore not optimized. In this case, the entire table is looped through and spatial indexes are not used. 

```txt
FOR EACH File 
	IF WLanguage_function(File.Spatial_item, Spatial_variable) = True THEN
    ...
    END
END
```
