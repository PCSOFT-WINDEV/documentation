


## HReindexAsynchronous (Function)

***In french: HRéindexeAsynchrone***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Rebuilds the index of an HFSQL Client/Server table (".NDX" file). This operation is asynchronous, i.e., it is performed on the server and does not block the client side. 

You can also reindex: 

- full-text indexes (".FTX" files),

- spatial indexes (".SDX" files). 


A table can be reindexed even when it is accessed by one or more applications. For more details, see [the remarks](#NOTE0_1).

**Reminder**: Reindexing reorganizes indexes and can free up space left when records are deleted. After reindexing, the access to indexes is optimized. Reindexing a table can become necessary further to the loss or modification of the index file. [HCheckIndex](../WDLang4/3044044.md) is used to regularly check the status of the index file.

## Example


```wl
DatabaseConnection is Connection
FileArray is array of hFileParameter
MyFileParam is hFileParameter
MyFileParam.Name = "AvailableAction"
MyFileParam.Password = "Password"
// Option property of variable hFileParameter not taken into account
ArrayAdd(FileArray, MyFileParam)
// Starts reindexing
IF bBackgroundTask THEN
	HReindexAsynchronous(DatabaseConnection, FileArray, hBackgroundTask, 60, CB_HReindexAsynchronous)
ELSE
	HReindexAsynchronous(DatabaseConnection, FileArray, 60, CB_HReindexAsynchronous)
END

	INTERNAL PROCEDURE CB_ReindexAsynchronous(MyFile is string, Res is boolean)
		IF Res THEN
			Trace("File processed: " + MyFile)
		ELSE
			Trace("File error " + MyFile + ErrorInfo())
		END
	END
```

## Syntax
<a name="SYNTAXE1"></a>

`<Result> = HReindexAsynchronous(<Connection> , <Tables to check> [, <Mode> , <Density rate>] [, <WLanguage procedure>])`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the check has been started,

- <u><u><u><u>False</u></u></u></u> otherwise. 




**`<Connection>: (String or Connection variable)`**

Connection to the server containing the tables to be manipulated. This connection corresponds to:

- the name of the connection defined in the data model editor or with [HDescribeConnection](../WDLang4/3044205.md) or [HOpenConnection](../WDLang4/3044107.md).

- the name of a variable of type [Connection](../WDLang4/1514073.md).




**`<Tables to check>: (Array of hFileParameter variables)`**

Name of the array of [hFileParameter](../WDLang4/1000018900.md) variables corresponding to the list of tables to be processed. 

**`<Mode>: (Optional Integer constant (or combination of constants))`**

Reindexing configuration:


|   |   |
| --- | --- |
| *hFTX* | Reindexing of full-text indexes. |
| *hMmoCompact* | Compression and defragmentation of "Mmo" files.<br><br>**Caution**: This constant cannot be combined with the *hNdxCompact*, *hCheckMemo*, *hFTX*, *hSDX*, *hNdxNormal* or *hNdxDelete* constants. |
| *hNdxCompact* | Reindexing with compression: Only active records are preserved. All the other records are permanently deleted. The space left by the deleted records is deleted from the table and the index (".FIC" and ".NDX" files, respectively).<br>Note: If one or more records are in a transaction, compression is automatically disabled. |
| *hNdxMinimal* | Reindexing while taking into account only corrupted keys. This parameter is ignored if the *hNdxDelete* or *hNdxCompact* constant are enabled. |
| *hNdxSilent* | Reindexing without display. |
| *hNdxNormal*<br>(default value) | Standard reindexing (with statistics and without compression).<br>Statistics help optimize queries and filters (see the Notes). Only active records are taken into account for calculating statistics. |
| *hNdxNoStat* | Reindexing without calculating statistics. This constant saves space by reducing the index file size.<br>**Note**: Statistics are important to achieve acceptable execution times when using queries, conditional filters and views with conditions. |
| *hNdxDelete* | Reindex and delete damaged records. |
| *hSDX* | Reindexing of spatial indexes. |
| *hBackgroundTask* | Reindexing in the background. Applications are not locked during reindexing. |
| *hCheckMemo* | Standard reindexing with verification of Memo items and correction if necessary (can be used to retrieve damaged memos). <br><br>![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png)![WEBDEV - Server code](https://doc.pcsoft.fr/ext/images/us/WBS.png) Note: You can regularly check the status of memos before reindexing them, using the following functions:<br><br>- [HCheckMemo](../WDLang4/1000023126.md).<br><br>- [HCheckMemoAsynchronous](../WDLang4/1410091107.md).<br><br><br> |



**`<Density rate>: (Integer between 1 and 100)`**

Density rate of indexes. This rate is set to 60 by default. 
**The higher this rate is,** the denser and smaller the index is. In this case, iterations, searches, filters and queries will be faster. Adding and modifying records may take longer. 
**The smallest this rate is,** the less dense and the bigger the index will be. In this case, iterations, searches, filters and queries will be slower. Adding and modifying records will be faster.

**`<WLanguage procedure>: (Optional procedure name)`**

Name of the WLanguage procedure ("callback") called for each table processed. This procedure is used to manipulate the current table.

For more details on this procedure, see [Parameters of the procedure used by HReindexAsynchronous](../WDLang4/1410091054.md).

## Remarks


### Use conditions
<a name="use_conditions_ELTPARAGRAPHE000196"></a>

- **HReindexAsynchronous** is used to reindex Client/Server HFSQL tables.

- **HReindexAsynchronous** is used to reindex tables in a cluster. In this case: 

	- Reindexing is performed on the node to which the user is connected. 

	- Only zero-downtime reindexing is available (*hBackgroundTask* constant).

### "Zero-downtime" reindexing
<a name="zerodowntime_reindexing_ELTPARAGRAPHE000231"></a>

Client/Server HFSQL tables can be reindexed even if they are being accessed by an application.

Any applications that manipulate data in the table (read or write) will be temporarily stopped/blocked until reindexing is complete.
![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) A window is displayed, indicating that the table is currently reindexed (also called reorganization). This window is displayed during reindexing and cannot be closed. A progress bar indicates the reindexing progress status.<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=HF_Reindexation.gif)
You can customize this window or don't allow it to open again. For more details, see [HFSQL error handling help](../WDLang4/3044188.md).

To avoid flickering issues, the indexing window is displayed only if the reindexing process takes more than 2 seconds. In this case, this window is displayed after 0.7 seconds.

**Remarks**:

- Zero-downtime reindexing cannot be performed if records are locked in read/write mode in the table to be reindexed. If records are locked in write mode only, zero-downtime reindexing can still be performed.

- If the *hBackgroundTask* constant is used, the reindexing process is run in the background and the applications that use the table are not stopped. 



<a name="NOTE0_4"></a>


### Calculating statistics
<a name="calculating_statistics_ELTPARAGRAPHE000257"></a>

Statistics help optimize queries and filters in the table. Only active records are taken into account for calculating statistics. This data can also be calculated using:

- the [HStatCalculate](../WDLang4/3044134.md) function, 

- the [HStatCalculateAsynchronous](../WDLang4/1410091108.md) function.




**Note**: For optimal results, this calculation must include all tables (e.g. multi-table query).
<a name="NOTE0_5"></a>


### Directory of temporary files
<a name="directory_temporary_files_ELTPARAGRAPHE000279"></a>

Temporary files can be created during reindexing. By default, these files are created in the Windows temporary directory or in the current directory if there is not enough space.

The directory used to store temporary files on the server can be defined as follows: 

- in the [HFConf.INI](../WDLang4/3044345.md) file. 

- using the [HSetServer](../WDLang4/3044359.md) function. 



<a name="NOTE0_7"></a>


### Access rights to the table
<a name="access_rights_the_table_ELTPARAGRAPHE000299"></a>

Reindexing recreates the table on disk. In an allocation system that manages permissions at file level (NTFS, etc.), the reindexed table will have the permissions of the directory to which it belongs.

If the table had different rights from those of the folder before reindexing, you must redefine them in Windows after reindexing.
