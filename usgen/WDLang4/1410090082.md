


## HOpenComplementaryAnalysis (Function)

***In french: HOuvreAnalyseComplémentaire***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Opens a new database schema, but keeps the main database schema of the application. Already open database schemas are not closed. 

Warning: To use this function, you must first have declared or opened a main database schema (function [HOpenAnalysis](../WDLang4/3044106.md)). 
<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
// Open a complementary database schema
HOpenComplementaryAnalysis("C:\SALESMGT\SALESMGT.WDD", "Password")
```

<a name="XSYNTAXE"></a>

## Syntax
<a name="SYNTAXE1"></a>

`<Result> = HOpenComplementaryAnalysis(<WDD file path> [, <Password>])`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the database schema was opened,

- <u><u><u><u>False</u></u></u></u> otherwise. [HError](../WDLang4/3044088.md) returns more details about the problem.




**`<WDD file path>: (Character string)`**

Full path of the ".WDD" file of the database schema. This file contains the description of the database schema to be opened.

![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png)![WEBDEV - Server code](https://doc.pcsoft.fr/ext/images/us/WBS.png) If only the drive and the name of the database schema are specified, the database schema is searched for in the current directory of the specified drive. 
If neither the drive, nor the database schema path are specified, the database schema is searched for in the current directory of the current disk.
The &lt;Unit&gt;:&lt;database schema name&gt; syntax is used to search for the database schema in the current directory of the specified drive. 

**`<Password>: (Optional string or Secret string)`**



- Database schema password, defined in the data model editor. 

- Empty string ("") if no password is associated with the database schema.
	**Secret strings**: If you use the secret string vault, the type of secret string used for this parameter must be "ANSI or Unicode string".
	To learn more about secret strings and how to use the vault, see [Secret string vault](../Editeurs/1410087353.md).

## Remarks


### Launching an application associated with a main database schema
<a name="launching_application_associated_with_main_database_schema_ELTPARAGRAPHE000061"></a>

- The main database schema is automatically opened when the application is launched. The database schema is searched for in the main library of the application, then in the directory of the application. 
	To make sure the database schema is found, we advise you to include the database schema in the main library of the application.

- If **HOpenComplementaryAnalysis** is called by an application associated with a main database schema, this function:

	- has no effect if the path of the specified database schema corresponds to the path of the database schema associated with the application.

	- returns <u><u><u><u>False</u></u></u></u> if the path of the specified database schema does not exist. In this case, the application keeps working with the current database schema.

	- opens the database schema and returns <u><u><u><u>True</u></u></u></u> if the specified database schema exists and if it is valid.






<a name="NOTE0_2"></a>


### Starting an application not associated with a database schema
<a name="starting_application_not_associated_with_database_schema_ELTPARAGRAPHE000085"></a>

When an application that is not associated with a database schema is started, no database schema is automatically opened. In this case, you need to use the [HOpenAnalysis](../WDLang4/3044106.md) function.

To open a complementary database schema, use **HOpenComplementaryAnalysis**. The database schema opened by **HOpenComplementaryAnalysis** is searched:

- first, in the main library of the application according to its full physical name.

- then, on the current disk.



<a name="NOTE0_2B"></a>


### Automatically hide tables with the same name in different database schemas
<a name="automatically_hide_tables_with_the_same_name_different_database_schemas_ELTPARAGRAPHE000257"></a>

Different database schemas can contain tables with the same name. In this case, only one table will be used. This table relies on the order specified for the different database schemas, either in the project description or through the opening sequence defined using [HOpenAnalysis](../WDLang4/3044106.md) and [HOpenComplementaryAnalysis](../WDLang4/1410090082.md). Here is how it works: 

- Database schema 1: 

	- Table A

	- Table B




- Database schema 2:

	- Table B. This table will be "hidden", as it is present in Database Schema 1. 
			**To use table B in database schema 2**, it is necessary to rename this table in database schema 2. 

	- Table C




- Database schema 3:

	- Table B: This table will be "hidden", as it is present in Database schema 1. 
			**To use table B in database schema 3**, it is necessary to rename this table in database schema 3.

	- Table C: This table will be "hidden", as it is present in Database Schema 2. 
			**To use table C in the database schema 3**, it is necessary to rename this table in the database schema 3.

	- Table D. 





In the "Database Schema" action of the "Project Explorer" pane, the following tables will be shown: 

- Table A (database schema 1)

- Table B (database schema 1)

- Table C (database schema 2)

- Table D (database schema 3).



<a name="NOTE0_3"></a>


### Opening a database schema that is already open
<a name="opening_database_schema_that_already_open_ELTPARAGRAPHE000106"></a>

If the database schema you are trying to open with **HOpenComplementaryAnalysis** is already open, the function has no effect.
<a name="NOTE0_5"></a>


### Database schema version supported by HOpenComplementaryAnalysis
<a name="database_schema_version_supported_docparampagetitleshort_ELTPARAGRAPHE000115"></a>

**HOpenComplementaryAnalysis cannot be used to open Hyper File 5.5 database schemas (and earlier versions). Only HFSQL Classic database schemas can be opened.**
