


## HForward (Function)

***In french: HAvance***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Moves several records forward from the current position in the table, according to a specified item.

The destination Record is read and loaded into memory: HFSQL variables are updated (e.g. Customer.Name, i.e. the field *Name* field of the table *Client*).

Several cases may occur after the call to **HForward**:

- there are no more records in the table: function [HOut](../WDLang4/3044094.md) returns <u><u><u>True</u></u></u>. No read operation is performed.

- the function attempts to block a record already blocked in play mode: function [HErrorLock](../WDLang4/3044099.md) returns <u><u><u>True</u></u></u> and function [HOut](../WDLang4/3044094.md) returns <u><u><u>True</u></u></u>.
	![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png) Management of locks not available in PHP.
	![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) JDBC access: lock management is not supported for databases that are accessed through JDBC. 
	![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png) Management of locks not available in SQLite databases. 




This function can be used with the tables, HFSQL views, or queries.

## Example
<a class="notetitle" target="_blank" href="$DOC$=1000003044154&name=hforward_function">See additional examples</a>

```wl
// Moves to the 2000th record
// of the Customer table according to the CustomerName key
HReadFirst(Customer, CustomerName)
HForward(Customer, CustName, 1999)
```

## Syntax

`<Result> = HForward([<Table>] [, <Item> [, <Step> [, <Options>]]])`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the table has been scrolled,

- <u><u><u><u>False</u></u></u></u> in case of error (block, end of table, etc.): the record is not read. [HError](../WDLang4/3044088.md) is used to identify the error.




**`<Table>: (Optional character string)`**

Name of the table, view or query used. 
If this name is not specified, **HForward** will use the last table used by the last HFSQL function (function starting with "H").

![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png) This parameter corresponds to a file name.

**`<Item>: (Optional character string)`**

Name of item according to which the browse is performed. 
If this name is not specified, **HForward** handles the last item in the table used by the last HFSQL function (function starting with "H").

**`<Step>: (Optional integer)`**

Number of steps forward (which means number of records to browse). By default, &lt;Step&gt; = 1.
![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png) &lt;Step&gt; is mandatory if &lt;Item&gt; was specified.

**`<Options>: (Optional Integer constant (or combination of constants))`**

Configures:

- the lock mode applied to the record read. By default, the lock performed corresponds to the current lock.
	


|   |   |
| --- | --- |
| *hLockNo* | No blocking: the Record can be played back or modified by another application during playback. |
| *hLockReadWrite* | Read/write lock: the record being read cannot be read or modified by another application. |
| *hLockWrite* | Write lock: the record currently read can be read by another application but it cannot be modified by another application. |


	![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png)![Native Connectors (Native Accesses)](https://doc.pcsoft.fr/ext/images/us/AN.png) The lock options will have no effect if the locks are not supported by the OLE DB provider or by the Native Connector.
	![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) JDBC access: lock management is not supported for databases that are accessed through JDBC. 
	![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![Android Widget ](https://doc.pcsoft.fr/ext/images/us/ANDROIDWIDGET.png) Management of locks not available in SQLite databases. 

- the management of duplicates during the browse. By default, all duplicates are iterated over.
	


|   |   |
| --- | --- |
| *hDistinct* | Only one record is read if duplicates are found when looping through a key item. |




![Hyper File 5.5](https://doc.pcsoft.fr/ext/images/us/HF55.png) &lt;Options&gt; is ignored.![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png) &lt;Options&gt; is ignored.

## Remarks


### Read operation according to a key item or not
<a name="read_operation_according_key_item_not_ELTPARAGRAPHE000207"></a>

In all cases, the route must have been initialized with one of the following functions: [HReadFirst](../WDLang4/3044051.md), [HFirst](../WDLang4/3044113.md), [HReadSeekFirst](../WDLang4/3044036.md), [HSeekFirst](../WDLang4/3044125.md), [HChangeKey](../WDLang4/3044151.md), [HRestorePosition](../WDLang4/3044137.md).

If the item used is a key item:

- if the *hDistinct* constant is not specified, **HForward** moves forward &lt;Step&gt; key values from the current position.

- if the *hDistinct* constant is specified, **HForward** moves forward &lt;Step&gt; key values from the current position. If duplicates are found, a single duplicate is read.




If the item used is not a key item:

- the *hDistinct* constant is not available.

- **HForward** moves foward from &lt;Step&gt; active records from the current position.



<a name="NOTE0_2"></a>


### Memos
<a name="memos_ELTPARAGRAPHE000250"></a>

The memos associated with the record can be automatically read (or not) when reading the record. [HSetMemo](../WDLang4/3044139.md) is used to customize this automatic read operation.

If the memos are supported, the associated text memos are read when the record is read. The binary memos are read only when they are explicitly used ([HExtractMemo](../WDLang4/3044072.md)).
<a name="NOTE0_3"></a>


### Lock
<a name="lock_ELTPARAGRAPHE000267"></a>

By default (no lock variable specified), the lock performed corresponds to the current lock mode.

If a lock is specified (*hLockWrite* or *hLockReadWrite* constant), the record will be read and locked only if it is not already locked by another application.

![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png)![Native Connectors (Native Accesses)](https://doc.pcsoft.fr/ext/images/us/AN.png) The lock options will have no effect if the locks are not supported by the OLE DB provider or by the Native Connector.

![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png) Locks are not supported.
<a name="NOTE0_4"></a>


### Miscellaneous
<a name="miscellaneous_ELTPARAGRAPHE000286"></a>

- The result of [HFound](../WDLang4/3044104.md) must be ignored ([HFound](../WDLang4/3044104.md) must be used for the searches performed by [HReadSeek](../WDLang4/3044050.md)).

- [HRecNum](../WDLang4/3044063.md) returns the current record number.

- **HForward** respects the current active filter (defined by [HFilter](../WDLang4/3044100.md)).

- [HChangeKey](../WDLang4/3044151.md) changes the search key while keeping the position on the current record.

- **HForward**(Customer,Name) is equivalent to [HReadNext](../WDLang4/3044037.md)(Customer,Name)
