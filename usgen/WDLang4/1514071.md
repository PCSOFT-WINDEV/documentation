


## Item Description (Variable type)

***In french: Description de Rubrique (Type de variable)***
				



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
An **Item Description** variable is used to describe one or more items in a table programmatically. The description of each item is validated by [HDescribeItem](../WDLang4/3044233.md).

After this validation:

- This item can be handled like any other item described in the database schema.

- The "Item Description" variable is reinitialized and can be used to describe another table item programmatically.





<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
MyItem is Item Description
MyItem1, MyItem2 are Item Descriptions
```


<a name="Exemple2"></a>

```wl
// Describe the AFile table
...
// Description of the "NAME" item
MyItem is Item Description
MyItem.Name = "NAME"
MyItem.Type = hItemText
MyItem.Size = 40
MyItem.KeyType = hUniqueKey
// Validate the description of the "NAME" item
HDescribeItem(AFile, MyItem)

// Validate the description of the AFile table
...
```

## Syntax

### Declaring one or more item descriptions

`<Variable name> is Item Description
<Variable name 1>, <Variable name 2> are Item Descriptions`
---

**`<Variable name>: ()`**

Name of the "Item Description" variable to declare.

Note: The keywords <u><u><u><u>une</u></u></u></u> and <u><u><u><u>des</u></u></u></u> are not mandatory: they are approval words..

``

**Special case: Describing a compound key**
When describing a composite key programmatically, **[Type](../Proprietes/2510131.md)** is optional. On the contrary, [KeyExpression](../Proprietes/2512035.md) must be used to describe the composition of the composite key.

**Special case: Describing a primary key**: 

- You must indicate that the item is a primary key, using the [KeyType](../Proprietes/2512060.md) property. 

- If the item can hold null values ([NullAllowed](../Proprietes/1000019492.md) property set to <u><u><u><u>True</u></u></u></u>) but can also be primary key, the [NullAllowed](../Proprietes/1000019492.md) property of the item will be automatically set to <u><u><u><u>False</u></u></u></u>.   




**Special case: Describing a Combination or Enumeration heading**: 

- You must call [TypeDescription](../Proprietes/1000021596.md) to define the type used by the item. 

- It is necessary to specify the type with the [Type](../Proprietes/2510131.md) property before specifying the default value with the [DefaultValue](../Proprietes/2512092.md) property.




**Special case: Describing a Timestamp field**: 

- The item must be a DateTime, Date or Time item. 

- It is necessary to specify the timestamp type with the [TimestampType](../Proprietes/1000021954.md) property.




**Special case: Describing a Formule heading**: 
The [Type](../Proprietes/2510131.md) property must not be used to describe an Expression item. You must use [CalculatedItemExpression](../Proprietes/1000021823.md) to describe the calculation expression.

### How to describe tables programmatically
<a name="how_describe_tables_programmatically_ELTPARAGRAPHE000353"></a>

To describe tables programmatically:

1. For each table:

	- Describe the characteristics of the table using [HFSQL properties](../Proprietes/2512070.md).

	- Describe the characteristics of the items using [HFSQL properties](../Proprietes/2512070.md).

	- Validate the description of each item ([HDescribeItem](../WDLang4/3044233.md)).

	- If necessary, describe the characteristics of full-text indexes using [HFSQL properties](../Proprietes/2512070.md).

	- Validate the description of each full-text index ([HDescribeFullTextIndex](../WDLang4/1000017407.md)).

	- Validate the table description ([HDescribeFile](../WDLang4/3044206.md)).




2. If necessary, describe the characteristics of the links using [HFSQL properties](../Proprietes/2512070.md).

3. If necessary, validate the description of each link ([HDescribeLink](../WDLang4/3044191.md)).



<a name="NOTE0_3"></a>


### Handling the items of a table described programmatically
<a name="handling_the_items_table_described_programmatically_ELTPARAGRAPHE000395"></a>

When creating a table in the data model editor, the names of the tables and items are automatically recognized by the compiler.

When creating a table using a "File Description" variable, the names of the table and its items can be defined with the [Name](../Proprietes/2510082.md) property. These names are not automatically recognized by the compiler. A compilation error occurs if these names are used to identify the table or the items.

To allow the compiler to recognize the names of the table and items described in the code, the table name must be declared as [data source](../WDLang4/1514053.md). Then, this table and its items can be handled by their name in the code editor.

For example:


```wl
AFile is File Description
...
AFile.Name = "CUSTOMER"
...
HDescribeFile("CUSTOMER")
...
CUSTOMER is Data Source
...
HReadFirst(CUSTOMER, "CUSTNAME")
```


**Remark**: It is also possible to declare the name of the table with the keyword [Extern](../Motscles/1511013.md).. However, the process execution will be slower.
<a name="NOTE0_4"></a>


### Logging
<a name="logging_ELTPARAGRAPHE000421"></a>

When the table is described programmatically:

- if the table is logged and if no item is logged, all the items (except for the composite keys) are automatically logged.

- if the table is logged and if at least one item is logged, the other items are not modified.
