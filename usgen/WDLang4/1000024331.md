


## &lt;Source&gt;.Write (Function)

***In french: &lt;Source&gt;.Ecrit***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Writes a record into a table without updating the indexes corresponding to all keys used in the table. The memos are added if necessary (if the management of memos is enabled, [&lt;Source&gt;.SetMemo](../WDLang4/1000024987.md)).

After the call to **&lt;Source&gt;.Write**:

- integrity and duplicate errors are not checked.

- if a lock problem occurs (attempt to modify a locked record), [HErrorLock](../WDLang4/3044099.md) returns <u><u><u>True</u></u></u> and the record is not modified.

- the current record number is modified: the current record corresponds to the written record.




**Remarks**:

- To update the indexes during a write operation, use [&lt;Source&gt;.Add](../WDLang4/1000024187.md) or [&lt;Source&gt;.Modify](../WDLang4/1000025038.md). 
	![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png)![Native Connectors (Native Accesses)](https://doc.pcsoft.fr/ext/images/us/AN.png) **&lt;Source&gt;.Write** and [&lt;Source&gt;.Modify](../WDLang4/1000025038.md) are equivalent. The indexes on the database are updated.

- If a key value is modified with **&lt;Source&gt;.Write**, the index will no longer be consistent. It must be re-indexed ([&lt;Source&gt;.Index](../WDLang4/1000025060.md)).

- This function can be used to write a record in a selection made by a query (query executed with the constant *hWithFilter* constant only).







<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
// Write a record at the end of a table
Customer.Write(HNbRec() + 1)
```

## Syntax

`<Result> = <Source>.Write([<Record number> [, <Options>]])`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the writing was performed in the table, 

- <u><u><u><u>False</u></u></u></u> in the event of an error (blocking, etc.): the record is not modified. [HError](../WDLang4/3044088.md) is used to identify the error.




**`<Source>: (Type corresponding to the specified source)`**

Name of the table used. 

**`<Record number>: (Optional integer)`**

Number of the record to write. The record loaded in memory is re-written on the specified record. 
If this number is greater than the total number of records in the table, intermediate deleted records will be created in order for the sequential reading of the table ([&lt;Source&gt;.Read](../WDLang4/1000025019.md)) to be consistent. 
If this parameter is not specified (equal to 0 or to the *hCurrentRecNum* constant), **&lt;Source&gt;.Write** modifies the current record in the table.
![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png)![Native Connectors (Native Accesses)](https://doc.pcsoft.fr/ext/images/us/AN.png) **&lt;Source&gt;.Write** modifies the current record only. You cannot specify a record number other than the current one (to specify the current record number, use the *hRecNumCurrent* constant).

**`<Options>: (Combination of optional constants)`**

Configures:

- **automatic identifier calculation mode** For details of how to manage the automatic identifier when adding a record, see [Managing the automatic identifier during an addition](../WDLang4/3044183.md).
	


|   |   |
| --- | --- |
| *hForceIDAuto* | The automation ID is not calculated at the time of writing: the ID value will be the one stored at the time of writing. |
| *hRecalculateIDAuto* | The automatic identifier of the record will be re-calculated during the write operation. This constant has priority over *hForceIDAuto* and *hSetIDAuto*. |
| *hSetIDAuto* | The automation ID is not calculated at the time of writing: the ID value will be that stored at the time of writing. <br>The next identifier value calculated by the HFSQL engine will correspond to the largest identifier value in the +1 table. |
| *hWriteDefault*<br>(Default value) | **If the written record is not a deleted record**, the automatic identifier (if it exists) of the record in the table is re-used. <br>**If the written record is a deleted record**, a new automatic identifier is calculated for the record.<br>The *hWriteDefault* constant is ignored if *hWriteDefault* is specified with one of the other constants. |


	A WLanguage error is generated if the three constants (*hForceIDAuto*, *hSetIDAuto* and *hRecalculateIDAuto*) are used at the same time.

- **the lock mode applied to the record.**
	If no lock constant is specified, the record is not locked.
	


|   |   |
| --- | --- |
| *hLockNo* <br>(Default value) | No blocking: the written record will not be blocked. |
| *hLockReadWrite* | Read/write lock: the written record will be locked in read and write mode. This record cannot be read or modified by another application. Only the current application can modify it, read it or unlock it. |
| *hLockWrite* | Lock in write mode: the written record will be locked in write mode. This record can be read by another application but it cannot be modified by another application. Only the current application can modify it or unlock it. |





![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png)![Native Connectors (Native Accesses)](https://doc.pcsoft.fr/ext/images/us/AN.png) Lock options will have no effect if the OLE DB provider or Native Connector (also called Native Access) does not support locks.
![Hyper File 5.5](https://doc.pcsoft.fr/ext/images/us/HF55.png) &lt;Options&gt; is ignored.

## Remarks


### Managing automatic identifiers
<a name="managing_automatic_identifiers_ELTPARAGRAPHE000370"></a>

By default, the "automatic identifier" item is automatically updated when a record is added into a table.

The *hForceIDAuto* and *hSetIDAuto* constants are used to modify the default behavior of the automatic identifier.

For more details on automatic identifiers for new records, see [Managing the automatic identifier](../WDLang4/3044183.md).


![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png)![Native Connectors (Native Accesses)](https://doc.pcsoft.fr/ext/images/us/AN.png) **Special cases**

- If the database generates an automatic identifier, the HFSQL engine keeps this value. If the *hForceIDAuto* or *hSetIDAuto* constant is specified, the HFSQL engine replaces the generated value by the desired value.
	**Note** The constant *hForceIDAuto* is equivalent to *hFixeIDAuto*: the automatic identifier calculated by the HFSQL engine the next time a table is added will be unique in the table.

- If no automatic identifier is generated by the database, the HFSQL engine generates the value and assigns it to the automatic identifier.

### Version of the table after a write operation
<a name="version_the_table_after_write_operation_ELTPARAGRAPHE000411"></a>

If the record was written (no lock problem, etc.), the table version number is modified. To get the version number, use [&lt;Source&gt;.Version](../WDLang4/1000025082.md).
<a name="NOTE0_4"></a>


### Managing binary memos
<a name="managing_binary_memos_ELTPARAGRAPHE000426"></a>

When a record is modified, the memos are modified if necessary (if the management of memos is enabled by [&lt;Source&gt;.SetMemo](../WDLang4/1000024987.md)). 
**Reminder** To initialize a binary memo item, use function [&lt;Source&gt;.LinkMemo](../WDLang4/1000024194.md).

### Browsing and writing a record
<a name="browsing_and_writing_record_ELTPARAGRAPHE000464"></a>

If the write operation is performed during a browse, the record written will be visible in the current browse only. If other browse operations have been defined on this database, the record written will only be visible once these browse operations have been reinitialized.
