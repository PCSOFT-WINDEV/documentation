


## &lt;Source&gt;.DescribeTrigger (Function)

***In french: &lt;Source&gt;.DécritTrigger***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Adds or modifies a trigger on an HFSQL table. A trigger is a WLanguage procedure automatically called by the HFSQL engine whenever an HFSQL function is run. UPDATE, INSERT and DELETE queries also trigger execution of the trigger (note: the trigger is not triggered on tables accessed via a Native Connector). 

For more details, see [Managing triggers](../WDLang4/3044271.md). 

![HFSQL Classic](https://doc.pcsoft.fr/ext/images/us/HF.png)![HFSQL Client/Server](https://doc.pcsoft.fr/ext/images/us/HFCS.png) This function is only available on the client side. Use [&lt;Connection variable&gt;.DescribeServerTrigger](../WDLang4/1000022653.md) to define a server trigger for an HFSQL Client/Server database.


<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
// In the initialization code of the project
Local
	TriggerResult is boolean
// Create trigger for customer table
ResultTrigger = Client.DescribeTrigger("HAJOUTE,HMODIFIE,HSUPPRIME,HRAYE,HECRIT", ...
	"CheckUserRights", hTriggerBefore)
// "CheckUserRights" is a global procedure of the project
IF TriggerResult = False THEN
	 Error("Error on a trigger: " + HErrorInfo)
	 RETURN
END
```

## Syntax

`<Result> = <HFSQL table>.DescribeTrigger(<List of HFSQL functions> , <WLanguage procedure> , <Type of trigger>)`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the operation was performed, 

- <u><u><u><u>False</u></u></u></u> if a problem occurs. [HErrorInfo](../WDLang4/3044071.md) is used to identify the error.




**`<HFSQL table>: (Name of table)`**

Logical name of an HFSQL table.

**`<List of HFSQL functions>: (Character string)`**

Name of one or more HFSQL or TableXXX functions on which the trigger must be implemented. To specify several names of functions, the names of functions must be separated by a comma (","). You have the ability to define triggers on the following functions:

- [&lt;Source&gt;.Modify](../WDLang4/1000025038.md)

- [&lt;Source&gt;.Add](../WDLang4/1000024187.md)

- [&lt;Source&gt;.Delete](../WDLang4/1000025071.md)

- [&lt;Source&gt;.Write](../WDLang4/1000024331.md)

- [&lt;Source&gt;.Cross](../WDLang4/1000025051.md)




**`<WLanguage procedure>: (Procedure name)`**

Name of the WLanguage procedure that will be run when a trigger is activated on the specified HFSQL functions.

**`<Type of trigger>: (Integer constant)`**

Indicates the type of trigger.


|   |   |
| --- | --- |
| *hTriggerAfter* | The procedure is run after the HFSQL function. |
| *hTriggerBefore* | The procedure is run before the HFSQL function. |

## Remarks


### Trigger on the functions for manipulating Table controls
<a name="trigger_the_functions_for_manipulating_table_controls_ELTPARAGRAPHE000254"></a>

Table field manipulation functions ([&lt;Table&gt;.Add](../WDLang1/1000023600.md), [&lt;Table&gt;.AddLine](../WDLang1/1000023404.md), [&lt;Table&gt;.Delete](../WDLang1/1000024289.md), [&lt;Table&gt;.Modify](../WDLang1/1000024273.md), etc.) implicitly use the following HFSQL functions: [&lt;Source&gt;.Add](../WDLang4/1000024187.md), [&lt;Source&gt;.Delete](../WDLang4/1000025071.md) and [&lt;Source&gt;.Modify](../WDLang4/1000025038.md).

When using one of these functions for handling tables, if a trigger is defined for the corresponding HFSQL function, the trigger is automatically activated.
<a name="NOTE0_2"></a>


### Variables used to manage the triggers
<a name="variables_used_manage_the_triggers_ELTPARAGRAPHE000301"></a>

A procedure (or stored procedure) of the trigger type receives no parameters. However, some HFSQL state variables are positioned before each call:


|   |   |
| --- | --- |
| H.FileName | Character string: Logical name of the table for which the trigger is activated. <br><br>**Warning** Depending on the logical name used by the application, the value of the variable **H.FileName** variable may be different (using aliases, for example). It is recommended to use: <br><br>- MyFile.DescribedName to find out the logical name of the table being manipulated (without taking aliases into account). <br><br>- MyFile.PhysicalName to find out the physical name of the table being manipulated.  <br><br><br> |
| H.Action | Character initialized to "A" for a Before trigger and to "P" for an After trigger. |
| H.TriggerFunction | String: Name of the HFSQL function that triggered the trigger. <br><br><br>	<B><B><B><B>Warning</B></B></B></B><br><br>	 The Variable **H.FunctionTrigger** is deprecated in favour of the variable **H.FunctionTriggerNumber**. The information given by the Variable is independent of the language used to run the application.<br>
 |
| H.TriggerFunctionNumber | Constant used to identify the function that triggered the trigger: <br><br>- *htrgHAjoute* The function that triggered the trigger is [&lt;Source&gt;.Add](../WDLang4/1000024187.md). <br><br>- *htrgHEcrit* The function that triggered the trigger is [&lt;Source&gt;.Write](../WDLang4/1000024331.md). <br><br>- *htrgHModifies* The function that triggered the trigger is [&lt;Source&gt;.Modify](../WDLang4/1000025038.md). <br><br>- *htrgHRaye* The function that triggered the trigger is [&lt;Source&gt;.Cross](../WDLang4/1000025051.md). <br><br>- *htrgHSuppresses* The function that triggered the trigger is [&lt;Source&gt;.Delete](../WDLang4/1000025071.md). <br><br><br> |
| H.ToDo | During the execution of a before trigger:<br><br>- cancelling the execution of the current HFSQL function by assigning **"A"** to the HFSQL state variable: H.ToDo = "A". In this case, the action is not performed and the function (HAdd, HModify, etc.) returns <u><u><u><u>True</u></u></u></u> (no error).<br><br>- cancelling the execution of the ongoing HFSQL function by assigning **"E"** to the HFSQL state variable: H.AFaire = "E". In this case, the action is not performed and the function (HAdd, HModify, etc.) returns <u><u><u><u>False</u></u></u></u>. The error message reads: "Action on table XXX has been interrupted by the trigger".<br><br><br> |


**Note** In the case where a "BEFORE" and an "AFTER" trigger are associated with an HFSQL function, if the "BEFORE" trigger cancels the execution of the HFSQL function (by setting H.AFaire to "A"), the "AFTER" trigger is not triggered.
