


## &lt;Source&gt;.CreateIfNotFound (Function)

***In french: &lt;Source&gt;.CréationSiInexistant***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Performs the following operations:

- If the table does not exist, creates an empty table (".FIC" extension) with the index file and the memo file if necessary.
	The function is equivalent to [&lt;Source&gt;.Creation](../WDLang4/1000024207.md).

- If the table exists, opens the table. 
	In this case, the function is equivalent to [&lt;Source&gt;.Open](../WDLang4/1000025043.md). 
	To optimize the call to **&lt;Source&gt;.CreateIfNotFound**, the table can be opened only when accessed for the first time (using the *hDelayedOpening* constant).




**Note**: The automatic creation of non-existing tables can be enabled in the project description ("Tables" tab of the project description, "Automatically create the tables when they are opened"). **&lt;Source&gt;.CreateIfNotFound** is automatically used if the table does not exist when it is handled for the first time.

### Characteristics of created table
<a name="characteristics_created_table_ELTPARAGRAPHE000404"></a>

The characteristics of the created table are as follows:

- *Name of the table*:
	Physical name defined during the file description in the data model editor. This name can be modified by [&lt;Source&gt;.ChangeName](../WDLang4/1000024201.md) before creating the table.

- *Directory of table*:
	Directory defined during the file description in the data model editor. This directory can be changed with [&lt;Source&gt;.ChangeDir](../WDLang4/1000024202.md) and [HSubstDir](../WDLang4/3044028.md) before creating the table.
	**Note**: If UAC is active (Windows Vista and above), data localization is specific: data will not be located in the application directory, but in a specific Windows directory. In this case, you must create the application data directory (you can get the path with [fDataDirUser](../WDLang1/3036071.md)).

- The order of items created in the physical file is the physical order of items created in the database schema (and not the logical order).

- *Content of the table*:
	The created table is empty, which does not mean that its size is null (the table contains a header describing its structure).


**Note**: If the table already exists (same name, same directory), this table is opened. If the *hDelayedOpening* constant is specified, the table will only be opened the first time it is accessed (optimizes the speed of **&lt;Source&gt;.CreateIfNotFound**).

### Additional files created
<a name="additional_files_created_ELTPARAGRAPHE000449"></a>

When creating a table, the following tables can be created in addition to the table:

- **An index file** (".NDX" extension) if one or more keys have been defined in the file description.

- **A memo file** (".MMO" extension) if one or more memo items have been defined in the file description.

- **A log file** (".JNL" extension). This file is created only if the corresponding option was selected during the file description (see next paragraph).
	![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![Android Widget ](https://doc.pcsoft.fr/ext/images/us/ANDROIDWIDGET.png)![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png)![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png) This file is not created.

- **A &lt;ProjectName&gt;.REP file**. This file contains the list of tables handled by the application. This file is created (or filled) if the management of .REP is enabled ([HSetREP](../WDLang4/3044061.md)). If the *hDelayedOpening* constant is specified, the .REP file will be updated during the automatic file opening performed during the first access to the table. For more details, see [.REP file](../WDLang4/3044186.md).
	![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png) This file is not created.

### Managing passwords
<a name="managing_passwords_ELTPARAGRAPHE000478"></a>

The password can be defined:

- when the table is created or opened by **&lt;Source&gt;.CreateIfNotFound**.

- before the table is created by [&lt;Source&gt;.Password](../WDLang4/1000025044.md).**Attention**: The password is independent of data encryption. The data encryption must be configured during the file description in the data model editor ("Details" tab).


![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png)![Native Connectors (Native Accesses)](https://doc.pcsoft.fr/ext/images/us/AN.png) The password is not associated with a table but with a database. This password must be specified during the connection ([HConnect](../WDLang4/3044263.md)).

### Managing fatal errors when creating a table
<a name="managing_fatal_errors_when_creating_table_ELTPARAGRAPHE000505"></a>If a fatal error occurs when creating a table, it may be interesting to continue the program while checking whether the table was created or not. To do so, we recommend that you perform the following exception process:

```wl
WHEN EXCEPTION IN
	Parent.CreateIfNotFound()
DO
	Error("HFSQL error: " + HError())
ELSE
	Trace("The file is created")
END
```

### Managing non-Latin character sets 
<a name="managing_nonlatin_character_sets_ELTPARAGRAPHE000523"></a>

If the *hChangeCharset* constant is specified, the character set used in the table will be the one specified by [ChangeCharset](../WDLang1/3054001.md). Sorts, searches, etc. on string keys (strings, characters, date and time) will be performed according to this character set.

The character set used can be modified by [&lt;Source&gt;.Index](../WDLang4/1000025060.md).

**Note**: the length of string fields specified in the database schema is in bytes, not characters. Depending on the character set used, you may have to increase the item size (if the characters used are coded on 2 bytes for example).

For more details, see [Managing specific character sets in the tables](../WDLang1/3054017.md).

### Replication: Range of Identifiers
<a name="replication_range_identifiers_ELTPARAGRAPHE000552"></a>

The automatic identifiers for the files of subscriber replicas are using a range of identifiers that differs from the one used by the file of master replica and by the other files of subscriber replicas.

This range of automatic identifiers is written in the header of each table (".FIC" extension).
This range is initialized:

- when creating a table ([&lt;Source&gt;.Creation](../WDLang4/1000024207.md), **&lt;Source&gt;.CreateIfNotFound**).

- via [WDReplic](../WDReplic/3520016.md).

- when [&lt;Source&gt;.InitSubscriber](../WDLang4/1000024998.md) is used.


For more details, see the [consequences of implementing the replication](../WDLang4/3044246.md).

### Priority for defining the location of log files
<a name="priority_for_defining_the_location_log_files_ELTPARAGRAPHE000592"></a>

The location of log files is defined according to the following priority order:

1. Location specified when creating the logged table (**&lt;Source&gt;.CreateIfNotFound**).

2. Location specified by [&lt;Source&gt;.ChangeLogDir](../WDLang4/1000024203.md).

3. Location specified in the database schema.

4. Location of the logged table.




If another application uses [&lt;Source&gt;.DeclareExternal](../WDLang4/1000024214.md) on a logged table, the changes made by this application are saved in the log files specified in the header of the logged HFSQL table.
![HFSQL Client/Server](https://doc.pcsoft.fr/ext/images/us/HFCS.png) The location of Log files is fixed and it cannot be modified. For more details, see [Log files in Client/Server mode](../WDLang4/3044197.md).

### Creating or opening an existing table
<a name="creating_opening_existing_table_ELTPARAGRAPHE000629"></a>

If the table already exists, the table is opened.

If the table does not already exist, the table is created. When creating a table, WINDEV and WEBDEV try to create the items in the OLE DB type corresponding to the HFSQL type. If this type is not supported, the HFSQL engine successively tries all the "compatible" OLEDB types until it finds a type that is supported by the OLEDB database.

### Managing indexes
<a name="managing_indexes_ELTPARAGRAPHE000643"></a>

**&lt;Source&gt;.CreateIfNotFound** does not return any error messages if an index cannot be added. The table is created without the index that is causing the problem. In this case, duplicates may be found in an item defined as unique key by WINDEV or WEBDEV if the external database does not support the unique keys.

### Creating the table from its description
<a name="creating_the_table_from_its_description_ELTPARAGRAPHE000655"></a>

The table can be directly created from its description in the data model editor. To do so, select "Create the table" in the context menu of the table (in the database schema graph) and select the directory in which the table must be created.
