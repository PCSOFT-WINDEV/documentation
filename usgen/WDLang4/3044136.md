


## HSavePosition (Function)

***In french: HSauvePosition***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Stores the current context of a table: current record, filter, read pointers. This allows you to temporarily suspend the current process in order for the table to be used somewhere else (to perform checks for example). The saved context can be restored by [HRestorePosition](../WDLang4/3044137.md). Then, the main process can continue.

**HSavePosition** is used to save:

- the number of the record used,

- the different pointers in the index (the position in the index is saved for each key), 

- the current filter. You will have to use the *hRPFilter* constant in [HRestorePosition](../WDLang4/3044137.md) to restore the stored filter.  




This function can be used with the tables, HFSQL views, or queries.

<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
// Find a record
HReadSeekFirst(Customer, Name, Name)
WHILE HFound(Customer) = True
	// Saves the current context
	nPos = HSavePosition(Customer, Name)
	// Check a customer with another name
	HReadSeek(Customer, Name, Name2)
	IF HFound() = True THEN Counter = Counter + 1
	// Restores the context
	HRestorePosition(nPos)
	HReadNext(Customer, Name)
END
```

## Syntax

`<Result> = HSavePosition([<Table> [, <Item>]] [, <Options>])`
---

**`<Result>: (Integer)`**



- Number of the position that was saved,

- -1 if an error occurred.




**`<Table>: (Optional character string)`**

Name of the table, view or query used. If this name is not specified, **HSavePosition** will use the last table used by the last HFSQL function (function starting with "H").

**`<Item>: (Optional character string)`**

Name of the item used. If this parameter is not specified, **HSavePosition** saves the positions of all items being looped through.
![Hyper File 5.5](https://doc.pcsoft.fr/ext/images/us/HF55.png) The &lt;Rubrique&gt; parameter will be ignored: the position will be saved for all browse items in progress.

**`<Options>: (Optional integer constant)`**

Used to configure the backup:



|   |   |   |
| --- | --- | --- |
| *hSaveItems* | Saves the values of items in memory when using **HSavePosition**. These values will be restored next time [HRestorePosition](../WDLang4/3044137.md) is called.<br><br>![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![Android Widget ](https://doc.pcsoft.fr/ext/images/us/ANDROIDWIDGET.png)![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) This constant is only available for HFSQL tables. |   |

## Remarks


### Example for managing the positions in a table
<a name="example_for_managing_the_positions_table_ELTPARAGRAPHE000120"></a>

**HSavePosition** and [HRestorePosition](../WDLang4/3044137.md) can be used in the following cases for example:

- form used to display a record and to loop through the table according to a key. Another window is called to display the data as a table. Positions allow you to easily go back to desired record in the iteration.

- viewing a table in a Table control. When selected, the record is displayed as a form, with the possibility of looping through forms. The position management allows you to display the Table control again while being properly positioned on the table.



<a name="NOTE0_2"></a>


### Reinitializing positions
<a name="reinitializing_positions_ELTPARAGRAPHE000137"></a>

Please note: all functions which open or close a table reset the context numbers (e.g. [HCreation](../WDLang4/3044255.md), [HClose](../WDLang4/3044073.md), ...).
<a name="NOTE0_3"></a>


### Miscellaneous
<a name="miscellaneous_ELTPARAGRAPHE000152"></a>

- The number of calls to **HSavePosition** is not limited.

- You have the ability to nest **HSavePosition** and [HRestorePosition](../WDLang4/3044137.md) for the same table.

- If the record pointed during the call to **HSavePosition** is deleted, [HRestorePosition](../WDLang4/3044137.md) cannot be called anymore.

### Repositioning by OLE DB and Native MySQL, DB2 and Informix Connectors
<a name="repositioning_ole_and_native_mysql_db2_and_informix_connectors_ELTPARAGRAPHE000177"></a>

If the database or the status of the iteration (e.g., reinitialized) does not allow resetting the position directly on the record, the position is set using the cache of records read.

The following functions reinitialize the iteration:

- [HReadFirst](../WDLang4/3044051.md)/[HFirst](../WDLang4/3044113.md).

- [HReadLast](../WDLang4/3044140.md)/[HLast](../WDLang4/3044101.md).

- [HSetMemo](../WDLang4/3044139.md).




This operating mode is the same in Java.
