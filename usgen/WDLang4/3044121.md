


## HCross (Function)

***In french: HRaye***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Crosses a record in a table. The record is deleted logically and it can be retrieved if necessary.

The following operations are performed:

- the record becomes inactive. The data is stored (which is not the case when a record is deleted by [HDelete](../WDLang4/3044018.md)).

- the indexes (corresponding to the record keys) are deleted from the index file.

- the memos associated with the record are stored.




This function can be used on the tables, the HFSQL Mobile views, or the queries.




<a name="sample_code"></a>

## Example

<a name="Exemple1"></a>

```wl
// Crosses the record #123
HCross(Customer, 123)
```
<a name="Exemple2"></a>

```wl
// Cross the customer orders
HReadSeekFirst(ORDERS, CUSTNUM, ValCustNum)
WHILE HFound() = True
	HCross()
	HReadNext()
END
```

## Syntax

`<Result> = HCross([<Table> [, <Record number> [, <Options>]]])`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the record was crossed,

- <u><u><u><u>False</u></u></u></u> in case of error (blocked record, integrity problem, etc.). [HErrorInfo](../WDLang4/3044071.md) returns more details.




**`<Table>: (Optional character string)`**

Name of HFSQL table, query or view used. 
If this parameter is an empty string (""), **HCross** manipulates the last table used by the last HFSQL function (function starting with "H").

**`<Record number>: (Optional integer)`**

Number of the record to cross. 
If this parameter is not specified (equal to 0 or the constant *hNumEnrEnCours*), the current Record will be scratched.

**`<Options>: (Optional constant)`**

Configures:

- the lock mode applied to the crossed record. If no lock constant is specified, the crossed record is not locked.
	


|   |   |
| --- | --- |
| *hLockNo*<br>(default value) | No blocking: scratched recordings will not be blocked. |
| *hLockReadWrite* | Lock in read/write mode: the currently scratched record cannot be viewed or reactivated by another application. |
| *hLockWrite* | Lock in write mode: the currently scratched record can be read and consulted (function [HRead](../WDLang4/3044047.md)) by another application, but cannot be reactivated by another application. Only the current application can re-enable it. |



- the integrity management applied to the crossed record.
	


|   |   |
| --- | --- |
| *hCheckIntegrity* | Checks the integrity for the operation, even if the automatic integrity check is disabled ([HSetIntegrity](../WDLang4/3044058.md)). |
| *hIgnoreIntegrity* | Ignores the integrity check for this operation, even if the automatic integrity check is enabled ([HSetIntegrity](../WDLang4/3044058.md)). |


	A WLanguage error occurs if the two constants are used at the same time. These constants have no effect on the cascading deletion.

## Remarks


### Handling a crossed record
<a name="handling_crossed_record_ELTPARAGRAPHE000158"></a>

- A crossed record will not be read:

	- nor by path functions: [HFirst](../WDLang4/3044113.md), [HLast](../WDLang4/3044101.md), [HNext](../WDLang4/3044027.md), [HPrevious](../WDLang4/3044112.md), [HReadFirst](../WDLang4/3044051.md), [HReadLast](../WDLang4/3044140.md), [HReadNext](../WDLang4/3044037.md), [HReadPrevious](../WDLang4/3044048.md), [HForward](../WDLang4/3044154.md), [HBackward](../WDLang4/3044126.md)

	- or search functions: [HSeekFirst](../WDLang4/3044125.md), [HReadSeekFirst](../WDLang4/3044036.md), [HSeekLast](../WDLang4/3044129.md), [HReadSeekLast](../WDLang4/3044034.md).




- A crossed record can be read by [HRead](../WDLang4/3044047.md).

- A crossed record can be re-enabled by [HModify](../WDLang4/3044042.md) or [HWrite](../WDLang4/3044092.md).

- [HState](../WDLang4/3044081.md) is used to find out the record status (active, crossed, deleted, etc.).

- The physical location of a crossed record can only be reused (by [HAdd](../WDLang4/3044147.md) for example) after:

	- the execution of [HFree](../WDLang4/3044064.md),

	- a reindex (with compression) has been performed.






<a name="NOTE0_2"></a>


### Number of crossed records
<a name="number_crossed_records_ELTPARAGRAPHE000235"></a>

[HNbRec](../WDLang4/3044006.md) is used to find out the number of crossed records in the table.

Note: For compatibility with WEBDEV 1.5/WINDEV 5.5, it is also possible to find out the number of scratched records using the variable *h.NbSup*.
<a name="NOTE0_3"></a>


### Version of table
<a name="version_table_ELTPARAGRAPHE000248"></a>

If **HCross** is successful, the table version number is modified. This version number is returned by [HVersion](../WDLang4/3044020.md).
<a name="NOTE0_4"></a>


### Crossing a record from a query
<a name="crossing_record_from_query_ELTPARAGRAPHE000262"></a>

A record can be crossed:

- in the query result.

- or directly in the tables manipulated by the query (constant *HModifiesTable*used in functions [HExecuteQuery](../WDLang4/3044080.md) or [HExecuteSQLQuery](../WDLang4/3044084.md)). In this case, the *hWithFilter* constant is automatically selected.




Regardless of how the query is executed (with or without the constant *hWithFilter*constant), the **HCross** function can only be used on single-file requests.

Caution: 

- Records cannot be crossed in a query that uses groups or aggregates.

- Integrity and duplicates are not managed by operations on multi-file queries: it is advisable to use transactions to avoid any problems.



<a name="NOTE0_5"></a>


### Special cases
<a name="special_cases_ELTPARAGRAPHE000289"></a>

- **Blocking management**: 
	If a lock problem occurs when "crossing" a record (attempt to cross a record locked in write mode for example), the record is not modified and [HErrorLock](../WDLang4/3044099.md) returns <u><u><u><u>True</u></u></u></u>.

- **Managing the referential integrity**
	If the management of the referential integrity is enabled ([HSetIntegrity](../WDLang4/3044058.md)) and if the integrity is not checked during the deletion, **HCross** is not run. [HErrorIntegrity](../WDLang4/3044086.md) must be checked after **HCross**.

- **Deleted records**
	**HCross** must not be called on a record that was deleted beforehand.

### xBase tables
<a name="xbase_tables_ELTPARAGRAPHE000327"></a>

The [HDelete](../WDLang4/3044018.md) function has the same effect as the **HCross FUNCTION** The Record is scratched, not deleted. Therefore, the record can be re-enabled using [HModify](../WDLang4/3044042.md). In this case, [HState](../WDLang4/3044081.md) returns the *hStateCrossed* constant for a deleted record (instead of *hStateDel*).
