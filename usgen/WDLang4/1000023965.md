


## &lt;Connection variable&gt;.Transaction (Function)

***In french: &lt;Variable Connexion&gt;.Transaction***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Starts a transaction on the tables (HFSQL or accessed via a Native Connector) and creates the transaction table.

**What information is saved in the transaction file?** Whenever a WLanguage function modifies a table or an index file during a transaction, the former values of the record and the operation performed are stored in the transaction file.

![HFSQL Client/Server](https://doc.pcsoft.fr/ext/images/us/HFCS.png) This function proposes two operating modes of transactions: 

- The transaction can be started on a connection: in this case, only the tables associated with this connection are transacted. This mode is required to manage the [isolation levels of transactions](../WDLang4/1000017316.md). 

- The transaction can be started on all HFSQL connections (existing ones or future ones). In this case, **&lt;Connection variable&gt;.Transaction** starts both an HFSQL Classic transaction (ISAM) and an HFSQL Client/Server transaction.


![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![Android Widget ](https://doc.pcsoft.fr/ext/images/us/ANDROIDWIDGET.png)![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png)![IOS Widget](https://doc.pcsoft.fr/ext/images/us/WIDGETIOS.png)![Mac Catalyst](https://doc.pcsoft.fr/ext/images/us/CATALYST.png) The management of transactions is available for HFSQL Client/Server databases.

**Note**: This function is equivalent to [&lt;Connection variable&gt;.TransactionStart](../WDLang4/1000023967.md).

<a name="sample_code"></a>

## Example


```wl
MyConnection1 is Connection

// Start transaction on tables associated with MyConnection1
MyConnection1.Transaction()
Add_Order()
WHEN EXCEPTION IN
	// Add the order
	Order.Add() 
	// Validate the addition
	MyConnection1.TransactionEnd()
DO
	// Delete the order lines
	MyConnection1.TransactionCancel()
END
```

## Syntax

### Starting a Client/Server transaction on a specific connection

`<Result> = <Connection>.Transaction([<List of tables>])`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the transaction was started,

- <u><u><u><u>False</u></u></u></u> if a problem occurs. [HErrorInfo](../WDLang4/3044071.md) returns more details about the error.




**`<Connection>: (Connection variable)`**

Name of the [Connection](../WDLang4/1514073.md) variable that describes the connection to use.

**`<List of tables>: (Optional character string)`**

List of logical names of one or more tables to take into account (or not) in the transaction (in this case, the table name is preceded by the "-" sign).


|   |   |
| --- | --- |
| **If this parameter is not specified** | All tables used during the transaction will be taken into account in the transaction. |
| **If all tables are prefixed with the "-" sign**<br>For example: "-Customer, -Product" | All tables specified in the list and used during the transaction will not be taken into account by the transaction.<br>All tables not specified in the list will be taken into account and used during the transaction. |
| **If no table on the list is prefixed with the "-" sign**<br>For example: "Customer, Product" | All tables specified in the list and used during the transaction will be taken into account in the transaction. <br>All tables not specified and manipulated during the transaction will be ignored in the transaction. |
| **If some tables are prefixed with "-" and others are not**<br>For example: "-Customer, Product" (equivalent to "Product") | All tables in the list prefixed with "-" and used during the transaction will be ignored in the transaction.<br>All tables in the list not prefixed with "-" and used during the transaction will be taken into account in the transaction.<br>Tables not specified in the list will be excluded from the transaction. |


![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png)![Native Connectors (Native Accesses)](https://doc.pcsoft.fr/ext/images/us/AN.png) This parameter is ignored. All the tables associated with the connection are in transaction on the native server.

## Remarks
<a name="NOTE0_2"></a>


### Locking records
<a name="locking_records_ELTPARAGRAPHE000426"></a>

The added, modified or deleted records in a transaction are locked in write mode.
<a name="NOTE0_3"></a>


### Error cases
<a name="error_cases_ELTPARAGRAPHE000436"></a>

- Transaction nesting: It is impossible to nest transactions (i.e. to call the **function &lt;Connection variable&gt;.Transaction** within a transaction).. In this case, error 70031 occurs.

- A fatal error is displayed in the following cases: 

	- A transaction is started on all the connections while there is at least one connection in transaction. 

	- A transaction is started on a connection while a transaction was already started on all the connections. 

	- A transaction is started on all the connections while there is at least one connection whose isolation level is not "Read Uncommitted".






<a name="NOTE0_4"></a>
<a name="NOTE0_5"></a>


### Handling records during a transaction
<a name="handling_records_during_transaction_ELTPARAGRAPHE000469"></a>

During a transaction, some rules must be complied with when handling the records. For more details, see [Transactions: Handling the records during a transaction](../WDLang4/3044336.md).
<a name="NOTE0_6"></a>


### Transactions and independent HFSQL context
<a name="transactions_and_independent_hfsql_context_ELTPARAGRAPHE000482"></a>

When copying a context, if a transaction is in progress on the first context, the new context is not in transaction. You must call **&lt;Connection variable&gt;.Transaction** to start a transaction in the new context.
