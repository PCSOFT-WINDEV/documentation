


## HViewToFile (Function)

***In french: HVueVersFichier***

<DIV class="specObsolete">
	<IMG style="float:left;margin-right:10px;" src="$IMGLOCAL$=warning_big.png"><B>Warning</B><BR>
	From version <B>20</B>, SQL views and the materialized views are available.<br>The views handled by this function correspond to the former view mechanism. They do not correspond to SQL views or to materialized views. 
</DIV><a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Saves the modifications performed in an HFSQL view (by [HModify](../WDLang4/3044042.md), [HDelete](../WDLang4/3044018.md) or [HCross](../WDLang4/3044121.md)) in the corresponding table.

**Note**: This operation can only be performed if the view has been created with the constant *hVueBlocage* (i.e. records imported into the view have been blocked in the table). After the call to **HViewToFile**, the records are unlocked in the view source file.

## Example
<a class="notetitle" target="_blank" href="$DOC$=1000003044021&name=hviewtofile_function">See additional examples</a>

```wl
// Saves the modifications of Customer34 view
// into Customer file
HViewToFile(Customer34)
```

## Syntax

`<Result> = HViewToFile(<View>)`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the view was transferred into the table, 

- <u><u><u><u>False</u></u></u></u> otherwise. [HError](../WDLang4/3044088.md) returns more details about the problem.




**`<View>: (Character string)`**

Name of view used. If this name is not specified, **HViewToFile** will handle the last view used by an HFSQL function (function starting with "H").  



<a name="NOTE0"></a>
<a name="NOTE0_1"></a>

## Remarks
If an error occurs when updating the table, [HError](../WDLang4/3044088.md) is used to identify the records that caused the problem. Simply loop through the view again and run [HError](../WDLang4/3044088.md) on each record in the view.
