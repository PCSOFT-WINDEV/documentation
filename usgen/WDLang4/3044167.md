


## HChangeLocation (Function)

***In french: HChangeLocalisation***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Modifies the search mode of physical tables (.FIC, .NDX, ...). By default, the physical tables are sought in the application library then on disk. 

Reminder: Physical tables can be found:

- on disk (most common case).

- in the WINDEV libraries (WDL files).

- in the executable.

- in a component.





<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
// Find tables in libraries 4, 6 and 9
HChangeLocation(CustomerFile, hWDL, 4, 6, 9)
```

<a name="SYNTAXE1"></a>

## Syntax

`<Result> = HChangeLocation(<Table> , <Search mode> [, <Parameters>])`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the operation was performed, 

- <u><u><u><u>False</u></u></u></u> if a problem occurs. [HError](../WDLang4/3044088.md) is used to identify the error.


![HFSQL Client/Server](https://doc.pcsoft.fr/ext/images/us/HFCS.png) If the function **HChangeLocation** is used, &lt;Result&gt; = <u><u><u><u>True</u></u></u></u>, but the function has no effect: the data files being manipulated are still on the server.

**`<Table>: (Character string)`**

Name of the table (defined in the database schema). 
If this parameter is equal to "\*", the search mode will change for all the known tables (described in the database schema). 
**Attention**: the tables concerned are automatically closed.. 
This parameter can also correspond to the name of a [group of files (or custom-folder) defined in the database schema](../Editeurs/2011003.md).

**`<Search mode>: (Constant)`**

Configures the search mode of tables:


|   |   |
| --- | --- |
| *hDisk* | The tables are sought on disk only. This is the most common case. |
| *hWDL*<br>(Default value) | The tables are sought:<br><br>1. In the main WDL; <br><br>2. If &lt;Paramètres&gt; is not specified: searches for tables in WDLs in order of loading, then on disk. <br>	If &lt;Paramètres&gt; is specified: Searches for tables in the specified WDL(s), then on disk. <br><br>3. In the main WDL of the component. <br><br>4. In the secondary WDLs of the component according to the load order.<br><br><br> |



**`<Parameters>: (Optional character string)`**

Identifier of the WDLs where the search must be performed. These WDLs must be loaded by [LoadWDL](../WDLang1/3013020.md) that returns the identifier of the WDL.

## Remarks


### Why include the tables in a library?
<a name="why_include_the_tables_library_ELTPARAGRAPHE000127"></a>

Including the tables in a library presents the following benefits:

- data protection: tables are read-only. 

- data grouping: all files required for execution are grouped together in a single file.
