


## HDuplicateRecord (Function)

***In french: HDupliqueEnregistrement***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Duplicates the record read in a table: the record found in memory is added into the table (query or view). The indexes corresponding to all the keys used in the table are automatically updated. The possible memos are added if the management of memos is enabled ([HSetMemo](../WDLang4/3044139.md)).

After the call to **HDuplicateRecord**:

- Automatic error handling is available for several types of error: Duplicate error, Integrity error, Password error, Modification conflict and status error during modification conflict, Blocking error, etc. For more details, see [HFSQL error handling help](../WDLang4/3044188.md).

- If the management of duplicates is enabled and if the table contains a unique key, [HErrorDuplicates](../WDLang4/3044077.md) returns <u><u><u>True</u></u></u> if the value of added key is not unique. The record is not added.

- The added record becomes the current record. The automatic identifier is automatically filled. By default, the current iteration is not affected.




**Note** The entire record in memory (the content of the previously read record) is written to the table. 

Remarks: 

- This function can also be used on a view or on a query.

- **HDuplicateRecord** and [HAdd](../WDLang4/3044147.md) are equivalent.

## Example


```wl
// Duplicates the current record
HDuplicateRecord(Customer)
```

## Syntax

`<Result> = HDuplicateRecord([<Table> [, <Options>]])`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the record was added,

- <u><u><u><u>False</u></u></u></u> if a problem occurred (integrity error, duplicate error, ...). [HError](../WDLang4/3044088.md) is used to identify the error.




**`<Table>: (Optional character string)`**

Name of the table, view or query used. If this name is not specified, **HDuplicateRecord** will use the last table used by the last HFSQL function (function starting with "H").

**`<Options>: (Optional constant)`**

Used to configure:

- the effect of addition on the current browse.

- the mode for calculating the automatic identifier. For more details, see [Managing the automatic identifier during an addition](../WDLang4/3044183.md).

- the lock mode applied to the added record.

	- ![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png) Management of locks not available in PHP.

	- ![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![Android Widget ](https://doc.pcsoft.fr/ext/images/us/ANDROIDWIDGET.png) Management of locks not available in SQLite databases.

	- ![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) JDBC access: lock management is not supported for databases that are accessed through JDBC.




- the management of duplicates.

- the management of integrity.

## Remarks


### Managing automatic identifiers
<a name="managing_automatic_identifiers_ELTPARAGRAPHE000270"></a>

By default, the "automatic identifier" item is automatically updated when a record is added into a table. There is no need to read the record again to find out the value of the automatic identifier. Simply use the syntax &lt;Nom fichier de données&gt;.&lt;Nom rubrique Identifiant automatique&gt;.

The *hForceIDAuto* and *hSetIDAuto* constants are used to modify the default behavior of the automatic identifier.

For more details on automatic identifiers for new records, see [Managing the automatic identifier during an addition](../WDLang4/3044183.md).
![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![Android Widget ](https://doc.pcsoft.fr/ext/images/us/ANDROIDWIDGET.png)![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png)![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png)![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png)![Native Connectors (Native Accesses)](https://doc.pcsoft.fr/ext/images/us/AN.png) **Special case**

- If the database generates an automatic identifier, the HFSQL engine keeps this value. If the *hForceIDAuto* or *hSetIDAuto* constant is specified, the HFSQL engine replaces the generated value by the desired value. 
	Note: the constant *hForceIDAuto* is equivalent to *hFixeIDAuto*: the automatic identifier calculated by the HFSQL engine the next time a table is added will be unique in the table.

- If no automatic identifier is generated by the database, the HFSQL engine generates the value and assigns it to the automatic identifier.

### Reusing the deleted or freed records
<a name="reusing_the_deleted_freed_records_ELTPARAGRAPHE000296"></a>

When adding a new record, the HFSQL engine optimizes the filling of the table. The space corresponding to the deleted or freed records is used first when a new record is added.

The crossed records are not re-used.

### Version of table after an addition
<a name="version_table_after_addition_ELTPARAGRAPHE000309"></a>

If the record was added to the table (no duplicate error and no integrity error), the version number of the table is modified. To get the version number, use [HVersion](../WDLang4/3044020.md).
<a name="NOTE0_4"></a>


### Adding a record into a query
<a name="adding_record_into_query_ELTPARAGRAPHE000321"></a>

Adding a record into a query can be performed:

- in the query result.

- in the tables handled by the query (*hModifyFile* constant used in [HExecuteQuery](../WDLang4/3044080.md) or [HExecuteSQLQuery](../WDLang4/3044084.md)). In this case, the *hWithFilter* constant is automatically selected.




Regardless of how the query is executed (with or without the constant *hWithFilter*constant), adding records to a query is only possible for single-file queries. The calculated items specified during the addition are ignored. They are automatically calculated.

Caution:

- No addition is allowed in a query that uses groups or aggregates.

- Integrity and duplicates are not managed by operations on multi-file queries: it is advisable to use transactions to avoid any problems.

### Adding records into a view
<a name="adding_records_into_view_ELTPARAGRAPHE000348"></a>

You have the ability to add records into a view created on tables in HFSQL Classic format. These records are added in memory only. To add them into the table linked to the view (simple view for example), you must use [HViewToFile](../WDLang4/3044021.md).
<a name="NOTE0_6"></a>


### Browsing and adding records
<a name="browsing_and_adding_records_ELTPARAGRAPHE000360"></a>You can configure the effect of adding a record during the browse of a table (*hWriteDefault* and *hAffectBrowse* constants). The operating mode of the earlier versions can be kept by using the *hAffectBrowse* constant.

### Slowness when adding or deleting a record for the first time in an HFSQL table
<a name="slowness_when_adding_deleting_record_for_the_first_time_hfsql_table_ELTPARAGRAPHE000372"></a>

Accessing a record in an HFSQL table for the first time may take long. To fix this problem:

- Disable the antivirus for .FIC,.NDX,.MMO and.REP files.

- Disable the "Restore the system" option in Windows XP.

### Addition into a database in Hyper File 5.5 format
<a name="addition_into_database_hyper_file_55_format_ELTPARAGRAPHE000386"></a>

**If you are using HDuplicateRecord with a database in Hyper File 5.5 format:**

- The add options (&lt;Options&gt;) are ignored.

- The TEXT items are automatically filled with space characters.

- **HDuplicateRecord** cannot be used on a view created from Hyper File 5.5 tables.
