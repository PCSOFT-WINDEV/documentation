


## WDModFic: Tool for automatic modification of tables
			



<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000380"></a>


### WDModFic
<a name="wdmodfic_ELTPARAGRAPHE000011"></a>

WDModFic is a tool for the automated modification of tables on the development seat and on end-user seats.

By default, the automatic table modification is performed on the end-user computers or on the deployment computer of the site when updating applications. However, in some cases (tables found on a laptop computer not connected to the network when the update was performed, failed update, ...), **WDModFic** must be used to perform this automatic modification once the application was updated.

**Warning**: Use of WDModFic is reserved for experienced users (e.g. the application administrator).

**Reminder**: Automatic data modification means that changes made in the HFSQL database schema are reflected in the tables. For more details, see [Automatic table modification](../WDLang4/3044195.md).

**Conditions of use**: WDModFic is not automatically installed with applications developed with WINDEV or WEBDEV. The WDModFic.exe file must be selected along with the necessary files (see the next paragraph) when creating the setup.

The license agreement of WINDEV and WEBDEV is fully enforced.

**Note**: Tables can also be modified automatically by programming them with the [HModifyStructure](../WDLang4/1000019439.md) function.

## Starting WDModFic
<a name="starting_wdmodfic_ELTTEXTE000404"></a>
WDModFic can be started:

- in command line mode (without displaying the wizard of WDModFic). HFSQL Classic or HFSQL Client/Server tables can be modified.

- in interactive mode (while displaying the wizard of WDModFic):

	- on the "Database schema" tab, in the "Database schema" group, expand "Synchronization" and select "Synchronize Structure and Deployed Data (SDD, Auto Modif...") (from the data model editor on the development computer only).

	- run "WDModFic.EXE" directly.

## Using WDModFic in command line mode
<a name="using_wdmodfic_command_line_mode_ELTTEXTE000434"></a>
To perform an automatic modification of the tables, the syntax is as follows:


```txt
WDModFic.EXE [-subdir][-report][-error][-wizard][-nobackup][-noprogress][-nolink]
			[-noanaguid][-noanaconnection]
			/WDD=<WDDPath>
			/PWD=<WDDPassword>
			/DIR=<DataFileDir>
			/FILE=<DataFile>
			/FILEPWD=<MotPasseFichierDeDonnées>
			/PRJ=<ProjectName>
			/SERVER=<HFSQLClientServerDatabase>
			/US
```


Details of parameters:

| Parameter | Meaning |
| --- | --- |
| -subdir | If this parameter is specified, the tables are searched in the specified directory ("/DIR" parameter) and its subdirectories.<br><br>By default, if this parameter is not specified, the tables are only searched in the specified directory ("/DIR" parameter) |
| -report | If this parameter is specified, a status report will be displayed at the end of the automatic modification of the tables.<br><br>If this parameter is not specified, no status report will be displayed at the end of the automatic modification of the tables. |
| -error | If this parameter is specified, when an error occurs, a message will be displayed at the end of the automatic modification of the tables.<br><br>If this parameter is not specified, no error message will be displayed at the end of the automatic modification of the tables. |
| -wizard | If this parameter is specified, the wizard for automatic modification of the tables will be started.<br><br>By default, if this parameter is not specified, the wizard for automatic modification of the tables will not be started. |
| -nobackup | If this parameter is specified, the automatic backup of the modified tables will not be performed.<br><br>By default, if this parameter is not specified, the automatic backup of the modified tables will be performed. |
| -noprogress | If this parameter is specified, no progress bar will be displayed during the automatic modification. |
| -noanaguid | If this parameter is specified, the automatic modification of tables will apply to table descriptions which do not belong to the current database schema (for example, when recreating a table description, or re-creating a database schema, etc.).<br><br>To perform the automatic modification, the HFSQL engine will use the logical name of the table. After automatic table modification, the tables become linked to the database schema. |
| -nolink | If this parameter is specified, the automatic table modification will not create the integrity links when updating the HFSQL Client/Server database. <br><br>By default, this parameter is not specified: automatic modification of tables creates integrity bindings when updating a HFSQL Client/Server database. |
| -noanaconnection | If this parameter is specified, the automatic modification will not use the connections defined in the database schema.<br><br>By default, the automatic table modification will use the connections defined in the table model editor. |
| -nobackground | If this parameter is specified, no "hot" automatic modification will be performed.<br><br>In Client/Server mode, this parameter allows you not to ask for a password when the tables are password protected without being encrypted. |
| /WDD=&lt;WDDFile&gt; | Character string containing the name and full path of the database schema file (".WDD" file) that describes the new structure of the tables.&gt;. <br><br>This parameter is **mandatory** except if the "-wizard" parameter is specified. |
| /PWD=&lt;WDDPassword&gt; | Character string containing the runtime password of the specified database schema (password defined in the database schema description).<br><br>This parameter must be specified only if the database schema is password protected. |
| /DIR=&lt;DataFileDir&gt; | Character string containing the directories where the tables to update will be searched. Only the tables that must receive an automatic modification will be taken into account.<br><br>If this parameter is specified, the "/FILE" parameter must not be specified.<br><br>If the tables to update are found in different directories, WDModFic must be run for each directory.<br><br>Note: If ".REP" files are present in this directory, the location of the tables indicated in these ".REP" files will also be taken into account. |
| /FILE=&lt;DataFile&gt; | Character string containing the name and full path of the table (".FIC" file) to update.<br><br>If this parameter is specified, the "/DIR" parameter must not be specified.<br><br>If several tables must be updated, WDModFic must be run for each table. |
| /FILEPWD=&lt;MotPasseFichierDeDonnées&gt; | Character string containing the password of the specified table (password defined by [HPass](../WDLang4/3044108.md), [HCreation](../WDLang4/3044255.md) or [HCreationIfNotFound](../WDLang4/3044254.md), or during a previous [automatic data modification](../WDLang4/3044195.md)).<br><br>This parameter must be specified only if the specified table is password protected.<br><br>Note: Changing the password of a table is only possible in interactive mode. |
| /PRJ=&lt;ProjectName&gt; | Character string containing the name of the project to use (without its path).<br><br>If the "-PDA" parameter is specified and if the "-wizard" parameter is not specified, this parameter is **mandatory**. |
| /US | If this parameter is specified, the screens of the interactive mode of WDModFic are displayed in English.<br><br>If this parameter is not specified, the screens are displayed in French. |
| /SERVER=&lt;HFSQLClientServerDatabase&gt; | String format: **[&lt;login&gt;[:&lt;password&gt;]@]&lt;server&gt;[:&lt;port&gt;]/&lt;Database&gt;**<br>In this string:<br><br>- &lt;login&gt; corresponds to the login of the user<br><br>- &lt;password&gt; corresponds to the password of the user.<br><br>- &lt;server&gt; corresponds to the name of the HFSQL server. This parameter must be specified.<br><br>- &lt;port&gt; corresponds to the port number of the HFSQL server. This parameter is optional. The port 4900 will be used by default.<br><br>- &lt;Database&gt; corresponds to the name of the HFSQL Client/Server database. This parameter must be specified.<br><br><br>**Example** /SERVER=Flo:pass@ServeurHF/Mabase<br>**Note**: If spaces are present in the database name, use quotation marks. Example: /SERVER="Flo:pass@ServeurHF/Ma base" |

**Note**: The above array shows the various parameters that can be used to launch WDModFic in command line mode. To get these parameters when starting WDModFic, use one of the following syntaxes:

```txt
- WDModFic.EXE /help
- WDModFic.EXE /?
```

### Examples
<a name="examples_ELTPARAGRAPHE000280"></a>

- The following command line is used to **apply the changes made in the database schema** "D:\\MyApplication\\MyAnalysis.WDD" to the tables found in "C:\\MyDataFiles" and in its subdirectories ("-subdir" parameter). If an error occurs, a message is displayed at the end of the automatic modification of the tables ("-error" parameter). The wizard for automatic modification of the tables will not be started. A backup will be performed for the modified tables. Example:
	
	```wl
	ExeRun("C:\MyDirectory\WDModFic.EXE -subdir -error " + ...
		"/WDD=D:\MyApplication\MyAnalysis.WDD " + ...
		"/DIR=C:\MyDataFiles")
	```


- The following command line allows you to **apply the modifications performed in the database schema** named "D:\\MyApplication\\MyDatabaseSchema.WDD" to the "C:\\MyTable.FIC" table. A success or error message will be displayed at the end of the automatic modification of the tables ("-report" parameter). The wizard for automatic modification of the tables will not be started. The backup of the modified tables will not be performed ("-nobackup" parameter).
	
	```wl
	ExeRun("C:\MyDirectory\WDModFic.EXE -report -nobackup " + ...
		"/WDD=D:\MyApplication\MyAnalysis.WDD " + ...
		"/FILE=C:\MyDataFile.FIC")
	```


- **Using long names**: When using long names, double quotation marks are required.. 
	The following command line is used to apply the modifications performed in the "D:\\MyWinDevApplication\\MyDatabaseSchema.WDD" database schema into the table named "C:\\MyTable.FIC". A success or error message will be displayed at the end of the automatic modification of the tables ("-report" parameter). The wizard for automatic modification of the tables will not be started. The backup of the modified tables will not be performed ("-nobackup" parameter).
	
	```wl
	ExeRun("""C:\My Application Directory\WDModFic.EXE -report -nobackup " + ...
		"/WDD=D:\My WINDEV Application\MyAnalysis.WDD " + ...
		"/FILE=C:\MyDataFile.FIC""")
	```


- **Using WDModFic for an HFSQL Client/Server database**
	
	```wl
	// Parameters for the automatic modification of tables
	// Directory that contains WDModFic
	sWDModFicDirectory is string = "C:\Program Files\WinDev 2024\Programs\"
	// Full name of WDD with its path (in the same directory)
	sFullWDDName is string = CompleteDir(fExeDir())+"MyAnalysis.wdd"
	// User and password on the HFSQL server
	// (with the rights to make changes to the structure of tables)
	sUser is string = "guest"
	sPassword is string = ""
	// IP address or DNS name of the computer hosting the HFSQL server
	sAddressOrNameHFServer is string = "ComputerName"
	// Port of HFSQL server
	sPortNumHFServer is int = 4900
	// Name of the database in which the tables to be modified are located
	sDatabaseName is string = "MyAnalysis"
	sCommandLine is string
	// Build the command line 
	// Remove /report to avoid displaying a dialog box at the end
	sCommandLine = StringBuild([
		"%1WDModFic.exe" /WDD="%2" /SERVER="%3:%4@%5:%6/%7" -report
		], CompleteDir(sWDModFicDirectory), ...
		sFullWDDName, sUser, ...
		sPassword, sAddressOrNameHFServer, ...
		sPortNumHFServer, sDatabaseName)
	
	// For test, you have the ability to display the command line
	// to perform a visual check
	// //Info(sCommandLine)
	// Start the automatic modification while waiting for the end
	IF NOT ExeRun(sCommandLine, exeActive, exeWait) THEN
		// Launch failure, display the error
		Error("Unable to execute automatic data modification: ", ErrorInfo(), ...
			"Command line used: ", sCommandLine)
	ELSE
		// Automatic modification performed
	END
	```


- **Example that uses variables to define the different paths.**
	
	```wl
	ModFicDir is string
	AnalysisDir is string
	DataDir is string
	ModFicDir = """C:\WINDEV\Programs\WDModFic.EXE"""
	AnalysisDir = """C:\My Projects\CRM\Exe\CRM.wdd """
	DataDir = """C:\My Projects\CRM\Exe\Data"""
	
	ExeRun(ModFicDir + " -subdir -nobackup -" + "/WDD=" + AnalysisDir +"/DIR=" + DataDir, exeActive, exeWait)
	```

## Using WDModFic in interactive mode
<a name="using_wdmodfic_interactive_mode_ELTTEXTE000464"></a>
The wizard of WDModFic is started when WDModFic is started:

- in interactive mode:

	- on the "Database schema" tab, in the "Database schema" group, expand "Synchronization" and select "Synchronize Structure and Deployed Data (SDD, Auto Modif...") (from the data model editor on the development computer only).

	- run "WDModFic.EXE" directly.




- in command line mode with the "-wizard" parameter.




**To perform the automatic modification of the tables with the wizard**:

1. Select the database schema (".WDD" file) that describes the new structure of the tables.
	**Note** If the specified database schema is protected by a runtime password, enter the password.

2. Select the tables (".FIC" tables) to update.

3. To save the tables before performing the automatic modification, check "Perform a backup before modification" and select the backup directory.

4. To specify or modify the passwords of the different tables to update, check "I want to enter or change passwords for the new structures", select the desired tables and enter the corresponding password twice.

5. Validate to start the automatic modification.
