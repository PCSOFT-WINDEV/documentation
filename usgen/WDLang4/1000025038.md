


## &lt;Source&gt;.Modify (Function)

***In french: &lt;Source&gt;.Modifie***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Modifies the specified record or the record found in memory in the table (query or view). The indexes corresponding to all the keys used in the table are automatically updated. The memos are added (if necessary) if the management of memos is enabled ([&lt;Source&gt;.SetMemo](../WDLang4/1000024987.md).

After the call to **&lt;Source&gt;.Modify**:

- it is recommended to configure the management of errors:
	![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png) WINDEV offers automatic error handling for the following 5 types of error: Duplicate error, Integrity error, Password error, Modification conflict and status error during modification conflict, Blocking error. For more details, see [HFSQL error handling help](../WDLang4/3044188.md).
	![WEBDEV - Server code](https://doc.pcsoft.fr/ext/images/us/WBS.png) It is advisable to check that no errors have been generated: Duplicate error, Integrity error, Password error, Modification conflict and Status error during modification conflict.. For more details, see [HFSQL error handling help](../WDLang4/3044188.md).

- If the management of duplicates is enabled and if the table contains a unique key, [HErrorDuplicates](../WDLang4/3044077.md) returns <u><u><u>True</u></u></u> if the value of modified key is not unique. The record is not modified.

- if a lock problem occurs (attempt to modify a locked record), [HErrorLock](../WDLang4/3044099.md) returns <u><u><u>True</u></u></u> and the record is not modified.
	![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png) The management of locks is not available.
	![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) JDBC access: lock management is not supported for databases that are accessed through JDBC. 

- the number of the current record is not modified. By default, the current iteration is not affected.




**Note**: This function can be used on a table, an HFSQL view or a query.

<a name="sample_code"></a>

## Example


```wl
// Finds the record
Customer.ReadSeekFirst(Name, "Smith")

IF Customer.Found() = True THEN
	// Modify a record in a table
	// (record described through programming)
	Customer.FirstName = "Vince"
	Customer.City = "San Francisco"
	Customer.Zip = "94102"
	Customer.Country = "USA"
	Customer.Modify()
END
```
<a name="Exemple2"></a>

```wl
// Modify current record of "Customer"
// displayed in a window
Customer.ToFile() 
Customer.Modify()
```

## Syntax

`<Result> = <Source>.Modify([<Record number> [, <Options>]])`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the record was modified, 

- <u><u><u><u>False</u></u></u></u> in the event of a problem (integrity error, duplicates, etc.): the record is not modified. [HError](../WDLang4/3044088.md) is used to identify the error.




**`<Source>: (Type corresponding to the specified source)`**

Name of table, HFSQL view or query used.

**`<Record number>: (Optional integer)`**

Number of the record to modify. The record loaded in memory is re-written on the specified record. 
If this number is greater than the total number of records in the table, intermediate deleted records will be created in order for the sequential reading of the table ([&lt;Source&gt;.Read](../WDLang4/1000025019.md)) to be consistent. 

If this parameter is not specified (equal to 0 or to the *hCurrentRecNum* constant),  **&lt;Source&gt;.Modify** will modify the current record in the table.

**CAUTION: Do not confuse the Record number with the automation identifier associated with the Record.**. In most cases, these two numbers are not identical. The record number is returned by [&lt;Source&gt;.RecNum](../WDLang4/1000025041.md). 

To use the &lt;Options&gt; parameter, &lt;Record number&gt; must necessarily be specified.
               
![Hyper File 5.5](https://doc.pcsoft.fr/ext/images/us/HF55.png) This parameter is ignored.   
![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png)![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png)![Native Connectors (Native Accesses)](https://doc.pcsoft.fr/ext/images/us/AN.png) This parameter must correspond to the current record number (*hCurrentRecNum* constant).![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) JDBC access: This parameter must correspond to the current record number (constant *hNumEnrEnCours*). 

**`<Options>: (Optional constant)`**

Configures:

- the effect of modification on the current iteration,

- the mode for calculating the automatic identifier,

- the lock mode applied to the modified record. If no lock constant is specified, the modified record is unlocked.
	![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png) The management of locks is not available.
	![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) JDBC access: lock management is not supported for databases that are accessed through JDBC.




- the management of duplicates,

- the management of integrity.              


Note: To use this parameter, it is necessary to specify the &lt;Record Number&gt; parameter.

### Managing automatic identifiers
<a name="managing_automatic_identifiers_ELTPARAGRAPHE000573"></a>

By default (without using the constants for modifying the automation identifier), the function **&lt;Source&gt;.Modify** function used on an active or scratched record does not modify the automatic identifier (even if the automatic identifier has been assigned in the language): the automatic identifier present in the table is re-used.

The *hForceIDAuto* and *hSetIDAuto* constants are used to modify the default behavior of the automatic identifier.

For more details, see [Managing the automatic identifier during a modification](../WDLang4/3044183.md).
![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png)![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png)![Native Connectors (Native Accesses)](https://doc.pcsoft.fr/ext/images/us/AN.png) 

- *If the database generates an automatic identifier*, the HFSQL engine keeps this value. If the *hForceIDAuto* or *hSetIDAuto* constant is specified, the HFSQL engine replaces the generated value by the desired value.
	**Note** The constant *hForceIDAuto* is equivalent to *hFixeIDAuto*: the automation identifier calculated by HFSQL the next time a table is added will be unique in the table. 

- *If no automatic identifier is generated by the database*, the HFSQL engine generates the value and assigns it to the automatic identifier.

### Modification conflict or deletion conflict
<a name="modification_conflict_deletion_conflict_ELTPARAGRAPHE000612"></a>

Modification or deletion conflict errors appear only if **&lt;Source&gt;.Modify** is used on the current record. If a record number is specified, there can be no conflict, since the record was not read before the modification.

For more details, see [HFSQL error handling help](../WDLang4/3044188.md).

### Managing duplicates and integrity
<a name="managing_duplicates_and_integrity_ELTPARAGRAPHE000629"></a>

The integrity and duplicate checks are performed on the keys for which:

- a check is enabled, 
	
	and

- the value of the item is modified in relation to the record found in the table.




Example:

```wl
...
Customer.LastName = "TUBE"
Customer.FirstName = "Milo"
Customer.Add()    // integrity and duplicate check performed on 
				// LastName and FirstName if active management
Customer.FirstName = "Mark"
Customer.Modify()   // integrity and duplicate check performed on 
				// FirstName only if active management
...
```

### Modifying a record selected in a query
<a name="modifying_record_selected_query_ELTPARAGRAPHE000696"></a>

The modification of a record in a query can be performed:

- in the query result

- in the tables handled by the query (*hModifyFile* constant used in [&lt;Source&gt;.ExecuteQuery](../WDLang4/1000024944.md) or [&lt;Source&gt;.ExecuteSQLQuery](../WDLang4/1000024948.md)). In this case, the *hWithFilter* constant is automatically selected.


We must distinguish between two cases, depending on the runtime mode of the query (with or without the *hWithFilter* constant).


|   |   |
| --- | --- |
| Running the query with the *hWithFilter* constant | <br><br>- Only the modification of the current record is allowed.<br><br>- If the function is run to modify a query based on several tables, the modification is applied to the linked tables.<br><br>- A WLanguage error occurs when the content of a calculated item is modified. The content of these items is automatically calculated when modifying the record.<br><br><br> |
| Running the query without the *hWithFilter* constant | <br><br>- If the function is run to modify a query based on several tables, the modification is applied to the linked tables.<br><br>- If the modified record does no longer correspond to the query selection, the record will still be found in the result of the query<br><br>- A WLanguage error occurs when the content of a calculated item is modified. The content of these items is automatically calculated when modifying the record.<br><br><br> |

Caution:

- No modification is allowed in a query that uses groups or aggregates.

- Integrity and duplicates are not managed by operations on multi-file queries: it is advisable to use transactions to avoid any problems.

### Modifying and looping through a record
<a name="modifying_and_looping_through_record_ELTPARAGRAPHE000741"></a>

If the modification is performed during an iteration, the modified record will be visible in the current iteration only. If other iterations have been defined on this database, the modified record will be visible once these iterations have been reinitialized. 

Using the *hAffectBrowse* constant slows down the modification because the table or the query is refreshed.

WARNING: If the **&lt;Source&gt;.Modify** function is used in a browse and the browse item value is modified, **the current Record may be replayed at the end of the route.**. Indeed, modifying the browse item updates the index key of the table. This modification is taken into account when reading the next records.
