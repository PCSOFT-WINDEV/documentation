


## &lt;Source&gt;.ReadFirst (Function)

***In french: &lt;Source&gt;.LitPremier***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Positions on the first file record according to a browse item. The record is read and the HFSQL variables (e.g. Customer.Name, i.e. the field *Name* field of the table *Client* table) are updated.

Values in the browse item are read in ascending order (for more details, see the the remarks).

In most cases, **&lt;Source&gt;.ReadFirst** is used to set the position in the table in order to perform a read loop with [&lt;Source&gt;.ReadNext](../WDLang4/1000025035.md).

Several cases may occur after the call to **&lt;Source&gt;.ReadFirst**:

- the table is empty or there is no record corresponding to the filter (defined by [&lt;Source&gt;.Filter](../WDLang4/1000024960.md)): no reading is performed and function [&lt;Source&gt;.Out](../WDLang4/1000024605.md) returns <u><u><u>True</u></u></u>.

- the function tries to read a Record already blocked in playback: no playback is performed, function [HErrorLock](../WDLang4/3044099.md) returns <u><u><u>True</u></u></u> and function [&lt;Source&gt;.Out](../WDLang4/1000024605.md) returns <u><u><u>True</u></u></u>.
	![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png) The management of locks is not available.
	![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) JDBC access: lock management is not supported for databases that are accessed through JDBC.




This function can be used with the tables, HFSQL views, or queries.

<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
Customer.ReadFirst(Name)
WHILE Customer.Out() = False
	// Process the record
	Customer.ReadNext(Name)
END
```

## Syntax

`<Result> = <Source>.ReadFirst([<Browse item> [, <Options>]])`
---

**`<Result>: (Boolean)`**

Corresponds to: 

- <u><u><u><u>False</u></u></u></u> if an error occurs. In this case, [HError](../WDLang4/3044088.md) returns an integer other than 0. [HErrorInfo](../WDLang4/3044071.md) returns more details about the error. The record is not read. 

- the value of [&lt;Source&gt;.Found](../WDLang4/1000025076.md) in the other cases (the record can be read, even if &lt;Result&gt; returns <u><u><u><u>False</u></u></u></u>).




**`<Source>: (Type corresponding to the specified source)`**

Name of table, HFSQL view or query used. 

**`<Browse item>: (Optional character string)`**

Name of the item used to browse the table or view (this parameter is not taken into account for queries). If this name is not specified, **&lt;Source&gt;.ReadFirst** will use:

- ***In the case of a table*** the last browse item used on this table by the last HFSQL management function (function beginning with the letter H). If this item does not exist, the best browse item is automatically used. 

- ***In the case of a query*** ORDER BY of the query if available, otherwise according to the last field used. 

- ***In the case of a view***: the sort item of the view (if there is one), otherwise the last item used.




**`<Options>: (Optional constant)`**

Used to configure:

- the lock set on the record read by **&lt;Source&gt;.ReadFirst**

- whether the filter that was defined must be taken into account.

## Remarks


### Browse item
<a name="browse_item_ELTPARAGRAPHE000482"></a>

If the browse item is a key, **&lt;Source&gt;.ReadFirst** reads the record with the lowest key value. The sort order taken into account is the one specified in the database schema for this key. If duplicates are found, **&lt;Source&gt;.ReadFirst** reads the first "duplicate" record according to the sequence of record numbers.

If the browse item is not a key, **&lt;Source&gt;.ReadFirst** reads the first active record. When browsing the table, the records will be sorted according to their record number. 
In this case, the selected browse item will appear in red in the code editor and a warning will be displayed in the ["Code" pane](../Editeurs/2027009.md).

**Note**: The [automatic completion](../Editeurs/2013001.md) only offers the key items.

### Browsing queries
<a name="browsing_queries_ELTPARAGRAPHE000512"></a>

By default, **&lt;Source&gt;.ReadFirst** re-executes the query to refresh the result. To avoid re-executing the query, we recommend that you use the *hNoRefresh* constant.

**Browsing a query run with the hQueryWithoutCorrection constant**:

To browse the records in the order returned by the database, there is no need to specify a browse item. Example:

```wl
MyQuery.ExecuteQuery(hQueryWithoutCorrection)
...
MyQuery.ReadFirst(hNoRefresh)
```
If a browse item is specified, the query result is retrieved and indexed in its entirety. The iteration is performed on the specified item. The initial sort of the query (specified by ORDER BY) is ignored. The created index (in HFSQL format) is sensitive to the case, to the punctuation, to the accented characters and in ascending order.

Example:

```wl
MyQuery.ExecuteQuery(hQueryWithoutCorrection)
...
MyQuery.ReadFirst(MyItem, hNoRefresh)
```
The created index is used to perform searches on the query result.

### Locks
<a name="locks_ELTPARAGRAPHE000546"></a>

By default (&lt;Options&gt; not specified), the record is not locked.

If a lock is requested (*hLockWrite* or *hLockReadWrite* constant), the record will be read only if this record is not already locked.

![OLE DB](https://doc.pcsoft.fr/ext/images/us/OLEDB.png)![Native Connectors (Native Accesses)](https://doc.pcsoft.fr/ext/images/us/AN.png) The lock options will have no effect if the locks are not supported by the OLE DB provider or by the Native Connector.

### Memos
<a name="memos_ELTPARAGRAPHE000562"></a>

The memos associated with the record can be automatically read (or not) when reading the record. [&lt;Source&gt;.SetMemo](../WDLang4/1000024987.md) is used to customize this automatic read operation.

If the memos are supported, the associated text memos are read when the record is read. The binary memos are read only when they are explicitly used ([&lt;Source&gt;.ExtractMemo](../WDLang4/1000024957.md)).
<a name="NOTE0_5"></a>


### Password
<a name="password_ELTPARAGRAPHE000584"></a>

If **&lt;Source&gt;.ReadFirst** is the first function that handles the specified table, the password is checked when opening the table. If the password is incorrect, [HErrorPassword](../WDLang4/3044082.md) returns <u><u><u><u>True</u></u></u></u> and [&lt;Source&gt;.Out](../WDLang4/1000024605.md) returns <u><u><u><u>True</u></u></u></u>.

### Native XML Connector
<a name="native_xml_connector_ELTPARAGRAPHE000614"></a>

The behavior of **&lt;Source&gt;.ReadFirst** depends on [&lt;Source&gt;.ActivateAutoFilter](../WDLang4/1000024171.md)/[&lt;Source&gt;.DeactivateAutoFilter](../WDLang4/1000024219.md).

[&lt;Source&gt;.ActivateAutoFilter](../WDLang4/1000024171.md) is enabled by default.

Therefore, to read the content of XML file, read the content of main file (the parent) then read the content of linked files (the children).

When reading a table, a filter is automatically applied to the linked tables in order to only read the records corresponding to the main table.

For example:<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=XML_2.GIF)
When browsing the Person file, it is possible to find out the person's email address.

To do so, simply set the position on the "Person" file and apply **&lt;Source&gt;.ReadFirst** to the "Email" file.

In this case, the record read in the "Email" file will correspond to the first email associated with the current record in the "Person" file.

If this mechanism is disabled ([&lt;Source&gt;.DeactivateAutoFilter](../WDLang4/1000024219.md)), the record read in the "Email" file will correspond to the first record found in the Email file (and not to the child of the record read in the "Person" file).
