


## Administrator: Configuring and executing action plans
			



<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000190"></a>
Once action plan libraries have been published, they and their associated action plans appear in the "Warehouse" tab of the Software Factory administrator. 

To run the action plans:

- define their different parameters

- configure their activation mode. 




These operations are performed in the Software Factory administrator. 

Remarks: 

- You can also run an action plan from a WINDEV application or WEBDEV website with [ActionPlanExecute](../WDLang6/1000021332.md). 

- You can also configure the execution of an action plan from a WINDEV application or WEBDEV website with [ActionPlanConfigure](../WDLang6/1000021598.md). 






## How to?
<a name="how_ELTTEXTE000214"></a>


### Configuring the action plans
<a name="configuring_the_action_plans_ELTPARAGRAPHE000035"></a>

In most cases, the action plans can be configured, especially the name of the project. Therefore, the same action plan can be reused for different projects. Configuring an action plan means creating an instance of the action plan for a specific run.  

To configure an action plan:

1. Launch the Software Factory administrator. Go to the "Tools" tab, "Utilities" group, and click "WDFAdmin".

2. In the window that appears, specify the name of the coordinator to which the administrator must connect. 

3. The Software Factory administrator opens. Action plans can be configured:

	- from the "Action plans" tab. 

		- Click "Use an action plan". 

		- Select the action plan you want to configure and confirm. 




- from the "Warehouse" tab. 

	- Select the action plan you want to configure

	- Click "Configure action plan". 

	- Select the action plan you want to configure and confirm.

4. In the window that appears, you can indicate:

	- The name of the configuration. Each configuration is an instance of an action plan. It is recommended to give the configuration a clear name and a description. 

	- The value of the parameters ("Parameters" tab).

	- The maximum duration for running the action plan, expressed in minutes ("Parameters" tab). 

	- The recipients of the notifications ("Notifications" tab). 

	- Labels that will tell the robots to run the action plan ("Labels" tab). 




5. Validate. 

6. The custom action plan appears in the "Action plans" tab. 




**Note**: By default, the "Action plans" tab of the Software Factory administrator only shows the action plans of the "current" developer. To see the action plans of all the developers, expand "Action plans of " and select "".

### Defining when to run an action plan
<a name="defining_when_run_action_plan_ELTPARAGRAPHE000086"></a>

The custom action plan can be triggered on demand or at set intervals. 

To define when to run an action plan:

1. Launch the Software Factory administrator. Go to the "Tools" tab, "Utilities" group, and click "WDFAdmin".

2. In the window that appears, specify the name of the coordinator to which the administrator must connect. 

3. The Software Factory administrator opens. 

4. Go to the "Action plans" tab and select the desired action plan. 

5. You can: 

	- run the action plan directly ("Execute action plan"). In this case, the action plan is automatically added to the action plan spool. 

	- schedule the execution of the action plan ("Schedule action plan"). A wizard starts, allowing you to define all the scheduling options. 
			Note: You can also schedule the action plan in the configuration window. 







**Caution**: If you have used parameters to define your action plans, don't forget to specify the parameters to be executed (see previous paragraph). 

If you have scheduled the execution of an action plan, the schedule appears in the "Schedules" tab of the Software Factory administrator. A checkmark appears next to the schedule, indicating that the schedule is enabled. 



## Remarks
<a name="remarks_ELTTEXTE000244"></a>


### Execution on a robot
<a name="execution_robot_ELTPARAGRAPHE000121"></a>

A robot will be chosen to run an action plan. The compilation computer (robot computer) must have a version of WINDEV, WEBDEV or WINDEV Mobile corresponding to the project to compile. 

During the execution, WINDEV, WEBDEV or WINDEV Mobile opens and switches to "Software Factory" mode. In this case, it is important not to handle the computer on which the robot is run to avoid distorting the results (by moving the mouse during a unit test for example). 

Note: The Software Factory administrator allows you to monitor the execution of action plans via an action plan spooler ("Robots" tab).  An action plan may have priority. The order of action plans in the spool can be modified via the arrow buttons.


### Reusing the action plans
<a name="reusing_the_action_plans_ELTPARAGRAPHE000133"></a>

An action plan can be reused by as many projects and developers as required. Simply create a new action plan with the same parameters. 


### Result of the action plans
<a name="result_the_action_plans_ELTPARAGRAPHE000138"></a>

In the parameters of action plan, you can: 

- define the method used to send the action plan status report (Control Centers messaging solution, email, etc.). 

- see the result of the last execution.
