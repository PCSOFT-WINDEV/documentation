


## Breakpoints
			



<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000433"></a>
When testing an application in the editor, breakpoints make it possible to automatically launch the debugger from a given line of code.

This help page presents: 

- [How to insert a breakpoint in the code](#NOTE2_1). 

- [What are the different types of breakpoints and how to use them](#NOTE2b_1). 

- [How to handle breakpoints (delete, list, etc.)](#NOTE3_1).






<a name="NOTE2"></a>
<a name="NOTE2_1"></a>


## Inserting breakpoints in the code
<a name="inserting_breakpoints_the_code_ELTTEXTE000457"></a>
Several methods can be used to insert a breakpoint:

- Click on the left of the line where the breakpoint must be inserted. The mouse cursor turns into a hand and the ![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=ico_PointArret.gif) icon appears.

- On the "Code" tab, in the "Breakpoints" group, expand "Breakpoint" and select "Add a breakpoint".

- Press Ctrl + B.

- Open the context menu of the breakpoint bar and select "Add a breakpoint".<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Ajout_pointarr%EAt%20-%20HC%20N%B0001.gif)





**Note**: Breakpoints are only taken into account when testing the application in the WINDEV, WEBDEV or WINDEV Mobile editor. When using the executable, breakpoints are ignored.

## Breakpoint properties
<a name="breakpoint_properties_ELTTEXTE000481"></a>
By default, breakpoints automatically launch the debugger. 

In the breakpoint properties window, you can define:

- [debugger launch conditions](#NOTE2b_2).

- [actions to be performed (these actions can be combined)](#NOTE2b_3). 




You can view the properties of a breakpoint:

- in the code editor. To do so, go to the "Code" tab, "Breakpoints" group, expand "Breakpoint" and select "Breakpoint properties".

- via the context menu of the breakpoint. Simply right-click the breakpoint and select "Breakpoint properties".



<a name="NOTE2b_2"></a>


### Options for conditional breakpoints
<a name="options_for_conditional_breakpoints_ELTPARAGRAPHE000098"></a>

When debugging a loop, it may be useful to trigger the debugger after a number of passages (after the 35th iteration for example). 

To set a conditional breakpoint: 

1. Create a breakpoint (see [Inserting a breakpoint](#NOTE2_1)). 

2. Open the breakpoint properties. 

3. Under "Conditions", specify the conditions under which the breakpoint will be taken into account:<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Gestion_des_points_d'arr%EAt_2%20-%20HC%20N%B0002%201.gif&type=thumb)


	- **Always** (default value): The breakpoint will not be conditional and will always be taken into account. 

- **When the number of times a breakpoint has occurred is**: Sets a conditional breakpoint. To do so, select a condition and the desired number of passages.

- **When the expression below is true**: Sets a conditional breakpoint. Simply enter the condition directly in the "If" field. 

4. Confirm. The conditional breakpoint is displayed in the editor (![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Gestion_des_points_d'arr%EAt_2%20-%20HC%20N%B0003.gif)).



<a name="NOTE2b_3"></a>


### Available actions for breakpoints
<a name="available_actions_for_breakpoints_ELTPARAGRAPHE000134"></a>

By default, a breakpoint is used to pause program execution and launch the debugger. However, a breakpoint can also perform one of the following actions:

- [Add a message to the debugger trace](#NOTE2_6),

- [Starting the performance profiler](#NOTE2_7), 

- [Perform a memory usage diff operation](#NOTE2_8).




To set a breakpoint with a specific action:

1. Create a breakpoint (see [Inserting a breakpoint](#NOTE2_1)). 

2. Open the breakpoint properties. 

3. In the "Actions" box, specify the action to be taken when passing through the breakpoint (these actions can be combined). <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Gestion_des_points_d'arr%EAt_2%20-%20HC%20N%B0002%202.gif)


4. Confirm. The ![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Gestion_des_points_d'arr%EAt_2%20-%20HC%20N%B0003.gif) breakpoint icon indicates that it includes specific properties.



<a name="NOTE2_6"></a>


### Adding a message to the debugger trace
<a name="adding_message_the_debugger_trace_ELTPARAGRAPHE000172"></a>

When debugging an application, you may want to know the line of code on which a given process was executed, but without pausing execution and opening the debugger. In this case, a single information must be displayed in the trace window. 

If the "Add message to debugger trace" option is checked, when execution reaches the breakpoint, the message specified in the "[Debugger trace](../Editeurs/2027028.md)" pane will be added to the trace. 

Note: If no message is specified, the name of the current process will be displayed in the "Debugger trace" pane. 
<a name="NOTE2_7"></a>


### Running the performance profiler
<a name="running_the_performance_profiler_ELTPARAGRAPHE000188"></a>

In some cases, when debugging, it is necessary to run the performance profiler on a section of code. This makes it possible to get the details of all the actions, corresponding processes and their duration. 

To implement this functionality, you need to create two breakpoints: One to launch the performance profiler, and another to stop it. 

At runtime: 

- The performance profiler is launched after execution of the line on which the starting breakpoint is set. 

- Press F7 to continue execution down to the ending breakpoint. 




After execution of the line of code that stops the performance profiler, debugging will stop and a window will appear with the results. <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Gestion_des_points_d'arr%EAt_3%20-%20HC%20N%B0005.gif&type=thumb)


Several methods are available for defining the various breakpoints:

- **Method 1**: 

	1. Create two breakpoints to start and stop the performance profiler (see [Inserting a breakpoint](#NOTE2_1)). 

	2. In the context menu of each breakpoint, expand "Performance profiler" and select the desired option:<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Gestion_des_points_d'arr%EAt_3%20-%20HC%20N%B0001%201.gif)


		- "Start performance profiler". The icon changes to indicate that the breakpoint corresponds to the start of the performance profiler (![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Gestion_des_points_d'arr%EAt_3%20-%20HC%20N%B0003.gif)).

- "Stop performance profiler". The icon changes to indicate that the breakpoint corresponds to the end of the performance profiler (![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Gestion_des_points_d'arr%EAt_3%20-%20HC%20N%B0004.gif)).

- **Method 2**: 

	1. Create two breakpoints to start and stop the performance profiler (see [Inserting a breakpoint](#NOTE2_1)). 

	2. Open the properties of each breakpoint. 

	3. Under "Actions", check Performance profiler and select the desired option to start or stop the performance profiler. 

	4. Confirm. The icon changes to indicate what the breakpoint does:

		- Start the performance profiler (![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Gestion_des_points_d'arr%EAt_3%20-%20HC%20N%B0003.gif)).

		- Stop the performance profiler (![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Gestion_des_points_d'arr%EAt_3%20-%20HC%20N%B0004.gif)).







Note: The code analyzed by the performance profiler must not contain any breakpoints. 
<a name="NOTE2_8"></a>


### Memory usage diff
<a name="memory_usage_diff_ELTPARAGRAPHE000247"></a>

In some cases, when debugging, it is necessary to measure and compare the amount of memory used by an application. This technique isolates resources that use memory in operations that should be memory-neutral. This allows you to improve the code and add memory freeing commands where necessary (unused queries, unused global object, etc.).

To implement this functionality, you need to create two breakpoints: One to launch the memory usage diff, and another to stop it. 

At runtime: 

- The memory usage diff is launched after execution of the line on which the starting breakpoint is set. 

- Press F5 to continue execution down to the ending breakpoint. 




After execution of the line of code that stops the memory usage diff, debugging will stop and a window will appear with the results. <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Gestion_des_points_d'arr%EAt_4%20-%20HC%20N%B0005.gif&type=thumb)


- **Method 1**: 

	1. Create two breakpoints to start and stop the memory usage diff (see [Inserting a breakpoint](#NOTE2_1)). 

	2. In the context menu of each breakpoint, expand "Memory usage diff" and select the desired option:<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Gestion_des_points_d'arr%EAt_4%20-%20HC%20N%B0001%201.gif)


		- "Start memory usage diff". 

- "Stop memory usage diff". 

- **Method 2**: 

	1. Create two breakpoints to start and stop the memory usage diff (see [Inserting a breakpoint](#NOTE2_1)). 

	2. Open the properties of each breakpoint. 

	3. Under "Actions", check "Memory usage diff" and select the desired option to start or stop the memory usage diff. 

	4. Confirm. 







Note: The code analyzed by the memory usage diff must not contain any breakpoints.

## Handling breakpoints (delete, list, etc.)
<a name="handling_breakpoints_delete_list_etc_ELTTEXTE000535"></a>
<a name="NOTE2_2"></a>


### Disabling/Enabling a breakpoint
<a name="disablingenabling_breakpoint_ELTPARAGRAPHE000297"></a>Disabled breakpoints remain in the code editor, but are grayed out and are ignored when debugging the application. 
Several methods can be used to disable the breakpoint for the current line:

- On the "Code" tab, in the "Breakpoints" group, expand "Breakpoint" and select "Disable breakpoint".

- Press Ctrl + Shift + B.

- Open the context menu of the breakpoint bar and select "Disable breakpoint": <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Code_Menu_PointArret.gif)



Note: The breakpoint can be re-enabled at any time with "Enable breakpoint".
<a name="NOTE2_3"></a>


### Deleting one or more breakpoints
<a name="deleting_one_more_breakpoints_ELTPARAGRAPHE000324"></a>

Several methods can be used to delete a breakpoint:

- In the code editor, click the breakpoint. The mouse cursor turns into a hand and the ![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=ico_PointArret.gif) icon appears.

- On the "Code" tab, in the "Breakpoints" group, expand "Breakpoint" and select: 

	- "Delete breakpoint" to delete the breakpoint from the current line.

	- "Remove all breakpoints" to remove all breakpoints.




- In the debugger, click the ![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=ico_paspointarret.gif) icon.

- Open the context menu of the breakpoint bar: <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Code_Menu_PointArret.gif)


	- select "Delete breakpoint" to delete the breakpoint set on the current line.

- select "Remove all breakpoints" to delete all breakpoints. 



<a name="NOTE2_4"></a>


### Listing breakpoints
<a name="listing_breakpoints_ELTPARAGRAPHE000363"></a>

There are several methods to list the breakpoints of the current project:

- In the code editor, go to the "Code" tab, "Breakpoints" group, expand "Breakpoint" and select "List breakpoints".

- In the debugger, click the ![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=ico_Liste_pointarret.gif) icon.

- Open the context menu of the breakpoint bar and select "List breakpoints". <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Code_Menu_PointArret.gif)
