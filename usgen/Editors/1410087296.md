


## Project with multiple database schemas
			



<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000224"></a>
A single WINDEV, WEBDEV or WINDEV Mobile project can now use multiple database schemas (data descriptions). 
WINDEV 2024 makes it possible to use two or more different database schemas in the same project. 
You can use multiple database schemas permanently, or as a one-off alternative in order to run specific queries. 
All the tables from all the database schemas support databinding.

<a name="NOTE2"></a>
<a name="NOTE2_1"></a>


## How to?
<a name="how_ELTTEXTE000248"></a>


### Defining a project with multiple database schemas in the editor
<a name="defining_project_with_multiple_database_schemas_the_editor_ELTPARAGRAPHE000024"></a>

To use multiple database schemas in a single project: 

1. Open your project in WINDEV, WEBDEV or WINDEV Mobile. 

2. Open the project description window. To do so, go to the "Project" tab, "Project" group, and click "Description". 

3. On the "Database schema" tab, indicate the different database schemas used by the current project via the "Create a database schema", "Add a database schema", or "Import a database schema from the SCM" buttons. <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Description_Projet_Onglet_Analyse%20-%20HC%20N%B0001.gif)


4. Use the arrow buttons to define the order in which database schemas are used. This is an important step, especially if the database schemas contain tables with the same name (see below). 

5. Confirm. 





### Defining a project with multiple database schemas programmatically
<a name="defining_project_with_multiple_database_schemas_programmatically_ELTPARAGRAPHE000048"></a>

The [HOpenAnalysis](../WDLang4/3044106.md) function opens a database schema in HFSQL Classic format. This allows you to access the tables defined in the database schema as well as their structure.

To open an additional database schema programmatically, use [HOpenComplementaryAnalysis](../WDLang4/1410090082.md).

## Remarks
<a name="remarks_ELTTEXTE000278"></a>


### Automatically hide tables with the same name in different database schemas
<a name="automatically_hide_tables_with_the_same_name_different_database_schemas_ELTPARAGRAPHE000071"></a>

Different database schemas can contain tables with the same name. In this case, only one table will be used. This table relies on the order specified for the different database schemas, either in the project description or through the opening sequence defined using [HOpenAnalysis](../WDLang4/3044106.md) and [HOpenComplementaryAnalysis](../WDLang4/1410090082.md). Here is how it works: 

- Database schema 1: 

	- Table A

	- Table B




- Database schema 2:

	- Table B. This table will be "hidden", as it is present in Database Schema 1. 
			**To use table B in database schema 2**, it is necessary to rename this table in database schema 2. 

	- Table C




- Database schema 3:

	- Table B: This table will be "hidden", as it is present in Database schema 1. 
			**To use table B in database schema 3**, it is necessary to rename this table in database schema 3.

	- Table C: This table will be "hidden", as it is present in Database Schema 2. 
			**To use table C in the database schema 3**, it is necessary to rename this table in the database schema 3.

	- Table D. 





In the "Database Schema" action of the "Project Explorer" pane, the following tables will be shown: 

- Table A (database schema 1)

- Table B (database schema 1)

- Table C (database schema 2)

- Table D (database schema 3).





### Multi-server queries
<a name="multiserver_queries_ELTPARAGRAPHE000109"></a>

If you use multiple database schemas containing tables that use connections to different servers, it is recommended to define the connections in the data model editor (and not programmatically). This allows you to make sure you are associating the right connection with the table (especially when there are tables with the same name). 


### WLanguage functions: Adaptations made to manage projects with multiple database schemas
<a name="wlanguage_functions_adaptations_made_manage_projects_with_multiple_database_schemas_ELTPARAGRAPHE000114"></a>

The following functions manipulate database schemas, tables, relationships, etc. They have been improved to manage projects with multiple database schemas. 


|   |   |
| --- | --- |
| [HChangeConnection](../WDLang4/3044150.md) | If the table name is not specified, changes the connection for the tables defined in the different database schemas. |
| [HChangeDir](../WDLang4/3044168.md) | If the table name is not specified, changes the directory for the tables defined in the different database schemas. |
| [HCloseAnalysis](../WDLang4/3044054.md) | Closes all the database schemas associated with the project. |
| [HCreationIfNotFound](../WDLang4/3044254.md) | If the table name is not specified, all tables for all database schemas will be created or opened. |
| [HInfoAnalysis](../WDLang4/1000019773.md) | If the database schema is not specified, only the main database schema is used. |
| [HListConnection](../WDLang4/3044046.md) | Please provide the text you want transformed. |
| [HListCustomFolder](../WDLang4/1000019775.md) | If there are multiple database schemas, lists all the Custom-Folders of all the database schemas. |
| [HListFile](../WDLang4/3044045.md) | If there are multiple database schemas, lists all the tables of all the database schemas. |
| [HListLink](../WDLang4/3044138.md) | If there are multiple database schemas, lists all the links of all the database schemas. |
| [HListREP](../WDLang4/3044229.md) | If there are multiple database schemas, only the main database schema is used. |
| [HSetREP](../WDLang4/3044061.md) | If you only specify the parameter that enables or disables the .rep file, the change is made in all the database schemas associated with the project. |
| [ProjectInfo](../WDLang1/3064004.md) | If there are multiple database schemas, the *piAnalysis* constant gets only the name of the main database schema. |
