


## Docusign: Electronic signature
			



<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000244"></a>
It is now common for individuals or businesses to sign contracts electronically. Electronic signatures make it possible to:

- notify different contributors that the document has been read and its content validated. 

- prevent a document from being edited. The slightest modification of the document will invalidate the signature. Users will be notified that the document has been modified since the last signature.




Docusign is one of the leading electronic signature solutions. Starting with version 2024, you can integrate Docusign functionalities in WLanguage via a wizard.

Note: To sign documents using Docusign solutions, an API key is required. To obtain this key, you need to subscribe to one of the plans offered by Docusign.

## Principle
<a name="principle_ELTTEXTE000268"></a>


### Signature workflow with Docusign
<a name="signature_workflow_with_docusign_ELTPARAGRAPHE000025"></a>

1. The WINDEV application provides Docusign with the document (usually as a PDF file) to be signed and the list of people who need to sign it.

2. Docusign then sends an email to the signatories with a link to the Docusign website for signing. 

3. Once all the signers have signed, Docusign notifies the WINDEV application. The application then retrieves the signed document from Docusign.




The Docusign wizard in version 2024 allows you to manage all the stages of the signature workflow, view the status of a document signature, etc. 


### Signature
<a name="signature_ELTPARAGRAPHE000034"></a>

A document is signed by a trusted third party, Docusign in this case. This trusted third party is responsible for the validity of the signature.

It is possible to request 3 types of electronic signatures:

- Simple electronic signature (SES)

- Advanced electronic signature (AES), which uses at least identity verification via SMS. In this case, a phone number has to be provided. 

- Qualified electronic signature (QES), which involves an ID document verification. 




Note: Qualified electronic signatures are only form of electronic signature that is considered equivalent to a handwritten signature.

## Prerequisites
<a name="prerequisites_ELTTEXTE000298"></a>


### Testing prerequisites
<a name="testing_prerequisites_ELTPARAGRAPHE000051"></a>

To test the integration of electronic signature functionalities in your application, please follow these steps: 

1. Create a Docusign developer account in the demo environment. You can create this account at no cost at: [https://developers.docusign.com/platform/account/](https://developers.docusign.com/platform/account/).
	This account will be the application owner.
	Note: To create an account, click "Developer Account", "Create account" and specify the required information.   

2. Creating an application in Docusign: 

	- In the main menu, select "Settings". The settings page opens. 

	- In the left-side menu, click "Apps and Keys". 

	- Click "Add App and Integration Key". In the popup window, enter the name of the application and click "Create App". 

	- The application details are displayed. 




3. Get application keys: 

	- Copy and save the "Integration Key" code. 

	- In "User Application", click "Add Secret Key".  

	- Copy and save the "Secret Key" code.

	- In "Additional settings", click "Add URI" and add a Redirect URL. By default, this URL is "http://localhost:29024" (or "myapp://ds_auth" on iOS).  




4. Confirm the creation of the application. 




Note: In this mode, signature request emails are sent, but the content indicates that the email is sent for test purposes only. 


### Prerequisites for using Docusign
<a name="prerequisites_for_using_docusign_ELTPARAGRAPHE000080"></a>

To take full advantage of all the features in Docusign: 

1. Create a Docusign developer account in the production environment: [https://account.docusign.com/|https://account.docusign.com/](https://account.docusign.com/|https://account.docusign.com/)

2. Purchase a Docusign Developer API plan: [https://ecom.docusign.com/plans-and-pricing/developer](https://ecom.docusign.com/plans-and-pricing/developer)

3. Promote your application to production. This operation is referred to as "Go-Live" in Docusign. 




For more details, see: 

- The application requirements: [https://developers.docusign.com/docs/esign-rest-api/go-live/#review](https://developers.docusign.com/docs/esign-rest-api/go-live/#review)

- The step-by-step process of promoting an application to production: [https://developers.docusign.com/docs/esign-rest-api/go-live/](https://developers.docusign.com/docs/esign-rest-api/go-live/)

## Docusign wizard
<a name="docusign_wizard_ELTTEXTE000328"></a>


### Opening the code wizard
<a name="opening_the_code_wizard_ELTPARAGRAPHE000105"></a>

To use the Docusign code wizard: 

1. Select the control that should start the Docusign signing process and open the code editor. 

2. Type "Docusign" and confirm.
	<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Docusign%20-%20HC%20N%B0001.gif)

	The Docusign wizard opens. 

3. The first step is to enter the integration key and secret key previously obtained via the Docusign account <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Docusign%20-%20HC%20N%B0002.gif)


4. In the next step, you can select the service you want to use.

<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Docusign%20-%20HC%20N%B0003.gif)



### Signature request
<a name="signature_request_ELTPARAGRAPHE000122"></a>

To implement Docusign signature features in your application, the first step is to request a signature. This feature is available in the Docusign wizard: 

1. Select "Request a signature" and go to the next step. 

2. Indicate the document to be signed.<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Docusign%20-%20HC%20N%B0004.gif)
 This document can be: 

	- a variable, a control or a document returned by a function. 

	- a file. In this case, simply indicate the file path. 




3. The next step is to select the document recipients.<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Docusign%20-%20HC%20N%B0005.gif)
For each recipient, specify: 

	- The identity of the recipient.  

	- Whether the recipient should sign the document or simply receive a copy. 

	- If the recipient should sign the document, please indicate the desired signature level and the recipient's email address and/or phone number. 

	- If the recipient should simply receive a copy, only their email address is required. 




4. For each signer, the wizard then allows you to specify the location of the following elements on the document: <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Docusign%20-%20HC%20N%B0006.gif)


	- Signature location. 

- Initials location.

- Date location.

5. The next step is to configure the email that will be sent to the recipients.<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Docusign%20-%20HC%20N%B0007.gif)


6. The next step displays the generated code. This code can be copied and/or printed.<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Docusign%20-%20HC%20N%B0008.gif)


7. Finish the wizard. 

	- The WLanguage code is automatically integrated into the current code. You can adapt or edit this code later. 

	- The Docusign component is integrated into the project. Since it is written in WLanguage, this internal component performs low-level operations. 
			Note: It is not recommended to modify the code of this internal component.








### Other wizard features
<a name="other_wizard_features_ELTPARAGRAPHE000164"></a>

The Docusign wizard includes many document and signature management features: 

- Retrieve a document (signed or unsigned).

- Track the status of a signature request. 

- Get document details: date last modified, etc. 

- Get signer details: identity, signed documents, etc. 

- Cancel or list requests, 

- Import the component. 




For most of these actions, you need to specify the ID generated and sent by Docusign in the signature request response. This ID corresponds to the "sEnvelopeID" variable in the code generated for sending documents. 


### Docusign component
<a name="docusign_component_ELTPARAGRAPHE000178"></a>

The Docusign component is automatically integrated into your project. This component includes all the procedures required to use Docusign functionalities.
