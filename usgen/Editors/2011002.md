


## Managing the database schema versions
			



<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000202"></a>
WINDEV, WEBDEV and WINDEV Mobile allow you to manage the different versions of the database schema from the data model editor.

To open the database schema linked to the project, click ![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Analyse_bl.gif) in the quick access buttons.

You can manage database schema versions from the data model editor. Go to the "Database schema" tab, "Database schema" group, expand "Generation" and select "Manage versions". Each database schema version corresponds to a generation of the database schema.<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=GestionVersionAnalyse.gif&type=thumb)
You can work:

- On the current version of the database schema.

- On an earlier version of the database schema.




**Note**: When a database schema is damaged, you can:

- Repair the database schema. To do so, go to the "Database schema" tab, "Database schema" group, expand "Maintenance" and select "Repair database schema". For more details, see [Repair a database schema](../Editeurs/9500110.md).

- Restore an earlier version of the database schema.

- Retrieve the last version of the database schema. To do so, go to the "Database schema" tab, the "Database schema" group, expand "Generation" and select "Last version saved".




All the versions of the database schema are displayed as a graph. The yellow square indicates the generation number of the database schema and the caption (on the right) indicates the generation date.

"Small rectangles" are displayed between two versions:

- One rectangle: Few changes were made between the two versions.

- Several rectangles: Several changes were made between the two versions.




**To see the details of modifications performed between two versions**, double-click the line containing the "small rectangles" or click the "Modifications" button.

The options available in the manager of database schema versions are:

- Restoring a database schema.

- Undoing the last generation.

- Resetting the version number to 1.

## Restoring a database schema
<a name="restoring_database_schema_ELTTEXTE000226"></a>
To restore a database schema from the manager of database schema versions:

1. Select the version to restore.

2. You can:

	- Restore the version in the specified directory. An independent database schema corresponding to the selected version is created. This database schema will not be linked to the current project. This option is selected by default.

	- Overwrite the current database schema. The restored database schema will be automatically linked to the current project.




3. Validate. The restore operation is performed.




**Caution**: Tables associated with a database schema that is more recent than the restored version can no longer be opened. You must:

- Restore the tables corresponding to the database schema version that was restored (with [WDLog](../WDJournal/3516012.md) for example).

- Delete the existing tables in order to recreate them.

## Undoing the last generation
<a name="undoing_the_last_generation_ELTTEXTE000250"></a>
Undoing the last generation of the database schema allows you to restore the database schema to its state before the last generation. The modifications performed since the last generation are not applied.

**To cancel the last generation of the database schema**, on the "Database schema" tab, in the "Database schema" group, expand "Generation" and select "Cancel last generation".

<a name="NOTE4_1"></a>


## Resetting the version number to 1
<a name="resetting_the_version_number_1_ELTTEXTE000274"></a>
The version number of the database schema can be reset to 1. In this case:

- The version number of the database schema is reset to one. The users will not be able to see the number of generations that have been required to develop the application.

- The versions of the different generations of the database schema are deleted.
	**Note**: These versions are located in the "ANAxxx" subdirectories, in the "&lt;ProjectName&gt;.ANA" subdirectory of the project.




No specific action is performed on the tables. The version number of the table is not modified.

Resetting the version number of the database schema to 1 can be done at any time and it has no influence on the distributed database schema versions.

**To reset the version number of the database schema to 1**, on the "Database schema" tab, in the "Database schema" group, expand "Generation" and select "Reset database schema version to 1".
