


## Database schema: Description of table structure
			



<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000244"></a>
The database schema allows you to define the structure of tables used by the project.

You can describe in the database schema:  

- [a new table.](#NOTE2_1)

- [a preset table, provided with WINDEV, WEBDEV and WINDEV Mobile.](#NOTE2_2)

- [a table imported from an external database](../Editeurs/2011025.md) (also called "Third-party database").

- [a table imported from an earlier WINDEV version](../Editeurs/2011025.md).

- [an ISAM HFSQL table imported via the Windows File Explorer](../Editeurs/2011025.md).




**Note**: To modify the description of a table or its fields: 

- Select the table in the data model editor. 

- Select one of the following options in the context menu: 

	- "Table description".

	- "Description of items".







**Reminder**: In a WINDEV, WEBDEV or WINDEV Mobile application, the terms "MLD" and "Analyse" are used interchangeably to define the database structure associated with a project.

For details of how to manipulate a table or topic in the table model editor, see [Operations on a table](../Editeurs/2011007.md) and [Operations on an item](../Editeurs/2011009.md).

## Adding a new table
<a name="adding_new_table_ELTTEXTE000268"></a>


### Creating a new table
<a name="creating_new_table_ELTPARAGRAPHE000052"></a>

To create a new table:

1. On the "Database schema" tab, in the "Creation" group, click "New table
". The table creation wizard opens.

2. Select "Create a new table description". Go to the next step.

3. Specify:

	- the ***logical name of the table***. This name will be used to handle the table.

	- the ***caption*** that briefly describes the file subject.

	- the ***representation of a*** record in the table. This representation makes the questions asked when describing the links easier to understand. This option must be preceded by an indefinite article (A or AN).

	- whether the table includes an ***"Automatic identifier" item***. The value of this item is unique for each record and it is automatically calculated by the HFSQL engine.
			You can use: 

		- an 8-byte ID. This type of identifier is mandatory for the replication of HFSQL servers. 

		- a 4-byte ID. 




- an automatic UUID (128-bit). In this case, the identifier of each record corresponds to a 128-bit UUID (the UUID provides a unique non-sequential identifier). 

- an automatic UUID (256-bit). In this case, the identifier of each record corresponds to a 256-bit UUID (the UUID provides a unique non-sequential identifier).

4. In the next step, specify the ***type of database*** associated with the table. Depending on the type selected, this table will be handled by the HFSQL engine, an OLE DB driver or a Native Connector (SQL Server, Oracle, etc.).
	If you are using a database other than HFSQL Classic (Network or Single-user), the wizard asks for the database connection characteristics.

5. The new table becomes the current table. The description window of the table items opens automatically. It allows you to describe the file items.



<a name="NOTE2_2"></a>


### Importing a preset description of table
<a name="importing_preset_description_table_ELTPARAGRAPHE000098"></a>

To import a preset file description: 

1. On the "Database schema" tab, in the "Creation" group, click "New table
". The table creation wizard opens.

2. Select the option "Select a preset table description".

3. Choose the preset table(s) to create. <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Analyse_Fichierpredef.gif)
The wizard also proposes associated tables that can be added as links.

4. For each table, select the items to keep. These items can be modified later.

5. The preset tables are automatically inserted into the current database schema. Links between predefined tables are automatically created.

## Color for the descriptions of tables
<a name="color_for_the_descriptions_tables_ELTTEXTE000298"></a>
The following colors are used to quickly identify the types of tables in the data model editor: 

- Blue for the tables coming from a Native Connector.

- Orange for HFSQL Client/Server tables.

- Brown for HFSQL Classic tables.

- Green for ODBC tables. 

- Gray for Hyper File 5.5 tables.

## Security of an HFSQL table
<a name="security_hfsql_table_ELTTEXTE000322"></a>
To ensure the security of an HFSQL table:

1. Display the file description: 

	- Select the table in the data model editor. 

	- In the context menu, select "Table description".




2. In the "Details" tab: 

	- Enable encryption of tables, indexes, memos, etc. Several encryption modes are available. <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Base_HFSQLCS_Securite%20-%20HC%20N%B0001.gif)
The "Automatic (RC5 16 rounds if password)" option is selected by default when a table is created. This option automatically encrypts the table if a password is set with function [HPass](../WDLang4/3044108.md) on the table.

	- Enable the "Enable enhanced security " option.
			Note: By default, this option is selected when creating a table. This option allows you to request the password at each automatic modification of the table.




3. Generate the database schema: under the "Database schema" pane, in the "Database schema" group, pull down "Generation" and select "Generate". For more details, see [Generating a database schema](../Editeurs/2011012.md).

4. Specify a password for the table with [HPass](../WDLang4/3044108.md). 

5. Encrypt the connection to the database in the connections defined in the database schema, or programmatically with the [Encryption](../Proprietes/2512102.md) property.




**Note** AES encryption (128-bit, 192-bit and 256-bit AES encryption algorithm with OFB operation mode): 

- If the table uses AES encryption, it is necessary to use the same encryption method for memos and indexes. 

- If AES encryption is used, the "Enable enhanced security " option is automatically applied.
