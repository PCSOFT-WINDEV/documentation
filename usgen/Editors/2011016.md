
## Key and referential integrity
			



<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000127"></a>
In a database schema, the "Key" items are also used to manage the consistency of data (called referential integrity):

- consistency for a table.

- consistency between several tables.




<a name="NOTE2"></a>
<a name="NOTE2_1"></a>


## Consistency for a table
<a name="consistency_for_table_ELTTEXTE000151"></a>
The consistency of the records found in a table is defined via the unique keys.

For example, in a PRODUCT table, the product reference must be unique. Each record must correspond to a different product, identified by its reference.

To do so, the REFERENCE item must be defined as unique key.

<a name="NOTE3"></a>
<a name="NOTE3_1"></a>


## Consistency between several tables
<a name="consistency_between_several_tables_ELTTEXTE000175"></a>
The consistency between several tables is defined via the links. The main types of links are:

- [shared link](#NOTE3_2).

- [complex link](#NOTE3_3).



<a name="NOTE3_2"></a>


### Shared link
<a name="shared_link_ELTPARAGRAPHE000047"></a>

A record can be associated with several records of another table.

Example: A SUPPLIER distributes several ITEMS, but each ITEM is associated with a single SUPPLIER.

To manage the referential integrity in this type of link, the unique identifier of SUPPLIER must be included in the ITEM table (this operation is automatically performed in the data model editor).
<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=LiaisonPartagee.gif)


The referential integrity check makes sure that:

- the SUPPLIER exists for every new ITEM

- all the items associated with a supplier are deleted when the supplier is deleted.




Advanced rules can also be defined: 

- cascading deletion: In this case, when a supplier is deleted, all associated items are deleted.

- cascading modification: All the linked records are modified in cascade when the key item (automatic identifier or other) is modified in the source file.



<a name="NOTE3_3"></a>


### Complex link
<a name="complex_link_ELTPARAGRAPHE000070"></a>

Several records of a table can be associated with several records of another table and vice versa.

Example: An order can contain several products and each product can be used in several orders.

In this case, a junction table must be created. This file contains the unique key of each table that must be linked (as well as other information if necessary).

The complex binding then becomes a set of shared bindings.
