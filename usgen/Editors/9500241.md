
## Database schema description window
			

<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000330"></a>
The database schema description window includes all the characteristics and options of the current database schema. 

To open the database schema description window:

- on the "Database schema" tab, in the "Current element" group, click "Description". 

- in the context menu of the data model editor, select "Database schema description". 




The data model description window presents different options grouped by tabs. 

<a name="NOTE2"></a>
<a name="NOTE2_1"></a>


## "General" tab
<a name="general_tab_ELTTEXTE000354"></a>
The "General" tab provides general information about the current database schema.  

The available details are: 

- **Database schema name**: Name of the current database schema. This name can be modified. In this case, the database schema will be renamed. The data model editor then suggests associating the renamed database schema with the current project. 

- **Caption**: Text associated with the current database schema. 

- **Directory**: Directory in which the database schema is saved. 

- **Full name**: Full name of the "wda" table corresponding to the current database schema. 

- **Created by**: Author of the database schema. The creation date and time are also indicated. This information cannot be modified. 

- **Updated by**: Name of the user who modified the database schema. The modification date and time are also indicated. This information cannot be modified. 

- **Database schema GUID**: Database schema ID. This information cannot be modified. You can also get this information programmatically, using the [GUIDAnalysis](../Proprietes/2512098.md) property.

## "Details" tab
<a name="details_tab_ELTTEXTE000378"></a>
The "Details" tab allows you to view and modify the database schema access options.  

The available details are: 

- **Editor password**: Password used to open the database schema in the table model editor.

- **Runtime password**: Database schema password used at runtime. This password is requested when opening the database schema in the HFSQL Control Center or with the [HOpenAnalysis](../WDLang4/3044106.md) function, for example. 

- **Default table directory**: Default directory used to create the tables of the current database schema. 

- **Description**: Database schema description to be included in the technical documentation. 

- **Database schema linked to a WINDEV 5.5 or WEBDEV 1.5 database schema**: If the database schema is compatible with WINDEV 5.5 or WEBDEV 1.5, you can select the corresponding database schema and its password, if necessary.

## "Logging" tab
<a name="logging_tab_ELTTEXTE000402"></a>
The "Logging" tab lets you view and modify general table logging options.  

The available details are: 

- Directory and password for files containing access history (JournalOperation and JournalIdentification files). 

- Directory containing replica descriptions for replicated tables.

## "Archiving" tab
<a name="archiving_tab_ELTTEXTE000426"></a>
The "Archiving" tab allows you to enable or disable the database schema archiving feature.

## "Language" tab
<a name="language_tab_ELTTEXTE000450"></a>
The "Language" tab allows you to get and set the programming language used by the database schema. The default language is WLanguage. 

You can use other programming languages. In this case, you need to specify the source generation directory.

For more details on programming with external languages, see [Overview of external languages](../LangageExt/7510002.md). 

<a name="NOTE7"></a>
<a name="NOTE7_1"></a>


## "International" tab
<a name="international_tab_ELTTEXTE000474"></a>
The "International" tab allows you to select the languages supported by the database schema. 

Database schemas can support more languages than the associated project. This can be necessary for database schemas shared by projects that support different languages. 

You can synchronize the languages of the database schema with the languages of the current project by clicking "Synchronize with project".

## "Options" tab
<a name="options_tab_ELTTEXTE000498"></a>
The "Options" tab allows you to view and change the display, synchronization and editing options in the data model editor. 

The available details are: 

- **Display item details in the graph**: Shows an icon next to the name of the item in the data model, to indicate the type of item. 

- **Links point to the linked keys**: Links defined in the editor are shown between linked keys in the tables. 

- **Show items with the same name in other tables**: When creating an item, opens a list of items with the same name in other tables in the current database schema. 

- **Restore deleted tables**: When you create a table with the same name as a recently deleted table, a window opens and lets you choose between creating a new file or restoring the old table along with its items. 

- **Restore deleted items**: When you create an item with the same name as a recently deleted item, a window opens and lets you choose between creating a new item or restoring the old item. 

- **Check subscription of tables when opening database schema**: Checks if changes were applied in the dictionary that contains the subscriber table. 
	Note: This option is kept for backward compatibility. It requires a personal [Dictionary](../Editeurs/2023002.md).   

- **Synchronization**: Indicates if the project and the database schema should be synchronized when changes are made to the database schema. This synchronization can be automatic or appear as a suggestion (default). 

- **When opening the project**: Desired action when the project opens:

	- Restore last database schema status,

	- Never open the database schema,

	- Always open the database schema. 




- **Propose to synchronize with the external databases**: Shows an automatic suggestion to synchronize data coming from an external database. Simply indicate how often the data should be synchronized. For more details, see [Synchronize database schema with external databases](../Editeurs/2011024.md).

- **Don't propose the SDD after the generation**: No longer suggests updating tables after generating the database schema. 

- **Allow special characters in item names**: Allows or prevents you from using special characters in the name of table items. Please note that this option is not compatible with the HFSQL engine. 

- **Automatically suggest Metatypes when creating the item**: Automatically suggests the metatypes defined in the database schema when creating an item. 

- **Unicode**: Allows or prevents using Unicode characters in the database schema AND executing stored procedures in Unicode mode.

## "Compilation" tab
<a name="compilation_tab_ELTTEXTE000522"></a>
The "Compilation" tab lets you view and change the compilation options of stored procedures defined in the data model editor. .  

The available options are: 

- **Enable compilation errors for 64-bit compatibility**: Shows errors that affect applications intended for 64-bit platforms.

- **Enable compilation errors for Linux compatibility**: Shows errors that affect applications intended for Linux. 

- **Programming standard: Standard or prefix syntax**: You can:

	- Allow both: In this case, no programming standard error will be displayed. 

	- Report use of prefix syntax: A programming standard error will appear if prefix syntax is used (e.g., "ListControl.Add"). 

	- Report use of standard syntax: A programming standard error will appear if standard syntax is used instead of an available prefix syntax. 




- **Programming standard: Report shared multilingual messages**: If checked, this option allows you to quickly identify shared multilingual text, by generating a compilation error. This option should be used when converting multilingual text to format 27 and higher. For more details, see [Translating programming text](../Editeurs/2013004.md).

- **Allow "[% %]" in strings**: This option allows the direct input of a variable name in a character string (also called "dynamic string construction"). To do so, use the following syntax: 
	
	```txt
	[%VariableName%]
	```
For example: 
	
	```wl
	// Ask for customer confirmation
	IF YesNo(Yes, "Do you confirm the creation of customer [%sCustomerName%]") = No THEN
		RETURN
	END
	```
**Caution**: Using this option may mean modifying the code for certain WLanguage functions that already use the "[% %]" characters in their parameters. In this case, to avoid interpreting the "[% %]" characters, they must be preceded by "-%". Example: 
	
	```wl
	grTooltip(GR_Deadline, grTooltipFormat, "[%CATEGORY%]" + CR + CR+ "[%VALUE%]" + " H")
	```
 becomes
	```wl
	grTooltip(GR_Deadline, grTooltipformat, -%"[%CATEGORY%]" + CR + CR + -%"[%VALUE%]" + " H")
	```
For more details, see [String interpolation](../Motscles/1514044.md). 

- **Allow nullable types**: Enables nullable types in a WINDEV, WEBDEV or WINDEV Mobile project. Allowing nullable types in a project changes the way your project handles null values. For more details, see [NULL values: Allowing nullable types](../Motscles/1511031.md). 

- **Arrays: Deep copy**
	This option makes arrays local by default. This means that the ** '='** operator performs a deep copy of the values in the array.
	If necessary, you can use the "dynamic" keyword so that the arrays point to the same reference.

- **Arrays: Protected access to elements passed as parameters to a procedure**
	This option protects an array element passed to a procedure as a parameter. You can modify, delete or add elements to the array from this procedure. 
	Note: When enabled, this option may slow down access to the array.  

- **Optimization: enable inline expansion**: This option speeds up code execution. Whenever possible, the compiler automatically replaces the procedure call with its code. This may result in an overall increase in code size, but faster procedure calls.

- **"Data source names"**:

	- "Variable name": 
			"Data source" variables create a data source that use the name of the variable. This may cause a problem in the following cases: 

		- use of arrays of data sources

		- use of data sources as class members.

		- when two windows use the same Data Source variable.




- "Automatic name": 
			"Data Source" variables use a unique name for the data source. Please note quotation marks must be removed to manipulate the data source. Don't write: 
			
		```txt
		M1 is Data Source
		HReadFirst("M1")
		```
 but 
		```txt
		M1 is Data Source
		HReadFirst(M1)
		```


- "Automatic name with references":
			"Data Source" variables use a unique name for the data source. It is now possible to reference an existing data source, for example using the following syntax: 
			
		```txt
		x is Data Source
		x = FileName
		x = QueryName
		```
The NULL value is supported. 
			![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png) The "Automatic name with references" option is not available.
