
## HFSQL Control Center: Optimizing and repairing tables
			

<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000196"></a>
The HFSQL Control Center allows you to optimize and repair HFSQL tables in both Classic and Client/Server modes. 

Two optimization modes are available:

- Synchronous optimization: The optimization settings window remains displayed during reindexing. 

- Asynchronous optimization: Optimization runs as a background task on the server. The optimization settings window can be closed. The result of the optimization is displayed in the "Optimizations" tab, which is available for databases. 
	Note: Asynchronous mode can be enabled in the [HFSQL Control Center options](../CCHF/3540001.md). 
	
	







### Optimizing and repairing tables
<a name="optimizing_and_repairing_tables_ELTPARAGRAPHE000028"></a>

To optimize and repair one or more tables:

1. Connect to an HFSQL server (if necessary) and double-click the name of the desired database or table in the tree structure to open its description window.

2. In the ribbon, click "Optimize and repair". The optimization window appears: 

	- in synchronous mode:<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=CC_HF_Requ%EAtes%20-%20HC%20N%B0002.gif)


	- in asynchronous mode.

3. Specify the desired options. 

4. Run the table optimization. 




**Note**: If optimization was run in asynchronous mode, the "Optimizations" tab will appear in the database details. This tab displays the results of optimizations run over the last 48 hours. If necessary, you can re-run an optimization from this tab.

## Optimization and reindexing options
<a name="optimization_and_reindexing_options_ELTTEXTE000235"></a>


### Configuration of optimization options
<a name="configuration_optimization_options_ELTPARAGRAPHE000052"></a>

The different options are as follows: 

- **Check indexes**: Checks consistency between the index and the tables.

- **Optimize speed of indexes (recalculate statistics)**: Optimizes indexes by calculating index statistics. These statistics are used to optimize filters, queries and HFSQL views. 
	Note: The more the table is modified, the less the statistics reflect the content of the HFSQL table.. The more records a table contains, the less impact the modification of a record has on the statistics.

- **Rebuild indexes (classic + full-text + spatial + semantic)**: Optimizes access to table records and recalculates statistics. All crossed records are automatically deleted. If this option is enabled, the advanced configuration options become available. 

- **Rebuild indexes and fix damaged memos**: Optimizes the entire table, its index and memos. If this option is enabled, the advanced configuration options become available. 

- **Compact memos**: Optimizes the entire table, its index and memos. Memos will be compressed. 
	Remarks: 

	- The table is created again. The last write date of the last record (returned by [HRecordDate](../WDLang4/3044338.md)) is set to the current date.

	- Timestamp items are also modified and are set to the date and time at which the optimization is performed. 







If **"Optimize without blocking client computers"** is checked, reindexing will be performed in the background and client applications will not be stopped. 
**Note**: This option is only taken into account for HFSQL Client/Server tables. 

**Remarks**:

- All optimization modes block tables during optimization, except "Optimize speed of indexes (recalculate statistics)". Users are informed that the table is in maintenance mode.

- When reindexing is completed, the current HFSQL context is restored (unless the memo compression option has been selected).





### Advanced reindexing parameters
<a name="advanced_reindexing_parameters_ELTPARAGRAPHE000110"></a>

Advanced parameters are:

- **Delete damaged records**
	If this option is checked, damaged records are automatically deleted.

- **Delete inactive records (deleted or crossed records)**
	If this option is selected, the crossed records are permanently deleted.
	**Reminder**: When a record is crossed, it is logically deleted and may be recovered at a later date. The record is still found in the table. Deleting crossed records deletes them permanently and optimizes the size of the file.

- **Density of the index**
	Corresponds to the density rate of the indexes. This rate is set to 80 by default. 
	A higher rate increases the density of the index and reduces its size. In this case, the browses, searches, filters and queries are faster. Adding and modifying records may take longer. 
	A smaller rate reduces the density of the index and increases its size. In this case, iterations, searches, filters and queries will be slower. Adding and modifying records will be faster. 
	Note: This parameter can only be used on HFSQL Classic or Client/Server tables.

- **Charset**
	The character set of the table is kept by default. However, a reindexing operation can be performed by changing the character set of the table. In this case, the new character set will be taken into account during the reindex operation. Sort and search operations performed on string keys (strings, characters, date and time) will use the new character set.
