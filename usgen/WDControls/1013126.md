


## TreeView control linked to a table
			



<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000129"></a>
It is possible to create TreeView control fields directly linked to the data. 

You can create a **TreeView control File**: the TreeView control will be linked to a table or a query. 

TreeView control programming has been greatly simplified: it is no longer necessary to directly use Arbrexxx. 



## How to?
<a name="how_ELTTEXTE000153"></a>


### Create a TreeView control linked to a table
<a name="create_treeview_control_linked_table_ELTPARAGRAPHE000019"></a>

To create a TreeView control linked to a table: 

1. Create a TreeView control (on the "Creation" tab, in the "Data" group, click "TreeView").

2. Open the control description window (select "Description" in the context menu). 

3. In the "Content" tab, select "Table/Query". <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Arbre_Contenu.gif&type=thumb)


4. Click "Add". A "&lt;None&gt;" data source is automatically added.

5. Define the characteristics of this source:

	- Source: corresponds to the name of the table or query to be browsed.

	- Route: corresponds to the route key used to browse the source.

	- Displayed: corresponds to the item displayed in the TreeView control.




6. Add (if necessary) a second source for the next level ("Add" button). In this case, you have the ability to define the source of the link for the previous level. 
	For example, if the first level loops through the Customer table, the second one can loop through the Orders table. The items that will be used to set the relation are "Customer.CustomerID" and "Orders.CustomerID". By default, the source of the link is automatically deduced from the items and links defined in the database schema.

7. Define as many sources as necessary. 
	**Special case: TreeView control linked to a recursive table**
	A TreeView control linked to a table can display records dependent on the previous record (the classic case of a recursive link to manage/child parents, for example). 
	To manage this type of TreeView control, a reflexive link can be defined in the "Contents" tab of the TreeView control description window.

8. Validate the TreeView control description window. The TreeView control is now linked to a table.

### "Populate sub-levels dynamically" option
<a name="populate_sublevels_dynamically_option_ELTPARAGRAPHE000062"></a>

When a TreeView control field linked to a table has many elements and sub-elements, it can take a long time to fill it completely. 

The "Populate sub-levels dynamically (faster)" option populates each sub-level only when the user expands a level. The population time is optimized and it takes less time to populate the control the first time. 

**Note**: To use this option on a TreeView control populated programmatically, use the [AddChildDelayed](../Proprietes/1000020927.md) property. 



## Manipulating a data-bound TreeView control
<a name="manipulating_databound_treeview_control_ELTTEXTE000183"></a>
A TreeView control linked to a table is very easy to handle:

- If the TreeView control can be edited, the changes made to the control are automatically reflected to the bound data source. 

- If the TreeView control does not allow user input, the bound data source will not be modified.
