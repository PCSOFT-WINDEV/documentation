


## ParallelTaskExecute (Function)

***In french: TâcheParallèleExécute***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Triggers the execution of a parallel task.

<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example
<a class="notetitle" target="_blank" href="$DOC$=1000021588&name=paralleltaskexecute_function">See additional examples</a>

```wl
// Use the syntax 1 
t1 is ParallelTask = ParallelTaskExecute(ProcedureA, (), ptoMainThread)
```

```wl
// Use the syntax 2 
t1 is ParallelTask
t1.Procedure = Procedure3
t2 is ParallelTask = ParallelTaskExecute(t1)
```

```wl
// Use the syntax 3 
t3 is Description of ParallelTask
t3.Procedure = Procedure3
ParallelTaskExecute(t3)
```

```wl
// Use the syntax 3 
t3bis is Description of ParallelTask
t3bis.Procedure = Procedure3bis
t3bis.Parameter[1] = Today()
t3bis.Parameter[2] = TimeSys()
ParallelTaskExecute(t3bis)
```

```wl
// Declare several tasks and run a process at the end of all these tasks
MyTaskDescription is Description of ParallelTask
arrMyTasks is array of ParallelTask // Result of parallel tasks functions 
// Task #1
MyTaskDescription.Procedure = Example2_Step1
// Runs the parallel tasks
// Add the task returned to an array of tasks 
// in order to re-use them in ParallelTaskExecuteAfterAll
Add(arrMyTasks, ParallelTaskExecute(MyTaskDescription))
// Task #2
MyTaskDescription.Procedure = Example2_Step2
Add(arrMyTasks, ParallelTaskExecute(MyTaskDescription))
// Specify the procedure to run once 
// once all the tasks found in the arrMyTasks array are ended
ParallelTaskExecuteAfterAll(arrMyTasks, Example2_End, (), ptoMainThread)
```

## Syntax
<a name="SYNTAXE1"></a>

### Running a parallel task

`<Result> = ParallelTaskExecute(<Procedure> [, <Parameters> [, <Options>]])`
---

**`<Result>: (ParallelTask variable)`**

[ParallelTask](../WDLang1/1000021220.md) variable corresponding to the task to run.

**`<Procedure>: (Character string or Procedure variable)`**

Procedure to be executed. This parameter can correspond to: 

- the name of the procedure to be executed. 

- the name of the [Procedure](../Motscles/1000018907.md) variable corresponding to the procedure to be executed.




**`<Parameters>: (List of values enclosed in brackets, separated by commas)`**

Parameters of the procedure to be executed. This list of parameters has the following format:


```txt
(<Parameter 1>, ..., <Parameter N>)
```
where: 

- &lt;Parameter 1&gt; is the first parameter of the procedure.

- ...

- &lt;Parameter N&gt; is the nth parameter of the procedure.




**Warning** Parameters are passed by value. In the case of variables of complex types (arrays, object), the value is the element itself.. To restrict access to this variable, you can: 

- make a copy of the variable (with the LOCAL keyword),

- use critical sections (with [CriticalSectionStart (Function)](../WDLang1/3077001.md) or the &lt;critical section&gt; attribute)




**`<Options>: (Optional Integer constant (or combination of constants))`**

Options of task to run:


|   |   |
| --- | --- |
| *ptoDelayedCopyHFSQLContext*<br>(Default value) | Triggers a light copy of HFSQL context **during the first access to the HFSQL data**. |
| *ptoFullCopyHFSQLContext* | Triggers the immediate copy of the current HFSQL context.<br>Recommended, for example, if the parallel task must take into account the current positions in the files and queries of the context of the caller. |
| *ptoLightCopyHFSQLContext* | Triggers the immediate copy of a part of the current HFSQL context. <br>Only the directories containing the tables in HFSQL Classic mode and/or the connections in HFSQL Client/Server mode are stored. |
| *ptoMainThread* | Runs the task in the main thread.<br>This constant can be combined with one of the other constants. <br>Warning: This constant cannot be used to execute a parallel task in the main thread from within the main thread. |


Note: To find out which type of copy to choose, see [comparison between the different copy modes](#NOTE0_1). 


<a name="SYNTAXE2"></a>

### Running a parallel task described beforehand (ParallelTask variable)

`<Result> = ParallelTaskExecute(<Task>)`
---

**`<Result>: (ParallelTask variable)`**

[ParallelTask](../WDLang1/1000021220.md) variable corresponding to the task run.

**`<Task>: (ParallelTask variable)`**

Name of the [ParallelTask](../WDLang1/1000021220.md) variable corresponding to the task to run. 

Warning: If the task is already running or has already been executed, a WLanguage error will be triggered.


<a name="SYNTAXE3"></a>

### Running a parallel task identified by its description (Description of ParallelTask variable)

`<Result> = ParallelTaskExecute(<Task description>)`
---

**`<Result>: (ParallelTask variable)`**

[ParallelTask](../WDLang1/1000021220.md) variable corresponding to the task run.

**`<Task description>: (Description of ParallelTask variable)`**

Name of the [Description of ParallelTask](../WDLang1/1000021586.md) variable that describes the task to be executed. 



<a name="NOTE0"></a>
<a name="NOTE0_1"></a>

## Remarks


- The task is saved in the queue of tasks to run. 

- **ParallelTaskExecute** is not a blocking function and does not wait for task to be completed.

- Comparison between the different types of copy for the HFSQL context: 
	

| Type of copy | Benefits | Drawbacks |
| --- | --- | --- |
| **Full copy** | Copies: <br><br>	- the extensive connection parameters (connections, physical paths, ...).<br><br>	- positions, filters, etc. defined on tables.<br><br>	- the queries. <br><br><br> | Memory consumption (on the client and on the server). |
| **Light copy** | Copies the extensive connection parameters (connections, physical paths, ...).<br><br>No memory consumption on the server. | The records and the current filters are not copied. Therefore, the records must be repositioned by HReadSeek for example. <br><br>No copy of queries. <br><br>Memory consumption on the Client computer |
| **Delayed copy** | No memory consumption (on the client and on the server). | Risk: If the connection parameters are modified, the last modification will be taken into account. <br><br>The records and the current filters are not copied. Therefore, the records must be repositioned by HReadSeek for example. <br><br>No copy of queries. |





In most cases, the delayed copy is recommended provided that you don't change the connection parameters and that you perform the necessary calls to **HReadSeek**.
