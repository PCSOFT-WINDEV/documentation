


## HashCheckFile (Function)

***In french: HashVérifieFichier***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Checks the Hash of a file for a specific type of algorithm. You have the ability to check: 

- a simple hash.

- a hash with message authentication.

- a hash obtained with a key derivation function that takes a salt as parameter (PBKDF2).
	![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![Android Widget ](https://doc.pcsoft.fr/ext/images/us/ANDROIDWIDGET.png)![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png)![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png) Not available.




**Reminder** Hashing is used to produce a condensed summary of a file or character string. This summary is called Hash.

## Example

![WINDEV](https://doc.pcsoft.fr/ext/images/us/WD.png)![WEBDEV - Server code](https://doc.pcsoft.fr/ext/images/us/WBS.png)![Reports and Queries](https://doc.pcsoft.fr/ext/images/us/ER.png)![User code (UMC)](https://doc.pcsoft.fr/ext/images/us/MCU.png)![Ajax](https://doc.pcsoft.fr/ext/images/us/AJAX.png) 
```wl
// Calculate the Hash of the "C:\Temp\File.txt" file
HashMyFile is string 
HashMyFile = HashFile(HA_MD5_128, "C:\Temp\File.txt")

// Process on the file
// ...

// Checks whether the file was modified
IF HashCheckFile(HA_MD5_128, "C:\Temp\File.txt", ...
		HashMyFile) = False THEN
	Info("The file was modified.")
END
```

## Syntax

### Checking a simple hash

`<Result> = HashCheckFile(<Type of algorithm> , <File path> , <Hash>)`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the result when &lt;File path&gt; was hashed by &lt;Type of algorithm&gt; corresponds to &lt;Hash&gt;,

- <u><u><u><u>False</u></u></u></u> otherwise.




**`<Type of algorithm>: (Integer constant)`**

Indicates the type of algorithm used when hashing the &lt;File path&gt; file:



|   |   |
| --- | --- |
| MD4 family | *HA_MD4*<br><br> |
| MD5 family | *HA_MD5_128*<br><br>Please note: this type of algorithm is currently deprecated. |
| MURMUR family | <br><br>- *HA_MURMUR_1* Murmur algorithm version 1: 32-bit hash result<br><br>- *HA_MURMUR_2* Murmur algorithm version 2: 32-bit hash result<br><br>- *HA_MURMUR_2_64A* Murmur algorithm version 2: 64-bit hash result optimized for 64-bit processors<br><br>- *HA_MURMUR_2_64B* Murmur algorithm version 2: 64-bit hash result optimized for 32-bit processors<br><br>- *HA_MURMUR_2_A* Murmur version 2 incremental algorithm: 32-bit hash result<br><br>- *HA_MURMUR_2_BIG_ENDIAN* Murmur algorithm version 2 for big-endian machine: 32-bit hash result<br><br>- *HA_MURMUR_2_ALIGNE* Murmur algorithm version 2 for aligned machine: 32-bit hash result<br><br>- *HA_MURMUR_3_32* Murmur algorithm version 3: 32-bit hash result<br><br>- *HA_MURMUR_3_128_X86* Murmur algorithm version 3: 128-bit hash result optimized for 32-bit processors<br><br>- *HA_MURMUR_3_128_X64* Murmur algorithm version 3: 128-bit hash result optimized for 64-bit processors<br><br><br><br><br>![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) The constants of this family are not available. |
| RIPEMD family | <br><br>- *HA_RIPEMD_128*<br><br>- *HA_RIPEMD_160*<br><br><br><br><br>![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) The constants of this family are not available. |
| SHA family | <br><br>- HA_SHA_160 (also called SHA-1)<br><br>- HA_SHA_256 (FIPS PUB 198 specifications)<br><br>- HA_SHA_256_DOUBLE<br><br>- HA_SHA_384<br><br>- HA_SHA_512<br><br><br> |
| SHA-3 family | <br><br>- *HA_SHA3_224*<br><br>- *HA_SHA3_256*<br><br>- *HA_SHA3_384*<br><br>- *HA_SHA3_512*<br><br><br><br><br> |
| TIGER family | <br><br>- *HA_TIGER_128*<br><br>- *HA_TIGER_160*<br><br>- *HA_TIGER_192*<br><br><br>![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) The constants of this family are not available. |

| CKSUM family | <br><br>- *HA_CKSUM_8*<br><br>- *HA_CKSUM_16*<br><br>- *HA_CKSUM_32*<br><br>- *HA_CKSUM_64*<br><br><br><br><br>![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) The constants of this family are not available. |





- MD4 / MD5 / SHA / RIPEMD algorithms: classic cryptographic hash functions.

- TIGER / WHIRLPOOL algorithms: hash functions with very good cryptographic properties, optimized for 64-bit (but can be used in 32-bit).

- CKSUM algorithms: hash functions with no cryptographic properties, to be used only for minimal checks or hash tables.

- MURMUR algorithm: very fast hash functions with no cryptographic properties. This algorithm is used by the "bloom filter" of bitcoin wallets.




**`<File path>: (Character string)`**

Path of file for which the Hash will be checked.

**`<Hash>: (Character string)`**

Hash of file to check. This Hash must be the result of [HashFile](../WDLang1/1000007112.md) previously called for &lt;File path&gt; using the &lt;Type of algorithm&gt;.
