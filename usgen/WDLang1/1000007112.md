


## HashFile (Function)

***In french: HashFichier***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Calculates the Hash of a file according to a specific algorithm. You have the ability to calculate: 

- a simple hash.

- a hash with message authentication.

- a hash obtained with a key derivation function that takes a salt as parameter (PBKDF2).
	![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![Android Widget ](https://doc.pcsoft.fr/ext/images/us/ANDROIDWIDGET.png)![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png)![PHP](https://doc.pcsoft.fr/ext/images/us/PHP.png) Not available.




**Reminder** Hashing is used to produce a condensed summary of a file or character string. This summary is called Hash.

**Caution**: Result may contain characters that cannot be displayed. If you want to get a string with the hexadecimal representations of bytes (to use it in a REST or SOAP API, for example) you can use [BufferToHexa](../WDLang1/1000019916.md) with the *NoGrouping* constant on the result buffer.

<a class="notetitle" target="_blank" href="$DOC$=1000007118&name=hashfile_function">See additional examples</a>

```wl
// Calculate the Hash of two files
Hash1 is Buffer = HashFile(HA_MD5_128, "C:\My files\FileA.txt")
Hash2 is Buffer = HashFile(HA_MD5_128, "D:\My files\FileB.txt")
// Compare the two Hash
IF Hash1 = Hash2 THEN Info("The two files are identical.")
```

## Syntax

### Calculating a simple hash

`<Result> = HashFile(<Type of algorithm> , <File path> [, <Progress Bar>])`
---

**`<Result>: (Buffer)`**

Result of &lt;File path&gt; hashing with the &lt;Type of algorithm&gt; algorithm.

**`<Type of algorithm>: (Integer constant)`**

Indicates the type of algorithm used when hashing the &lt;File path&gt; file:



|   |   |
| --- | --- |
| MD4 family | *HA_MD4*<br><br> |
| MD5 family | *HA_MD5_128*<br><br>Please note: this type of algorithm is currently deprecated. |
| MURMUR family | <br><br>- *HA_MURMUR_1* Murmur algorithm version 1: 32-bit hash result<br><br>- *HA_MURMUR_2* Murmur algorithm version 2: 32-bit hash result<br><br>- *HA_MURMUR_2_64A* Murmur algorithm version 2: 64-bit hash result optimized for 64-bit processors<br><br>- *HA_MURMUR_2_64B* Murmur algorithm version 2: 64-bit hash result optimized for 32-bit processors<br><br>- *HA_MURMUR_2_A* Murmur version 2 incremental algorithm: 32-bit hash result<br><br>- *HA_MURMUR_2_BIG_ENDIAN* Murmur algorithm version 2 for big-endian machine: 32-bit hash result<br><br>- *HA_MURMUR_2_ALIGNE* Murmur algorithm version 2 for aligned machine: 32-bit hash result<br><br>- *HA_MURMUR_3_32* Murmur algorithm version 3: 32-bit hash result<br><br>- *HA_MURMUR_3_128_X86* Murmur algorithm version 3: 128-bit hash result optimized for 32-bit processors<br><br>- *HA_MURMUR_3_128_X64* Murmur algorithm version 3: 128-bit hash result optimized for 64-bit processors<br><br><br><br><br>![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) The constants of this family are not available. |
| RIPEMD family | <br><br>- *HA_RIPEMD_128*<br><br>- *HA_RIPEMD_160*<br><br><br><br><br>![Java](https://doc.pcsoft.fr/ext/images/us/JAVA.png) The constants of this family are not available. |

- MD4 / MD5 / SHA / RIPEMD algorithms: classic cryptographic hash functions.

- TIGER / WHIRLPOOL algorithms: hash functions with very good cryptographic properties, optimized for 64-bit (but can be used in 32-bit).

- CKSUM algorithms: hash functions with no cryptographic properties, to be used only for minimal checks or hash tables.

- MURMUR algorithm: very fast hash functions with no cryptographic properties. This algorithm is used by the "bloom filter" of bitcoin wallets.




**`<File path>: (Character string)`**

Path of file on which the calculation will be performed.

### Calculating a hash using a key derivation function that takes a salt as parameter (PBKDF2)

`<Result> = HashFile(<Type of algorithm> , <File path> , <Salt> , <Iteration> , <Length> [, <Progress Bar>])`
---

**`<Result>: (Buffer)`**

Result of &lt;File path&gt; hashing with the &lt;Type of algorithm&gt; algorithm.

Warning: This result may contain characters that cannot be displayed.

**`<Type of algorithm>: (Integer constant)`**

Indicates the type of pseudo-random function used by PBKDF2 to hash the &lt;File path&gt; file:



|   |   |
| --- | --- |
| MD4 family | *HA_PBKDF2_HMAC_MD4* |
| MD5 family | *HA_PBKDF2_HMAC_MD5_128*<br><br>Please note: this type of algorithm is currently deprecated. |
| RIPEMD family | <br><br>- *HA_PBKDF2_HMAC_RIPEMD_128*<br><br>- *HA_PBKDF2_HMAC_RIPEMD_160*<br><br><br> |
| SHA family | <br><br>- *HA_PBKDF2_HMAC_SHA_160*<br><br>- *HA_PBKDF2_HMAC_SHA_256*<br><br>- *HA_PBKDF2_HMAC_SHA_256_DOUBLE*<br><br>- *HA_PBKDF2_HMAC_SHA_384*<br><br>- *HA_PBKDF2_HMAC_SHA_512*<br><br><br> |
| SHA-3 family | <br><br>- *HA_PBKDF2_HMAC_SHA3_224*<br><br>- *HA_PBKDF2_HMAC_SHA3_256*<br><br>- *HA_PBKDF2_HMAC_SHA3_384*<br><br>- *HA_PBKDF2_HMAC_SHA3_512*<br><br><br> |
| TIGER family | <br><br>- *HA_PBKDF2_HMAC_TIGER_128*<br><br>- *HA_PBKDF2_HMAC_TIGER_160*<br><br>- *HA_PBKDF2_HMAC_TIGER_192*<br><br><br> |
| WHIRLPOOL family | *HA_PBKDF2_HMAC_WHIRLPOOL* |





- MD4 / MD5 / SHA / RIPEMD algorithms: classic cryptographic hash functions.

- TIGER / WHIRLPOOL algorithms: hash functions with very good cryptographic properties, optimized for 64-bit (but can be used in 32-bit).




**`<File path>: (Character string)`**

Path of file on which the calculation will be performed.

**`<Salt>: (Character string)`**

Cryptographic salt used. String (usually random) added to the file to make it more complex.  

**`<Iteration>: (Integer)`**

Number of iterations of the algorithm (10000 by default). This number depends on the power of the computing machine and the complexity of the hash. A minimum of 1000 iterations is generally recommended.

**`<Length>: (Integer)`**

Length of the derived key. By default, corresponds to the size of the key generated by the pseudo-random function. This length is technically unbounded but due to the algorithm, it is limited to (2^32 - 1) \* (output length of the algorithm used by PBKDF2).

## Remarks


### Notes
<a name="notes_ELTPARAGRAPHE000658"></a>

- Two files with an identical content will have, for the same type of algorithm, two identical Hashes.

- The result of the Hash may contain non-displayable characters. These characters will not be visible when using [Info](../WDLang1/3021011.md) or [Trace](../WDLang1/3013050.md) for example.

### Availability of algorithms
<a name="availability_algorithms_ELTPARAGRAPHE000674"></a>

- HA_HMAC_MD5_128

- HA_HMAC_SHA_160, HA_HMAC_SHA_256, HA_HMAC_SHA_384, HA_SHA_HMAC_512

- HA_HMAC_SHA_256_DOUBLE

- HA_MD4

- HA_MD5_128

- HA_SHA_160, HA_SHA_256, HA_SHA_384, HA_SHA_512

- HA_SHA_256_DOUBLE
