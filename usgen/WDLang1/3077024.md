


## ThreadExecute (Function)

***In french: ThreadExecute***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Starts the execution of a secondary thread. The instruction is non-blocking: the two processes run in parallel.

**Reminder** A thread is a process launched in parallel with the current application ("main thread"). This allows you to run a task in the background (e.g. backup, etc.).






<a name="sample_code"></a>

## Example

<a name="Exemple2"></a>

```wl
// Run a thread while passing parameters 
sDate is string 
sDate = DateSys()
// Run the thread
ThreadExecute("THREADNAME", threadNormal, "pExecQry", (sDate))
// ---------------------------------------------------------
// Details of the "pExecQry" procedure 
// This procedure expects a date as parameter of a query 
PROCEDURE pExecQry(sDate)
IF HExecuteQuery(Del_Date, hQueryDefault, sDate) = False THEN
	Error(HErrorInfo())
ELSE
	HReadFirst(Del_Date)
END
```
<a name="Exemple1"></a>

```wl
// Compatible syntax
ThreadExecute("Thread1", threadNormal, ThreadProcedure) 
...
// Call to a global method of a class
ThreadExecute("Thread2", threadNormal, CClass::GlobalMethod)
```

### Declaring and executing a Thread variable

`<Result> = ThreadExecute(<WLanguage procedure> [, <Parameters>] [, <Options>])`
---

**`<Result>: (Thread variable)`**

[Thread](../WDLang1/1000024879.md) variable corresponding to the thread executed.

**`<WLanguage procedure>: (Procedure name)`**

Name of the WLanguage procedure run. This procedure is run in parallel with the application.

**`<Parameters>: (List of values enclosed in brackets, separated by commas)`**

Parameters of the procedure to be executed. This list of parameters has the following format:


```txt
(<Parameter 1>, ..., <Parameter N>)
```
where: 

- &lt;Parameter 1&gt; is the first parameter of the procedure.

- ...

- &lt;Parameter N&gt; is the nth parameter of the procedure.




**Warning** Parameters are passed by value. In the case of variables of complex types (arrays, object), the value is the element itself.. To restrict access to this variable, you can: 

- make a copy of the variable (with the LOCAL keyword),

- use critical sections (with [CriticalSectionStart (Function)](../WDLang1/3077001.md) or the &lt;critical section&gt; attribute)




**`<Options>: (Optional constant)`**

Thread start mode.

### Executing a thread already described (Thread variable)

`<Result> = ThreadExecute(<Thread>)`
---

**`<Result>: (Thread variable)`**

[Thread](../WDLang1/1000024879.md) variable corresponding to the thread executed.

**`<Thread>: (Thread variable)`**

Name of the [Thread](../WDLang1/1000024879.md) variable corresponding to the thread to execute. 
This thread is a secure thread, which implies the following: 

- a compilation error will occur if the controls are accessed in the thread. 

- an exception will be raised: 

	- if the thread accesses the controls at runtime,

	- if the [ThreadStop](../WDLang1/3077019.md) function is called.




- when the window that triggered the thread is closed, a request to stop the thread is generated (but the thread continues to run after the window is closed). 




Warning: If the thread is already running or has already been executed, a WLanguage error will be triggered.

## Remarks


### Characteristics of a thread created in WLanguage
<a name="characteristics_thread_created_wlanguage_ELTPARAGRAPHE000203"></a>

A thread created in WLanguage can only be a procedure or a class method. The thread cannot correspond to a WLanguage process (code of a control for example).

If the thread is a class method, **ThreadExecute** must be run from one of the processes of the class (constructor or method).
<a name="NOTE0_2"></a>


### Thread and HFSQL
<a name="thread_and_hfsql_ELTPARAGRAPHE000214"></a>

When executing the **ThreadExecute FUNCTION**function, HFSQL contexts are automatically duplicated: there are as many HFSQL contexts as there are threads running. The entire HFSQL context is copied (filter, search condition, etc.). The HFSQL context evolves independently in each thread.

This allows you, for example, to perform two different iterations on the same table in two different threads. 

Two methods can be used to copy HFSQL contexts: 

- Full copy of context (by default)

- Light copy of context. 




For more details on how HFSQL contexts are copied and their limits (depending on the database used), see [Managing HFSQL contexts](../WDChamp/1010029.md).

**Example**: 

- A filter is created on the Customer table. 

- [ThreadExecute](../WDLang1/3077024.md) is called to create the CTX2 thread. 

- The Customer table is filtered in each thread (main and CTX2). The filter will still be enabled in the CTX2 thread even if the filter is disabled in the main thread.




**Special cases**:

- **Assisted HFSQL error handling** If several threads are used on tables, it is advisable to customize HFSQL error handling so that the default windows are not displayed. To do so, use [HOnError](../WDLang4/3044017.md) to disable the automatic management of errors or to redirect the management of errors to a custom procedure (without displaying windows). For more details, see [HFSQL error handling help](../WDLang4/3044188.md).

- **Writes and assigns in a thread** If writes or assigns are performed in a thread, other running threads do not share this information. Some inconsistencies may occur.

### Lifecycle of a thread
<a name="lifecycle_thread_ELTPARAGRAPHE000273"></a>

The thread is automatically stopped at the end of the execution of the WLanguage procedure started by **ThreadExecute**. 

The thread is also stopped in the following cases: 

- if **ThreadExecute** is called from the code of a window, the thread will be stopped when the window is closed. 

- if **ThreadExecute** is called from a global process (initialization, explicit call in the main context), the thread will be stopped when the application is terminated. 

- if **ThreadExecute** is called in a class method, the thread is stopped when the object is destroyed. 




To force the execution of the thread in the main context, use the *threadGlobalContext* constant. 

To force the thread to stop, use [ThreadStop](../WDLang1/3077019.md). This function can be used to stop a thread from the main thread.

**Note** It is advisable to check that threads have been stopped (using functions [ThreadState](../WDLang1/3077016.md) or [ThreadWait](../WDLang1/3077020.md)) before closing windows or destroying objects.  
<a name="NOTE0_5"></a>




### Handling errors
<a name="handling_errors_ELTPARAGRAPHE000310"></a>

A fatal error occurs in the following cases:

- if the procedure does not exist.

- if a thread with the same name is currently running.



<a name="NOTE0_6"></a>


### Forbidden processes
<a name="forbidden_processes_ELTPARAGRAPHE000568"></a>

Please note: the following processes cannot be run in threads:

- opening windows with WLanguage functions such as [Open](../WDLang1/3038035.md), [Use](../WDLang1/3038044.md), [Close](../WDLang1/3038018.md), etc. A specific management mode must be implemented if some windows must be handled in threads (rare case). For more details, see [Opening a window in a secondary thread](../WDLang1/3077015.md).

- managing events.

- multitask.

- managing timers.





|   |
| --- |
| **Warning: it is forbidden to manipulate the UI (windows, fields, etc.) in a secondary thread.**<br> When a secondary thread must interact with the user or update the UI, it must use a process started from the main thread. This process can correspond to:<br><br>- a global procedure of the project or a local procedure (of a window, etc.) called by [ExecuteMainThread](../WDLang1/1000019862.md),<br><br>- the "Request for refreshing the display" event of a window run by [RequestRefreshUI](../WDLang1/1000023899.md).<br><br><br> |

### Stopping a thread
<a name="stopping_thread_ELTPARAGRAPHE000325"></a>

[ThreadStop](../WDLang1/3077019.md) is not available in Android. 

Only the thread itself must stop thread, at the end of the WLanguage procedure called by **ThreadExecute**.

Example: 


```txt
ThreadExecute("th", threadNormal, ProcThread)
```

```txt
PROCEDURE ProcThread
bThreadAlive is boolean = True
WHILE bThreadAlive

	//... Process

	// Test the end condition of the thread
	IF <THREAD END CONDITION> THEN
		bThreadAlive = False
	END
END
```
