
## BuildBrowsingTable (Function)

***In french: ConstruitTableFichier***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Creates a Table control from the items of a table (view or query). Each column of the control is bound to an item in the table. The width of the columns changes automatically according to the data in the file or query.

This function is used to get a Table control adapted to the browse of a specific table.


<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example
<a class="notetitle" target="_blank" href="$DOC$=1000003074002&name=buildbrowsingtable_function">See additional examples</a>

```wl
// Displays the contents of the "CLIENTS" table in a Table field linked to a table 
BuildBrowsingTable(TABLE_TABLE1, "CUSTOMERS", taWithAutoID)
```


<a name="Exemple2"></a>

```wl
// Displays the query content in a Table control populated programmatically
IF HExecuteQuery(QRY_LIST_ACTIVE_CUSTOMERS) = True THEN
	BuildBrowsingTable(TABLE_CUSTOMERS, ...
			QRY_LIST_ACTIVE_CUSTOMERS, taFillTable)
END
```

## Syntax

`BuildBrowsingTable(<Table control> , <Table> [, <Options>])`
---

**`<Table control>: (Control name)`**

Table field name (data-related Table field or programmatically populated Table field). 

Warning: This field must exist in the. It may have been created by [ControlCreate](../WDLang1/1000020876.md).

The records in the table can be viewed directly if this parameter corresponds to a data-bound Table control.

**`<Table>: (Character string)`**

Name of table, view or query used as a base for creating the Table control.

**`<Options>: (Optional constant (or combination of constants))`**

Configures the creation mode of columns in the Table control.

|   | Operating mode with the constant | Default operating mode |
| --- | --- | --- |
| *taWithBinary* | Binary items (link composite key for example) are added to the Table control. | Default: Binary fields (e.g. compound link key) are not added to the Table control. |
| *taWithAutoID* | A column is generated for the automatic identifier. | Default: No column for automation identifier. |
| *taWithDetailsBinding* | A sub-table is automatically generated to display the bound items from the tables of the database schema. | Default: No "line detail" window is displayed. |
| *taSingleLineColumn* | By default, text columns are created with the [Multiline](../Proprietes/2510105.md) property set to <u><u><u><u>False</u></u></u></u>. | Default: Text columns corresponding to memo items are multiline and other text columns are monoline. |
| *taMultiLineColumn* | By default, text columns are created with the [Multiline](../Proprietes/2510105.md) property set to <u><u><u><u>True</u></u></u></u>. | Default: Text columns corresponding to memo items are multiline and other text columns are monoline. |
| *taKeepBrowseKey* | The search key of the data-bound Table control does not change (this search key is returned by the [BrowsedItem](../Proprietes/2510111.md) property). | Default setting: The first key item encountered is set as the browse item. |
| *taKeepColumn* | The existing columns in the Table control are not deleted. | Default: Existing columns are deleted. |
| *taImageSizeOnly* | Image memo columns display Length only and never load images. | Default: Image memo columns display images. |
| *taItemCaption* | The captions of items are used for the titles of columns. | Default: Use field name as column heading. |
| *taByLogicalOrder* | The columns are created according to the logical order of items defined in the data model editor.<br>For the queries, the logical order and the physical order of items are identical. | Default: The physical order of fields in the table is used.<br>For the queries, the logical order and the physical order of items are identical. |
| *taFillTable* | A Table control is populated programmatically with the contents of the table (Caution: time-consuming operation that can saturate memory). | Default: Table fields are not populated programmatically. |
| *taWithAutoID* | Input allowed in the column associated with the automatic identifier (if it exists and if the Table control is in edit). |   |
| *taNoAdjust* | The width of the columns is not adjusted (the records are not read). |   |
| *taNoMemoText* | The 'text memo' items are not added into the Table control. | Default: Text memo' fields are added to the Table control. |
| *taNoMemoImage* | The "image memo" items are not added into the Table control. | Default: Image memo' fields are added to the Table control. |

## Remarks




### Table control features (by default)
<a name="table_control_features_default_ELTPARAGRAPHE000178"></a>

- The columns of Table control defined in the editor are deleted.

- The input modes defined in the editor for the Table control are kept.

- A column whose type is identical to the item type is created for each item of the table.

- No column is created for the binary memo items (a column is created for the text memo items or for the image memo items).

- The properties of Table controls and columns are updated to allow the file to be browsed through:
	
	```txt
	<Table control>.BrowsedFile = <Table name>
	```

	and for each column:
	
	```txt
	<Column name>.DataBinding = <Name of the bound item>
	<Nom Colonne>CategoryCurve = <Première clé du fichier de données>
	```

### Table control populated programmatically
<a name="table_control_populated_programmatically_ELTPARAGRAPHE000197"></a>

If &lt;Table control&gt; corresponds to a Table control populated programmatically, no data is displayed (the Table control is empty) but the Table control and column properties are assigned like in the case of a data-bound Table control.

To display data in the Table control, use the [TableAdd](../WDLang1/3074017.md) or **BuildBrowsingTable** functions with the *taFillTable* constant.

**Note**: The constant *taRemplirTable* does not allow a table control to be populated programmatically with image memos. To add an image into a Table control populated programmatically, the corresponding file must be found in the application library (WDL file) or it must be accessible from the current computer.
<a name="NOTE0_3"></a>




### Columns
<a name="columns_ELTPARAGRAPHE000214"></a>

The created columns are named "_COL1", "_COL2", "_COL3", etc. These columns are accessible programmatically via the indirection operator { }.

**You cannot write**:


```wl
TABLE_TABLE1._COL1.Width = 120 // Generates an error "_COL1 unknown"
```


You must write:


```wl
{"TABLE_TABLE1._COL1"}..Width = 120
```

<a name="NOTE0_4"></a>




### Miscellaneous
<a name="miscellaneous_ELTPARAGRAPHE000230"></a>

- **BuildBrowsingTable** traverses the table. The current record may be modified once this function has been used.

- Filling the table with the **BuildBrowsingTable** function takes place in a parallel background process: if the data source is a query, this query must not be released until the window is closed or the Table control reset.
