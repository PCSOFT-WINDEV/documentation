


## InUniversalWindowsAppSimulatorMode (Function)

***In french: EnModeSimulateurUniversalWindowsApp***

<a name="Utilisation"></a>
<a name="description"></a>
Indicates whether the code is run in the simulator for Universal Windows Platform applications.


<a name="Exemple1"></a>
<a name="sample_code"></a>

## Example


```wl
// Code run in the Universal Windows 10 app simulator?
If InUniversalWindowsAppSimulatorMode() = True THEN
	// Specific code for the simulator 
END
```

<a name="XSYNTAXE"></a>

## Syntax
<a name="SYNTAXE1"></a>

`<Result> = InUniversalWindowsAppSimulatorMode()`
---

**`<Result>: (Boolean)`**



- <u><u><u><u>True</u></u></u></u> if the code is run in the simulator for Universal Windows Platform applications, 

- <u><u><u><u>False</u></u></u></u> otherwise.


![WEBDEV - Browser code](https://doc.pcsoft.fr/ext/images/us/WBN.png) This parameter always corresponds to <u><u><u><u>False</u></u></u></u>.




## Remarks


### Function availability
<a name="function_availability_ELTPARAGRAPHE000180"></a>

**InUniversalWindowsAppSimulatorMode** can be used in all IDEs to allow for cross-platform code. Functions or procedures that use **InUniversalWindowsAppSimulatorMode** can be shared between several products without generating any compilation error.


### Running processes containing compilation errors
<a name="running_processes_containing_compilation_errors_ELTPARAGRAPHE000194"></a>

By default, the security mechanism of WLanguage is triggered only if the line containing the compilation error is run.

For example, if a function not allowed in the current product is found in a loop (IF), the security mechanism of WLanguage will be triggered only if the line containing this function is run.
