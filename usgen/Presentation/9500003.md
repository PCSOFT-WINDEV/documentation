		MULTIPLE BROWSER TABS: "OPEN LINK IN NEW TAB"
	

	
		 
	
		Open several browser tabs on the same site
	

	
		In Session mode, end users frequently express the need to be able to open several pages simultaneously in different browser tabs, while keeping their session active. 
It's the "open in a new tab" right-click we all know in our browser. 
And what's also required is to open the same page several times (several instances), for example several customer files in parallel. 

	




 
	
		A new option on the page
	

	
		Version 2026 introduces a new "Allow opening in new tabs" option. 
When this option is checked (default mode), the end user can open additional instances of the current page in different browser tabs. 

<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=wb-application-site-dans-4-onglets.png)

	




 
	
		programming
	

	
		Programming remains unchanged. 
Each page instance automatically maintains its own server-side memory context: field values, global variables, etc... 
What's more, activating this option automatically generates an independent HFSQL context for each instance of the page, ensuring complete isolation of data between tabs. 
This function is also automatically provided on third-party databases accessed via a native connector. 

	




 
	
		open in a new browser window
	

	
		In version 2026, users can open a WEBDEV site page in a new window. Simply use the "Open in a new window" option in the link's context menu. 

	



	








<a name="les_donnees_au_fil_de_l_eau"></a>

	
		AUTOMATIC BLOCK (CHUNK) DATA FLOW MANAGEMENT: "STREAMING" DATA
	

	
		 
	
		What's it for?
	

	
		You're familiar with the way conversational AI works in a browser: once you've asked a question, the answer comes in "blocks" as the model generates them. 
The benefits are obvious: you can read the answers without waiting for a response. 
WEBDEV version 2026 makes it easy to carry out this type of processing on both the server side (sending data) and the client side (retrieving data). 
Important: data can be sent via a WEBDEV server or a third-party server. 
Data can also be received by a WEBDEV (or WINDEV or WINDEV Mobile) application or a third-party application. 

	




 
	
		The "Chunked transfer encoding" mechanism
	

	
		With version 2026, it's easy to implement block data retrieval as you go. 
Each time a block of data is received in the application (site), a callback is automatically called with the data content as a parameter. 
This mechanism can be used, for example, to receive updates from a server (SSE technology: Server-Sent Events). 

	




 
	
		Customer area &#58
	

	
		The client receives data in blocks as they are sent by the server. 
The application is not blocked and can display data progressively. 

	




 
	
		customer part &#58
	

	
		Simply create a variable of type HTTPRequest . 
Version 2026 adds a new property to the HTTPRequest type: DataProcedure . 
All you need to do is specify the procedure to be called for each "Chunk" (block of data received). 
Code example: 

```wl
MaReq is an httpRequest
MyReq.DataProcedure = ProcData
INTERNAL PROCEDURE ProcData(bufMorceau is a Buffer)
// Corresponding bufMorceau processing
// to retrieved data
END
```

In general, data is returned in the form of a "JSON Line".  
When data is received, for example, it is easy to display immediately. Customer receives data as it is processed. 

	




 
	
		server part &#58
	

	
		To implement a Chunk HTTP server, simply create a REST Webservice. 
In the web service procedure, simply call the WLanguage function WebserviceEnvoieMorceau to return each of the data chunks. 
The size of the data chunks is free and can vary. 
The size of the chunks of data is defined by the web service: according to the number of bytes, according to the recovery time.

		TCD: BRING YOUR DATA TO LIFE
	

	
		 
	
		dynamic array &#58
	

	
		The "Pivot Table control" field dynamically displays cross-referenced data from different files in a database. 
Some examples include: sales by product family, by product, by region, over time, with or without details. <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=wb-tcd%20-%20v1.png)

The Pivot Table performs all the calculation itself. 
All the data is dynamically calculated and displayed. 
Note: this crosstab field is also known as an "rOlap" cube. 

	




 
	
		Automatically created and populated
	

	
		Creating a Pivot Table control in WEBDEV 2026 is remarkably easy. Simply answer a series of questions in the wizard to define the data to be displayed. 
Filling the TCD is very simple: there's nothing to program, everything is automatic! 
The WEBDEV 2026 ROLAP engine automatically reads the data and performs the necessary calculations for all the possible levels of detail. 
It automatically populates the row and column headers. 

	




 
	
		Use
	

	
		End users can choose the desired level of detail. Rows and columns can be expanded and collapsed as required. 
The displayed result can be exported to Excel, Word, PDF, etc., as with any other table in WEBDEV. 
The Excel export functionality is widely used for simulations. 

	




 
	
		Automatic period comparison
	

	
		The end user may ask to compare a given period to the same period of previous years. via context menu options. 
For example, compare sales in October 2025 with sales in October of the previous two years. 
Percentages and differences are calculated and displayed automatically. 

	




 
	
		Asynchronous display (calculation) mode
	

	
		A DCT may have to display millions of items of information. 
Calculating this information can take some time. 
Calculation is started by programming (WLanguage function tcdCalculToutAsynchrone ). 
By default, this function is non-blocking, so as not to block the browser for the duration of the calculation. 
The principle of updating the TCD is identical (WLanguage function tcdCalculMiseAJourAsynchrone ). 
Note that it is possible to request a synchronous calculation, which is therefore blocking.

<a name="champ_bouton_segmente_en_webdev"></a>

	
		SEGMENTED BUTTON CONTROL IN WEBDEV
	

	
		 
	
		Segmented Button control available in WEBDEV
	

	
		The Segmented Button control introduced in WINDEV version 2025 is now available in WEBDEV. 
As a reminder, a Segmented Button control corresponds to a group of ON/OFF buttons within the same field. 
This type of field is visually appealing and offers standardized operation: 


- exclusive or multiple selection, depending on settings,

- each option can display a text or image.


The associated programming has also been simplified, making integration faster and more intuitive. <br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=wb-bouton-segmente-2.png)<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=wb-bouton-segmente-4.png)<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=wb-bouton-segmente-1.png)

	




 
	
		Segmented Button control &#58
	

	
		The Segmented Button control offers many configurable parameters, including: 


- Number of segments (or boxes)

- Content of each segment (box): text or image

- Selection mode: exclusive (a single choice) or multiple (several simultaneous choices)

- Anchoring and automatic width adjustment

- Display separator between segments (optional)

- Separator style (lines, margins, etc.)

- Frame customization: general field outline and button outlines


You can transform a Check Box control into a multiple-choice Segmented Button control, or a Radio Button control into a single choice Segmented Button control. 

	




 
	
		Programming
	

	
		Programming a Segmented Button control is much simpler and more centralized than programming a set of conventional Selectors, Check Box controls or ON/OFF buttons. 
In particular, it allows you to: 


- retrieve the status (checked/unchecked) of a segment,

- grayed or hide an individual segment,

- dynamically modify a segment's label or tooltip,

- add segments to the runtime,

- easily manage multilingual labels.

		JAVASCRIPT SECURITY: CSP
	

	
		 
	
		Injecting javascript into a web page
	

	
		WEBDEV allows you to develop web applications in WLanguage. When a site is generated, the WLanguage code intended for the UI is automatically converted to JavaScript so that it can be interpreted by the end user's browser. 
Since JavaScript is executed on the client side, it is technically possible to inject JavaScript code into a web page, even one generated by WEBDEV. All web browsers allow scripts to be modified or added dynamically to an HTML page. 
This possibility, while sometimes useful for debugging or automation, also presents security risks (notably XSS attacks) and must be used with care. 

	




 
	
		Protect yourself against javascript injections
	

	
		HTML features a security mechanism designed to limit the risk of JavaScript code injection. This mechanism is known as Content Security Policy (CSP). 
The CSP policy allows you to define, via a "meta" tag in the HTML, the authorized sources for loading and executing scripts, images, etc. 
It is an effective defense against XSS-type attacks. 
In version 2026, WEBDEV offers a project-level option for automatically activating CSP throughout the site. 

	




 
	
		WEBDEV generates suitable javascript code
	

	
		When the CSP option is active, the code generated by WEBDEV is modified so as to no longer allow external modifications of Javascript code. 
In particular: 


- activation generates the appropriate "meta" tag in the pages served to the browser

- scripts are explicitly declared

- script tags are validated by a key (CRC)

- Inline scripts are no longer allowed.
