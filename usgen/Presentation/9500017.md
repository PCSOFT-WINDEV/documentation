		LOW SLIDING WINDOW
	

	
		 
	
		New window option: low sliding
	

	
		Version 2024 of WINDEV Mobile offers a new, highly practical automatic window display mode: the "low sliding" mode. This window opens from the bottom of the screen. 
This mode allows you to display a minimum of information in the window, and to deploy the window (upwards) if necessary, for example to display more detailed information, or to allow input.

For more details, see [Bottom sliding window (Bottom sheet)](../WDChamp/9000216.md). 
	


 
	
		3 sizes &#58
	

	
		The bottom sliding window has 3 possible sizes. Each size can be configured. 
The window can be resized by the user, or by programming, according to the 3 sizes:

- Summary view: small window.

- Medium view: medium window.

- Maximum view: all information is displayed.




For more details, see [Bottom sliding window (Bottom sheet)](../WDChamp/9000216.md). 
	


 
	
		How to create a low sliding window
	

	
		The creation of a low sliding window uses the concept of "internal windows".. 
To enlarge this internal window, you can choose between 2 methods:

- anchors, for simple cases,

- layouts, for sophisticated UIs: with additional fields, etc.


A "low sliding" window offers 3 options:

- modal window or not: the user can continue to interact with the main window,

- automatic window (dismiss): a sill in the main window folds or closes the sliding window,

- on the UI side, window corners can be rounded.


The new WLanguage function [WinSlidingVisible](../WDLang1/1000020978.md) and the keyword **MyLowSlidingWindow** are available.

For more details, see [Bottom sliding window (Bottom sheet)](../WDChamp/9000216.md).

		ACCESSIBILITY ON MOBILE DEVICES
	

	
		 
	
		Screen reader: the phone reads what's displayed (VoiceOver and TalkBack)
	

	
		On smartphones and tablets, there is an operating mode designed for visually impaired and blind users. 
This mode is called TalkBack on Android and VoiceOver on iOS. 
In version 2024, WINDEV Mobile allows you utilize these modes. 
By default, each control now includes a generic description. You can customize this description where necessary.<br>![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=WM%20-%20Accessibilite%20-%207onglets.png)
By default, the generic description is the label or hint text of the Edit control. 
The custom description is a text entered in the application, either via the "7 tabs", or using the new properties **Accessibility Description**, **..Accessibility..Decor**, **..Accessibility..ReadOrder**.

For more details, see [Accessibility in mobile applications](../WDLang1/1410090337.md)
	


 
	
		Interactivity
	

	
		This accessibility mode also lets you interact with the application via special standard gestures:

- a single press selects and reads the field content,

- double press performs the action,

- scroll with 2 or 3 fingers,

- etc


In this accessibility mode, entering an Edit control field activates the phone's microphone (automatically or by clicking) to allow the user to dictate the text, which will then be filled in by voice recognition.
	


 
	
		Advanced options
	

	
		Accessibility mode lets you define a wide range of options.

- Do not read field content (7 tabs, "Decorative control" option: field content is not read),

- Program a specific label to be read at runtime,

- Indicate possible actions on the field; they will be read,

- Indicate a particular reading order,

- Suppress animation execution.



	


 
	
		Miscellaneous
	

	
		In addition to the options that can be activated via the 7 tabs or by programming, WINDEV Mobile applications allow you to use the following iOS and Android options. 
Android: support for "Enlarge" mode (magnifier), bold labels, high-contrast text display, color inversion. 
On iOS, color filters are supported.

		Push notifications &#58
	

	
		Android supports Topics push notifications. 
A topics is a precise subject of the application: promotion, new features of a specified model, etc. 
The application lets you subscribe to the topics of your choice. 
When the application editor wishes to send a notification to applications subscribed to a given topic, it calls the WLanguage function [NotifPushSend](../WDLang3/1000020819.md) specifying the topic concerned. 
Notifications are sent automatically by Google to all terminals whose applications have subscribed to this topic. 
With this method, there's no need to store and manage tokens for each user.

For more details, see [Push notifications](../WDLang3/1000021015.md).
