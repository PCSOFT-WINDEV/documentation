


## WDLog: Backup of HFSQL tables
			



<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000350"></a>
WDLog allows you to save all the HFSQL tables used by a WINDEV or WEBDEV application.

The following file is required to perform this backup:

- the database schema file (.WDD),

- the .REP file that contains the different paths of the tables managed by the project.




This backup can be performed:

- In interactive mode (WDLog is started).

- In "Command line" mode. The "Command line" mode allows you to include the management of file backups in your applications. In this case, no specific operation must be performed by the user.




**Important** Don't forget to note the references of all backups (date of backup, backup directory, type of backup, location of backup, etc.). This information is essential for restoring tables.

<a name="NOTE2_1"></a>


## Interactive mode
<a name="interactive_mode_ELTTEXTE000374"></a>


### Saving the HFSQL tables associated with a database schema
<a name="saving_the_hfsql_tables_associated_with_database_schema_ELTPARAGRAPHE000030"></a>

To save the HFSQL tables associated with a database schema:

1. Start WDLog.

2. Select "Backups .. Save the data" (or click the orange arrow).

3. With the "Browse" button, select:

	- The database schema file (.WDD) that contains the description of tables managed by the project.

	- The .REP file that contains the different paths of the tables managed by the project.




4. The list of tables found in the application .REP is displayed. In this list, you can:

	- Delete HFSQL tables (.FIC, .MMO or .NDX files) with the "Remove" button.

	- Add HFSQL tables (.FIC, .MMO or .NDX files) with the "Other" button.

	- Save the list of tables in a "List" file (LST extension) with the "Save" button. This list file can be read by WDLog or used in command line. 
			Caution: Each time you save, the "list" file is not emptied.

	- Open a list of tables with the "Open" button.




5. Click the "OK" button to validate the backup of tables.

6. Specify the following elements in the backup window:

	- Backup directory: Directory in which the backup directory will be created.

	- Backup name: Name of the directory in which the backup will be made.

	- Specify the backup options:

		- ***Do not create a subdirectory of the backup name*** The backup directory is not created.

		- ***Compression***: compresses files during backup. This option is used to reduce the storage size of backups. A single archive file (WDZ) will be created. 
						If this option is not checked, the files will only be copied into the backup directory.

		- ***Multi-volume***: compacts files during backup and groups files into 1.4 MB archives. This option automatically enables the "Compression" mode.

		- ***Do not save indexes (.NDX)***: reduces the size of the backup. If this option is checked, the files must be reindexed once they have been restored. 
						Reminder: WINDEV offers various solutions for reindexing the tables: WDTool (not redistributable), WDOptimizer, WDMAP (not redistributable), or by programming with the WLanguage function **HReindex**.

		- ***Do not block files***: saves files even when they are in use. This option is not recommended because the backup may contain locked records that can no longer be accessed. 
						This option is recommended in some rare cases (for applications run in background tasks that open tables but that do not use transactions, for instance). This option can also be used with applications that handle independent tables (not linked in the database schema).




7. Click the "OK" button to start the backup.

## Command Line mode
<a name="command_line_mode_ELTTEXTE000398"></a>
Two types of backups are available in command line mode:

- Saving all the tables described either in a database schema, or in the .REP file of the application.

- Saving a list of tables.




For more details, see the previous paragraph ("Interactive mode").

**Note**: A "WDJournal.LOG" file is automatically created. This file contains the operations performed.
<a name="NOTE3_2"></a>


### Saving all the tables found in a WDD file or in a .REP file
<a name="saving_all_the_tables_found_wdd_file_rep_file_ELTPARAGRAPHE000085"></a>

The following syntax allows you to save all the tables found in a WDD file or in a .REP file:


```txt
WDLog/APPLI=<NomCompletWdd ou NomCompletREP>
/REP = <BackupDir>
/COMPRESS = <True/False>
/MUET = <True/False>
/MULTI = <True/False>
/SANSBLOCAGE = <True/False>
/SANSINDEX = <True/False>
/SANSSOUSREP = <True/False>
```


Details of parameters:

| Parameter | Meaning |
| --- | --- |
| /APPLI = &lt;FullWDDName or FullREPName&gt; | Character string containing the full name of the database schema (".WDD" file) or the full name of the ".REP" file of the application. |
| /REP=&lt;BackupDir&gt; | Path where the files will be saved |
| /COMPRESS=&lt;True/False&gt; | The tables will be compressed if this option is set to "True". The files will be saved in an archive (.WDZ file).<br>Otherwise, the files will not be compressed.<br>This option is set to "True" by default. |
| /MUET=&lt;True/False&gt; | If this option corresponds to "True", if a locking error occurs, all the operations performed will be written into a result file (.LOG file). The execution of WDLog will not be locked.<br>Otherwise, a window will be displayed if an error occurs.<br>This option is set to "False" by default. |
| /MULTI=&lt;True/False&gt; | The backup archive will be divided into files (1.4 MB) if this option is set to "True". There is no need to specify the compression option if this option is used.<br>Otherwise, the archive will not be divided.<br>This option is set to "False" by default. |
| /SANSBLOCAGE=&lt;True/False&gt; | Only the tables that are not locked will be saved if this option is set to "True".<br>Otherwise, all the tables will be saved.<br>This option is set to "False" by default. |
| /SANSINDEX=&lt;True/False&gt; | The indexes of the tables will not be saved if this option is set to "True".<br>Otherwise, the indexes will be saved.<br>This option is set to "False" by default. |
| /SANSSOUSREP=&lt;True/False&gt; | The backup subdirectory will not be created if this option is set to "True". The backup will be performed in the &lt;BackupDir&gt; directory.<br>Otherwise, a backup subdirectory will be created.<br>This option is set to "False" by default. |


**Example**: The following command line saves all the files from the "C:\\MyProject\\MyDatabaseSchema.WDD" database schema in the "D:\\Save my projects" directory. These files will be compressed. The index files will not be saved.

**Warning**: If directory names use spaces, the parameter must be enclosed in quotation marks.


```wl
ExeRun("WDLog /APPLI= C:\MyProject\MyAnalysis.WDD " + ...
	"/REP=""D:\Backup of my projects"" /COMPRESS=True /SANSINDEX=True")
```

### Saving all the tables found in a database schema HFSQL Client/Server
<a name="saving_all_the_tables_found_database_schema_hfsql_clientserver_ELTPARAGRAPHE000164"></a>

The following syntax allows you to save all the tables found in an HFSQL Client/Server database:


```txt
WDLog /SERVEUR = <Server Name>
	/BD = <Database name>
	/NOM = <Username>
	/MDP_DB = <Password>
	/REP = <BackupDir>
	/COMPRESS = <True/False>
	/MUET = <True/False>
	/MULTI = <True/False>
	/SANSSOUSREP = <True/False>
	/LISTE = <FileName>
	/APPLI = <AppName>
```


Details of parameters:

| Parameter | Meaning |
| --- | --- |
| /SERVEUR=&lt;Server name&gt; | Character string containing the name or IP address of the HFSQL Client/Server server. |
| /BD = &lt;Database name&gt; | Character string containing the name of the HFSQL Client/Server database to save. |
| /NOM = &lt;Username&gt; | Character string containing the name of the user who connects to the database. |
| /MDP_DB = &lt;Password&gt; | Character string containing the password associated with the user for the database. |
| /REP=&lt;BackupDir&gt; | Path where the files will be saved |
| /COMPRESS=&lt;True/False&gt; | The tables will be compressed if this option is set to "True". The files will be saved in an archive (.WDZ file).<br>Otherwise, the files will not be compressed.<br>This option is set to "True" by default. |
| /MUET=&lt;True/False&gt; | If this option corresponds to "True", if a locking error occurs, all the operations performed will be written into a result file (.LOG file). The execution of WDLog will not be locked.<br>Otherwise, a window will be displayed if an error occurs.<br>This option is set to "False" by default. |
| /MULTI=&lt;True/False&gt; | The backup archive will be divided into files (1.4 MB) if this option is set to "True". There is no need to specify the compression option if this option is used.<br>Otherwise, the archive will not be divided.<br>This option is set to "False" by default. |
| /SANSSOUSREP=&lt;True/False&gt; | The backup subdirectory will not be created if this option is set to "True". The backup will be performed in the &lt;BackupDir&gt; directory.<br>Otherwise, a backup subdirectory will be created.<br>This option is set to "False" by default. |
| /LISTE = &lt;FileName&gt; | Full name of the table containing the list of tables to save. This text file contains one file name per line. It can be created by WDLog ("Save" button).<br>Example: <br><br><pre><code>E:\WD Stock Chart\Exe\Action.FIC <br>E:\WD Stock Chart\Exe\Share2000.FIC<br>E:\WD Stock Chart\Exe\Rate.FIC</code></pre><br> |
| /APPLI=&lt;AppName&gt; | Name of the application that will be used to identify the backup ("Automatic backup of " + &lt;AppName&gt;). |


**Example**: The following command line saves all the files in the "MabaseHF" database in the "D:\\Save my projects" directory. These files will be compressed. The index files will not be saved.


```wl
ExeRun("WDLog/SERVER=123.123.123.1" + "/BD=MaBaseHF/NOM=Flo/MDP_DB=Test" + ...
	"/REP=""D:\Saving my projects""" + ...
	"/COMPRESS=True /SANSINDEX=True /APPLI=MaBaseHF")
```

### Saving all the tables found in a list
<a name="saving_all_the_tables_found_list_ELTPARAGRAPHE000249"></a>

To save a list of tables, create a text file containing the different physical names of the tables to save. This file can be created by WDLog run in interactive mode.

The command line is as follows:


```txt
WDLog /LISTE = <FileName>
          /REP = <BackupDir>
          /COMPRESS = True
          /MUET = True
          /MULTI = True
          /SANSBLOCAGE = True
          /SANSINDEX = True
          /SANSSOUSREP = True
```


The table below presents the different elements that can be found on the command line:

| Parameter | Meaning |
| --- | --- |
| /LISTE = &lt;FileName&gt; | Name of the table containing the list of tables to save. This text file contains one file name per line. It can be created by WDLog ("Save" button).<br>Example:<br><br><pre><code>E:\WD Stock Chart\Exe\Action.FIC<br>E:\WD Stock Chart\Exe\Share2000.FIC<br>E:\WD Stock Chart\Exe\Rate.FIC</code></pre><br> |
| /REP=&lt;BackupDir&gt; | Path where the files will be saved |
| /COMPRESS=True | The tables will be compressed if this option is set to "True". The files will be saved in an archive (.WDZ file) |
| /MUET=True | If this option corresponds to "True", if a locking error occurs, all the operations performed will be written into a result file (.LOG file). The execution of WDLog will not be locked. |
| /MULTI=True | The backup archive will be divided into files (1.4 MB) if this option is set to "True". There is no need to specify the compression option if this option is used. |
| /SANSBLOCAGE=True | Only the tables that are not locked will be saved if this option is set to "True". |
| /SANSINDEX=True | The indexes of the tables will not be saved if this option is set to "True". |
| /SANSSOUSREP=True | The backup subdirectory will not be created if this option is set to "True". The backup will be performed in the &lt;BackupDir&gt; directory. |


**Example**: The following command line saves the tables in the list "C:\\MaListe.LST" in the "D:\\Backup" directory. The files currently used will not be saved.


```wl
ExeRun("WDLog /LISTE=C:\MyList.LST /REP=D:\Backup/SANSBLOCAGE=True")
```
