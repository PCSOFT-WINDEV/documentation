## Install the files of a static or PHP site on a web server
<a name="install_the_files_static_php_site_web_server_ELTTEXTE000186"></a>
To install static or PHP site files on a Web server:

1. **Start WDDeploy**: 

	- If the site displayed in WEBDEV is a static or PHP site: in the "Tools" pane, in the "Web utilities" group, click on "WDDeploy".

	- Run the WDDeploy.exe program, located in the "Programs" subdirectory of the WEBDEV installation directory. In this case, a window opens, allowing you to choose the desired type of deployment. In our case, simply select "Static site". 




2. **Create or select the profile corresponding to your site**. 
	Note: This profile is created by a wizard and can be modified via various tabs:

	- **General information**:

		- name of the profile. 
						A default name is automatically given to the profile. This name can be modified.

		- location of local files of the site ("&lt;MyProject&gt;_WEB" subdirectory for a static WEBDEV website).

		- address of WEBDEV website.

		- deploy a single language for the site. If this option is selected, your site can be deployed in one of the languages supported by the project. Please note: in this case, your site must not use options or functions that allow you to change languages or manage multiple languages.




- **Authentication**

	- location of files of deployed site (network directory or FTP server).

	- characteristics of the FTP server used to update the site (deployment via FTP only). 
						These characteristics are provided by the hosting provider. 
						Note: To use an SFTP server, enter an address such as "sftp://&lt;Adresse du serveur&gt;".

3. **Click the "Prepare" button**. WDDeploy prepares the list of files to install. 
	For an update, WDDeploy compares the files located on the development computer with those already installed.

4. If necessary, specify **the various actions to be performed** when synchronizing the various files to be installed:

	- button "Copy to local": copies the selected files from the remote site to the local site.

	- Button "Remote Copy": copies the selected files from the local site to the remote site.

	- "Erase remotely" button: deletes the selected files from the remote site.

	- button "Do nothing": perform no operation on the selected files.




5. **Click the "Synchronize" button**. The site files are automatically copied to the location specified in the profile.




Remarks: 

- The "Options" button is used to specify the synchronization options. For more details, see Remarks.

- When creating a new profile, a wizard helps you enter the parameters and offer preset profiles fro the main hosts.

## Compressing and creating an archive with the files of a remote site
<a name="compressing_and_creating_archive_with_the_files_remote_site_ELTTEXTE000210"></a>
To compress and group the files of a remote site in archives:

1. Launch WDDeploy: under the "Tools" pane, in the "Web utilities" group, click on "WDDeploy".

2. Click on "Save".

3. Enter the name of the archive to create (".WDZ" file) and specify the creation directory. The files found in the remote site specified in the profile are automatically compressed and grouped in the created archive.

## Restoring the files found in an archive
<a name="restoring_the_files_found_archive_ELTTEXTE000234"></a>
To restore the files found in an archive:

1. Launch WDDeploy: under the "Tools" pane, in the "Web utilities" group, click on "WDDeploy".

2. Click the "Restore" button.

3. Select the archive file (".WDV" file) to restore.

4. Select the directory in which the files found in the archive must be restored and validate.

## Notes
<a name="notes_ELTTEXTE000258"></a>
The WDDeploy options are as follows: 

- "**Display tooltip on file table**"Displays a tooltip for each file hovered over:

	- the name, date and time the file was created on the development computer.

	- the name, date and time the file was created on the deployment computer.




- "**Do not process subdirectories**Do not process subdirectories": ignores local site subdirectories when deploying site files.

- "**Do not propose to modify the local site, even if the remote files are more recent**": does not update the more recent remote files on the development workstation. When preparing for synchronization, WDDeploy will not prompt you to replace local files with more recent remote files.

- "**Do not display files already synchronized**"Displays only files modified since the last synchronization.
