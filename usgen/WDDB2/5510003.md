


## DB2 Native Connector: Programming with HFSQL functions
			



<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000186"></a>
To use a DB2 database with the Native Access Connector, it is necessary to **import the DB2 table structure into a WINDEV or WEBDEV database schema**. 

**Differences from SQL programming**: To manipulate DB2 data, queries are not mandatory. In fact, you can directly use HFSQL functions to read your data, perform searches and filters, etc. However, it is necessary to import the DB2 file structure into the WINDEV or WEBDEV database schema.

<a name="NOTE3"></a>
<a name="NOTE3_1"></a>


## Importing the structure of files
<a name="importing_the_structure_files_ELTTEXTE000210"></a>


### The import steps
<a name="the_import_steps_ELTPARAGRAPHE000020"></a>

1. Launch the data model editor: click on ![](https://doc.pcsoft.fr/en-US/images/image.awp?langid=214&name=Ico_Analyse.gif) among the quick access buttons.

2. On the "Database schema" tab, in the "Creation" group, expand "Import" and select "Import file/table descriptions...".

3. The wizard starts. A connection to the DB2 database is automatically established and it is associated with the tables imported into the database schema. This connection will have to be used to handle the DB2 table programmatically.




In the different steps of the wizard, choose the following options:

- Database type: DB2. 

- Connection features: Data server, User and password, Database.  

- The application will access the data in the current format.

- When the connection is established, all you have to do is select the tables that will be imported into the WINDEV or WEBDEV database schema. These tables can be handled through programming with the HFSQL functions of WLanguage. These tables will be displayed in blue in the data model editor.



<a name="NOTE3_2"></a>


### Taking into account the evolution of the DB2 database
<a name="taking_into_account_the_evolution_the_db2_database_ELTPARAGRAPHE000050"></a>

To take account of changes to tables imported into the data model editor, in the "Database schema" pane, in the "Database schema" group, pull down "Synchronization" and select "Update database schema from external databases".

A wizard starts, allowing you to:

- analyze the differences for the imported tables, 

- analyze the differences for all the DB2 tables.

## Programming
<a name="programming_ELTTEXTE000240"></a>


### 1. Establish connection
<a name="1_establish_connection_ELTPARAGRAPHE000076"></a>

To open the connection to the DB2 database, use [HOpenConnection](../WDLang4/3044107.md) and specify the name of the connection to open. The connection name was defined when importing the structure of tables into the database schema.

To modify some parameters of this connection (username or password for example), call [HConnect](../WDLang4/3044263.md).

**Note** If you try to read the table directly (function **HReadFirst**function, etc.), the connection associated with the table description in the database schema will be opened automatically.
<a name="NOTE4_2"></a>


### 2. Running queries
<a name="2_running_queries_ELTPARAGRAPHE000093"></a>

**[HExecuteQuery](../WDLang4/3044080.md)** and **[HExecuteSQLQuery](../WDLang4/3044084.md)** are used to run queries on the current database.

- **HExecuteQuery** Allows you to execute a predefined query using the query editor.

- **HExecuteSQLQuery** allows you to execute a query by directly specifying the query's SQL code and the name to be allocated to this SQL code.



```wl
// Initialize the "Customer_84" query
HExecuteQuery(CUSTOMER_84, "DB2Database", hQueryWithoutCorrection)
HExecuteSQLQuery(CustomerQry, "DB2Database", hQueryWithoutCorrection, ...
		"SELECT NAME FROM CUSTOMER")
```

<a name="NOTE4_3"></a>


### 3. Retrieving the result
<a name="3_retrieving_the_result_ELTPARAGRAPHE000111"></a>

The result is browsed using all the classic read functions: [HReadFirst](../WDLang4/3044051.md), [HReadNext](../WDLang4/3044037.md), [HReadSeek](../WDLang4/3044050.md), ...
<a name="NOTE4_4"></a>


### 4. Closing the connection
<a name="4_closing_the_connection_ELTPARAGRAPHE000127"></a>

[HCloseConnection](../WDLang4/3044095.md) is used to close the connection to the database once all the necessary queries have been run.
<a name="NOTE4_5"></a>


### Optimizing HFSQL functions
<a name="optimizing_hfsql_functions_ELTPARAGRAPHE000136"></a>

- **Query-based data-bound Table control fields are optimized.** You can sort the contents of a Table control by clicking on one of its columns.

- To avoid re-running the same query several times when browsing its result, we advise you to use the ***hNoRefresh*** constant (if the data is modified by a single computer for example).
