


## EmailOpenMail (Function)

***In french: EmailOuvreMessagerie***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Opens the default messaging software: 

- of the user on the browser.

- of the user on the current Windows computer.

## Example


```wl
// Opens the messaging software
EmailOpenMail()
```
<a name="Exemple2"></a>

```wl
// Opens the software and specifies the email recipient
// the subject and text of the email
EmailOpenMail("pcsoft@windev.com", "Subject: What's new in WINDEV", "Text: New features are now available")
```

## Syntax

`EmailOpenMail([<Email address> [, <Email subject> [, <Message body>]]])`
---

**`<Email address>: (Optional character string)`**

Email address of recipient. This address will be displayed in the messaging software.

**`<Email subject>: (Optional character string)`**

Email subject that will be displayed in the messaging software.

**`<Message body>: (Optional character string)`**

Text of message. Non-alphanumeric characters are automatically converted in order to allow for special characters to be passed (carriage returns, tabulations, ...).

## Remarks
![WEBDEV - Browser code](https://doc.pcsoft.fr/ext/images/us/WBN.png) 

### Action of EmailOpenMail
<a name="action_docparampagetitleshort_ELTPARAGRAPHE000085"></a>

**EmailOpenMail** triggers an action on the page displayed in the user's browser. However, Internet browsers allow *one single action* on the page *per process*.

For example, if a process performs the following actions:

1. Send a page to the server ([PageSubmit](../WDLang2/3058020.md)).

2. Open the messaging software (**EmailOpenMail**).




Only the last action (open the messaging software) will be performed.
<a name="NOTE0_2"></a>
![WEBDEV - Browser code](https://doc.pcsoft.fr/ext/images/us/WBN.png) 

### In which code should I use EmailOpenMail?
<a name="which_code_should_use_docparampagetitleshort_ELTPARAGRAPHE000109"></a>

In WEBDEV, some types of buttons automatically trigger an action on the page:

- "submit" button, 

- "other" button whose action differs from "none".




If **EmailOpenMail** is used in the browser-side click process of these buttons (or in a procedure called by this process), the function will be ignored. Only the button action will be performed.

**Consequences**: **EmailOpenMail** cannot be used in a code that triggers an action. This function is ignored:

- in the click code of a "submit" button.

- in the click code of an "other" button whose action is different from "none".

- if it is followed by [PageSubmit](../WDLang2/3058020.md) or by **EmailOpenMail** (in the current process, in a procedure called by the current process or in another process called by [Execute](../WDLang1/3013041.md)).




To use **EmailOpenMail** from a button (browser click code of the button), this button must have the following characteristics:

- button type: "Other".

- action: "None".

### Special cases
<a name="special_cases_ELTPARAGRAPHE000150"></a>

- A non-fatal error is triggered if no email application is found on the device. To find out whether the email application failed to start, use the [ErrorOccurred](../WDLang1/3087001.md) variable.

- ![Android](https://doc.pcsoft.fr/ext/images/us/ANDROID.png)![Android Widget ](https://doc.pcsoft.fr/ext/images/us/ANDROIDWIDGET.png)![iPhone/iPad](https://doc.pcsoft.fr/ext/images/us/IPHONE.png)![IOS Widget](https://doc.pcsoft.fr/ext/images/us/WIDGETIOS.png)![Mac Catalyst](https://doc.pcsoft.fr/ext/images/us/CATALYST.png) **EmailOpenMail** can be used in the emulator. It cannot be used in the simulator.

- **EmailOpenMail** is a non-blocking function. The code that follows the call to this function will continue to run as soon as the email application is launched. 

- There is no way to find out whether the sending of the email was validated by the user.

### Application in the background: Specific case from Android 10
<a name="application_the_background_specific_case_from_android_10_ELTPARAGRAPHE000313"></a>

Starting with Android 10, it is no longer possible to open a window when the application is in the background. 

**EmailOpenMail** can open a window. If this function is used while the application is in the background, a fatal error will occur. 

Tips: 

- It is possible to determine if the application is in the background using [InBackgroundMode](../WDLang1/1000023457.md). 

- If an application needs to interact with the user while it is in the background, the solution is to display a notification (via the [Notification](../WDLang3/1000019441.md) type). The application will be brought back to the foreground when the notification is clicked, if the **ActivateApplication** property is set to <u><u><u><u>True</u></u></u></u>. You can also open a window from the procedure passed to the **ActionClick** property.




For more details, see [Android 10: Behavior of applications in the background](../Editeurs/9000195.md).
