


## Pre-launched sessions
			



<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Overview
<a name="overview_ELTTEXTE000286"></a>
A pre-launched session is a website (or web service) session launched automatically on the web server from the WEBDEV Application Server. 

Pre-launched sessions speed up page display by anticipating time-consuming processes such as database connections and page configuration loading.

Pre-launched sessions can be used with:

- WEBDEV sites in Session mode,

- sites in Active WEBDEV Page mode,

- SOAP and REST web services. 
	In the case of web services, you can also "recycle pre-launched session".




This does not have any impact on the process. 

**Note**: Pre-launched sessions are only allowed on servers that support 10 or unlimited connections. They are not enabled on the development computer.

## Importance of pre-launched sessions
<a name="importance_prelaunched_sessions_ELTTEXTE000310"></a>


### Principle of a request for displaying an Active WEBDEV Page
<a name="principle_request_for_displaying_active_webdev_page_ELTPARAGRAPHE000034"></a>

To understand the importance of pre-launched sessions (especially for Active WEBDEV Pages), let's take a look at the principle of Active WEBDEV Pages.

When a Web user performs a request from an Active WEBDEV Page, the following operations are performed: 

1. The request is transmitted from the browser to the Web server. 

2. The Web server studies the request. 

3. The Web server transmits the request to the WEBDEV Application Server. 

4. The WEBDEV Application Server: 

	- loads the project corresponding to the page. 

	- runs the project initialization code, then the page code. 

	- returns the response to the Web server. 




5. The Web server returns the response to the browser. 





### Benefit of pre-launched sessions
<a name="benefit_prelaunched_sessions_ELTPARAGRAPHE000051"></a>

When displaying an Active WEBDEV Page, each call to the WEBDEV Application Server is entirely independent. 

As a consequence, every time a request is made (and therefore on each page change or Ajax call), the WEBDEV Application Server reloads the project and re-executes the initialization code. The project initialization code often runs "long" operations: 

- connecting to the database,

- loading configuration files,

- ...




The pre-launched sessions ask the WEBDEV Application Server to perform these operations in advance. 

Therefore, when the request of the Web user reaches the WEBDEV Application Server, the application server only has to run the request and to return the result. 

Using pre-launched sessions results in shorter response times, since part of the code is executed in advance. However, pre-launched sessions do not reduce server load (the code is still executed) and do not replace the optimization of initialization code. 

**Additional option for web services**: 
In the case of web services, an additional option is available: **recycle pre-launched sessions**. 
If this option is enabled: 

- The WEBDEV Application Server does not terminate the pre-launched session associated with the web service after it is called.

- The "Recycle a pre-launched session" event associated with the project is then executed. For example, this event can reset variables or connections specific to the client that called the web service. 

- WEBDEV Application Server resumes waiting for connection to the web service (in pre-launched session mode).

<a name="implementation_ELTTEXTE000340"></a>

4. [Enable pre-launched sessions on the WEBDEV Application Server](#NOTE3_4). 



<a name="NOTE3_2"></a>


### Enabling pre-launched sessions
<a name="enabling_prelaunched_sessions_ELTPARAGRAPHE000106"></a>

To enable pre-launched sessions:

1. Open the site or web service configuration description window:

	- In the "Project explorer" pane, select the desired configuration. 

	- Open the context menu and select "Description". 




2. On the "Options" tab, check "Enable pre-launched sessions on the Application Server". 
	**For a web service**, you can also enable connection recycling by checking "Recycle pre-launched sessions". 
	This option offers the following advantages:

	- Less server resources required, as there is no need to create a session for each request.

	- Optimal database performance, as a single connection is preserved instead of creating a new connection for each call.

	- More responsive web services. 




3. Confirm. The project will then be recompiled. 




To use pre-launched sessions, a series of events are associated with the project:

- "Initialization", a project event run before the request reaches the WEBDEV Application Server. This code is run when starting the pre-launched session. 

- "Initialization in pre-launched session mode", executed when the WEBDEV Application Server processes the request. 

- "Recycle a pre-launched session", if session recycling has been enabled for the web service configuration.




If your project configuration uses pre-launched sessions, certain functions can no longer be used in the project initialization code. The corresponding errors appear in the "Compilation error" pane. 
Reminder: To display the "Compilation errors" pane, go to the "Home" tab, "Environment" group, expand "Panes", select "Panes", and then select "Compilation errors".

### Web services: "Recycle a pre-launched session" event
<a name="web_services_recycle_prelaunched_session_event_ELTPARAGRAPHE000178"></a>

In the "Recycle a pre-launched session" event, it is important to reset all global variables that were initialized in "Initialization in pre-launched session mode".

For example, if the client's IP address is stored in a variable during a call, this variable must be emptied when the call is recycled. For example: 

```wl
// -- Initialization in pre-launched session mode
// Gets the client's IP address
gsIPAddress = WebserviceClientIPAddress()

// -- Recycle a pre-launched session
// Reset client IP address
gsIPAddress = ""
```


**Using a return value to recycle pre-launched sessions:**

- If the "Recycle a pre-launched session" event returns True or no value, the session will be recycled, provided that all deferred tasks, threads and parallel tasks have been completed once the request is made. 

- If the "Recycle a pre-launched session" event returns False, the session will not be recycled. 


This makes it possible to use one cache per pre-launched session, controlling the recycling of the session when the cache expires.

### Enabling pre-launched sessions on the server
<a name="enabling_prelaunched_sessions_the_server_ELTPARAGRAPHE000200"></a>

To enable pre-launched sessions for a site or web service:

1. Start the WEBDEV administrator. 

2. Go to the "Configuration" tab. 

3. Check "Allow pre-launched sessions.". By default, all the sites and web services have 0 pre-launched sessions. 

4. Select the site or the web service to configure ("Sites" tab or "Web services" tab). 

5. In the site parameters ("Parameters" option in the "Sites" tab) or Webservice parameters ("Parameters" option in the "Web services" tab), specify the maximum number of pre-launched sessions to be used. 

6. Confirm. 




Remarks: 

- Pre-launched sessions are counted in the total number of connections to the site (or to the web service). This information must be taken into account when configuring the WEBDEV Application Server. 

- The number of pre-launched sessions to be defined depends on the server usage and the number of requests.

	- When a user logs in (sites in Session mode) or displays a page (AWP sites), the WEBDEV Application Server uses a pre-launched session of this application, if any. Otherwise, the WEBDEV Application Server launches a normal session, as if the site didn't have any pre-launched sessions.

	- The number of available pre-launched sessions is checked every second, per site. Therefore, the number of pre-launched sessions depends on the number of connections (Session mode) or the number of times a page is displayed (AWP sites) per second.

	- Take into account the time it takes to launch the pre-launched sessions. if it takes takes more than one second to (pre) launch a session, the number of available pre-launched sessions decreases.




- Web services with session recycling:

	- sessions are not recycled in the following cases:

		- WLanguage error raised in the code.

		- thread (or parallel task) active after the response has been sent.

		- using [EndProgram](../WDLang1/3013033.md).




- sessions can be recycled a maximum of 200 times. Beyond this number, standard pre-launched sessions are used. 

- you can use [InRecycleMode](../WDLang1/1410090740.md) to determine if the current code is being executed from the "Recycle a pre-launched session" event.
