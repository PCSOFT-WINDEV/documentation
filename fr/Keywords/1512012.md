
## Instruction &lt;TOOL IA&gt;

***En anglais : AI tool***
				



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Permet de déclarer les procédures WLangage utilisables par l'IA conversationnelle du champ Chat IA (dans votre application WINDEV).

Ces procédures sont appelées des "Tools" (outils). 

Via ces "tools", le champ Chat IA pourra exécuter les opérations demandées par l'utilisateur.

**Remarques** : 

- Seules les procédures globales (présentes dans une collection de procédure) peuvent correspondre à des tools.  

- Le bloc &lt;TOOL IA&gt; doit être présent dans la procédure. Il ne doit pas être placé au dessus du prototype de la procédure. 

- Le bloc &lt;TOOL IA&gt; peut être en français ou en anglais. Il sera interprété de la même façon par le modèle d'IA utilisé. 



<a name="Exemple1"></a>
<a name="sample_code"></a>

## Exemple


```wl
PROCEDURE RécupèreMétéo(latitude est réel, longitude est réel, date_prévision est chaîne = "") : JSON

<TOOL IA>
nom: get_weather_forecast
description: Requests weather forecast information to an external webservice
paramètres:
    latitude: latitude du point où récupérer la météo
    longitude: longitude du point où récupérer la météo
    date_prévision: date pour laquelle on veut la prévision, si vide, correspond à dans 24h
<FIN>
```

<a name="XSYNTAXE"></a>
<a name="SYNTAXE1"></a>

## Syntaxe

### Description d'une procédure globale de type "Tool"

`<TOOL IA>
   nom : <Nom du tool>
   libellé : <Libellé du tool>
   description: <Description du tool>
   paramètres: <Nom et description des paramètres>
<FIN>
`
---

**`<TOOL IA> : ()`**

Signale le début de la description pour le modèle d'IA. 

**`<Nom du tool> : (Chaîne de caractères)`**

Nom du tool associé à la procédure. Ce nom sera le nom connu par le modèle d'IA. Il peut être différent du nom de la procédure. Ce paramètre est obligatoire.  

**`<Libellé du tool> : (Chaîne de caractères optionnelle)`**

Libellé du tool affiché dans le champ Chat IA lors de l'appel au tool. Si ce libellé n'est pas spécifié, seul le nom du tool sera affiché.

**`<Description du tool> : (Chaîne de caractères)`**

Description du tool en langage naturel (phrases et mots dans n'importe quelle langue). Via cette description, le modèle d'IA utilisé sait ce que fait la procédure et quand utiliser cette procédure.
**Attention** : La longueur des descriptions a un impact sur la qualité des réponses. Des descriptions trop longues peuvent confondre le modèle, et ralentir la génération.

**Remarque** : Pour résoudre des scénarios complexes, différents tools peuvent être combinés. Pour préciser cette combinaison de tools, il est recommandé d'utiliser le prompt système (plutôt que de décrire les comportements dans la description des tools).  

**`<Nom et description des paramètres> : (Chaîne de caractères)`**

Nom et description des paramètres de la procédure. Cette description est de la forme : 

```txt
paramètres :
<Nom paramètre 1> : <Description 1> 
<Nom paramètre 2> : <Description 2> 
...
```
où : 

- &lt;Nom paramètre x&gt; correspond au nom du paramètre présent dans le prototype de la procédure. 

- &lt;Description x&gt; correspond à la description du paramètre en langage naturel.




**`<FIN> : ()`**

Signale la fin de la description.

<a name="NOTE0_1"></a>

## Remarques


### Description des paramètres
<a name="description_des_parametres_ELTPARAGRAPHE000061"></a>

- Tous les paramètres de la procédure doivent être typés.

- Le type de retour est nécessairement JSON. Si le type de retour n'est pas précisé dans le prototype de la procédure, le type JSON est automatiquement utilisé. 

- Seuls certains types de données simples sont supportés :

	- Chaîne de caractères

	- Entier

	- Réel




- Les paramètres avec une valeur par défaut seront considérés comme optionnels pour l'IA. L'IA peut alors décider de ne pas passer ce paramètre, qui aura donc sa valeur par défaut.
	Exemple : 
	Un tool d'addition de 3 réels, "addition" pourrait avoir une valeur par défaut égale à 0 dans son dernier paramètre. L'IA peut donc utiliser 
	
	```txt
	addition(a, b)
	```


- Chaque paramètre doit avoir une description. Le type de chaque paramètre est déduit depuis le prototype.





### Divers
<a name="divers_ELTPARAGRAPHE000080"></a>

- Les différentes chaînes utilisées pour décrire le nom, le tool, les paramètres peuvent contenir n'importe quel caractère. Les guillemets sont mis tels quels dans la description. Il n'y a pas besoin de mettre les chaînes entre guillemets.

- Indentation des blocs : Un espace (ou une tabulation) suffit pour indenter un paramètre. Il est possible d'en utiliser autant que voulu : il en faut au moins 1. 

- Utilisation des ":" pour séparer le paramètre et la description : il est possible de mettre ou non un ou plusieurs espaces avant et après les ":".
