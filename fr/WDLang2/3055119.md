
## AJAX : Appel direct de procédures
			

<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Présentation
<a name="presentation_ELTTEXTE000238"></a>
A partir de la version 2024, l'utilisation des fonctions [AJAXExécute](../WDLang2/3055114.md) et [AJAXExécuteAsynchrone](../WDLang2/3055115.md) pour effectuer des appels AJAX n'est plus nécessaire. Il suffit d'appeler directement les procédures serveur depuis le code navigateur. 

<a name="NOTE2"></a>
<a name="NOTE2_1"></a>


## Type des procédures Serveur
<a name="type_des_procedures_serveur_ELTTEXTE000262"></a>
Une procédure serveur peut être "automatique", "accessible" ou "inaccessible". Cette caractéristique est indiquée dans le bandeau de la procédure.  

Par défaut, lors de sa création, une procédure serveur est en mode "automatique". 
<br>![](https://doc.pcsoft.fr/fr-FR/images/image.awp?langid=5&name=Ajax_procedures%20-%20HC%20N%B0002.gif)


Le mode automatique détecte automatiquement s'il y a des appels à la procédure serveur réalisés dans un code navigateur (aussi bien par la fonction [AJAXExécute](../WDLang2/3055114.md) par exemple que par un appel direct). Le nombre d'appels détectés automatiquement est affiché dans le bandeau de la procédure. 

Deux autres modes sont disponibles, sélectionnables via le menu contextuel du bandeau de la procédure : <br>![](https://doc.pcsoft.fr/fr-FR/images/image.awp?langid=5&name=Ajax_procedures%20-%20HC%20N%B0003.gif)


- le mode "Toujours accessible depuis le code navigateur" (ou accessible). 

- le mode "Jamais accessible depuis le code navigateur" (ou inaccessible). 




Il est possible de forcer le mode "Toujours accessible depuis le code navigateur" afin de gérer le cas où la détection de l'appel ne se fait pas automatiquement. C'est le cas notamment lorsque les procédures se trouvent dans des composants externes et les appels sont effectués depuis le projet. 

Il est également possible de forcer le mode "Jamais accessible depuis le code navigateur". Dans ce cas, la procédure ne pourra jamais être appelée depuis un code navigateur. 

**Remarque** : Une procédure accessible depuis le code navigateur peut être exécutée avec de mauvaises intentions. Le mode "Inaccessible" représente une sécurité supplémentaire par rapport au mode automatique. En effet, le mode "Automatique" rend la procédure "inaccessible" depuis un navigateur uniquement si elle n'est jamais appelée depuis un code navigateur.

## Appel AJAX des procédures
<a name="appel_ajax_des_procedures_ELTTEXTE000286"></a>
Une procédure "automatique" ou "Accessible" peut être appelée depuis un code navigateur. Plusieurs syntaxes d'appel sont disponibles : 

- [syntaxe synchrone](#NOTE3_2). 

- [syntaxe asynchrone](#NOTE3_3). 

- [attribut &lt;asynchrone&gt;](#NOTE3_4). 

- [automatisme de procédures](#NOTE3_5)



<a name="NOTE3_2"></a>


### Syntaxe synchrone
<a name="syntaxe_synchrone_ELTPARAGRAPHE000071"></a>Une procédure serveur appelée depuis un code navigateur déclenche automatiquement une requête AJAX. 

Tant que le résultat de la procédure serveur n'est pas récupéré, aucun autre traitement n'est exécuté : l'appel à la procédure est un appel synchrone. 

Remarque : Dans les versions précédentes, ce fonctionnement correspondait à l'appel de la fonction AJAXExécute, avec différentes constantes. 

**Exemple** : 

- Une procédure serveur VérifieCaptcha() : 
	Procédure locale VérifieCaptcha (serveur)

	```wl
	PROCEDURE VérifieCaptcha()
	
	RENVOYER CPTCH_Formulaire.Vérifie(SAI_Vérification)
	```


- Le code de clic navigateur du bouton de création de compte BTN_Créer_Compte appelle la procédure navigateur : 
	Clic navigateur du bouton BTN_Créer_Compte

	```wl
	SI PAS VérifieCaptcha() ALORS
		Erreur("La saisie captcha est incorrecte")
		RepriseSaisie(SAI_Vérification)
	FIN
	```


- Appel équivalent dans les versions précédentes : 
	Clic navigateur du bouton BTN_Créer_Compte

	```wl
	SI PAS AJAXExécute(ajaxActualiseChamps + ajaxEnvoieValeurChamps + ajaxTypesStructurés + ...
			ajaxSynchroniseVariablesServeur, VérifieCaptcha) ALORS
		Erreur("La saisie captcha est incorrecte")
		DonneFocusEtRetourUtilisateur(SAI_Vérification)
		// Equivalent à : RepriseSaisie(SAI_Vérification)
	FIN
	```




<a name="NOTE3_3"></a>


### Syntaxe asynchrone
<a name="syntaxe_asynchrone_ELTPARAGRAPHE000100"></a>Pour effectuer un appel asynchrone d'une procédure serveur en code navigateur, il est nécessaire d'utiliser l'instruction APRES .. FAIRE. 

Exemple : A chaque modification de SAI_CodePostal (navigateur)

```wl
sResult est une chaîne

APRES sResult = RécupèreCodePostalVille() FAIRE
	LISTE_CP_VILLE.SupprimeTout()
	LISTE_CP_VILLE.Ajoute(sResult)
FIN
```
Le code situé entre les mots-clés FAIRE et FIN sera exécuté après l'exécution de la procédure serveur "RécupèreCodePostalVille" de manière asynchrone. L'utilisateur ne sera pas bloqué pendant l'exécution de la procédure serveur. 

Remarque : Appel équivalent dans les versions précédentes : 
A chaque modification de SAI_CodePostal (navigateur)

```wl
SI AJAXAppelAsynchroneEnCours(ID) ALORS
	AJAXAnnuleAppelAsynchrone(ID)
FIN

ID = AJAXExécuteAsynchrone(ajaxActualiseChamps + ajaxEnvoieValeurChamps + ajaxTypesStructurés + ...
		ajaxSynchroniseVariablesServeur, RécupèreCodePostalVille, afficheResultats)

	PROCEDURE INTERNE afficheResultats(sResul chaîne)
		LISTE_CP_VILLE.SupprimeTout()
		LISTE_CP_VILLE.Ajoute(sResul)
	FIN
```



<a name="NOTE3_4"></a>


### Attribut &lt;asynchrone&gt;
<a name="attribut_ELTPARAGRAPHE000123"></a>Avec la syntaxe asynchrone, les appels à la procédure serveur ne sont pas exécutés simultanément. Les appels sont exécutés de manière successive. 

Ainsi, si la procédure est appelée 5 fois, le 5ème appel sera lancé uniquement lorsque les 4 premiers seront terminés. 

Pour lancer les appels en parallèle, il suffit d'utiliser l'attribut **&lt;asynchrone&gt;** lors de la déclaration de la procédure. Dans ce mode : 

- la procédure est exécutée dans un thread sécurisé sur le serveur. Le thread principal n'est donc pas bloqué. 

- il devient impossible d'accéder aux champs de la page. Dans ce mode, la procédure reçoit généralement le contenu des champs en paramètre et renvoie les valeurs à afficher. 




Exemple : Procédure locale récupèreCodePostalVille (serveur)

```wl
PROCÉDURE récupèreCodePostalVille(sCodePostal) <asynchrone>

tabRésultats est un tableau de chaînes
REQ_CODEPOSTAUX.ParamCodePostal = sCodePostal
HExécuteRequête(REQ_CODEPOSTAUX)
POUR TOUT REQ_CODEPOSTAUX
	TableauAjoute(tabRésultats, REQ_CODEPOSTAUX.CodePostal + " " + REQ_CODEPOSTAUX.VILLE)
FIN
RENVOYER tabRésultats
```
Etant donné le caractère asynchrone de l'exécution, le dernier appel au serveur n'est pas toujours celui qui se termine en dernier. Il peut être nécessaire de s'assurer que le code situé entre FAIRE et FIN est uniquement déclenché par le retour du dernier appel serveur lancé. Pour cela, il est possible d'utiliser l'attribut **&lt;dernier appel&gt;** dans la déclaration de la procédure. 

Exemple : 

- Procédure WLangage serveur : 
	ProcAsychrone_RenvoyerLeDernierAppel (serveur)

	```wl
	PROCEDURE ProcAsychrone_RenvoyerLeDernierAppel(Param) <asynchrone, dernier appel>
	ThreadPause(1s)
	Trace('ProcAsychrone_RenvoyerLeDernierAppel([%Param%])')
	RENVOYER "RenvoyerLeDernierAppel=[%Param%]"
	```


- Appel de la procédure : 
	Appel de la procédure (navigateur)

	```wl
	PROCEDURE INTERNE AppelleProcédure() <délai=10cs>
		APRES r = ProcAsychrone_RenvoyerLeDernierAppel(1) FAIRE
			SAI_Trace += [RC] + 'Après ProcAsychrone_RenvoyerLeDernierAppel(1) => [%r%]'
			SAI_Trace += [RC] + Trace_Get()
		FIN
	FIN
	```






<a name="NOTE3_5"></a>


### Automatisme de procédure
<a name="automatisme_procedure_ELTPARAGRAPHE000162"></a>Il est possible de définir via les automatismes de procédure si une procédure serveur est une procédure synchrone ou asynchrone. 

Pour définir les automatismes de procédure : 

1. Affichez le code de la procédure.

2. Affichez la fenêtre de description des automatismes de la procédure :

	- Cliquez sur l'icône ![](https://doc.pcsoft.fr/fr-FR/images/image.awp?langid=5&name=Proc_auto_WB%20-%20HC%20N%B0001.gif) présente dans le bandeau de la procédure.

	- Sélectionnez l'option "Paramétrer les automatismes de la procédure" dans le menu contextuel de la procédure (volet "Explorateur de projet").

	- Sélectionnez l'option "Propriétés" du menu contextuel de la procédure dans le volet "Code".




3. Dans la fenêtre qui s'affiche : <br>![](https://doc.pcsoft.fr/fr-FR/images/image.awp?langid=5&name=Proc_auto_WB%20-%20HC%20N%B0002.gif)


	- Sélectionnez le type d'automatisme : Exécution asynchrone. 

- Si nécessaire, cochez l'option "En cas d'appels concurrents, ne renvoyer que le dernier appel". Cette option est équivalente à l'attribut "**&lt;dernier appel&gt;**". 
			

4. Validez. Un pictogramme apparaît à côté du nom de la procédure pour indiquer qu'un automatisme est appliqué. <br>![](https://doc.pcsoft.fr/fr-FR/images/image.awp?langid=5&name=Proc_auto_WB%20-%20HC%20N%B0003.gif)
