
## Déclarer une application WINDEV dans le portail Azure
			

<a name="NOTE1"></a>
<a name="NOTE1_1"></a>


## Présentation
<a name="presentation_ELTTEXTE000157"></a>
L'API Graph de Microsoft permet d'interagir par programmation avec les services Microsoft 365 (Outlook, OneDrive, Teams etc.).

Voici les prérequis et les paramétrages Microsoft permettant ensuite d'appeler cette API en WLangage.

<a name="NOTE2"></a>
<a name="NOTE2_1"></a>


## Créer un compte Azure
<a name="creer_compte_azure_ELTTEXTE000181"></a>
Pour utiliser les API Graph de Microsoft, il est nécessaire de disposer d'un compte développeur Microsoft.

Créez un compte si nécessaire depuis le portail Azure : [https://portal.azure.com/](https://portal.azure.com/).





<a name="NOTE3"></a>
<a name="NOTE3_1"></a>


## Déclarer une application
<a name="declarer_une_application_ELTTEXTE000205"></a>
Pour déclarer une application auprès d'Azure : 

1. Affichez le portail Azure. 

2. Affichez la section "Microsoft Entra ID".
	Astuce : pour trouver rapidement une section dans le portail Azure, utilisez le champ de recherche en haut de la page Web.

3. Cliquez dans le menu de gauche sur "Gérer" puis "Inscriptions d'applications".

4. Cliquez sur "Nouvelle inscription".

5. Dans la page d'inscription : 

	- Saisissez le nom de l'application.

	- Sélectionnez le type de compte pris en charge par l'application.
			Par exemple, pour accéder uniquement aux emails de l'annuaire de l'entreprise, il suffit de sélectionner l'option "Comptes dans cet annuaire d'organisation uniquement".




6. Pour réaliser une authentification oAuth, il est nécessaire de fournir une URL de redirection :

	- pour la plateforme, sélectionnez toujours "Web",

	- pour l'URL, dans le cas d'une application WINDEV ou WINDEV Mobile, choisissez une URL de la forme "http://localhost:9874". Le numéro de port est libre, il suffira d'indiquer le même dans le code de l'application.
			**Important** : pour un site WEBDEV, saisissez cette URL de la forme suivante :
			"http(s)://localhost/WD310AWP/WD310Awp.exe/OAUTH2_RETOUR".




7. Validez en cliquant sur "S'inscrire" en bas de la page.

## Récupérer le ClientID et le ClientSecret
<a name="recuperer_clientid_clientsecret_ELTTEXTE000229"></a>
Pour réaliser la connexion oAuth en WLangage, il est nécessaire de disposer du **ClientID** et du **ClientSecret** de l'application. Ces informations doivent être récupérées sur le portail Azure.

**Récupérer le ClientID** :  

- Après la déclaration de l'application, la vue d'ensemble de l'application s'affiche.

- Copiez la valeur du champ "ID d'application (client)". Il s'agit du ClientID nécessaire pour la connexion en WLangage.


Note : pour retrouver ces informations sur une application déjà existante, saisissez le nom de l'application dans le champ de recherche du portail. Dans les résultats affichés, sélectionnez le choix "Application" dans la section "Microsoft Entra ID".

**Créer le ClientSecret** : 

- Dans le menu à gauche, cliquez sur "Gérer" puis "Certificats et secrets". 

- Cliquez sur "Nouveau secret client". Un assistant "Ajouter un secret client" s'affiche.

- Saisissez un nom pour le secret et choisissez une date d'expiration. La valeur recommandée est de 180 jours (6 mois) : le secret client devra alors être renouvelé tous les 6 mois. 
	Une autre solution consiste à choisir une validité plus longue que la fréquence moyenne des mises à jour de votre application. De cette façon, vos utilisateurs sont toujours à jour d'un secret valide.

- Validez la création du ClientSecret en cliquant sur "Ajouter".

- Copiez immédiatement la valeur du secret. Celle-ci n'est affichée qu'une seule fois. Cette valeur est nécessaire pour la connexion en WLangage.

## Récupérer le Tenant ID
<a name="recuperer_tenant_ELTTEXTE000253"></a>
Le "Tenant ID" doit également être récupéré : il s'agit de l'identifiant qui représente l'organisation.
Cet identifiant peut également être récupéré sur le portail Azure, en effectuant la recherche "Tenant ID" puis en cliquant sur le choix "Microsoft Entra ID" parmi les choix proposés.

## Gérer l'écran de consentement
<a name="gerer_ecran_consentement_ELTTEXTE000277"></a>
Dans les applications, lors de l'authentification, la demande d'autorisations de Microsoft est affichée à l'utilisateur.

Par défaut, l'écran de consentement est affiché pour chaque utilisateur lors de sa première connexion.

Pour que les utilisateurs n'aient pas à valider le consentement (pour avoir un flux de connexion plus fluide et éviter les erreurs de manipulation), il est possible d'accepter les permissions pour l'ensemble de votre "Entra ID". Ce paramétrage doit être réalisé sur le portail Azure.

Au niveau de l'application déclarée, dans le menu à gauche, cliquez sur "API autorisées" puis "Ajouter une autorisation".
Un assistant se lance :

- Sélectionnez "Microsoft Graph" puis "Autorisations déléguées".

- Recherchez et cochez l'autorisation à ajouter (par exemple "Mail.ReadBasic" pour lire les emails).

- Cliquez sur "Ajouter des autorisations" pour valider.

- Cliquez ensuite sur "Accorder un consentement d'administrateur". Toutes les permissions pour tous les membres de votre annuaire EntraID seront alors automatiquement validées.
