
## SectionCritiqueFin (Fonction)

***En anglais : CriticalSectionEnd***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Signale la fin d'une section critique : un autre thread pourra exécuter le code.

Pour signaler le début de la section critique, utilisez la fonction [SectionCritiqueDébut](../WDLang1/3077001.md).

![Windows](https://doc.pcsoft.fr/ext/images/fr/WINDOWS.png)![Linux](https://doc.pcsoft.fr/ext/images/fr/LX.png)![iPhone/iPad](https://doc.pcsoft.fr/ext/images/fr/IPHONE.png)![Apple Watch](https://doc.pcsoft.fr/ext/images/fr/APPLEWATCH.png) Lorsque les appels aux fonctions [SectionCritiqueDébut](../WDLang1/3077001.md) et [SectionCritiqueFin](../WDLang1/3077005.md) sont situés dans le même bloc de code, il est conseillé d'utiliser le type [SectionCritique](../WDLang1/1000023972.md) et la syntaxe [UTILISER ... DANS](../Motscles/1510025.md). 
Exemple : 

```wl
// Utilisation d'une variable de type Section Critique
S est une SectionCritique

// Utilisation pour un bloc de code
//---------------------------
UTILISER S DANS
	// code protégé par la section critique
	// un seul thread pourra exécuter ce code à un moment donné
FIN
```


## Syntaxe

### Terminer une section critique sur une section de code : utilisation du type SectionCritique

`SectionCritiqueDébut(<Section critique>)`
---

**`<Section critique> : (Variable de type SectionCritique)`**

Nom de la variable de type [SectionCritique](../WDLang1/1000023972.md) permettant d'identifier la section critique. 


<a name="SYNTAXE2"></a>
![Windows](https://doc.pcsoft.fr/ext/images/fr/WINDOWS.png)![Linux](https://doc.pcsoft.fr/ext/images/fr/LX.png)![iPhone/iPad](https://doc.pcsoft.fr/ext/images/fr/IPHONE.png)![Apple Watch](https://doc.pcsoft.fr/ext/images/fr/APPLEWATCH.png) 
### Termine une section critique sur une variable

`SectionCritiqueFin([<Nom de la variable>])`
---

**`<Nom de la variable> : (Tout type)`**

Nom de la variable WLangage qui a été protégée dans une section critique par la fonction [SectionCritiqueDébut](../WDLang1/3077001.md). Cette variable doit être définie avec l'attribut [&lt;section critique&gt;](../WDLang1/1000021292.md).


<a name="SYNTAXE3"></a>

### Termine une section critique nommée sur une portion de code

`SectionCritiqueFin([<Nom de la section>])`
---

**`<Nom de la section> : (Chaîne de caractères optionnelle)`**

Identifie la section critique.

## Remarques
<a name="NOTE0_2"></a>
<a name="NOTE0_3"></a>


### Divers
<a name="divers_ELTPARAGRAPHE000115"></a>

- Pour plus de détails sur les sections critiques, consultez [Gérer les sections critiques](../WDLang1/1000021292.md). 

- Si un thread est détruit alors qu'il est dans une section critique, la section critique est automatiquement libérée.

- Il ne peut y avoir qu'un seul thread dans toutes les sections du même nom.

- Si des sections utilisent un nom différent, un thread peut exécuter le code d'une section pendant qu'un autre thread exécute le code d'une autre section.





- ![](https://doc.pcsoft.fr/fr-FR/images/image.awp?langid=5&name=WDThreadUI.gif) ***Exemples didactiques (WINDEV)*** : **WD ThreadUI** <br>L'utilisation de threads ou de tâches parallèles est très souvent obligatoire afin de répondre au besoin de rapidité des utilisateurs.<br>Avec le WLangage de WINDEV, le lancement de traitements en tâche de fond est simplifié à l'extrême avec :<br>- les fonctions de gestion des threads,<br>- le type Thread,<br>- les tâches parallèles.<br>Mais attention, s'il est facile de lancer un traitement en arrière plan, il faut néanmoins être précautionneux sur l'UI de l'application : seuls les traitements exécutés dans le thread principal sont autorisés à mettre à jour l'interface (affecter un champ, remplir une liste, combo, table, zone répétée...).<br>Cet exemple vous montre 4 façons de mettre à jour l'UI de vos applications avec des données provenant de threads secondaires.
