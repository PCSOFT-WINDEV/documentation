
## fRepCrée (Fonction)

***En anglais : fMakeDir***



<a name="XUtilisation"></a>
<a name="Utilisation"></a>
<a name="description"></a>
Crée un répertoire (et les répertoires intermédiaires si nécessaire).




<a name="Exemple1"></a>
<a name="sample_code"></a>

## Exemple
<a class="notetitle" target="_blank" href="$DOC$=1000003036043&name=frepcree_fonction">Voir des exemples supplémentaires</a>
![WINDEV](https://doc.pcsoft.fr/ext/images/fr/WD.png)![WEBDEV - Code Serveur](https://doc.pcsoft.fr/ext/images/fr/WBS.png)![Etats et Requêtes](https://doc.pcsoft.fr/ext/images/fr/ER.png)![Java](https://doc.pcsoft.fr/ext/images/fr/JAVA.png)![Code Utilisateur (MCU)](https://doc.pcsoft.fr/ext/images/fr/MCU.png)![PHP](https://doc.pcsoft.fr/ext/images/fr/PHP.png)![Ajax](https://doc.pcsoft.fr/ext/images/fr/AJAX.png) 
```wl
// Création d'un répertoire
ResCréation = fRepCrée("C:\MesRépertoires\MesFichiers")
// Si le répertoire MesRépertoires n'existe pas, 
// la fonction crée le répertoire MesRépertoires puis le répertoire MesFichiers
```

## Syntaxe

`<Résultat> = fRepCrée(<Chemin du répertoire à créer>)`
---

**`<Résultat> : (Booléen)`**



- <u><u><u><u>Vrai</u></u></u></u> si le répertoire a été créé ou si ce répertoire existe déjà, 

- <u><u><u><u>Faux</u></u></u></u> dans le cas contraire. Pour connaître le libellé de l'erreur, utilisez la fonction [ErreurInfo](../WDLang1/3013008.md) avec la constante *errMessage*.




![Android](https://doc.pcsoft.fr/ext/images/fr/ANDROID.png)![Widget Android](https://doc.pcsoft.fr/ext/images/fr/ANDROIDWIDGET.png)![Java](https://doc.pcsoft.fr/ext/images/fr/JAVA.png) Si le répertoire à créer existe déjà, la fonction retourne <u><u><u><u>Faux</u></u></u></u>.

**`<Chemin du répertoire à créer> : (Chaîne de caractères)`**

Nom et chemin complet (ou relatif) du répertoire à créer (260 caractères maximum). Un chemin de type UNC peut être utilisé. Ce nom de répertoire peut être terminé indifféremment par "\\" ou non. Si aucune lettre de lecteur n'est précisée, le répertoire est créé dans le répertoire en cours. Si ce paramètre contient plusieurs répertoires n'existant pas, tous les répertoires nécessaires sont créés.

![Windows](https://doc.pcsoft.fr/ext/images/fr/WINDOWS.png)![Linux](https://doc.pcsoft.fr/ext/images/fr/LX.png) Ce paramètre peut être au format Ansi ou Unicode.

![Android](https://doc.pcsoft.fr/ext/images/fr/ANDROID.png)![Widget Android](https://doc.pcsoft.fr/ext/images/fr/ANDROIDWIDGET.png) Ce paramètre peut correspondre à un chemin complet ou relatif par rapport au répertoire en cours (connu avec la fonction [fRepEnCours](../WDLang1/3036022.md)). Ce paramètre est sensible à la casse. 
**Rappel** : Sous Android, sur l'appareil comme sur l'émulateur, le système de fichiers est en lecture seule. Une application a uniquement le droit d'écrire dans son répertoire d'installation ou dans un de ses sous-répertoires, ainsi que sur la mémoire externe (SDCard).

![Android](https://doc.pcsoft.fr/ext/images/fr/ANDROID.png)![Widget Android](https://doc.pcsoft.fr/ext/images/fr/ANDROIDWIDGET.png)![Java](https://doc.pcsoft.fr/ext/images/fr/JAVA.png) Il n'est pas possible d'utiliser une syntaxe de chemin de fichier sans séparateur entre le nom du lecteur et le premier répertoire (ou fichier). La syntaxe "c:MonRépertoire" n'est pas supportée. 
![iPhone/iPad](https://doc.pcsoft.fr/ext/images/fr/IPHONE.png)![Widget IOS](https://doc.pcsoft.fr/ext/images/fr/WIDGETIOS.png)![Mac Catalyst](https://doc.pcsoft.fr/ext/images/fr/CATALYST.png) Ce paramètre peut correspondre à un chemin complet ou relatif par rapport au répertoire en cours (connu avec la fonction [fRepEnCours](../WDLang1/3036022.md)). Ce paramètre est sensible à la casse. 
**Rappel** : Sous les iPhone/iPad, sur l'appareil comme sur l'émulateur, le système de fichiers est en lecture seule. Une application a uniquement le droit d'écrire dans son répertoire d'installation ou dans un de ses sous-répertoires.

### Fonctionnement sous Windows Vista (et supérieur)
<a name="fonctionnement_sous_windows_vista_superieur_ELTPARAGRAPHE000239"></a>Si cette fonction ne fonctionne pas correctement sous Windows Vista (et supérieur), il est nécessaire de vérifier si le fichier ou le répertoire manipulé ne se trouve pas dans un des répertoires système (répertoire de Windows ou répertoire "Program Files").

**En effet, sous Windows Vista (et supérieur), avec le [mécanisme de l'UAC](../Editeurs/2025014.md) (contrôle des comptes utilisateurs) activé**, il est nécessaire d'avoir les privilèges administrateur pour manipuler / modifier des fichiers ou des répertoires présents dans les répertoires système (répertoire de Windows ou répertoire "Program Files").

**Conseil de programmation** : Si vous devez manipuler / modifier des fichiers ou des répertoires, sans avoir besoin de privilèges administrateur, il est conseillé :

- de ne pas écrire dans le répertoire de Windows ou dans le répertoire "Program Files",

- d'utiliser le répertoire système correspondant à l'application (connu par la fonction [SysRep](../WDLang1/3073026.md) par exemple avec la constante *srAppDataCommun*).




**Remarque** : Sous Windows Vista (ou supérieur), le mécanisme de la virtualisation permet de rendre les applications compatibles Vista. Si le fichier est créé dans un répertoire système sans avoir les droits nécessaires, ce fichier sera réellement créé dans un autre répertoire (C:\\Users\\&lt;LOGIN&gt;AppData\\Local\\VirtualStore\\Windows\\). Dans ce cas, le fichier ne pourra pas être partagé entre plusieurs applications.
